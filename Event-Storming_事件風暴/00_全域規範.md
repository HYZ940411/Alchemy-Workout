# 全域規範

> 本檔記錄跨所有流程共通的事件風暴規範，由 `/es-formulation` 依使用者裁決逐項寫入。

## Event 共通攜帶資訊

所有流程中的每一個 Event，發生時皆必須攜帶以下共通欄位：

| 欄位 | 型別 | 說明 |
|------|------|------|
| 事件ID | UUID | 事件唯一識別碼 |
| 發生時戳（UTC） | Timestamp（UTC，毫秒精度） | 事件發生的絕對時間 |
| 發生時戳（使用者當地時區） | Timestamp + 時區代碼 | 供跨時區規則判定使用 |
| 觸發 Actor | Actor 識別碼 | 執行 Command 導致此 Event 的角色 |
| 關聯 Aggregate ID | ID | 此 Event 所改變狀態的 Aggregate |

共通欄位之外，各 Event 另行定義其專屬欄位。

### 規則

- 每一個 Event 必須同時記錄 UTC 時戳與使用者當地時區時戳。
- 跨時區規則（簽到換日、每日任務重置、中斷判定）一律以使用者當地時區時戳為判定基準。
- UTC 時戳的精度為毫秒。

*來源：`.clarify/resolved/event/全流程Event_每個Event應攜帶哪些資訊與時間戳.md`（選項 B）*

## 通知 / 提醒類 Event 的軟體邊界

以下 6 個通知 / 提醒類 Event 保留為業務 Event，但標記為**不需精準追蹤**：僅記錄發生事實，不做嚴格規則驗收。

| Event | 所屬流程 |
|-------|----------|
| 每日登入提醒已發送 | 每日簽到流程 |
| 連簽中斷預告已發送 | 每日簽到流程 |
| 補簽提醒已發送 | 每日簽到流程 |
| 中斷預告已發送 | 訓練中斷流程 |
| 連練中斷通知已發送 | 訓練中斷流程 |
| 退步預告已發送 | 訓練中斷流程 |

### 規則

- 上述 Event 維持各自獨立，不合併為單一「通知已發送」Event。
- 上述 Event 不建立 Precondition / Postcondition 驗收條件。
- 推播發送失敗不阻斷其所屬流程的後續 Event。

*來源：`.clarify/resolved/event/全流程Event_通知與提醒類Event是否應納入軟體邊界.md`（選項 C）*

## Event 冪等性原則

所有流程中的 Event，重複發生時一律以 **Command 請求識別碼**去重。

### 規則

- 每一個 Command 請求必須攜帶請求識別碼。
- 系統以請求識別碼判定重複：識別碼已處理過者視為重複請求。
- 重複請求回傳原次執行的結果，不重複產生 Event。
- 本原則統一適用於全模型，各 Event 不另行定義冪等規則。

*來源：`.clarify/resolved/event/全流程Event_各Event重複發生時的冪等處理原則.md`（選項 A）*

## Actor 清單

全模型的 Actor 共五種，所有 Command 的執行者必須指派為其中之一。

| Actor | 類型 | 說明 |
|-------|------|------|
| 使用者 | 人 | 平台的一般使用者 |
| 管理員 | 人 | 平台管理員，具備審核與處置權限 |
| 系統 | 自動 | 排程、自動判定與套用調整的觸發者 |
| AI | 自動 | 產出訓練調整建議的角色，獨立於外部系統 |
| 外部系統 | 外部 | 平台外的服務，如 Google / Apple、App Store、物流商 |

### 規則

- 發文者、互動者、學徒、教官、成員、對方皆非獨立 Actor，一律歸為「使用者」。
- 上述稱呼僅為使用者在特定情境下的角色描述，不得作為 Command 的 Actor 值。
- 教官不因具備額外權限而獨立為 Actor，其權限差異以使用者的教官身分旗標表達。
- 團隊隊長不為獨立 Actor，其權限差異以團隊內的角色欄位表達。
- AI 僅負責產出建議，不執行套用；套用調整的 Actor 為系統。
- 本清單非封閉清單，新增 Actor 需經明確裁決。

*來源：`.clarify/resolved/command/Actor_模型中各角色名稱的定義與統一.md`（選項 A′）；
AI 一項與清單封閉性之修訂來源：`.clarify/resolved/command/AI已調整訓練_AI是否視為獨立Actor.md`（選項 D″）*

## Aggregate 邊界

### 使用者 Aggregate

「使用者」為核心 Aggregate，含身分與個人資料、三項成長數值、兩個旗標。

| 欄位群 | 內容 |
|--------|------|
| 身分與個人資料 | 帳密、身高、體重、性別、生日、單位偏好、健身偏好、時區 |
| 成長數值 | 經驗值、能力值、階級 |
| 旗標 | 社群互動功能解鎖旗標、教官身分旗標 |

#### 已定義欄位

| 欄位 | 型別 | 單位 | 合法範圍 | 說明 |
|------|------|------|----------|------|
| 身高 | float（一位小數） | 公分 | 50–250 | 儲存一律以公制為準 |
| 體重 | float（一位小數） | 公斤 | 20–300 | 儲存一律以公制為準 |
| 生日 | date | — | 對應年齡 13–120 歲 | 年齡為衍生欄位，不直接儲存 |
| 單位偏好 | 列舉 | — | 公制 / 英制 | 僅影響顯示，不影響儲存 |
| 能力值 | 6 維數值（每維 int） | — | 各維獨立 | 依肌群分維：胸 / 背 / 腿 / 肩 / 手 / 核心 |
| 性別 | 列舉 | — | 男 / 女 | 必填，二元列舉 |

其餘欄位的型別、單位與合法範圍由後續釐清項目逐一定義。

#### 規則

- 身高與體重一律以公制儲存，英制僅為顯示偏好，由單位偏好欄位決定。
- 英制顯示範圍由公制範圍換算：身高 20–98 in、體重 44–661 lb，不另設獨立範圍。
- 年齡不直接儲存，一律由生日衍生計算。
- 年齡未滿 13 歲者不得完成註冊。
- 性別為必填的二元列舉，值域為男 / 女，不含其他選項，亦不可留白。

- 經驗值與階級的門檻計算關係在使用者 Aggregate 內部保證一致，不跨 Aggregate。
- 能力值的提升與退步皆改動使用者 Aggregate。
- 能力值為 6 個肌群維度：胸、背、腿、肩、手、核心，各維獨立升降。
- 能力值的提升依動作所屬肌群，只提升該動作對應的維度。
- 「能力值已提升」「能力值已退步」「能力值已部分回復」三個 Event 皆須攜帶所影響的肌群維度。
- 動作 Aggregate 須具備「所屬肌群」欄位，值域為上述 6 個肌群。
- 訓練屬性（力量 / 耐力 / 爆發）本階段不進模型，列為未來擴充。
- 能力值退步為每滿 120 小時未訓練退步固定百分比，可持續發生。
- 能力值退步的下限為註冊初始值，不低於該值。
- 六個肌群維度各自獨立計時：自該維最後一次訓練起算滿 120 小時，才退該維。
- 退步僅影響逾時的維度，其餘維度不受影響。
- 社群互動功能解鎖旗標為單調遞增，一經設定不可撤銷。
- 教官身分旗標承載教官的權限差異，教官不因此成為獨立 Actor。

### 獨立 Aggregate 清單

以下 32 項各自為獨立 Aggregate，不併入使用者：

| 分類 | Aggregate |
|------|-----------|
| 訓練 | 訓練紀錄、訓練進度條、動作、自訂訓練、訓練計畫、連續訓練 |
| 成長設定 | 階級設定 |
| 簽到 | 連續簽到、補簽券 |
| 任務 | 新手任務範本、新手任務、每日任務池、每日任務、回歸任務 |
| 成就與獎勵 | 成就定義、使用者成就解鎖紀錄、獎勵定義、獎勵發放紀錄、個人排行榜分數 |
| 社群 | 貼文、檢舉 |
| 師徒與教官 | 師徒關係、教官聲望、帶徒上限設定、教官測驗設定、教官測驗 |
| 團隊 | 團隊 |
| 商城 | 商品、訂單、虛擬貨幣 |
| 訂閱 | 權益設定、會員權益 |

#### 規則

- 個人排行榜分數不併入使用者，因其具週期重置與跨使用者排序的獨立生命週期。
- 訓練紀錄不併入使用者，因其為一人多筆的高頻寫入資料。

*來源：`.clarify/resolved/aggregate/使用者_使用者Aggregate的欄位與邊界尚未定義.md`（選項 B-1）*

### 成就結構

成就拆為兩個 Aggregate，因兩者生命週期不同。

| Aggregate | 層級 | 說明 |
|-----------|------|------|
| 成就定義 | 平台級 | 成就的類型、門檻、對應獎勵；由平台維護，可調整 |
| 使用者成就解鎖紀錄 | 每使用者 | 該使用者已解鎖的成就與解鎖時點 |

全模型共 7 類成就，皆共用上述結構：

| 成就類型 | 所屬流程 |
|----------|----------|
| 連簽成就 | 每日簽到流程 |
| 累簽成就 | 每日簽到流程 |
| 連續訓練成就 | 訓練結算流程 |
| 累積訓練成就 | 訓練結算流程 |
| 新手成就 | 新手任務流程 |
| 互動成就 | 發文與互動流程（分享 / 發文 / 按讚 / 留言 4 類） |
| 粉絲成就 | 關注流程 |

#### 規則

- 成就門檻屬成就定義 Aggregate，調整門檻不改動任何既有的解鎖紀錄。
- 使用者成就解鎖紀錄一經寫入不再變動。
- 7 個「⋯成就已解鎖」Event 維持各自獨立，不合併為單一「成就已解鎖」Event。

*來源：`.clarify/resolved/aggregate/成就_各類成就的統一資料結構.md`（選項 B）*

### 動作 Aggregate

動作分兩種來源，共用同一個 Aggregate。

| 欄位 | 型別 | 說明 |
|------|------|------|
| 名稱 | 字串 | 動作名稱 |
| 所屬肌群 | 列舉 | 胸 / 背 / 腿 / 肩 / 手 / 核心 |
| 所需器材 | 列舉 | 健身房（全器材）/ 居家器材 / 徒手 |
| 示範內容 | — | 動作示範 |
| 來源 | 列舉 | 平台動作庫 / 使用者自建 |
| 建立者 | 使用者 ID | 來源為使用者自建時才有值 |

#### 規則

- 平台動作庫由平台維護，所有使用者皆可選用。
- 使用者可自建私人動作，僅建立者本人可選用。
- 使用者自建的動作**不計入能力值計算**，訓練該動作不產生「能力值已提升」。
- 所需器材的值域與註冊流程「使用者已選擇健身器材」一致。

*來源：`.clarify/resolved/aggregate/動作_動作清單的來源與欄位定義.md`（選項 B）*

### 訓練紀錄 Aggregate

| 欄位 | 型別 | 單位 | 合法範圍 |
|------|------|------|----------|
| 重量 | float（精度 0.5） | 公斤 | ≥ 0 |
| 次數 | int | 次 | ≥ 1 |

#### 規則

- 重量允許為 0，用於自身體重（徒手）動作。
- 重量不允許負值。
- 次數最小為 1，不記錄次數為 0 的失敗組。
- 重量一律以公制儲存，英制顯示沿用使用者 Aggregate 的單位偏好欄位，訓練紀錄不另存單位。

*來源：`.clarify/resolved/aggregate/訓練紀錄_重量的單位精度與零或負值是否合法.md`（選項 A）*

### 訓練進度條 Aggregate

進度百分比 ＝ **已完成組數 / 總計畫組數**

#### 規則

- 訓練進度條**不要求單調遞增**。
- AI 調整訓練導致總計畫組數變動時，進度百分比允許下降。
- 總計畫組數為 0（空白課表）時不顯示進度條，進度條不成立。

*來源：`.clarify/resolved/aggregate/訓練進度條_進度百分比的計算公式為何.md`（選項 D①）*

### 連續訓練 Aggregate

連續訓練天數以**自然日**計數，並提供 **36 小時寬限**。

#### 規則

- 同一自然日內訓練一次以上，該日計為 1 天，不重複計數。
- 距上一次訓練未超過 36 小時再次訓練，連續天數續計，即使中間跨過一個未訓練的自然日。
- 距上一次訓練超過 36 小時，連續訓練天數歸零。
- 自然日與 36 小時的判定一律以使用者當地時區時戳為基準。

*來源：`.clarify/resolved/aggregate/連續訓練_連續訓練天數的判定基準.md`（選項 C）*

### 連續簽到 Aggregate

| 欄位 | 型別 | 初始值 | 說明 |
|------|------|--------|------|
| 連續天數 | int | 首次簽到為 1 | 簽到中斷時歸零 |
| 累計天數 | int | 首次簽到為 1 | 永不歸零，單調遞增 |
| 中斷前連續天數 | int | 0 | 中斷發生時保存歸零前的連續天數，供補簽回復使用 |
| 歷史最長連續天數 | int | 首次簽到為 1 | 永不減少，記錄歷來達到過的最大連續天數 |

#### 規則

- 累計天數為單調遞增，任何情況下皆不減少。
- 歷史最長連續天數為單調遞增，任何情況下皆不減少。
- 連續天數於簽到中斷時歸零，歸零前先將原值寫入中斷前連續天數。
- 補簽成功時，連續天數回復為：中斷前連續天數 ＋ 補回的天數 ＋ 中斷後已簽到的天數。
- 補簽券使用後，中斷前連續天數清空為 0。
- 不變條件：累計天數 ≥ 歷史最長連續天數 ≥ 連續天數。
- 不變條件：中斷前連續天數 > 0 代表存在一次尚可補救的中斷。

*來源：`.clarify/resolved/aggregate/連續簽到_連續天數與累計天數的定義與型別.md`（選項 D′）*

### 虛擬貨幣 Aggregate

站內虛擬貨幣只有一種，名稱為**金幣**。

| 欄位 | 型別 | 說明 |
|------|------|------|
| 金幣餘額 | int | 持有的金幣數量 |

#### 規則

- 全模型僅有金幣一種虛擬貨幣，不區分免費幣與付費幣。
- 金幣的取得來源為各類獎勵發放與儲值。
- 金幣的消耗用途為購買虛擬商品與購買補簽券。
- 金幣餘額不得為負值。

*來源：`.clarify/resolved/aggregate/虛擬貨幣_虛擬貨幣的種類取得與消耗規則.md`（選項 A）*

### 補簽券 Aggregate

| 欄位 | 型別 | 說明 |
|------|------|------|
| 持有張數 | int | 上限 5 張 |

#### 規則

- 補簽券的取得來源為簽到成就、任務獎勵，以及以金幣購買。
- 持有上限為 5 張，達上限後不再取得，購買亦受此上限限制。
- 補簽券無有效期限，不會過期，故無「補簽券已到期」Event。

*來源：`.clarify/resolved/aggregate/補簽券_補簽券的取得來源與持有上限.md`（選項 B + 第 38 題之使用者更正）*

### 自訂訓練 Aggregate 狀態機

| 狀態 | 說明 |
|------|------|
| 草稿 | 設計中，尚未儲存 |
| 已儲存 | 私人課表，僅自己可用 |
| 已發布 | 對關注者可見 |
| 已申請公開 | 已送出公開申請，待管理員審核 |
| 已公開 | 審核通過，進入公開課表 |

#### 合法轉換

| 起始狀態 | 觸發 Event | 目標狀態 |
|----------|-----------|----------|
| 草稿 | 使用者已儲存自訂訓練 | 已儲存 |
| 已儲存 | 使用者已發布自訂訓練 | 已發布 |
| 已發布 | 使用者已取消發布自訂訓練 | 已儲存 |
| 已發布 | 使用者已申請公開訓練 | 已申請公開 |
| 已申請公開 | 管理員已審核公開訓練 | 已公開 |
| 已申請公開 | 公開訓練審核未通過 | 已發布 |

#### 規則

- 發布與申請公開皆為選用步驟，停留在已儲存即可自己使用。
- 已發布可退回私人，回到已儲存狀態。
- 審核未通過退回已發布狀態，可修改後重新申請，不限次數。
- 「發布」的可見對象為關注者，不使用「追蹤者」一詞。

*來源：`.clarify/resolved/aggregate/自訂訓練_已儲存與已發布與已申請公開三個狀態的狀態機.md`（選項 B）*

### 新手任務範本 Aggregate

新手任務的項目清單由管理員於後台設定，屬平台級可調參數。

| Aggregate | 層級 | 說明 |
|-----------|------|------|
| 新手任務範本 | 平台級 | 任務項目清單與數量；由管理員維護，可調整 |
| 新手任務 | 每使用者 | 指派給該使用者的任務與完成進度 |

#### 規則

- 新手任務範本由管理員設定，非寫死於系統。
- 「新手任務已指派」時依當時的範本內容產生該使用者的新手任務。
- 範本調整不改動任何使用者已指派的新手任務。
- 全平台使用同一份範本，不依註冊資料或會員身分產生差異。

*來源：`.clarify/resolved/aggregate/新手任務_任務項目內容與數量由誰定義.md`（選項 B）*

### 每日任務池 Aggregate

每日任務的項目由管理員於後台設定任務池，每日隨機抽取指派。

| Aggregate | 層級 | 說明 |
|-----------|------|------|

### 團隊分數 Aggregate

團隊有兩個獨立分數與兩個獨立排行榜，衡量不同的事。

| Aggregate | 計算方式 | 衡量對象 |
|-----------|----------|----------|
| 團隊日常分數 | 全體成員個人排行榜分數加總 | 成員的訓練努力程度 |
| 團隊限時分數 | 完成限時任務的成員數 × 固定分，全員完成時另加成 | 團隊的動員參與率 |

#### 規則

- 團隊日常分數直接沿用成員的個人排行榜分數，不另定一套計分規則。
- 團隊限時分數不依訓練量計算，每位成員完成一次限時任務即加固定分。
- 團隊全體成員皆完成限時任務時，額外給予加成。
- 限時任務為每日指派，非以排行榜週期為單位。
- 兩個分數不合併，兩個排行榜各自維護，對應兩種獨立的排行獎勵。
- 固定分的數值與全員完成的加成幅度尚未給定（待決策 Partial）。

## 統一語言：已定案術語

本章節為本模型的標準術語詞彙表。全模型的 Event、Command、Aggregate 命名一律以本表為準，
不另建獨立詞彙表檔案。

### 三個成長數值的區別

模型中有三個容易混淆的數值，其歸屬、用途與生命週期皆不同。

| 術語 | 所屬 Aggregate | 用途 | 生命週期 |
|------|----------------|------|----------|
| 經驗值 | 使用者 | 判定階級提升 | 單調遞增，永不減少 |
| 能力值 | 使用者 | 表達 6 個肌群的訓練成果 | 可升可降，下限為註冊初始值 |
| 個人排行榜分數 | 個人排行榜分數（獨立） | 排行榜排名與排行獎勵 | 每個排行榜週期結算時歸零 |

- 三者為**三個不同的數值**，不可互相取代或混用。
- 「經驗值已提升」「能力值已提升」「個人排行榜分數已增加」為三個不同的 Event。
- 同一次訓練結算可同時觸發三者，但各自的計算方式不同。

## 跨流程同名 Event

以下 Event 在多條流程中出現，經確認為**同一個事實**，統一定義一次，來源為其攜帶資訊。

| Event | 出現流程 | 攜帶的來源值 |
|-------|----------|--------------|
| 經驗值已提升 | 新手任務流程、每日簽到流程、訓練結算流程 | 新手任務 / 每日簽到 / 訓練結算 |
| 能力值已提升 | 新手任務流程、訓練結算流程 | 新手任務 / 訓練結算 |
| 個人排行榜分數已增加 | 每日任務流程（2 處）、訓練結算流程 | 每日任務進度 / 每日任務全部完成 / 訓練結算 |

### 規則

- 同名跨流程 Event 僅有一份定義，不依來源拆分為多個 Event。
- 來源以攜帶資訊區分，各來源的提升幅度由該來源流程的 Policy 決定。
- 「能力值已提升」與訓練中斷流程的「能力值已退步」為兩個獨立 Event，不合併為單一變動 Event。

### 規則

- 「中斷」一詞不得單獨使用，必須帶明確主體（單次訓練 / 連續訓練天數）。
- 「追蹤」為棄用詞，一律改用「關注」，對應 Event 為「使用者已關注帳號」。
- Policy 與 Rule 中引述行為時，一律直接使用既有 Event 全名，不得另造簡稱。

*來源：`.clarify/resolved/event/連練天數已中斷_與訓練紀錄流程的使用者訓練已中斷如何區分.md`（選項 B+C）*
