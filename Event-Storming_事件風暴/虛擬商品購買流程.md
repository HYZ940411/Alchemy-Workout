虛擬​商品​購買​流程
使用者​已​選擇虛擬​商品​  
使用者​已​選擇​數量​  
使用者​已​確認購買  
[狀態] ​訂​單​ →​ 待​付​款  
[支付方式] ​虛​擬​貨​幣​ / ​真​實​金​流​ / ​兩​者​併​用（​虛​擬​貨​幣​不​足​時​以​現​金​補​差​額）  
虛​擬​貨​幣​已​扣​除 〔虛擬貨幣＝金幣，站內唯一幣別〕  
[Rule] Precondition：​金​幣​餘​額​扣​除​後​不​得​為​負​值  
使用者​已​支付 〔真實金流〕 〔攜帶資訊：商品類型＝虛擬、支付管道＝App Store〕  
[Rule] Precondition：​併​用​時​，​虛​擬​貨​幣​扣​除​與​真​實​金​流​支​付​須​同​時​成​功​，​方​可​完​成​購​買  
[Rule] 金幣對法幣比率為全站單一固定比率，初始值 1 金幣 ＝ 1 元，由管理員於後台調整  
[Rule] 補差額金額 ＝（商品價格 − 可折抵金幣數）依比率換算後的法幣金額  
[Rule] Precondition：訂單成立時鎖定當時比率，其後比率變動不影響該筆訂單  
[決策] 不採逐商品規格自訂折抵率  
使用者​已​購買虛擬​商品​ 〔交易成立〕  
[狀態] ​待​付​款​ →​ 已​付​款  
[決策] ​「​使用者​已​購買虛擬​商品​」​與​「​商品​已​發放​」​為​兩​個​不​同​事​實，​不​合​併  
[Rule] Precondition：​「​使用者​已​購買虛擬​商品​」​已​發​生，​方​可​發​生​「​商品​已​發放​」  
[決策] ​發​放​可​為​非​同​步，​不​保​證​與​交​易​成​立​在​同​一​時​點  
商品​已​發放 〔道具入庫〕  
[狀態] ​已​付​款​ →​ 已​發​放（​終​止​狀​態）​  
[失敗路徑]  
[分支] ​餘​額​不​足​ / ​商​品​售​完​ / ​其​他​原​因​ → ​購​買​已​失​敗  
購​買​已​失​敗 〔攜帶資訊：失敗原因（餘額不足 / 商品售完 / 其他）〕  
[狀態] ​待​付​款​ →​ 已​失​敗（​終​止​狀​態）​  
[發放失敗路徑]  
[分支] 道具入庫未成功 → 商品發放已失敗  
商品發放已失敗 〔攜帶資訊：已重試次數、失敗原因〕  
[Rule] Postcondition：系統自動重試發放，重試次數上限 3 次  
[Rule] Postcondition：達重試上限仍失敗者轉人工處理  
[Rule] 「商品發放已失敗」不改變訂單狀態，訂單於發放成功前維持已付款  
[決策] 不自動退款；虛擬貨幣與真實金流併用時的雙向退款複雜度高於重試  
[決策] 保留發放為非同步的既有裁決，本路徑僅補失敗處理，不改為同步
