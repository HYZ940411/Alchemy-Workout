虛擬商品購買流程
使用者已選擇虛擬商品  
使用者已選擇數量  
使用者已確認購買  
[狀態] 訂單 → 待付款  
[支付方式] 虛擬貨幣 / 真實金流 / 兩者併用（虛擬貨幣不足時以現金補差額）  
虛擬貨幣已扣除 〔虛擬貨幣＝金幣，站內唯一幣別〕  
[Rule] Precondition：金幣餘額扣除後不得為負值  
使用者已支付 〔真實金流〕 〔攜帶資訊：商品類型＝虛擬、支付管道＝App Store〕  
[Rule] Precondition：併用時，虛擬貨幣扣除與真實金流支付須同時成功，方可完成購買  
[Rule] 「虛擬貨幣已扣除」與「使用者已支付」不直接改變訂單狀態，兩者為「使用者已購買虛擬商品」的 Precondition
[Rule] 虛擬訂單轉入已付款的唯一觸發 Event 為「使用者已購買虛擬商品」，其 Command 為「成立虛擬商品交易」（Actor：系統）
[決策] 理由為併用支付的原子性：錢已扣但補差額失敗時訂單不得為已付款，故那兩個 Event 天生是條件不是結果
[決策] 不新增「已收款」中間狀態：該狀態僅在併用支付且兩邊分別完成的瞬間存在，屬技術性中間態而非業務事實
[Rule] 實體訂單無此結構：其僅有單一支付管道，「使用者已支付」即直接轉入已付款
[Rule] 金幣對法幣比率為全站單一固定比率，**1 元 ＝ 5 金幣**（2026-08-08 定案，2026-08-20 訂正本行原記的占位值「1 金幣 ＝ 1 元」），由管理員於後台調整；推導依據見 02_Aggregate定義.md〈比率的推導依據〉  
[Rule] 補差額金額 ＝（商品價格 − 可折抵金幣數）依比率換算後的法幣金額  
[Rule] Precondition：訂單成立時鎖定當時比率，其後比率變動不影響該筆訂單  
[決策] 不採逐商品規格自訂折抵率  
使用者已購買虛擬商品 〔交易成立〕  
[狀態] 待付款 → 已付款  
[決策] 「使用者已購買虛擬商品」與「商品已發放」為兩個不同事實，不合併  
[Rule] Precondition：「使用者已購買虛擬商品」已發生，方可發生「商品已發放」  
[決策] 發放可為非同步，不保證與交易成立在同一時點  
商品已發放 〔道具入庫〕  
[狀態] 已付款 → 已發放（終止狀態）  
[Rule] 權限解鎖類虛擬商品（如進階訓練計畫）的「商品已發放」＝將解鎖標的寫入使用者的已購買計畫清單，永久保存
[Rule] **進階訓練計畫統一定價 600 金幣**（＝120 元，2026-08-20 定案），不逐計畫區分；為平台級可調參數，由管理員於後台調整
[Rule] Precondition：已以階級達標或金幣購買永久取得該訓練計畫者，不得重複購買
[Rule] 僅以會員身分解鎖者仍可購買該計畫，用途為在權益失效前轉為永久取得
[Rule] 權限解鎖類商品不適用庫存，不產生「商品已售完」
[串聯] 系統執行「解鎖進階訓練計畫」導致「進階訓練計畫已解鎖」— Actor：系統
進階訓練計畫已解鎖 〔攜帶資訊：解鎖方式＝金幣購買、訓練計畫 ID〕
[Rule] Precondition：「商品已發放」已發生且該商品為權限解鎖類，其解鎖標的為該訓練計畫
[Rule] 本路徑的解鎖為永久取得，不因會員權益失效而回退
[失敗路徑]  
[分支] 餘額不足 / 商品售完 / 其他原因 → 購買已失敗  
購買已失敗 〔攜帶資訊：失敗原因（餘額不足 / 商品售完 / 其他）〕  
[狀態] 待付款 → 已失敗（終止狀態）  
[發放失敗路徑]  
[分支] 道具入庫未成功 → 商品發放已失敗  
商品發放已失敗 〔攜帶資訊：已重試次數、失敗原因〕  
[Rule] Postcondition：系統自動重試發放，重試次數上限 3 次  
[Rule] Postcondition：達重試上限仍失敗者轉人工處理  
[Rule] 「商品發放已失敗」不改變訂單狀態，訂單於發放成功前維持已付款  
[決策] 不自動退款；虛擬貨幣與真實金流併用時的雙向退款複雜度高於重試  
[決策] 保留發放為非同步的既有裁決，本路徑僅補失敗處理，不改為同步
