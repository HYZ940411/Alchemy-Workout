## 元素一：Event（事件）
定義：系統狀態的改變，無論是業務專家還是技術專家都有興趣的「改變」。

特性：
代表潛在系統的邊界（可能需要開發軟體來運作的地方，未確定，但可以從事件切入來判斷哪些地方需要軟體支援）
在規格光譜上接近 Problem Domain
由 Actor 造成，或由天然事件（時間）觸發

範例：
- 學生已完成了課程
- 學生的道館挑戰題作業已經得到老師的批改
- 客戶已對訂單付款

你會發現，這些 Event 都是用「過去式」描述的。因為 Event 是「已經發生的事」，不是「將要發生的事」。而且啊，這些 Event 都是業務人員關心的。

業務會問：「學生的完課率怎麼樣？學生完成課程後進度能被追蹤嗎？」 QA 會問：「完成課程的前提是什麼？完成後會發生什麼事？」 工程師會問：「得知課程完成後，系統要做什麼？」

大家都在討論同一個 Event，只是關注的層次不同。這就是 Event 作為切入點的價值。
