自訂訓練流程（循環 1：使用者已選擇動作 &gt; 使用者已設定該動作的組數、循環 2：使用者已設定該組的重量&amp;次數）
使用者已開始設計訓練  
使用者已建立自訂動作  
[Rule] 動作的器材欄位只有「所需器材明細」一個；「可練場所」為衍生值，由所需器材明細推導，不儲存
[Rule] 每個器材品項於器材設定 Aggregate 標明「哪裡有」，動作需要多項器材時，可練場所為同時具備全部器材的場所
[決策] 管理員新增動作時只填器材，不需自行判斷該動作算健身房或居家
[Rule] 自建動作僅建立者本人可選用，不進入平台動作庫  
[Rule] 自建動作不計入能力值計算  
使用者已選擇動作 〔動作來源：平台動作庫 / 使用者自建〕  
使用者已設定該動作的組數  
使用者已設定該組的重量&次數  
[Rule] 課表內容為三層結構：動作清單 → 該動作的組數 → 每組的目標重量與目標次數  
[Rule] 每一組可各自設定不同的目標重量，不強制整個動作共用同一重量  
[Rule] 目標重量為必填，float 精度 0.5 公斤，≥ 0；值為 0 代表徒手（自身體重）動作  
[Rule] 目標次數為必填，int，≥ 1  
[Rule] 第三層為多型：動作類型為重訓者填目標重量與目標次數；動作類型為有氧者填目標時長（int，秒，10–18,000）
[Rule] 有氧的第三層只有目標時長一欄，無目標重量與目標次數；亦不設目標強度欄位
[決策] 有氧不設目標強度：強度的單位隨動作而異（跑步用配速、飛輪用瓦特、划船用槳頻），要定義即須另立單位對照表
[Rule] 時長以秒為單位而非分鐘：間歇訓練的單組可短至數十秒；顯示格式由前端決定
[Rule] 組數對有氧同樣適用，通常為 1；間歇訓練會做多組，結構上不為有氧例外
[Rule] 自訂訓練與訓練計畫的課表內容結構完全一致  
使用者已儲存自訂訓練  
[狀態] 草稿 → 已儲存；已儲存為未啟用狀態，不出現於課表選擇頁，不可選用於訓練
使用者已發布自訂訓練  
[狀態] 已儲存 → 已發布；發布為啟用動作，發布後方可自己選用於訓練
[Rule] 申請公開為選用步驟，停留在已發布即可自己使用
使用者已取消發布自訂訓練  
[狀態] 已發布 → 已儲存（退回未啟用）
[可見範圍]
[串聯] 使用者執行「變更自訂訓練可見範圍」導致「使用者已變更自訂訓練可見範圍」— Actor：使用者（建立者）
使用者已變更自訂訓練可見範圍 〔攜帶資訊：自訂訓練 ID、變更後的可見範圍〕
[Rule] 自訂訓練 Aggregate 具備「對關注者可見」欄位（bool，預設否），與狀態正交
[Rule] 為真時該課表出現於關注者的課表選擇頁並可被其選用
[Rule] Precondition：執行者為該自訂訓練的建立者
[Rule] Precondition：狀態為**已發布 / 已申請公開 / 已公開**者方可設為真；草稿與已儲存（未啟用）不可  
[裁決修正 2026-08-08] 原規則只寫「已發布或已公開」，漏掉狀態機路徑 已發布 → 已申請公開 → 已公開 的中段，使用者於送審期間將無法開啟本欄位  
[Rule] 狀態為已公開時本欄位不生效：已公開為全平台可用，關注者本即涵蓋在內
[決策] 採獨立欄位而非新增狀態：自己可用與關注者可見為兩件互相獨立的事，塞進同一條狀態鏈須新增狀態並補反向轉換
[決策] 變更建模為 Event：本欄位決定關注者能否選用該課表，屬他人下 Command 時的 Precondition，比照「隊長已變更團隊可見性」；與「六維能力值對外可見」的界線在於後者不影響任何規則判定
使用者已申請公開訓練  
[狀態] 已發布 → 已申請公開  
[分支] 審核通過 → 管理員已審核公開訓練；審核未通過 → 公開訓練審核未通過  
[串聯] 管理員執行「審核公開訓練」導致「管理員已審核公開訓練」— Actor：管理員（平台管理員）  
[Rule] 教官與一般使用者皆不可執行審核公開訓練  
[決策] 不設系統自動初審，審核為單一人工關卡  
[決策] 教官申請的課表不免審核，與一般使用者適用同一審核流程  
管理員已審核公開訓練  
[狀態] 已申請公開 → 已公開  
公開訓練審核未通過  
[狀態] 已申請公開 → 已發布（退回）  
[Rule] Postcondition：退回「使用者已發布自訂訓練」狀態，自己仍可使用，但不對外公開  
[Rule] Postcondition：可修改後重新申請公開，不限次數  
[已公開後的操作]
[串聯] 使用者執行「修改自訂訓練」導致「使用者已修改自訂訓練」— Actor：使用者（建立者）
使用者已修改自訂訓練
[狀態] 已公開 → 已申請公開（重新審核）
[Rule] Precondition：執行者為該自訂訓練的建立者
[Rule] Precondition：該自訂訓練的狀態為已公開
[Rule] Postcondition：課表內容更新，重新進入管理員待審佇列
[Rule] 已儲存與已發布狀態下的修改為自由編輯，不產生本 Event
[決策] 本 Event 僅適用已公開：其存在目的為堵「送審放正常課表 → 過審後改為危險內容」的規避漏洞，要記錄的事實是一份已通過審核的課表被動了
[決策] 不採適用全部狀態並以攜帶欄位區分修改前狀態：該做法使同一個 Event 時而改變狀態、時而不改，且 Precondition 只能寫成「該自訂訓練存在」，不可驗收
[決策] 編輯軌跡不由本 Event 承擔：模型對需要軌跡者的既有做法為 Aggregate 內的編輯歷史欄位（貼文與留言皆採此法），自訂訓練是否需要該欄位為另一個決策點
[串聯] 使用者執行「下架自訂訓練」導致「使用者已下架自訂訓練」— Actor：使用者（建立者）
使用者已下架自訂訓練
[狀態] 已公開 → 已儲存（未啟用）
[Rule] Precondition：執行者為該自訂訓練的建立者
[Rule] Precondition：該自訂訓練的狀態為已公開
[Rule] Postcondition：他人無法再選用該課表；為軟刪除，資料保留
[Rule] 下架後進行中的訓練不受影響：承快照脫鉤原則，選擇課表時已產生本次訓練課表快照
[決策] 管理員因違規強制下架不在本流程範圍：違規處置走管理員管理社群流程的「管理員已下架違規內容」，其對象類型已定案為貼文 / 留言 / 私訊；是否納入自訂訓練為另一個決策點
[Rule] 本流程的管理員審核設有審核時限，逾期產生「審核已逾期」，不改變案件狀態 → 見 02_Aggregate定義.md〈四類審核的時限與逾期處理〉
