師徒​互動​流程
[串聯] ​使​用​者​執​行​「​申​請​師​徒​關​係​」​導​致​「​使用者​已​申請 師徒關係​」— Actor：​使​用​者  
[決策] ​申​請​雙​向​皆​可（​學​徒​向​教​官​拜​師​、​教​官​向​學​徒​邀​請​收​徒），​維​持​單​一​ Event  
[Rule] Precondition：​教​官​的​名​額​佔​用​數（​已​建​立​師​徒​關​係​ ＋ ​申​請​中​申​請）​未​達​帶​徒​上​限  
[Rule] 一位學徒同時僅能有一位教官；一位教官可帶多位學徒（一對多）  
[Rule] Precondition：申請方為學徒時，該學徒須不存在生效中的師徒關係  
[決策] 不採多對多：師徒的價值在於一對一的針對性指導，多位教官會給出互相衝突的訓練建議，學徒無從取捨  
[決策] 學徒端不另設冷卻期：既有的「解除後 3 天內雙方皆不得與其他對象建立師徒關係」已涵蓋  
使用者​已​申請 師徒關係 〔攜帶資訊：申請方角色（學徒 / 教官）〕  
[分支] ​接​受​ →​ 對方​已​接受​申請；​拒​絕​ →​ 對方​已​拒絕​申請；​逾​期​未​回​應​ →​ 師徒申請​已​逾期  
[Rule] Postcondition：​釋​放​所​佔​用​的​帶​徒​名​額  
對方​已​接受​申請​  
師徒關係​已​建立​  
對方​已​拒絕​申請  
[Rule] Postcondition：​釋​放​所​佔​用​的​帶​徒​名​額  
師徒申請​已​逾期  
[Rule] Precondition：自「使用者已申請師徒關係」起算滿 168 小時（7 天）未回應  
[Rule] 計時起點為申請時戳，計時基準為使用者當地時區時戳  
[決策] 採 7 天而非 3 天：涵蓋「平日忙碌、週末才開 App」的常態；3 天會使週五申請、週一才看到即逾期  
[決策] 時限不做成可調參數：不影響營收與平衡性，僅為等待窗口，做成參數只是增加無人調整的後台欄位  
[Rule] Postcondition：​「​師徒申請​已​逾期​」​發​生​後​該​筆​申​請​自​動​失​效  
[決策] ​拒​絕​或​逾​期​後​可​再​次​向​同​一​對​象​申​請，​無​冷​卻​期  
學徒​已​提問​  
[Rule] 師徒問答為獨立 Aggregate，欄位含師徒關係 ID、提問者、提問內容、回答內容、學徒評分  
[Rule] 問答需獨立 ID 以承接「學徒已評分該次問答」的評分對象  
[Rule] 問答不設狀態機：一問一答，無作廢概念  
教官​已​回答  
學徒​已​評​分​該​次​問​答  
教官​已​指派師徒任​務  
[Rule] 師徒任務為獨立 Aggregate，欄位含師徒關係 ID、指派者、任務內容、狀態、學徒評分  
[狀態] 師徒任務狀態值域：已指派 / 已完成 / 已作廢  
[Rule] 「師徒關係已解除」使未完成的師徒任務轉為已作廢（終止狀態）  
[決策] 師徒任務與師徒問答分立為兩個 Aggregate；兩者生命週期不同  
學徒​已​完成​師徒任​務  
師​徒任​務獎勵​已​發放  
學徒​已​評​分​該​次​師徒任​務  
教官​聲望​已​變動  
[Rule] ​學​徒​評​分​ 1~5 ​星，​聲​望​變​動​依​序​為​ −2 / −1 / +1 / +2 / +3  
[Rule] ​聲​望​點​數​地​板​值​為​ 0，​扣​分​不​使​其​低​於​ 0  
[Policy]  ​聲望​達門檻 → ​提升​帶徒​上限  
教官​帶徒​上限​已​提升​  
[Rule] ​初​始​帶​徒​上​限​ 1 ​人，​每​達​一​個​聲​望​門​檻​ +1 ​人，​最​大​值​ 5 ​人  
[Rule] ​初​始​值​、​提​升​幅​度​、​最​大​值​與​聲​望​門​檻​皆​由​管​理​員​於​帶​徒​上​限​設​定​ Aggregate ​調​整  
[Rule] ​達​最​大​值​ 5 ​人​後，​聲​望​再​提​升​亦​不​增​加​上​限  
[Rule] 聲望門檻為 30 / 75 / 150 / 300，各達一門檻帶徒上限 +1 人  
[Rule] 教官初始聲望為 15，於「使用者已成為教官」時給予  
[Rule] 門檻採遞增（比例 1 : 2.5 : 5 : 10），因帶徒數愈多取得聲望愈快，等差會使後段升級失控  
[Rule] 初始聲望為第一門檻的一半；地板值 0 若同為初始值，新教官前幾次差評將無效果  
[Rule] ​帶​徒​上​限​為​單​調​遞​增，​聲​望​下​降​時​不​隨​之​降​低  
[決策] ​無​「​帶​徒​上​限​已​降​低​」​ Event  
[終止路徑]  
[Rule] Precondition：​解​除​需​經​多​次​確​認​，​避​免​誤​觸  
師徒關係​已​解​除  
[Rule] Postcondition：​教​官​與​學​徒​任​一​方​皆​可​單​方​面​解​除​，​不​需​對​方​同​意  
[Rule] Postcondition：​未​完​成​的​師​徒​任​務​作​廢  
[Rule] Postcondition：​釋​放​教​官​所​佔​用​的​帶​徒​名​額  
[Rule] Postcondition：​解​除​後​ 3 ​天​內​，​雙​方​皆​不​得​與​其​他​對​象​建​立​師​徒​關​係  
[Rule] Postcondition：​解​除​後​ 3 ​天​內​可​挽​回​，​恢​復​原​師​徒​關​係  
[串聯] 使用者執行「提出恢復師徒關係」導致「使用者已提出恢復師徒關係」— Actor：使用者（教官與學徒任一方皆可提出）  
[Rule] Precondition：距「師徒關係已解除」未滿 3 天，方可發生「使用者已提出恢復師徒關係」  
使用者已提出恢復師徒關係  
[分支] 同意 → 對方已同意恢復；拒絕 → 對方已拒絕恢復  
對方已同意恢復  
對方已拒絕恢復  
[Rule] Postcondition：拒絕後該筆恢復提議失效，3 天內可再次提出  
[Rule] Precondition：「對方已同意恢復」已發生，方可發生「師徒關係已恢復」  
[決策] 恢復需雙方同意，不採單方面恢復；建立關係一律需雙方同意（比照「對方已接受申請」）  
[決策] 解除為單方面、恢復需雙方同意，兩者刻意不對稱，避免一方反覆解除又拉回  
師徒關係​已​恢​復  
[Rule] Postcondition：3 天冷卻期解除，雙方恢復為師徒關係  
[Rule] Postcondition：重新佔用教官的帶徒名額  
[Rule] Precondition：教官的名額佔用數未達帶徒上限，方可發生「師徒關係已恢復」
