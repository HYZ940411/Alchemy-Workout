發文與​互動​流程
[區別] ​分​享​與​發​文​為​兩​種​不​同​行​為，​獎​勵​可​各​自​取​得，​不​互​斥  
[Rule] 解鎖條件以**歷史行為**計數：五個 Event 曾各發生一次即滿足，其後刪除貼文或取消按讚不影響計數  
[Rule] 已解鎖永久保留，不因行為被刪除而撤銷  
[決策] 門檻為各一次，用意在確認「此人使用過社群功能」，非評量活躍度；行為發生過即為事實，事後刪除不使其變為未發生  
[決策] 不採「刪除後低於門檻即撤銷解鎖」：與既有規則「社群互動功能解鎖旗標為單調遞增、一經設定不可撤銷」直接衝突  
[決策] 管理員處罰不改動本解鎖旗標：既有規則已定案社群功能停權一律以使用者 Aggregate 的處罰狀態欄位表達  
發文者​已​分享訓練​成果 〔轉發訓練成果，主要至站外，亦可轉發至站內〕  
[Rule] Postcondition：​所​產​生​貼​文​的​關​聯​訓​練​紀​錄​欄​位​必​有​值  
分享獎勵​已​發放  
發文者​已​發布貼文 〔站內原生貼文〕  
[Rule] ​貼​文​支​援​文​字​與​圖​片，​不​支​援​影​片，​無​標​籤​欄​位  
[Rule] ​發​文​者​於​發​布​時​指​定​可​見​範​圍：​公​開​ / ​僅​關​注​者​ / ​私​人  
[Rule] Postcondition：​所​產​生​貼​文​的​關​聯​訓​練​紀​錄​欄​位​為​空  
發文獎勵​已​發放  
互動者​已​按讚貼文  
[Rule] 按讚不建模為獨立 Aggregate，以貼文的關聯集合表達  
[Rule] 關聯的唯一鍵為 貼文 ID ＋ 互動者 ID，同一人對同一貼文只能有一筆  
[Rule] Precondition：​該​貼​文​依​其​可​見​範​圍​對​此​互​動​者​可​見  
按​讚獎勵​已​發放  
互動者​已​留言  
[Rule] 留言為獨立 Aggregate，欄位含作者、貼文 ID、文字內容、發布時間、狀態  
[Rule] 留言可被檢舉；檢舉對象類型「留言」指涉留言 Aggregate 的 ID  
[決策] 不支援巢狀回覆；模型無「回覆留言」Event，互動成就門檻亦只計留言次數  
[Rule] Precondition：​該​貼​文​依​其​可​見​範​圍​對​此​互​動​者​可​見  
留言獎勵​已​發放  
[Policy] 累計​互動成​就​門檻 ​（分享 / 發文 ​/ ​按​讚 /​ ​留言四​種成​就）​ 累計:​ 1 / 5 /​ 15 /​ 50 / ​100 / ​250 / 500 / ​750 / ​1000 ​次​  
互動成​就​已​解鎖  

[反向操作]  
貼文​已​刪除  
[狀態] 已發布 → 已刪除（終止狀態）  
[Rule] 刪除為軟刪除，資料保留；不採硬刪除，因貼文可被檢舉，硬刪除會使已成案的檢舉失去指涉對象  
[Rule] Postcondition：已刪除貼文的按讚與留言一併隱藏但保留，供獎勵回收與成就計數判定使用  
貼文​已​編輯  
[Rule] Postcondition：編輯前的文字內容與時戳寫入編輯歷史，保留完整歷史版本  
[Rule] Postcondition：已編輯旗標設為真，Read Model 須對讀者顯示「已編輯」  
[決策] 保留歷史以避免「發爭議內容 → 被檢舉 → 審視前改為無害內容」的規避漏洞  
[Rule] 留言的刪除與編輯規則比照貼文，不另定義  
按​讚​已​取消  
留言​已​刪除  
留言​已​編輯  
[決策] ​分​享​無​反​向​操​作​ Event  
[Rule] 取消按讚、刪除留言、刪除貼文皆**不回收**已發放的獎勵  
[Rule] 互動成就的計數為單調遞增，反向操作不使其遞減；已解鎖的成就不撤銷  
[Rule] 同一貼文重複按讚與取消**不重複發放獎勵**：按讚獎勵的請求識別碼為 貼文 ID ＋ 互動者 ID  
[Rule] 留言獎勵的請求識別碼為 留言 ID；刪除後重新留言為新的留言 ID，屬新的一次互動  
[決策] 防刷由「同一貼文只發一次」承擔，非由回收機制承擔：有了唯一鍵，按讚 / 取消 / 再按讚的刷取路徑即不成立，回收機制隨之不必要  
[決策] 不採獎勵回收與成就遞減：與「成就解鎖紀錄單調遞增、一經解鎖不可撤銷」的既有原則相反，該原則已於連簽成就與粉絲成就兩處適用  
[決策] 不採「行為發生 24 小時後才發放（延遲確認）」：須為每一次按讚維護一個排程，而按讚為全模型最高頻的行為，成本與價值不成比例
