發文與互動流程
[區別] 分享與發文為兩種不同行為，獎勵可各自取得，不互斥  
[Rule] 解鎖條件以**歷史行為**計數：五個 Event 曾各發生一次即滿足，其後刪除貼文或取消按讚不影響計數  
[Rule] 已解鎖永久保留，不因行為被刪除而撤銷  
[決策] 門檻為各一次，用意在確認「此人使用過社群功能」，非評量活躍度；行為發生過即為事實，事後刪除不使其變為未發生  
[決策] 不採「刪除後低於門檻即撤銷解鎖」：與既有規則「社群互動功能解鎖旗標為單調遞增、一經設定不可撤銷」直接衝突  
[決策] 管理員處罰不改動本解鎖旗標：既有規則已定案社群功能停權一律以使用者 Aggregate 的處罰狀態欄位表達  
發文者已分享訓練成果 〔轉發訓練成果，主要至站外，亦可轉發至站內〕  
[Rule] Postcondition：所產生貼文的關聯訓練紀錄欄位必有值  
分享獎勵已發放  
發文者已發布貼文 〔站內原生貼文〕  
[Rule] 貼文支援文字與圖片，不支援影片，無標籤欄位  
[Rule] 發文者於發布時指定可見範圍：公開 / 僅關注者 / 私人  
[Rule] Postcondition：所產生貼文的關聯訓練紀錄欄位為空  
發文獎勵已發放  
互動者已按讚貼文  
[Rule] 按讚不建模為獨立 Aggregate，以貼文的關聯集合表達  
[Rule] 關聯的唯一鍵為 貼文 ID ＋ 互動者 ID，同一人對同一貼文只能有一筆  
[Rule] Precondition：該貼文依其可見範圍對此互動者可見  
按讚獎勵已發放  
互動者已留言  
[Rule] 留言為獨立 Aggregate，欄位含作者、貼文 ID、文字內容、發布時間、狀態  
[Rule] 留言可被檢舉；檢舉對象類型「留言」指涉留言 Aggregate 的 ID  
[決策] 不支援巢狀回覆；模型無「回覆留言」Event，互動成就門檻亦只計留言次數  
[Rule] Precondition：該貼文依其可見範圍對此互動者可見  
留言獎勵已發放  
[互動獎勵的共通規則]  
[Rule] 四種互動獎勵**只發放經驗值，不發放金幣**（見 00_全域規範.md〈金幣的供給與消耗〉）  
[Rule] 各行為**每日各有獎勵發放次數上限**：發文 1、分享 3、按讚 10、留言 5  
[Rule] **超過上限仍可正常操作，僅不再發放經驗值**；不阻擋行為本身  
[Rule] **自己的貼文不計**：對自身貼文的按讚與留言不發放任何獎勵  
[Rule] 上限以使用者當地時區的 04:00 為換日時點，沿用模型唯一的換日時點  
[Rule] 四項上限皆為平台級可調參數，由管理員於後台維護  
[決策] 須設每日上限：互動獎勵的經驗值推動階級，而階級解鎖**進階訓練計畫**（10/25/45/70）、**自訂訓練名額 2→5**（25/45/70）、**第 9 類階級成就**與**教官初審門檻**（階級 ≥ 20）—— 無上限則按讚數百次即可繞過上述四者  
[決策] 不採「同一貼文的同一種互動只計一次」作為唯一防線：其僅防重複按同一篇，而社群動態牆的貼文數無上限，滑一小時按數百篇仍可拿滿  
[決策] 不擋行為本身：擋住按讚與留言會使社群變冷清，而社群活躍本身即為平台所欲；只停發獎勵即足  
[決策] 不另設「新帳號須完成新手任務方可取得互動獎勵」：新手任務為三選一、做一次即完成，擋不住有心刷者，卻使正常新使用者前幾天的互動拿不到獎勵；且模型已有「社群互動功能需解鎖」的既有機制  
[Rule] 上限不影響**累計互動成就**的計數：成就計的是行為次數，與獎勵發放與否無關  
[已知風險] 成就計數不受每日上限約束，故互動成就仍可被快速刷開（按讚數百次即可推進至高階門檻）。其總量有界（每個門檻終身僅解鎖一次），但**成就獎勵的數額須將此納入考量** → 併入 `aggregate/成就獎勵_發放路徑與數額尚未建模.md`  
[Policy] 累計互動成就門檻 （分享 / 發文 / 按讚 / 留言四種成就） 累計: 1 / 5 / 15 / 50 / 100 / 250 / 500 / 750 / 1000 次  
互動成就已解鎖  

[反向操作]  
貼文已刪除  
[狀態] 已發布 → 已刪除（終止狀態）  
[Rule] 刪除為軟刪除，資料保留；不採硬刪除，因貼文可被檢舉，硬刪除會使已成案的檢舉失去指涉對象  
[Rule] Postcondition：已刪除貼文的按讚與留言一併隱藏但保留，供獎勵回收與成就計數判定使用  
貼文已編輯  
[Rule] Postcondition：編輯前的文字內容與時戳寫入編輯歷史，保留完整歷史版本  
[Rule] Postcondition：已編輯旗標設為真，Read Model 須對讀者顯示「已編輯」  
[決策] 保留歷史以避免「發爭議內容 → 被檢舉 → 審視前改為無害內容」的規避漏洞  
[Rule] 留言的刪除與編輯規則比照貼文，不另定義  
按讚已取消  
留言已刪除  
留言已編輯  
[決策] 分享無反向操作 Event  
[Rule] 取消按讚、刪除留言、刪除貼文皆**不回收**已發放的獎勵  
[Rule] 互動成就的計數為單調遞增，反向操作不使其遞減；已解鎖的成就不撤銷  
[Rule] 同一貼文重複按讚與取消**不重複發放獎勵**：按讚獎勵的請求識別碼為 貼文 ID ＋ 互動者 ID  
[Rule] 留言獎勵的請求識別碼為 留言 ID；刪除後重新留言為新的留言 ID，屬新的一次互動  
[決策] 防刷由「同一貼文只發一次」承擔，非由回收機制承擔：有了唯一鍵，按讚 / 取消 / 再按讚的刷取路徑即不成立，回收機制隨之不必要  
[決策] 不採獎勵回收與成就遞減：與「成就解鎖紀錄單調遞增、一經解鎖不可撤銷」的既有原則相反，該原則已於連簽成就與粉絲成就兩處適用  
[決策] 不採「行為發生 24 小時後才發放（延遲確認）」：須為每一次按讚維護一個排程，而按讚為全模型最高頻的行為，成本與價值不成比例
