每​日​任​務流程
[串聯] ​管​理​員​執​行​「​設​定​每​日​任​務​池​」​導​致​「​管理員​已​設定​每​日​任​務​池​」— Actor：​管​理​員  
管理員​已​設定​每​日​任​務​池  
[Rule] ​每​日​重​置​時​自​任​務​池​隨​機​抽​取​固​定​數​量​指​派  
[Rule] ​任​務​池​調​整​不​改​動​任​何​使​用​者​當​日​已​指​派​的​任​務  
[Rule] 每日抽取數量為 3 項，存於每日任務池 Aggregate，由管理員調整  
[Rule] 允許與前一日重複，不做跨日去重  
[Rule] 任務池項目數少於抽取數量時，抽出全部項目  
[決策] 採 3 項而非 5 項：一日的合理行為量約為 3 項；5 項會使全部完成的加碼獎勵變成少數人才拿得到  
[Rule] 任務項目欄位：任務名稱、判定來源 Event、目標次數、獎勵定義 ID  
[Rule] 系統訂閱該項目的判定來源 Event，該 Event 每發生一次累計 1 次進度；達目標次數即該項完成  
[Rule] 任務項目為可組態的 Event 訂閱：管理員新增任務時只需指定 Event 與目標次數，不需改動系統程式  
[Rule] 進度的計數範圍限當日，隨「每日任務已重置」清空  
[推導] 同一個 Event 可同時被當日的多項任務訂閱，各自獨立累計，互不扣抵  
[決策] 不採使用者手動回報：每日任務全部完成另有加碼獎勵與加碼排行榜分數，手動回報無從驗證，等於開放刷分  
[決策] 不增設「任務類型」欄位與抽取分散規則：管理員若某類僅放一項則天天抽到同一項、某類未放則規則卡死，與既有「不做跨日去重」的裁決理由相同  
[決策] 每日任務的完成判定 Actor 為系統，與新手任務由使用者勾選的機制不同，兩者不共用任務項目結構  
[Policy] ​完成​每​日​訓​練 / ​互動 累計每​日​任務​進度​,  ​增加​個人​排行榜​分數​  
每​日​任務​進度​已​更​新  
個人​排行榜​分數​已​增加 〔攜帶資訊：來源＝每日任務進度〕  
[Rule] ​本​來​源​為​固​定​分​數，​與​訓​練​量​無​關  
[Policy] 每​日​任​務全部​完成​ 加碼獎勵與​分數​  
每​日​任​務​已​完成​  
[串聯] 使用者執行「領取每日任務獎勵」導致「使用者已領取每日任務獎勵」— Actor：使用者  
[Rule] Precondition：「每日任務已完成」已發生，且該筆獎勵尚未領取  
使用者已領取每日任務獎勵  
每日任務獎勵已發放  
[Rule] 「每日任務獎勵已發放」為多對一：由「使用者已領取每日任務獎勵」或「使用者已領取信箱獎勵」導致  
[Rule] 獎勵不於任務完成時自動發放，須由使用者主動點擊領取  
[決策] 保留領取這一步：領取的點擊本身即為回饋體驗的一環，自動發放會使使用者感受不到獲得  
[決策] 完成判定仍為系統自動（訂閱 Event），僅「領取」為使用者操作，兩者不衝突  
個人​排行榜​分數​已​增加 〔攜帶資訊：來源＝每日任務全部完成〕  
[Rule] ​本​來​源​為​固​定​加​碼​分​數  
[Policy] ​每​日​當​地​時​間 04​:00 ​重置清空當日​每​日​任務​進度​  
[Rule] 「當地時間」取自使用者裝置的當前時區，非使用者 Aggregate 儲存的時區欄位  
[決策] 儲存的時區為註冊當下填入，使用者出國或變更裝置語系後即過期，故不採用  
[Rule] 跨時區移動導致同一當地日期重複觸發重置時，由冪等機制擋下，不會重置兩次  
[Rule] 重置的換日時點與簽到一致，皆為當地時區 04:00  
每​日​任​務​已​重置  [Rule] Postcondition：重置時當日已完成但未領取的獎勵，一律補發至獎勵信箱，不作廢  
[串聯] 系統執行「補發獎勵至信箱」導致「獎勵已補發至信箱」— Actor：系統（重置時觸發）  
獎勵已補發至信箱  
[Rule] Precondition：該筆獎勵所屬任務已完成，且於重置時點仍未領取  
[串聯] 使用者執行「領取信箱獎勵」導致「使用者已領取信箱獎勵」— Actor：使用者  
使用者已領取信箱獎勵  
[決策] 未領取不作廢：完成任務是使用者已付出的行為，因忘記點擊而失去獎勵形同懲罰已完成的人  
[待決策 Partial] 信箱獎勵的有效期限、信箱容量上限、是否有逾期清除機制，皆尚未定案  
[待決策 Partial] 領取機制是否及於每日任務以外的其他獎勵來源（訓練、簽到、成就、排行），尚未定案
