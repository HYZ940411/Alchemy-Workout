# 釐清問題

使用者執行 Command「申請教官權限」前必須看到什麼？初審門檻（階級 ≥ 20、累積訓練次數 ≥ 50、AI 訓練品質評分 ≥ 60）與自身當前達成狀況是否應事前揭露？

# 定位

流程：教官申請流程
元素：Read Model（尚未定義）；支撐 Command「申請教官權限」「作答教官測驗」
細節：D6 Read Model 識別、E4 Read Model → Command 支撐、C5 失敗路徑的使用者回饋。
現況：初審為系統自動判定，未達門檻即「教官資格已駁回」；若使用者事前看不到門檻與自身進度，將反覆送出必然被駁回的申請。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 揭露全部三項門檻與自身當前值（階級、累積訓練次數、AI 訓練品質評分三維與加權平均）；即時 |
| B | 揭露階級與累積訓練次數兩項門檻與進度，**不揭露** AI 訓練品質評分（揭露評分維度將使造假者得以針對性規避「紀錄合理性」的偵測） |
| C | 同 B，但於被駁回後才揭露該次的評分結果與駁回階段，供改善 |
| D | 全部不揭露，僅呈現「申請」按鈕與駁回後的通用訊息；門檻為內部判定，避免使用者為達門檻而灌水訓練紀錄 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Read Model 清單、使用者 Aggregate 的階級與累積訓練次數查詢、AI 訓練品質評分的保存與否（不保存即無法於駁回後揭露）、「教官資格已駁回」攜帶的駁回階段資訊之用途，以及是否需限制重新申請的冷卻期。
相依：`event/AI已產出訓練品質評分_攜帶資訊與去重鍵與評分是否保存.md`、`aggregate/使用者_累積訓練次數欄位的定義與計入條件.md`。
相關待釐清項目：`rule/使用者已作答教官測驗_可否重考與重考間隔.md`。
相關已解決項目：`resolved/rule/教官資格已初審通過_初審門檻的階級與累積訓練次數為何.md`。
