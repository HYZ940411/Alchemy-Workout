# 釐清問題

使用者訂閱會員前必須看到什麼？權益項目清單、月繳與年繳的價格比較、目前生效狀態與到期時點是否需呈現？

# 定位

流程：會員訂閱流程
元素：Read Model（尚未定義）；支撐 Command「訂閱會員」「取消訂閱」
細節：D6 Read Model 識別、E4 Read Model → Command 支撐。
特殊性：訂閱與取消的 Actor 皆為**外部系統**（App Store 通知觸發），使用者的實際操作發生於 App Store。本 Read Model 支撐的是使用者「決定要不要去 App Store 訂閱」的決策，屬判準的邊界情形。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 建立：欄位＝權益項目清單（來源為權益設定 Aggregate）、月繳 / 年繳兩方案的價格（自 App Store 取得）、我的生效狀態與到期時點；即時 |
| B | 同 A，但價格不由本系統呈現（訂閱價格已定案不存於本模型），僅呈現權益項目與生效狀態，價格由 App Store 付款頁呈現 |
| C | 不建立：訂閱的 Command Actor 為外部系統，使用者未於本系統下任何 Command，屬純展示畫面 |
| D | 同 B，另加「我目前因非會員而受限的功能」提示，作為轉換誘因 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Read Model 清單、權益設定與會員權益兩個 Aggregate 的查詢、以及〈Read Model 建立原則〉判準在「Actor 為外部系統但決策者為使用者」情形下的適用（與 `read-model/任務清單頁_...` 同屬判準邊界案例，宜併題確立通則）。
相依：`aggregate/會員權益_權益項目的初始清單為何.md` — 權益項目未定則本 Read Model 無內容可呈現，該項目已連續兩輪 skip，宜一併處理。
相關待釐清項目：`rule/使用者已取消訂閱_取消後權益立即失效或於到期日失效.md`、`rule/會員權益已生效_訂閱到期後既有資料與權益如何處理.md`。
