# 釐清問題

使用者執行 Command「申請師徒關係」前必須看到什麼？如何找到可拜師的教官（或可收徒的學徒）？需呈現哪些欄位供判斷該教官是否適合？

# 定位

流程：師徒互動流程
元素：Read Model（尚未定義）；支撐 Command「申請師徒關係」「接受申請」
細節：D6 Read Model 識別（篩選、排序）、E4 Read Model → Command 支撐。
既有 Precondition「教官的名額佔用數（已建立師徒關係 ＋ 申請中申請）未達帶徒上限」—— 申請者若看不到剩餘名額，將反覆送出必然失敗的申請。
申請雙向皆可（學徒拜師 / 教官收徒），故可能需要兩個方向的清單。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 教官清單：欄位＝教官名稱、階級、六維能力值、聲望點數、剩餘帶徒名額、平均學徒評分；依聲望排序，名額已滿者不顯示 |
| B | 同 A，但不揭露聲望點數（避免數字化排序造成強者恆強），改為以星級區間呈現平均評分 |
| C | 同 A，另加教官方向的「可收徒學徒清單」（學徒的階級、六維能力值、健身目標、每週健身天數），支撐教官主動邀請 |
| D | 不建清單：師徒申請僅能在使用者個人檔案頁對特定對象發起，不提供瀏覽式配對 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Read Model 清單、教官聲望 / 帶徒上限設定 / 師徒關係三個 Aggregate 的查詢組合、「名額佔用數未達帶徒上限」Precondition 的事前可見性、以及〈Command 清單〉是否需新增查詢類 Command。
相依：`rule/使用者已申請師徒關係_一位學徒可否同時有多位教官.md`（決定申請方是否需看到自己已有幾位教官）。
相關已解決項目：`resolved/aggregate/教官聲望_聲望的計算公式與可否下降.md`、`resolved/aggregate/教官帶徒上限_帶徒上限的初始值與提升幅度.md`。
