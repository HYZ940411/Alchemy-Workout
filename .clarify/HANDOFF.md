## 5. 回寫模型時的技術注意事項

> **⚠️ 本節已於 2026-08-05（第八輪）失效，保留僅供理解歷史。**
> 零寬空格已全面清除，見本檔末〈第八輪〉之〈零寬空格已全面清除〉。
> **請直接使用 `grep` 與 `Edit`，不要再用下述 perl / Python 繞道做法。**

**（歷史）流程檔含零寬空格（U+200B）**，穿插在中文字之間（如 `訓練​進度​條​已​增加`）。後果：

- `grep "進度條"` **搜不到**
- `Edit` 工具的精確字串比對**會失敗**

**可用的做法**：

```bash
# 顯示（去除零寬空格）
perl -ne 's/\x{200b}//g; print "$.: $_"' 檔名.md

# 依行號插入（最可靠）
perl -i -ne 'print; if ($. == 13) { print "新內容\n"; }' 檔名.md
```

**務必以 byte mode 執行 perl（不要加 `-C` 系列旗標）**，否則 UTF-8 會被二次編碼成亂碼。
本輪曾因 `perl -CSD -i -pe` 造成 mojibake，需刪行重寫修復。

`00_全域規範.md` 為新增內容時**沒有**零寬空格問題，可正常使用 `Edit`。

共 4 次（「看不太懂問題」「這題在問什麼我看不太懂」「問題有點複雜」「看不太懂」）。

| # | 使用者的話 | 助理錯在哪 / 學到什麼 |
|---|-----------|-----------|
| 1 | 「看不太懂問題」（相對強度係數） | 助理直接用模型術語出題。**改用具體例子重講**（「胸部：槓鈴臥推 100kg vs 上斜啞鈴 60kg，同樣強度的人重量差很多」）後立刻理解 |
| 2 | 「在查證過一次」（錨點動作） | 助理憑訓練常識給了六個錨點，被要求查證後**改了兩個**（背：硬舉→高位下拉；核心：負重捲腹→Cable Crunch） |
| 3 | 「最符合 App Store 規範的是 A 嗎」 | **本輪最重大的一次**。助理憑記憶推薦，查證 Apple 官方文件後發現**推薦與模型既有裁決雙雙牴觸規範**，推翻自第四輪存在的裁決 |
| 4 | 「為什麼不推薦 B」（冷靜期計時） | 助理只因「模型有停權的判例可套」就推薦 A，**沒檢查判例的理由能否轉移**——停權是平台擋人、申請刪除是自己選的，該理由根本不成立。推薦反轉 |
| 5 | 「不是會有評分次數上限了嗎」 | 查證後發現**訓練體驗評分根本沒有任何上限**，同一人對同一份計畫可評無限多次且全進平均。該題因此多補一條上限規則 |
| 6 | 「以產品理念來看，這樣的錨點是否會讓使用者逐漸獲得成就感與成長？」 | 助理據此推算完整時間軸，**發現兩年後所有長線機制同時耗盡**（能力值頂 999、階級滿等、成就拿完），列為已知缺口 |
| 7 | 「分小題問我」「拆兩題問我」 | 共 2 次。**四個子問題或兩個子問題的複合題，一律預設拆開問**，不要等使用者要求 |

**本輪的錯誤形態（三種，皆為「沒有實際去查」）：**

1. **憑記憶判斷外部規範**（App Store）→ 已寫入 memory `verify-platform-rules-before-recommending`
2. **套用既有判例卻未檢查判例的理由是否適用**（停權 vs 帳號刪除）
3. **憑感覺給數字並冠上「符合多數人體感」**（有氧係數 100）——被追問「確定嗎」後自行撤回

**新增的查證清單第六項**：⑥ **這個判例的「理由」能不能轉移過來，不只是形狀像不像？**

### 其餘偏好（本輪新增觀察）

- **會要求用白話重講**：模型術語出題有 4 次被擋下。**出題時先問自己「不熟這個模型的人看得懂嗎」**，
  必要時附具體數字例子（如「80kg 男性臥推 60kg × 8 下」）。
- **會給產品層級的方向而非只選選項**：如「主要目的是讓使用者感覺到進步的回饋，
  進而培養內在運動習慣」——這類話**應直接寫進模型作為判準**，而非只當成選項的理由。
  本輪即據此把能力值錨點整組下調兩次。
- **對「已知缺口」接受度高，但要求明文記錄**：兩年後回饋耗盡、跳過偏好時段收不到提醒、
  同分機率升高，皆選擇「明示接受」而非增加機制。
- **會主動問「還有什麼沒做」**：交接前務必主動盤點未完成事項。

## 2. 本輪最重大的四件事

### 2.1 帳號刪除整段重寫（App Store 合規）

**推翻自第四輪即存在的「軟刪除、內容全數保留、僅匿名化 PII」裁決。**

Apple 官方文件（Offering account deletion in your app）明文：
- "Offer to delete the entire account record, along with associated personal data.
  **only offering to temporarily deactivate or disable an account is insufficient**"
- "This includes **user-generated content that's shared with others**, such as photos,
  video, text posts, and reviews."

新裁決：帳密、個資、訓練紀錄、成長數值、**貼文、留言、私訊、AI 調整對話**一律實際刪除；
僅「已成案且處理中」的檢舉／申訴證據暫留至結案。冷靜期 30 天維持（Apple 允許流程需時，但須告知）。

**另補上模型完全遺漏的一項**：Sign in with Apple 的 **revoke tokens API 呼叫**
（「刪除綁定記錄」與「撤銷授權權杖」是兩件不同的事）。

### 2.2 能力值映射改為仿射式 ＋ 錨點分佈定案

**原式 `點數 = DOTS × 係數` 在數學上做不到六階門檻**：純比例映射不改變倍數關係，
而未訓練者與頂尖者的單項 1RM 差距僅 3～5 倍，門檻卻要求 9 倍以上。
新式：**`點數 = min(999, (DOTS − 基準值) × 映射係數)`**。

錨點分佈（依使用者兩度下調的指示定案）：

| 等級 | 錨點動作 1RM | 對應 |
|------|-------------|------|
| E | 0.5× 體重 | 完全未訓練 |
| D | 0.6× | 1–2 個月 |
| C | 0.75× | 3–6 個月 |
| B | 0.875× | 8–10 個月 |
| **A** | **1.0×** | **規律訓練一年** |
| S | 1.25× 以上 | 一年半～兩年 |

六個錨點動作：胸＝槓鈴臥推、**背＝高位下拉**、腿＝槓鈴深蹲、肩＝站姿槓鈴肩推、
手＝槓鈴彎舉、核心＝負重繩索捲腹。

### 2.3 有氧不再計入訓練量

查證確認 **ACSM 對有氧與重訓為分開處方**（有氧用 MET-分鐘、重訓用每週天數與肌群），
**市場上不存在合併兩者的公認方法**——這就是「每分鐘訓練量係數」自第六輪卡到現在的真正原因。
總訓練量改為**單位公斤、僅承載重訓**，跨類型比較由既有的〈消耗大卡〉承擔。

### 2.4 訓練體驗評分補上次數上限

原本**完全沒有上限**，每次訓練結算都問、同一人對同一份計畫可評無限多次且全進彙總平均。
新增「每人每份訓練計畫終身僅一次」，並定為可跳過、可修改、獨立成 Aggregate。

## 5. 本輪一併清掉的回寫遺漏

`overview.md` 原 §0.2 列的假缺口已清理 9 個檔案，其中最嚴重的是
