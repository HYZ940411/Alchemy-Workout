# 釐清問題

回歸任務獎勵、師徒任務獎勵、限時任務獎勵、個人排行獎勵、團隊日常排行獎勵、團隊限時排行獎勵六個來源的初始內容與數量為何？

# 定位

流程：回歸任務流程、師徒互動流程、團隊任務流程、排行榜週期結算流程
元素：Aggregate「獎勵定義」的內容欄位（平台級）
細節：D2 欄位初始值、C3 數值邊界。

**本批的決策重心為競爭性獎勵的量級**：排行獎勵依**組內名次**發放（個人排行榜已定案為
階級區間分組、每 10 階一組），而分組的既有理由是「不分組時全平台前段永遠是同一批高強度使用者，
多數人一輪都領不到排行獎勵」。若排行獎勵的量級遠高於日常獎勵，分組所解決的公平性問題會再度浮現
—— 組內前段仍是固定的那幾人。

**回歸任務獎勵另有一層特殊性**：其對象是已 120 小時未訓練、能力值已退步的使用者。
獎勵過高會使「刻意停練再回歸」成為划算的策略。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 排行獎勵依名次分三段（組內前 3 / 前 10 / 前 50%），最高段約為單次訓練獎勵的 10 倍；回歸任務與師徒任務約等於單次訓練獎勵；限時任務略高 |
| B | 同 A 的結構，但排行獎勵最高段壓低至單次訓練獎勵的 3 倍，使排行成為榮譽而非主要收入來源 |
| C | 排行獎勵改為不可交易的稱號 / 徽章，不給金幣，徹底與虛擬經濟脫鉤 |
| D | 同 A，但回歸任務獎勵降至最低（僅象徵性），避免「刻意停練再回歸」成為划算策略 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 6 個「⋯獎勵已發放」Event 的 Postcondition、四個排行榜（個人週榜 / 個人月榜 /
團隊日常 / 團隊限時）的獎勵分佈、階級區間分組所欲達成的公平性是否被獎勵量級抵銷、
以及「刻意停練再回歸」與「刻意不升階留在低組」兩種刷獎勵策略的可行性。

相依：`rule/個人排行獎勵已發放_同分並列時的排名與獎勵規則.md`、
`rule/排行榜週期已結算_週期中升階跨組時分數與名次如何處理.md`（刷獎勵風險的另一面）、
`rule/團隊限時分數已增加_固定分與全員完成加成幅度為何.md`。
前置：第一批與第二批（本批數額需對照前兩批的量級）。
