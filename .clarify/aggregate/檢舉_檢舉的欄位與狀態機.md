# 釐清問題

檢舉 Aggregate 的欄位定義為何？可檢舉的對象類型有哪些？同一內容被多人檢舉如何處理？

# 定位

流程：管理員管理社群流程
元素：Aggregate：檢舉（模型中尚未定義）；Event：使用者已檢舉內容
細節：隱含但未明確定義的 Aggregate（D1）；欄位定義與狀態機（D2、D5）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 欄位含檢舉者 / 被檢舉對象 / 對象類型（貼文 / 留言 / 帳號）/ 理由 / 狀態；多人檢舉同一內容合併為同一案件 |
| B | 同上但多人檢舉各自獨立成案，管理員逐案處理 |
| C | 同 A，另加檢舉累積次數欄位，達門檻時自動暫時隱藏內容待審 |
| D | 不建立檢舉 Aggregate，檢舉僅為通知管理員的訊息 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響檢舉 Aggregate 的欄位與狀態機、使用者已檢舉內容的 Postcondition、管理員已審視檢舉的作用對象（單案或合併案）、以及自動隱藏機制是否需要額外 Event。
