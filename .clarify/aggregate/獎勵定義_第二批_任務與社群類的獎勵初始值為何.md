# 釐清問題

每日任務獎勵、分享獎勵、發文獎勵、按讚獎勵、留言獎勵五個來源的初始內容與數量為何？

# 定位

流程：每日任務流程、發文與互動流程
元素：Aggregate「獎勵定義」的內容欄位（平台級）
細節：D2 欄位初始值、C3 數值邊界。

**本批的決策重心為刷分風險**：按讚與留言的執行成本極低（一次點擊），
若給予金幣獎勵，使用者可於數分鐘內對大量貼文按讚換取金幣，而金幣已定案 1 金幣 ＝ 1 元、
可購買虛擬商品與補簽券。模型已有一個待釐清項目正在處理此問題的另一面
（`rule/發文獎勵已發放_互動獎勵是否有每日發放上限.md`），兩者宜併題處理。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 每日任務＝經驗值 20 ＋ 金幣 30（全部完成另加碼）；分享 / 發文＝金幣 10；按讚 / 留言＝金幣 2；並設每日發放上限 |
| B | 同 A 的數額，但按讚與留言**不給金幣**，僅計入互動成就的次數；分享與發文仍給 |
| C | 四種互動皆不給金幣，改給不可交易的道具或稱號，徹底切斷刷分與虛擬經濟的連結 |
| D | 同 A，但不設每日上限，改以「同一貼文只計一次」與「自己的貼文不計」兩條規則防刷 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 5 個「⋯獎勵已發放」Event 的 Postcondition、金幣的產出端量級、
師徒功能解鎖條件（需集滿關注 / 發文 / 按讚 / 留言 / 分享五個 Event 各一次）的取得難度、
互動成就的門檻合理性（累計 1 / 5 / 15 / 50 / 100 / 250 / 500 / 750 / 1000 次）、
以及取消按讚與刪除留言時的獎勵回收規則。

相依：`rule/發文獎勵已發放_互動獎勵是否有每日發放上限.md`（同一組決策，宜併題）、
`rule/按讚獎勵已發放_取消按讚或刪除留言時獎勵與成就是否回收.md`。
前置：`aggregate/獎勵定義_第一批_訓練與簽到類的獎勵初始值為何.md`（本批數額需對照第一批的量級）。
