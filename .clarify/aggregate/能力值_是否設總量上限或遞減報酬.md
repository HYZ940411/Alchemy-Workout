# 釐清問題

能力值累積無上限，規律訓練者永不退步。是否應設總量上限、遞減報酬或改為滾動值？

# 定位

流程：訓練結算流程、訓練中斷流程
元素：Aggregate「使用者」的能力值欄位；能力值提升公式
細節：Aggregate 內部不變條件（D3）；數值邊界（C3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 設硬上限：每維上限 N 點，達上限後不再提升 |
| B | 遞減報酬：該維實際提升 ＝ 基準公式結果 × (1 − 現值 ÷ 理論上限)，漸近逼近而不到達（理論上限初始值 1,000） |
| C | 改為滾動值：能力值 ＝ 近 N 週訓練量的換算值，自動有界且反映近況 |
| D | 維持無上限累積，接受長期成為年資指標 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響能力值提升公式、六維雷達圖的可讀性與頂端區辨度、能力值與經驗值的職能區隔。

**選項 C 會推翻既有裁決**：滾動值的下降由視窗滑出造成，將使
`resolved/rule/能力值已退步_退步百分比與六維註冊初始值為何.md`（2.5%／120 小時、下限 10）、
「能力值已退步」Event 與「退步預告已發送」全部作廢，須一併重做訓練中斷流程。

選項 A 的硬上限會使資深使用者的六維圖全部貼齊天花板，失去區辨度。
選項 B 保留頂端差異，且符合「新手進步快、老手進步慢」的真實訓練生理。
