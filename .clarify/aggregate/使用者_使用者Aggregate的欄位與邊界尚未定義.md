# 釐清問題

全模型的核心 Aggregate「使用者」尚未定義。其欄位邊界為何？哪些資料屬於使用者本體，哪些應獨立為其他 Aggregate？

# 定位

流程：全流程（註冊、訓練、社群、師徒、商城等）
元素：Aggregate：使用者（模型中完全未定義，卻被幾乎所有流程改動）
細節：隱含但未明確定義的 Aggregate（D1）；Aggregate 邊界（D1）；欄位定義（D2）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 使用者僅含身分與個人資料（帳密 / 身高 / 體重 / 性別 / 年齡 / 健身偏好 / 時區）；經驗值、能力值、階級、成就、連續紀錄各自獨立為 Aggregate |
| B | 使用者含身分資料加上經驗值、能力值、階級三個核心數值；其餘獨立 |
| C | 使用者為單一大 Aggregate，含所有個人相關狀態 |
| D | 使用者含身分資料與功能解鎖旗標；所有數值與紀錄皆獨立為 Aggregate |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響全模型的 Aggregate 邊界劃分、各流程 Command 修改哪個 Aggregate 的對應關係（E2）、跨 Aggregate 一致性要求（D4），以及所有 Postcondition 中欄位歸屬的正確性。這是 Aggregate 層的根本問題，應優先釐清。
