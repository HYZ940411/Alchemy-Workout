# 釐清問題

「管理員已設定限時任務」與「團隊已指派限時任務」已定案為每日指派，但限時任務的**內容結構**與「成員已完成一次限時任務」的判定條件皆未定義。

# 定位

流程：團隊任務流程
元素：Rule：Event「成員已完成一次限時任務」的 Precondition；Aggregate（限時任務的承接處未定）
細節：C1 前置條件完整性、D1 Aggregate 識別。
現況：〈獨立 Aggregate 清單〉團隊分類僅有「團隊」一項，無限時任務 Aggregate；「限時」一詞未量化（每日指派，但任務本身的有效時窗為何未定）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 比照每日任務池的結構：任務項目＝名稱 ＋ 判定來源 Event ＋ 目標次數 ＋ 獎勵定義 ID；限時任務為獨立 Aggregate，有效時窗為指派當日（當地 04:00 換日） |
| B | 同 A 的結構，但共用每日任務池 Aggregate，以「適用對象＝個人 / 團隊」欄位區分，不新增 Aggregate |
| C | 限時任務僅有名稱與說明，完成由成員自行回報（Actor：使用者），系統不自動判定 |
| D | 限時任務固定為「當日完成一次訓練」單一內容，不做成可設定的任務池 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響〈獨立 Aggregate 清單〉是否新增限時任務、「成員已完成一次限時任務」的 Precondition 可驗收性、團隊限時分數的計算輸入（完成人數）、「團隊全體成員皆完成時額外加成」的判定時點（每日結束時？即時？），以及團隊頁 Read Model 的欄位。
相依：`aggregate/每日任務池_任務項目的結構與完成判定來源為何.md`（若採選項 A 或 B，兩者結構應一致）。
相關待釐清項目：`rule/團隊已指派限時任務_全平台同一組任務或可分團隊指派.md`（指派範圍）、`rule/團隊限時分數已增加_固定分與全員完成加成幅度為何.md`（分數值） — 三者為同一組決策，宜併題處理。
