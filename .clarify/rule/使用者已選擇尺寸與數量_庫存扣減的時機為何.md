# 釐清問題

實體商品的庫存在哪一個時點扣減？是「使用者已確認購買」還是「使用者已支付」？未付款訂單的庫存如何處理？

# 定位

流程：實體商品購買流程、管理員商品上架流程
元素：Rule：使用者已確認購買 / 使用者已支付的 Postcondition；Aggregate：商品庫存
細節：跨 Aggregate 的一致性要求（D4）；時間邊界與時間窗（C3）；同時修改多個 Aggregate 的 Command（E2）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 確認購買時預扣庫存並保留 15 分鐘，逾時未付款自動釋放 |
| B | 支付成功後才扣減庫存，可能發生超賣需以失敗補償處理 |
| C | 確認購買時預扣，逾時未付款釋放，且釋放時需補上「庫存已釋放」Event |
| D | 不做預扣，出貨時才扣減，庫存為出貨後結算 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響庫存扣減的 Postcondition 與時機、訂單 Aggregate 與商品 Aggregate 的跨聚合一致性、「商品已售完」的判定時點、以及超賣的例外處理。

# 既有約束（來自已解決項目）

第 47 題（`resolved/aggregate/商品_商品的欄位定義與價格庫存設定.md`，選項 D）已裁決：
庫存屬**商品規格（尺寸）層級**，各規格獨立。
故扣減對象為所選規格的庫存，本題僅剩「扣減時機」（下單時 / 付款成功時）待確認。
