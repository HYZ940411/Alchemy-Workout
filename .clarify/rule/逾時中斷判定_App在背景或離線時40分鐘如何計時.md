# 釐清問題

「40 分鐘內未完成任何一組 → 中斷訓練」的計時，在 App 進入背景、被關閉或裝置離線時如何進行？由前端或後端計時？

# 定位

流程：訓練紀錄流程（循環：使用者已記錄重量 > 組間休息已結束）
元素：Rule / Policy：逾時中斷判定（中斷計時起點：使用者已開始訓練，每完成一組中斷計時歸零重算，40 分鐘內未完成任何一組 → 中斷訓練）
細節：時間邊界（C3）；系統自動觸發的 Command（B1）；跨系統邊界（A4）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 後端以最後一組的時戳為準判定，與 App 是否在前景無關 |
| B | 前端計時，App 關閉即視為中斷，直接產生使用者訓練已中斷 Event |
| C | 後端判定，但 App 回到前景時才實際觸發中斷結算（延遲判定） |
| D | 前端計時並在背景維持，離線時暫停計時，恢復連線後補算 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響使用者訓練已中斷的 Actor（排程系統或前端）與觸發源、訓練紀錄 Aggregate 是否需記錄每組完成時戳、以及訓練結算流程是否會延遲。此為 Event 是否成立的關鍵。
