# 釐清問題

AI 服務回應逾時、失敗或產出不合理方案時，系統的行為與對應 Event 為何？

# 定位

流程：AI 訓練前調整流程、AI 訓練中調整流程（插入訓練紀錄流程循環）、AI 自動優化訓練流程
元素：Rule：AI 調整相關 Command 的例外路徑
細節：失敗與例外路徑（C5）；跨系統邊界（A4）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 補上「AI 調整已失敗」Event，維持原訓練內容並提示使用者稍後再試 |
| B | 補上「AI 調整已失敗」Event，並自動改用規則式預設調整方案 |
| C | 不產生 Event，僅在前端顯示錯誤，訓練不受影響 |
| D | 補上「AI 調整已失敗」Event，且訓練中調整時直接沿用原課表繼續訓練 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響三條 AI 流程的例外路徑 Event、訓練課表 Aggregate 在失敗時的狀態一致性（是否需回復）、以及訓練中調整失敗時訓練紀錄流程能否繼續。

# 優先級

Medium

# 範圍擴充（2026-08-01，第四輪第 6 題）

本項目的適用範圍自三條 AI 調整流程**擴充至第四個 AI Event**：

| Event | 所屬流程 | 失敗的後果 |
|-------|----------|-----------|
| AI 已微調訓練強度 | AI 訓練前調整流程 | 使用者拿不到調整建議，但可照原課表訓練 |
| AI 已調整訓練 | AI 訓練中調整流程 | 同上 |
| AI 已優化訓練強度 | AI 自動優化訓練流程 | 課表範本不更新，無立即後果 |
| **AI 已產出訓練品質評分** | **教官申請流程** | **申請卡住：初審已定案「無人工介入，由系統依門檻自動判定」，AI 無評分即無從判定，該申請沒有任何 Event 可承接** |

第四項的後果最嚴重，且與前三項性質不同（前三項可降級為「不調整」，第四項無法降級）。
作答時請一併裁決該 Event 的處理方式，或明確指出四者採不同策略。

模型中同類問題的既有處理先例為「商品發放已失敗」：系統自動重試、上限 3 次、達上限轉人工處理。

**優先級調整**：Medium → **High**（因新增的第四個 Event 會使教官申請流程出現無出口的狀態）
