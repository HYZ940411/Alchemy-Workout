# 釐清問題

教官聲望 Aggregate 已定案「每位學徒每週最多 2 次任務評分計入聲望」的防刷機制，但〈Read Model：師徒互動頁〉（服務教官）是否呈現「本週是否已被該學徒評分」與「該學徒本週已計分的任務評分次數（0/1/2）」兩個欄位尚未裁決。未納入時，教官無從得知本週的任務評分是否已達上限，該規則將成為看不見的隱形規則。

# 定位

流程：師徒互動流程
元素：Read Model「師徒互動頁」
細節：既有裁決已明訂「不呈現個別評分內容」「不呈現該學徒本週是否已評分我」（避免教官反推評分者身分或催評分），但本題問的是「已計分次數（僅數字 0/1/2，不含評分內容）」是否可呈現，兩者的匿名性風險層級不同。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 兩者皆納入：「本週已計分任務評分次數（0/1/2）」讓教官知道還能不能靠任務評分累積聲望；「本週是否已被該學徒評分」（僅指每週互動評分這一項，不透露星等）讓教官知道該學徒本週的固定聲望管道是否已發生，兩者皆為次數/狀態而非分數內容，不洩漏匿名性（**推薦**：模型已為此規則的存在理由明文寫下「本規則需要被看見才有嚇阻效果」，若完全不呈現，防刷規則等同不存在；且「次數」與「是否已評」本身不透露星等，與既有的匿名性判準（教官不得反推評分者給了幾星）並不衝突） |
| B | 僅納入「已計分任務評分次數（0/1/2）」，不納入「本週是否已被評分」——後者仍可能被教官解讀為催評分的信號 |
| C | 兩者皆不納入，維持現行的完全不呈現，教官僅能透過聲望總平均的變化間接感受 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Read Model「師徒互動頁」的欄位定義；不影響 Aggregate 或 Command 結構（資料皆已存在於教官聲望 Aggregate 與師徒任務 Aggregate 中）。

# 解決結果

**選項 A：只納入 ②（本週已計分次數），不納入 ①（本週是否已被該學徒評分）。**

| 欄位 | 是否納入 | 理由 |
|------|---------|------|
| ① 本週是否已被該學徒評分 | **❌ 不納入** | 呈現此欄等同把「去催學徒評分」變成可執行的動作，而每週互動評分的意義在於它是**學徒自發的評價**；教官一催，該分數即不再是指導品質的訊號 |
| ② 該學徒本週已計分的任務評分次數（0 / 1 / 2） | **✅ 納入** | 每位學徒每週最多 2 次任務評分計入聲望（防「狂指派刷聲望」的合謀漏洞）；不呈現則該規則成為隱形規則，教官只會認為系統故障。且**本規則需要被看見才有嚇阻效果** |

**兩者分屬不同性質，各自的既有理由皆成立且不互相衝突**，故分別處理：
② 的作用是讓防刷規則可被理解（服務規則的可驗收性），
① 的作用是讓教官知道誰還沒評分（製造出一個不該存在的催促動作）。

② 的呈現不洩漏任何個別評分內容（只顯示次數、不顯示星等），
與〈評分對教官的揭露界線〉「教官看不到任何個別學徒給的評分」不衝突。

**本題與第 18、20 題同型**：模型的欄位表中「本週已計分次數 / 上限」已存在，
且〈本週已計分次數為必要欄位〉與〈不呈現「該學徒本週是否已評分我」〉兩節的論證皆已完備，
缺的僅是移除 `[待決策 Partial]` 標記並明確化兩者的取捨關係。
