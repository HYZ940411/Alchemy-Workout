# 釐清問題

〈訓練結算流程〉為模型中 31 條流程之一，是使用者每次訓練必經的終點畫面，
但 `00_全域規範.md` 已定義的 **24 個 Read Model 中沒有訓練結算頁**。
使用者在結算當下看到什麼，模型完全未定義。

# 定位

流程：訓練結算流程
元素：Read Model（識別缺口）
細節：D6 Read Model 識別、E4 Read Model→Command 支撐。
由助理於第八輪第 10 題查證「使用者回顧時會不會看到逾時中斷」時發現。

# 為何這是缺口而非可略過

〈Read Model 建立原則〉明訂「以 Command 為索引逐一詢問」。
訓練結算流程承載的事實密度為全模型最高者之一：

| 於結算時發生 | 已定義於 |
|-------------|---------|
| 訓練已結算（三種終止狀態皆進入） | 訓練紀錄 Aggregate |
| 訓練獎勵已發放（金幣、道具，含連續訓練加成） | 獎勵定義 |
| 經驗值已增加 → 可能觸發階級提升 | 階級設定 |
| 能力值已提升（六維各自累加） | 能力值 |
| 個人排行榜分數已增加 | 排行榜 |
| 團隊日常分數已增加 | 團隊任務 |
| 累積訓練次數 +1、連續訓練天數更新 | 使用者 Aggregate |
| 可能觸發訓練成就解鎖 | 成就定義 |

**這些全部在同一個畫面上對使用者揭露，但沒有任何一份定義說明揭露哪些、如何呈現。**

# 已由第 10 題確定的一條規則

**不呈現終止方式**（完成 / 提前結束 / 逾時中斷）。
理由：終止方式為內部事實，供 AI 訓練品質評分〈訓練規律性〉判讀，非給使用者看的評語；
且逾時中斷者多為練畢未按結束，標示出來等同對確實訓練者貼負面標籤。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 僅呈現本次訓練的實績（總訓練量、時長、完成組數）＋ 本次獲得的獎勵，其餘變動不呈現 |
| B | A ＋ 本次的成長（經驗值、六維能力值增量、階級或等級是否提升） |
| C | B ＋ 社群性數值（個人排行榜分數、團隊日常分數的增量與當前名次） |
| D | 全部呈現，且成就解鎖以獨立彈窗插播 |
| Short | 提供其他簡短答案（<=5 字） |

# 一併須裁決的子題

1. **成就解鎖如何呈現**：與其他數值並列，或獨立彈窗？（成就為終身一次的里程碑）
2. **階級提升如何呈現**：〈階級提升流程〉為獨立流程，其畫面與結算頁的關係為何？
3. ~~結算頁是否需「確認」動作~~ —— **本子題已由既有裁決回答，不需再問**：
   `resolved/event/訓練已結算_結算是自動觸發或需使用者確認.md`（選項 A）已定
   「由系統自動結算，不需使用者確認，亦無申訴 / 修正窗口」。
   故結算頁為**純呈現**，不支撐任何 Command，看完即可離開。
   **這使本項在 Read Model 中屬特例**：〈Read Model 建立原則〉以「支撐哪個 Command」
   為建立索引，而本頁不支撐任何 Command，其存在理由為**揭露已發生的事實**。
   建立時須說明此差異，否則與該原則相衝。

# 影響範圍

影響〈訓練結算流程〉全流程的 Read Model 支撐、可能連帶〈階級提升流程〉的畫面歸屬；
與 `read-model/訓練進行中頁_是否標示動作已被替換.md` 同屬訓練主動線的 Read Model 群組，
建議一併處理。

相關已解決項目：
`resolved/event/訓練已結算_結算是自動觸發或需使用者確認.md`（自動結算、無確認動作）、
`resolved/rule/訓練已結算_中斷的訓練是否進行結算與發放獎勵.md`（三種終止皆結算）、
`resolved/read-model/訓練歷史_可回溯時間範圍與圖表與搜尋.md`（回顧檢視，與本項互補）。

# 解決結果（2026-08-08，第八輪第 24 題，拆為 4 個子題）

使用者要求拆小題後逐題裁決。**核心設計約束為「重複性」** ——
本頁一年約呈現 150 次，內容若每次相同即淪為壁紙。
故版面分為**固定核心**與**條件式亮點**兩層。

## 24.1 核心區塊：D（五項全放）＋ 使用者新增小節點機制

| 欄位 | 說明 |
|------|------|
| 實績摘要 | 總訓練量、時長、完成組數 |
| **六維能力值增量** | 本區塊主角，模型中唯一表達「我變強了」的數值 |
| **能力值等級與小節點進度** | 格式 `B　+12　距 30 升 B+` |
| 連續訓練天數 | — |
| 經驗值增量與階級進度 | — |
| 金幣獎勵 | — |

**使用者主動提出的新機制：能力值每階內插入 `+` 與 `++` 兩個小節點。**

原因為助理指出「主階需 2–6 個月才跳一次，單次訓練推進不足 1%，進度條紋風不動」，
使用者以小節點補掉該缺口。18 個節點的分段見
`00_全域規範.md`〈能力值等級〉。附帶兩條規則：
**小節點不掛成就**（否則 12 枚膨脹至 36 枚以上）、
**小節點變動不產生「能力值等級已變動」Event**（頻率增為三倍而無讀者）。

## 24.2 社群區塊：B（團隊貢獻 ＋ 分享入口）

- 「為團隊貢獻了 X 分」**不需比較對象即成立** —— 語意為「我幫上忙了」而非「我排第幾」。
- 分享入口置於此：結算當下為最想炫耀的時刻。
- **不放個人排行榜名次**：意義來自比較，而本頁只有使用者自己；且排行榜為延遲更新，當下名次可能是錯的。
- **不放團隊限時任務進度**：置於此等同要求剛練完的使用者去催別人，將回饋時刻變成待辦事項。

## 24.3 ＋ 24.4 亮點區塊：收斂為「成就解鎖」單一項

**使用者提出整併**：「階級提升也可以跟成就綁一起？日常提升就跟經驗進度條綁一起？
能力值小節點提升跟能力值提升綁一起？」

助理查證後確認整併成立，但**模型的 8 類成就中沒有階級成就**，故需補上第 9 類。

| 原候選 | 歸屬 |
|--------|------|
| 階級提升 | **新增第 9 類「階級成就」** |
| 能力值主階提升 | 第 8 類能力值成就 |
| 能力值小節點提升 | 核心區塊（該行自行變化） |
| 連續訓練天數里程碑 | 第 3 類連續訓練成就（**使用者指出此點，助理原將其列為獨立候選，實為重複**） |
| 日常階級進度 | 核心區塊 |

**整併後的結構可一句話說明：核心區塊 ＝ 連續的進度，亮點區塊 ＝ 離散的里程碑，
而里程碑在模型中即稱為成就。**

不採彈窗插播：會打斷結算頁的閱讀，且成就與階級同時觸發時將連續彈出多次。

# 新增第 9 類成就「階級成就」

理由與新增第 8 類時同型：既有類別無一衡量該面向
（前 7 類衡量行為次數、第 8 類衡量變得多強、**第 9 類衡量投入了多久**）。
階級為模型中最長線的養成（99 階、約一年滿等），原本連一個里程碑都沒有。

`[待決策 Partial]` 枚數與門檻階級未給定，併入獎勵定義的虛擬貨幣經濟群組。
