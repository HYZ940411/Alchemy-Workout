# 釐清問題

全模型 28 條流程皆未定義任何 Read Model。應優先定義哪些 Read Model？定義的顆粒度為何（依畫面或依 Actor 決策點）？

# 定位

流程：全流程
元素：Read Model：全模型皆未定義（D6 檢查項全數 Missing）
細節：Read Model 識別（D6）；Read Model 支撐 Command（E4）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 依 Actor 決策點定義：每個需要判斷的 Command 前對應一個 Read Model（如訓練前的課表檢視、購買前的餘額與庫存檢視） |
| B | 依畫面定義：首頁 / 訓練頁 / 社群頁 / 排行榜 / 商城 / 個人檔案 / 師徒頁 / 管理後台，每頁一個 Read Model |
| C | 先僅定義高頻決策點的 Read Model（訓練、簽到、排行榜、商城購買），其餘延後 |
| D | 延後至實作規劃階段再定義，本階段不建模 Read Model |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Read Model 層的建模策略與工作量、每個 Command 是否有對應的判斷依據（E4）、以及是否存在無人使用的過度設計。建議在 Aggregate 定案後再展開。

High

# 待納入的顯示策略（來自已解決項目）

第 46 題（`resolved/aggregate/教官聲望_聲望的計算公式與可否下降.md`）討論中，
使用者關切「扣分會讓教官不爽」，經討論後同意將以下顯示策略留待本題正式定案：

- 教官端**只顯示平均星等**與「距離下一個帶徒上限的進度」，**不外顯聲望點數與逐筆扣分**。
- 進度以進度條呈現，不出現負數（聲望地板值 0 已於 Aggregate 層保證）。

本項為待定案的候選規則，非既定裁決。

# 解決結果

**選項 A｜僅為「Actor 下 Command 前必須看見」的資訊建立 Read Model**

- 判準為「是否支撐決策」，不是「是否跨 Aggregate」；單一 Aggregate 的查詢若攸關決策同樣成立。
- 純展示、與任何 Command 無關的畫面不納入模型。
- 盤點方式：以〈Command 清單〉的 226 個 Command 為索引逐一詢問，有答案者才立 Read Model。
- 每個 Read Model 須註明：服務的 Actor、支撐的 Command、欄位與來源、即時性要求。

使用者附帶指出：能力值 UI 將以六角雷達圖呈現，且需有成長 / 退步的動態。
該項依本原則成立（支撐「選擇訓練課表」「選擇動作」兩個 Command），
另立獨立釐清項目 `read-model/六維能力值雷達圖_欄位來源與即時性為何.md` 處理。
