# 釐清問題

使用者在執行簽到 Command 前，需要看到哪些資訊才能做決策？此 Read Model 應包含哪些欄位？

# 定位

流程：每日簽到流程
元素：Read Model：簽到頁（尚未定義）；服務對象 Actor：使用者
細節：Read Model 識別與欄位來源（D6）、Read Model 支撐 Command（E4）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 當日是否已簽到、連續天數、累計天數、次一個成就門檻與距離 |
| B | 上述加上本月簽到日曆、補簽券持有數量 |
| C | 上述全部加上今日簽到可獲得的獎勵預覽與連續加成 |
| D | 僅需「當日是否已簽到」與「連續天數」 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響簽到頁 Read Model 的欄位定義與資料來源（連續簽到 Aggregate、成就 Aggregate、補簽券 Aggregate）、即時性要求、以及是否揭露成就門檻參數給使用者。

# 優先級

Medium

# 既有約束（來自已解決項目）

第 5 題（`resolved/event/使用者已簽到_當日已簽到時再次簽到的Event為何.md`，選項 C）已裁決：
簽到入口的顯示與否由 Read Model 控制，重複簽到不產生失敗 Event。
因此本 Read Model **必須包含「當日是否已簽到」欄位**，此為既定前提，不再重新討論。

# 解決結果

**使用者自訂答案：「僅今天簽到即可，補簽要到其他畫面」**

- Read Model「簽到頁」僅一個欄位：今日是否已簽到（bool）。
- 連續天數、累計天數、歷史最長連續天數、連簽成就進度皆不納入：屬回顧型資訊，
  不影響「今天要不要簽」的決策，依第 3 題總綱判準不收。
- **補簽移出簽到頁**，由獨立畫面承載，另立 Read Model「補簽頁」處理
  （`read-model/補簽頁_補簽前需看到哪些資訊.md`）。
