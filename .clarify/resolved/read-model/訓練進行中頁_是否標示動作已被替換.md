# 釐清問題

第七輪第 1 題新增 Event「AI 已替換動作」，其攜帶原動作 ID、替換後動作 ID 與替換原因，
理由之一即為「供訓練進行中頁標示」。但〈Read Model：訓練進行中頁〉是否真的呈現該標示、
以何種形式呈現，尚未裁決。

# 定位

流程：訓練紀錄流程
元素：〈Read Model：訓練進行中頁〉
細節：D6 Read Model 識別、E4 Read Model→Command 支撐。
由助理於第七輪第 1 題回寫時標記為 `[待決策 Partial]`。

# 背景

替換發生於選定課表後、開始訓練前，且已落地為一份自訂訓練。
使用者進入訓練時看到的是替換後的動作，**若不標示，他不會知道課表被改過**。

反面考量：〈Read Model：訓練進行中頁〉的既有裁決方向為**減少干擾**
（防作弊的 30 秒阻擋是否顯示倒數，至今仍為待決策，理由即為不打擾訓練節奏）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | **不標示**：使用者在調整當下已看過並確認，訓練中不需再提醒 |
| B | **標示替換後動作**：該動作旁加一個「已替換」標記，點擊可看原動作 |
| C | **標示並顯示原動作名稱**：直接呈現「原：槓鈴臥推 → 現：啞鈴臥推」 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響〈Read Model：訓練進行中頁〉的欄位、本次訓練課表 Aggregate 是否需保存
「原動作 ID」（若不標示則該值只存在於 Event，Read Model 無來源）。

**須注意**：若選 A，「AI 已替換動作」攜帶原動作 ID 的三個理由中就少了一個，
剩餘理由（AI 品質分析、申訴舉證）仍成立，該欄位不因此移除。

# 解決結果（2026-08-08，第八輪第 29 題）

**D** —— 標示該動作已被替換、可展開檢視原動作，**並提供「換回原動作」的動作**。

## 標示與原動作（B 的部分）

- **使用者需要知道眼前的課表與他所選的那份不同**：他選的是胸推日，
  第一個動作卻變成啞鈴臥推 —— 無標示則會以為自己選錯課表或懷疑系統出錯。
- **原動作必須可見**：那是判斷「這個替換合不合理」的唯一依據；
  「AI 已替換動作」Event 本即攜帶原動作 ID，為現成資料。
- 本欄位同時服務**申訴舉證**與 **AI 品質分析**，
  承該 Event 攜帶兩個動作 ID 時所寫的原始理由 —— 該理由原本懸空，本題補上對應欄位。

## 還原路徑（D 的部分，使用者裁決）

新增 Command「**還原被替換的動作**」／ Event「使用者已還原被替換的動作」。

| 項目 | 內容 |
|------|------|
| Precondition | 該動作為「AI 已替換動作」的結果、**尚無任何已完成的組**、本次訓練尚未結算 |
| Postcondition | 本次訓練課表快照還原為原動作，含各組目標重量與次數 |
| Postcondition | **不改動已落地的自訂訓練**（承「訓練中的調整只改快照」） |
| 粒度 | 逐個動作各自還原，非整批 |

**「尚無已完成的組」的理由**：已有實績的組若被還原，
其實績將指向一個已不在課表中的動作，訓練量與能力值的歸屬無法判定。

## 助理原推薦 B，兩個反對理由中有一個不成立

| 原反對理由 | 檢驗結果 |
|-----------|---------|
| 還原的原動作可能因器材不足而做不了 | **成立**，已記為 `[已知風險]` |
| 「D 會從訓練中開後門」，牴觸「開始訓練前不可直接手動修改」 | **不成立** —— 該規則的範圍為**開始訓練前**，而本 Command 發生於訓練中；模型於訓練中本即允許修改重量與次數，並設有 AI 訓練中調整流程。助理當場更正 |

`[已知風險]`：使用者當初走到本路徑的原因為器材不足，還原的原動作有可能當下做不了。
模型不阻擋，由使用者自行判斷；其仍可透過 AI 訓練中調整再次更換。
