# 釐清問題

互動者執行 Command「按讚貼文」「留言」前必須看到什麼？社群動態牆呈現哪些貼文（依可見範圍與關注關係）、如何排序、即時性要求為何？

# 定位

流程：發文與互動流程
元素：Read Model（尚未定義）；支撐 Command「按讚貼文」「留言」「檢舉內容」
細節：D6 Read Model 識別（篩選、排序、分頁）、E4 Read Model → Command 支撐。
既有 Precondition「該貼文依其可見範圍對此互動者可見」，其判定所依據的資訊來源即為本 Read Model，但模型未定義。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 依時間新到舊排序；收錄「可見範圍＝公開」的全部貼文 ＋ 已關注者的「僅關注者」貼文；每筆呈現作者、內容、圖片、按讚數、留言數、已編輯旗標、我是否已按讚 |
| B | 同 A 的欄位，但預設僅收錄已關注者的貼文（追蹤流），公開貼文另立探索頁 |
| C | 同 A，另加「關聯訓練紀錄」的摘要（總訓練量、動作數）於分享訓練成果的貼文 |
| D | 同 C，並將排序改為互動熱度加權，非純時序 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Read Model 清單、貼文 / 留言 / 關注關係 / 封鎖四個 Aggregate 的查詢組合、「該貼文依其可見範圍對此互動者可見」Precondition 的判定依據、已刪除貼文與已封鎖對象的排除規則、以及師徒功能解鎖所需五項社群行為的可執行入口。
相依：`rule/使用者已封鎖對象_封鎖是否連帶解除關注與師徒與團隊關係.md`（封鎖對動態牆的過濾效果）。
相關已解決項目：`resolved/aggregate/貼文_貼文的欄位內容型態與可見範圍.md`、`resolved/aggregate/留言_留言與按讚是否為獨立Aggregate及其欄位.md`。

# 優先級

High

# 解決結果

**選項 D ＋ 使用者修正：作者資訊只到階級與聲望**

| 項目 | 裁決 |
|------|------|
| 範圍 | 兩個分頁並存：關注 / 探索（全平台公開貼文） |
| 排序 | 發布時間新到舊 |
| 作者資訊 | 顯示名稱、階級、聲望點數（僅教官身分者有值） |
| **不呈現** | **六維能力值與能力等級** —— 須點入個人檔案頁才可見 |
| 訓練成果分享 | 附帶課表名稱與總訓練量，不含逐組明細 |
| 即時性 | 即時 |

## 使用者修正的理由（助理補述）

- 個人檔案頁已承載六維能力值，動態牆再呈現一次為重複。
- 動態牆的決策是「按讚 / 留言」，不需要作者能力值；需要能力值的「關注」與
  「申請師徒關係」皆於個人檔案頁下達。
- 一併避開〈六維能力值的對外可見性〉的兩個待決策（綜合等級是否連動、教官可否隱藏）。

## 助理於提問時的兩處錯誤（已更正）

出題時稱選項 D「與模型衝突」，兩點皆不成立：

| 錯誤說法 | 實際 |
|----------|------|
| 「貼文與訓練紀錄的關聯模型中不存在，須新增結構」 | 〈貼文 Aggregate〉**已有**「關聯訓練紀錄」欄位，Event「發文者已分享訓練成果」已存在且該欄位必有值 |
| 「與〈訓練歷史不對外可見〉衝突」 | 該裁決的標的為**逐組重量與次數的原始紀錄**；D 帶的課表名稱與總訓練量屬彙總層，且分享為作者主動發起 |

根因：出題前未 `grep` 模型檔確認，憑記憶論斷。此為 `HANDOFF.md` §2 已記載過的同類錯誤。
