# 釐清問題

訓練紀錄 Aggregate 中重量欄位的單位、資料型別、精度為何？重量為 0（自身體重動作）是否合法？

# 定位

流程：訓練紀錄流程（循環：使用者已記錄重量 > 組間休息已結束）
元素：Aggregate：訓練紀錄，欄位：重量、次數
細節：欄位型別與單位（D2）；特殊值：空值、零、負值（C3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 重量 float（公斤，精度 0.5），允許 0（自身體重動作），不允許負值；次數 int >= 1 |
| B | 重量 float（公斤，精度 0.1），允許 0，次數 int >= 0（允許記錄失敗組） |
| C | 重量支援公斤與磅雙單位，需額外單位欄位；0 不合法，自身體重動作另以旗標標記 |
| D | 重量 int（公斤，整數），允許 0，次數 int >= 1 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響訓練紀錄 Aggregate 欄位定義、記錄重量 / 次數 Command 的輸入驗證 Precondition、總訓練量的計算公式（重量為 0 時的處理）、以及訓練結算流程的能力值計算輸入。

# 優先級

High

# 解決結果

A — 重量 float（公斤，精度 0.5），允許 0（自身體重動作），不允許負值；次數 int ≥ 1。

不採 C 的獨立單位欄位：第 27 題已定使用者 Aggregate 具「單位偏好」欄位，
訓練紀錄沿用該欄位控制英制顯示，不重複儲存單位。

不採 B 的「次數 ≥ 0」：不記錄次數為 0 的失敗組。

# 承接的既有裁決

第 32 題已定「徒手」為動作所需器材的值域之一，自身體重動作確實存在，
故重量為 0 必須合法。

# 連帶影響

`.clarify/pending-gaps.md` G18（能力值提升幅度公式）：
訓練總量的計算基礎已明確（重量 float 精度 0.5 × 次數 int ≥1 × 組數）。
但重量為 0 的徒手動作，其訓練總量以此公式計算恆為 0 —— 徒手動作如何計入能力值
