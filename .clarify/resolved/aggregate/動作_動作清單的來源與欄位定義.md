# 釐清問題

「使用者已選擇動作」所選的動作來自何處？動作 Aggregate 的欄位定義為何？使用者可否自建動作？

# 定位

流程：自訂訓練流程（循環 1：使用者已選擇動作 > 使用者已設定該動作的組數、循環 2：使用者已設定該組的重量 & 次數）
元素：Aggregate：動作（模型中尚未定義）；Event：使用者已選擇動作
細節：隱含但未明確定義的 Aggregate（D1）；欄位定義（D2）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 平台維護的固定動作庫，欄位含名稱 / 目標肌群 / 所需器材 / 示範內容，使用者不可自建 |
| B | 平台動作庫為主，使用者可自建私人動作，需補上「使用者已建立自訂動作」Event |
| C | 平台動作庫，且使用者可申請新增動作至公用庫，需管理員審核 |
| D | 僅有動作名稱字串，無獨立 Aggregate |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響是否需新增動作 Aggregate 與管理員維護流程、能力值分肌群計算的資料來源、註冊流程「依器材推薦」Policy 的比對依據、以及自訂訓練與動作的關聯關係（一對多）。

# 優先級

High

# 既有約束（來自已解決項目）

第 28 題（`resolved/aggregate/能力值_能力值的定義與提升計算方式.md`，選項 B）已裁決：
能力值為 6 個肌群維度（胸 / 背 / 腿 / 肩 / 手 / 核心），提升依動作所屬肌群。
故動作 Aggregate **必須具備「所屬肌群」欄位**，值域為上述 6 個肌群，此為既定前提。
訓練屬性（力量 / 耐力 / 爆發）本階段不進模型，動作 Aggregate 不需該欄位。

# 解決結果

B（含使用者補充） — 使用者原話：「B 但使用者自建不計算於能力值」。

平台動作庫為主，使用者可自建私人動作，新增 Event「使用者已建立自訂動作」。
自建動作僅建立者本人可選用，不進入平台動作庫，且**不計入能力值計算**。

動作 Aggregate 欄位：名稱、所屬肌群（6 肌群列舉）、所需器材、示範內容、來源、建立者。

# 承接的既有裁決

- 第 28 題：所屬肌群欄位為必要，值域 6 肌群；不需訓練屬性欄位。
- 第 23 題：所需器材值域與註冊流程一致（健身房 / 居家器材 / 徒手）。

# 連帶影響

- 訓練結算流程「能力值已提升」新增 Precondition：僅平台動作庫的動作計入。
- 自建動作是否需填所屬肌群，因不計入能力值而不再是必要條件 —— 但欄位仍存在於
  Aggregate 中，是否允許留空未表態，記錄於 `.clarify/pending-gaps.md` G20。
