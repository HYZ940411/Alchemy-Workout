# 釐清問題

教官帶徒上限的初始值、各聲望門檻與對應的上限值為何？上限是否有最大值？

# 定位

流程：師徒互動流程
元素：Aggregate：教官帶徒上限；Rule / Policy：聲望達門檻 → 提升帶徒上限（門檻與幅度未定義）
細節：待決事項與模糊描述（F3、F4）；數值邊界與最大值（C3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 初始 3 人，每達一個聲望門檻 +2 人，上限 15 人 |
| B | 初始 1 人，每達一個聲望門檻 +1 人，無最大值 |
| C | 初始 5 人，門檻與幅度由管理員後台設定，需要設定 Aggregate |
| D | 初始值依教官測驗成績決定，之後每達門檻 +2 人 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響教官帶徒上限的欄位定義與範圍、教官帶徒上限已提升的 Postcondition、師徒關係已建立的 Precondition（是否超過上限）、以及是否需要管理員設定流程。

# 既有約束（來自已解決項目）

第 46 題（`resolved/aggregate/教官聲望_聲望的計算公式與可否下降.md`，選項 B-2 + 地板值）已裁決：
帶徒上限為**單調遞增**，聲望下降時不隨之降低，無「帶徒上限已降低」Event。
聲望點數地板值為 0。

本題僅剩：帶徒上限的初始值、每次提升的幅度、觸發提升的聲望門檻。

# 解決結果

C 之機制 + 使用者給定的數值 + 代號① — 使用者原話：
「初始 1 人，每達門檻 +1 最多 5 門檻與幅度由管理員後台設定，需設定 Aggregate」「①」。

新增「帶徒上限設定」Aggregate（平台級），參數與預設值：

| 參數 | 預設值 |
|------|--------|
| 初始帶徒上限 | 1 人 |
| 每次提升幅度 | +1 人 |
| 帶徒上限最大值 | 5 人 |
| 聲望門檻清單 | 未給定（Partial） |

- 上述參數皆由管理員調整，非寫死於系統
- 達最大值 5 人後，聲望再提升亦不增加上限
- 參數調整不使既有帶徒上限降低（承第 46 題單調遞增裁決）

# 併同回答（第 11 題留下的問題）

代號① — **申請中的師徒申請佔用帶徒名額**：

- 名額佔用數 ＝ 已建立的師徒關係數 ＋ 申請中的師徒申請數
- 「使用者已申請師徒關係」的 Precondition：教官名額佔用數未達帶徒上限
- 「對方已拒絕申請」「師徒申請已逾期」「師徒關係已解除」發生時釋放名額

此規則避免了②的超收風險（上限 5 人卻同時收到 10 份申請並全部接受）。

# 承接的既有裁決

第 46 題：帶徒上限單調遞增，聲望下降時不隨之降低。
