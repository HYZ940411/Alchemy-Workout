# 釐清問題

連續訓練 Aggregate 的「上次訓練日期」欄位，在使用者從未訓練時的初始值與空值語意為何？

# 定位

流程：訓練中斷流程、訓練結算流程、回歸任務流程。
元素：Aggregate：連續訓練 —— 欄位「上次訓練日期」（檢查項 D2 欄位定義、D3 不變條件）。
細節：

- `02_Aggregate定義.md:2034-2040` 的欄位表僅一列：
  「上次訓練日期 | date | 使用者當地日期，作為中斷判定的計時基準」——
  **無初始值、無「/ 空值」型別標註、無空值時的行為說明**。
- 模型其他欄位遇同類情形皆有明確處理，本欄位為例外：
  - 回歸任務的「時限起算時戳」明寫「留空；**時限起算時戳為空值者，逾期判定不啟動**」
    （`回歸任務流程.md:9,11`）。
  - 使用者的「偏好訓練時段」明寫「跳過者本欄位維持空值…**該日不發送訓練提醒**」
    （`02_Aggregate定義.md:302`）。
  - 訂單、處罰到期時戳等皆以「Timestamp / 空值」標註型別。
- 本欄位是**四個排程判定的唯一計時基準**（`02_Aggregate定義.md:2058-2064`）：
  +24 中斷預告、+36 連續訓練天數已歸零、+96 退步預告、+240 能力值已退步。
- 連帶影響「能力值已退步」的冪等去重鍵 ——
  `00_全域規範.md` 定其週期起點為「該肌群維度的 240 小時計時起算點」，
  計時起算點無值時該去重鍵無法推導。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 型別改為「date / 空值」，初始為空值，並明訂「空值者四道中斷判定一律不啟動」（比照回歸任務時限起算時戳的既有寫法） |
| B | 初始值為註冊日，四道判定自註冊日的日界起算，欄位不允許空值 |
| C | 初始值為空值，但另以使用者 Aggregate 的「累積訓練次數 ＝ 0」作為判定不啟動的條件，本欄位不承載該語意 |
| D | 初始值為完成新手任務之日；未完成新手任務者維持空值且判定不啟動 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

- **四個排程類 Event 的 Precondition**：中斷預告已發送、連續訓練天數已歸零、退步預告已發送、能力值已退步 —— 四者的觸發母體全數取決於本題。
- **回歸任務**：其 Precondition 為「能力值已退步」已發生，故本題連帶決定回歸任務對從未訓練者是否指派。
- **冪等去重鍵**：「能力值已退步」的週期起點推導式（`00_全域規範.md`〈第一類：週期性重複判定〉）在空值下無法成立，選 A / C / D 須一併說明該情形下不產生請求識別碼即可（因 Event 本即不發生）。
- **能力值退步下限**：選 B 會使從未訓練者於註冊後第 10 日產生「能力值已退步」，惟六維初始值 10 同時為退步下限，實際點數不變 —— 須確認產生一個無狀態變化的 Event 是否可接受。
- **須與 `event/使用者已完成註冊_註冊後從未訓練者是否有任何召回機制.md` 一併裁決**：該題的選項 A 即等同本題的選項 B，兩題不可各自獨立回答。

# 解決結果

**選項 A**：「上次訓練日期」於註冊時填入註冊日，四道既有中斷門檻與回歸任務對從未訓練者照常運作，**不新增任何 Event、Command 或通知**。

- 連續訓練 Aggregate 的「上次訓練日期」**不允許空值**，初始值＝註冊日（使用者當地日期），
  於「使用者帳號已建立」時一併產生。
- 能力值 Aggregate 的「各維最後訓練日」六維**同採註冊日**為初始值，兩個計時器同時起算。
- 從未訓練者的召回路徑因此成立：註冊日 +24 小時中斷預告 → +96 小時退步預告 →
  +240 小時能力值退步 → 回歸任務指派。
- `[已知取捨]` 第 10 日的「能力值已退步」因六維初始值 10 即為退步下限，
  **點數實際不變**，等同產生一個無狀態改變的 Event；
  承既有判例「使用者已失去獎勵加成」之「可推導不等於不成立為 Event」，明示接受。
- 未採 B（新建新手專屬召回路徑）：須新增 Event 與 Command、另訂觸發天數、
  擠入推播優先序並與同日總量上限 3 則／日競爭，所做的事與既有四道門檻高度重疊。
- 未採 C（新手任務補上完成期限）：與既有裁決「新手任務無完成期限」直接衝突。
- 未採 D（明示接受）：既有兩處已接受的缺口皆為老使用者的長線問題，本處為新使用者且完全零介入。
