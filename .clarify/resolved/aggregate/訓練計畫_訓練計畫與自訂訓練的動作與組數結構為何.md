# 釐清問題

訓練計畫與自訂訓練 Aggregate 的「課表內容」結構為何（動作清單、每動作組數、每組目標重量與次數）？兩者是否共用同一結構？

# 定位

流程：註冊流程、自訂訓練流程、訓練紀錄流程、階級提升流程
元素：Aggregate「訓練計畫」「自訂訓練」
細節：欄位定義（D2）；Aggregate 內部不變條件（D3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 兩者共用同一「課表內容」結構：動作清單 →（每動作）組數 →（每組）目標重量與次數，皆為必填 |
| B | 共用同一結構，但目標重量為選填（僅設定組數與目標次數），重量於訓練當下決定 |
| C | 訓練計畫僅定義動作與組數（不定目標重量次數）；自訂訓練則三層皆定義，兩者結構不同 |
| D | 兩者合併為單一 Aggregate，以「來源＝平台 / 使用者自建」欄位區分 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響訓練進度條的「總計畫組數」計算來源、「使用者已設定該動作的組數」與「使用者已設定該組的重量&次數」兩個 Event 所寫入的欄位、
AI 調整的作用標的，以及註冊推薦 Policy 的比對資料。
本項為新掃描發現，非承接 `pending-gaps.md`。相關已解決項目：`resolved/aggregate/進階訓練計畫_解鎖的計畫內容與階級對應關係.md`（僅定義名稱 / 適用條件 / 所需階級三欄，未定義課表內容）。

# 解決結果

**選項 A ＋ 使用者補充**：兩者共用同一結構，目標重量必填。

**課表內容結構（三層，訓練計畫 / 自訂訓練 / 本次訓練課表共用）**：

| 層級 | 內容 |
|------|------|
| 第一層 | 動作清單 |
| 第二層 | 該動作的組數（int ≥ 1） |
| 第三層 | 每一組的目標重量與目標次數 |

| 第三層欄位 | 型別 | 單位 | 範圍 | 必填 |
|------------|------|------|------|------|
| 目標重量 | float（精度 0.5） | 公斤 | ≥ 0 | 必填 |
| 目標次數 | int | 次 | ≥ 1 | 必填 |

**使用者補充的三點**：

1. **逐組不同重量**：每一組可各自設定目標重量，不強制整個動作共用（與訓練紀錄逐組記錄實績一致）。
2. **徒手以 0 表示**：目標重量必填，值為 0 代表徒手。Read Model 顯示為「自重」，**儲存值一律為 0，不另存字串**（避免同欄位兩種型別）。
3. **帶入上次重量**：使用者曾做過該動作者，下次顯示上次的重量。

**追問（甲）**：平台訓練計畫的目標重量為管理員設定的**建議起始重量**。
不採乙（依能力值換算）因能力值計算公式尚未定案，會造成循環依賴；不採丁（一律填 0）因會與「徒手」的 0 撞義。

**快照產生時的目標重量帶入規則**（落在「使用者已開始訓練」的 Postcondition，非顯示層，
以確保 AI 調整與訓練進度條看到的是同一組數字）：

- 曾記錄過該動作者，帶入最近一次該動作的實際重量。
- 未曾記錄過者，沿用來源課表的值（平台計畫為建議起始重量）。
- 〔推導〕組序對應：以組序逐一對應；本次組數多於上次時，超出的組沿用上次最後一組的重量。
- 帶入只影響快照，不改動來源課表。

**共用結構同時消除了第 17 題的唯一維護風險**（快照不需處理多種來源形狀）。
