# 釐清問題

動作 Aggregate 的「所需器材明細」欄位，其完整值域清單為何？是否需要獨立的器材設定 Aggregate？粗層（健身房 / 居家器材 / 徒手）與細層的對應關係為何（「健身房」是否自動涵蓋全部明細）？

# 定位

流程：自訂訓練流程、訓練紀錄流程（動作庫）
元素：Aggregate「動作」之所需器材明細欄位
細節：D2 欄位定義、D4 Aggregate 間的關係。00_全域規範〈動作 Aggregate〉之 `[待決策 Partial]`。另註：該欄位在欄位表中**重複出現兩列**，須一併修正。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 值域固定寫死（啞鈴 / 槓鈴 / 壺鈴 / 彈力繩 / 機械 / 繩索 / 徒手 / 其他），不另立 Aggregate；粗層與細層**互相獨立**，各自標註，不做自動涵蓋 |
| B | 值域存於新的「器材設定 Aggregate」（平台級可調，比照健身目標設定與健身經驗設定的既有處理方式）；粗細兩層獨立，不做自動涵蓋 |
| C | 同 B 的獨立 Aggregate，但建立對應表：粗層「健身房」自動涵蓋全部明細、「居家器材」涵蓋彈力繩與小啞鈴、「徒手」僅涵蓋徒手，粗層由細層推導不另存 |
| D | 取消細層：動作庫的篩選僅保留粗層 3 級與肌群分頁，移除所需器材明細欄位 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響動作 Aggregate 的欄位定義（含移除重複列）、〈獨立 Aggregate 清單〉（B / C 選項自 45 項增為 46）、〈Read Model：動作庫〉的器材篩選（細）、訓練計畫推薦 Policy 的器材比對維度。
相關已解決項目：`resolved/aggregate/動作_動作清單的來源與欄位定義.md`、`resolved/read-model/動作庫_選擇動作前需看到哪些資訊.md`（器材兩層粒度 B）、`resolved/command/使用者已填入健身目標_動機類與常見目標類的完整值域清單為何.md`（平台級值域的既有處理方式）。

# 解決結果

**選項 C″（互動過程中收斂出的方案，非原四選項之一）**

## 動作端：只填器材，可練場所自動推導

| 欄位 | 型別 | 說明 |
|------|------|------|
| 所需器材明細 | 列舉複選 | **動作的器材欄位只有這一個** |
| 可練場所 | 列舉集合（**衍生**） | 由所需器材明細推導，不儲存 |

新增〈器材設定 Aggregate〉（第 49 個 Aggregate，留在系統邊界之外），
8 個器材品項各標明「哪裡有」：

| 器材品項 | 哪裡有 |
|----------|--------|
| 徒手 | 健身房 / 居家 / 徒手 |
| 彈力繩、啞鈴、壺鈴 | 健身房 / 居家 |
| 槓鈴、機械式器材、繩索（滑輪）、有氧器材 | 健身房 |

動作需要多項器材時，可練場所為**同時具備全部器材的場所**。
**管理員新增動作時只填器材，不需自行判斷該動作算健身房或居家。**

**原欄位表中「所需器材明細」重複出現兩列的錯誤已一併修正**，
且原本的「所需器材」（粗層儲存欄位）已移除，改為衍生。

## 使用者端：註冊填粗、設定填細

| 時點 | 填什麼 | 必填 |
|------|--------|------|
| 註冊 | 健身器材 3 級（可複選） | **必填**——推薦第一份訓練計畫需要它，且註冊當下尚無設定頁 |
| 之後（設定頁） | **持有器材明細**（使用者 Aggregate 新增欄位） | **選填**，填一次即可 |

**兩者不一致時以細項為準**；本欄位不建模為 Event（比照「六維能力值對外可見」）。

## 推翻的既有裁決

原規則「**明細篩選只能由使用者手動選取⋯明細層無預設值**」已推翻。
該規則的理由是「系統不知道使用者實際擁有哪些品項」，
而新增「持有器材明細」設定欄位後此前提不再成立。
動作庫的器材篩選改為**單一欄位**：預設帶入持有器材明細，未填者退回註冊的 3 級。

## 使用者的核心訴求

> 「我們是增加便利度！不是讓使用者在那邊勾來勾去，而便利度關鍵是 AI」
> 「使用者可以手動調整細層，但我們不想讓使用者浪費時間去調整，可以在設定給他，但是我們推的是 AI 便利」

故**主要動線為 AI 依可用器材推薦與替換動作**，手動調整留在設定頁、不在主要動線上。
該 AI 能力**模型中尚不存在**（三條 AI 流程調整的皆為訓練強度），
已另建 `rule/AI已調整訓練_AI依可用器材替換動作的能力尚未建模.md`（High）。

## 出題過程

助理原推薦 B（兩層獨立、不做自動涵蓋），使用者選 C 並說明理由。
助理指出 C 的原始形式有破綻（粗層為單選，從「啞鈴」推導不出單一值，
因啞鈴健身房與家裡都有），提出改為**集合**後 C 成立。
其後使用者補充「細層可手動調整但放設定頁」，收斂為 C″。
過程中助理的說明一度過於複雜，經使用者指出後改以簡化版本確認。
