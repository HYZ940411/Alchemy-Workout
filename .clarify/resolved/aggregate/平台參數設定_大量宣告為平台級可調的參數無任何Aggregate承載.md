# 釐清問題

模型中大量宣告為「平台級可調參數，由管理員於後台維護」的數值，有相當一部分**不存於任何 Aggregate**，其儲存位置應如何裁定？

# 定位

流程：跨全部流程。
元素：Aggregate（識別與欄位定義，檢查項 D1 / D2）。
細節：模型已為部分設定建立專屬 Aggregate（階級設定、帶徒上限設定、教官測驗設定、
健身目標設定、健身經驗設定、器材設定、教官專長設定、每日任務池、新手任務範本、
成就定義、獎勵定義、訓練計畫、權益設定、商品），但下列同樣宣告為平台級可調的參數
**無任何 Aggregate 承載，亦不在〈獨立 Aggregate 清單〉的 55 項之中**：

| 參數 | 現值 | 宣告處 | 現有承載處 |
|------|------|--------|-----------|
| **教官初審門檻**：需求階級 / 需求累積訓練次數 | 20 / 50 | `教官申請流程.md:14` | **無** |
| **教官初審**：品質分通過門檻 / 折抵門檻 / 一票否決門檻 ＋ 三維權重 | 60 / 80 / 40 | `教官申請流程.md:56` | **無** |
| **能力值**：六階門檻、基準值、映射係數、退步百分比、退步間隔、初始值 | 27.6 / 23.6 / 5% / 240h / 10 | `03_能力值.md:198` | `03_能力值.md` 明文寫「**不存於本 Aggregate**」，未說存於何處 |
| **內容過濾**：明顯違規 / 疑似違規的判定門檻 | 未給定 | `發文與互動流程.md:40` | **無** |
| **防作弊**：最小組間間隔 / 容許次數 | 30 秒 / 1 次 | `訓練紀錄流程.md:115` | **無** |

| **互動獎勵每日上限** | 發文 1 / 分享 3 / 按讚 10 / 留言 5 | `發文與互動流程.md:48` | **無** |
| **補簽回補範圍** | 7 天 | `補簽流程.md:7` | **無** |

對照：`04_ReadModel清單.md:1332` 明寫「門檻數值**取自平台級可調參數**，管理員調整後本 Read Model 即時反映」，
但同節的「資料來源」欄只列使用者 Aggregate 與教官測驗設定 Aggregate ——
兩者皆不含需求階級與需求次數，該 Read Model 的欄位來源目前無法推導。

# 多選題

| 選項 | 描述 |

| A | 新增單一「平台參數設定 Aggregate」，以「參數鍵 / 值 / 型別 / 值域 / 生效時戳」的鍵值結構統一承載全部無家可歸的參數 |

# 影響範圍

- **〈獨立 Aggregate 清單〉**：選 A 為 55 → 56；選 C 可能為 55 → 60 以上；選 D 為 55 → 48。
- **Read Model 的來源可推導性**：`04_ReadModel清單.md`〈教官申請頁〉的初審門檻對照欄位目前無來源可指；D6「Read Model 的每個欄位是否可從 Aggregate 推導」在此不成立。
- **既有的軟體邊界裁決**：`01_Command清單.md`〈平台級設定的軟體邊界〉已裁定「值域清單類設定留在邊界之外、不建 Command 與 Event」，但該節處理的是**是否建 Command/Event**，未處理**是否需要 Aggregate**；帶徒上限設定即為「在右欄（無 Command）但仍是 Aggregate」的既有先例，可作為本題的判準基礎。
- **不追溯原則**：既有規則「設定調整不改動任何已完成的既有紀錄」須在所選結構下仍可表達（選 A 的鍵值結構需有生效時戳方能稽核）。
- 相關已解決項目：`.clarify/resolved/aggregate/教官測驗_題數配分與及格標準.md`、`.clarify/resolved/aggregate/教官帶徒上限_帶徒上限的初始值與提升幅度.md`（兩者確立了「設定 Aggregate」的既有形狀）。

# 解決結果

**選項 C（每組各建專屬設定 Aggregate）**，分兩次提問裁決：

- **第 4-1 題（教官初審門檻）→ 選項 A**：新增〈教官初審設定 Aggregate〉。
  未併入教官測驗設定，理由為初審是考試之前的關卡、判定主體與時點皆不同，
  且多數被駁回者根本走不到測驗（承〈教官申請 Aggregate〉既有的同型理由）。
- **第 4-2 題（其餘各組）→ 選項 A（每組各一張小表）**：
  理由為與 4-1 同一標準，且通用鍵值大表寫不出不變條件
  （例如「六階門檻須嚴格遞增且連續無空隙」在鍵值表中無處可寫）。

**新增 7 個設定 Aggregate**（獨立 Aggregate 清單 55 → **62**）：

| Aggregate | 承載參數 |
|-----------|---------|
| 教官初審設定 | 需求階級 20、需求次數 50、品質分 60 / 80 / 40、折抵後次數 30、三維權重 |
| 能力值設定 | 六階門檻、基準值 27.6、映射係數 23.6、退步 5% / 240 小時、初始值 10、硬截斷 999、Epley 上限 10 下、相對強度係數、體重係數 |
| 內容過濾設定 | 明顯違規門檻、疑似違規門檻、違規類別清單（三者初始值仍待給定） |
| 防作弊設定 | 最小組間間隔 30 秒、容許次數 1 次 |
| 通知設定 | 同日推播總量上限 3 則／日、每日登入提醒時點 20:00 |
| 審核時限設定 | 檢舉 7 天、申訴 72 小時、教官測驗簡答題 7 個工作天、公開訓練 14 天 |
| 補簽設定 | 回補範圍 7 天 |

**兩組未另建表者（已明確歸位，於報告中揭露）**：

| 參數 | 處置 | 理由 |
|------|------|------|

| 換隊冷卻期 12 小時、無懲罰退出窗口 3 小時 | **不動** | 原即存於〈團隊 Aggregate〉之〈單一團隊歸屬與換隊冷卻〉參數表，本輪清查時誤列為無家 |
