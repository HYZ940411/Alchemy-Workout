# 釐清問題

新手任務完成時會觸發「能力值已提升」，但新手任務採簡化勾選機制、不產生訓練量，故不能依能力值提升公式（Epley + DOTS）計算，必須由獎勵定義 Aggregate 直接給定數額。目前該數額與所影響的肌群維度皆未給定。

# 定位

流程：新手任務流程、訓練結算流程
元素：Aggregate「獎勵定義」之新手任務獎勵一列；Rule「新手任務執行機制」
細節：`00_全域規範.md` 已明文「新手任務的『能力值已提升』只能由本表給定」，且獎勵定義表中該格標記「能力值（數額與維度待決策 Partial）」。三個候選動作各自對應不同肌群（見〈新手任務範本 Aggregate〉），故「所影響維度」需視使用者三選一選了哪個動作而定，或另訂固定規則。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 依三選一所選動作的所屬肌群，提升該維固定點數（如 +5 點），三個候選動作對應各自的維度（**推薦**：與能力值提升「依動作所屬肌群，只提升該動作對應的維度」的既有原則一致，避免新手任務成為唯一違反此原則的例外） |
| B | 不論選了哪個候選動作，一律固定提升某一維（如核心，因三個候選動作皆為全身性徒手動作），簡化規則 |
| C | 三個維度各給一個較小的固定點數（如三維各 +2），反映「剛開始全身都在動」 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響獎勵定義 Aggregate（新手任務獎勵一列）、「能力值已提升」Event 於新手任務流程中的攜帶欄位。此為 `pending-gaps-3.md` I15 之延續。

# 解決結果

**選項甲 ＋ 腿與核心 ＋ 數值 30**（本題於問答中收斂為新選項，原 A–D 皆未直接採用）。

**完成新手任務時，將「腿」與「核心」兩維的初始值由 10 拉高至 30；
不產生「能力值已提升」Event。**

## 收斂過程

1. 使用者選擇「固定加腿跟核心維度，新手任務主要是這種」——
   理由為候選動作（原地深蹲、開合跳等）本即以此二部位為主。
2. **助理指出一個衝突**：改採 1RM 後，該維點數的定義為「該肌群全部動作中歷史最高的
   標準化分數」，點數必須由實際訓練換算而來；而新手任務憑勾選給固定點數，
   其數字背後無任何實績，會 ① 破壞該不變條件；② **假點數蓋住真點數**
   （點數為單調遞增且取歷史最高，憑空的點數會蓋住其後第一次實際訓練算出的真實值）。
3. 助理提出三個解法，使用者選**甲**：改為拉高初始值而非產生「能力值已提升」。
   初始值本即憑空給定（註冊時六維皆 10），其職責為地板與退步下限，
   動的是地板而非紀錄，與「點數 ＝ 歷史最高的標準化分數」完全不牴觸。
4. 數值選 **30**：恰為 E+ 的門檻（E 級小節點分段 0–29 / 30–69 / 70–99），
   完成新手任務當下腿與核心由 `E` 變為 `E+`，為看得見的等級節點變化；
   承小節點「提供高頻進度回饋」的設計用意，並對應模型已識別的 **D7 留存缺口**。
   不採 20 或 15（皆停留在 E 基本段內，畫面上等級無變化）。

`[已知取捨]` 初始值同為點數的地板，第一次實際練腿時若算出的點數低於 30，
畫面顯示的仍為 30，最初期的真實成長會被蓋住一小段。
