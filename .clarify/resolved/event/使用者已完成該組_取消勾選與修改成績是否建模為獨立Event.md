# 釐清問題

訓練進行中取消勾選（該組回到未完成、進度條回退）與修改已記錄的重量次數，是否各自建模為獨立 Event？現有「訓練進度條已增加」為單向 Event，回退情境無 Event 承接。

# 定位

流程：訓練紀錄流程
元素：Event（尚未存在）；Command（尚未存在）
細節：A1 事件識別完整性、C4 可逆性。流程檔第 26–27 行已定案可取消勾選與可修改，第 32 行明載「[推導] 取消勾選是否建模為獨立 Event 尚未裁決」。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 新增「使用者已取消該組」與「訓練進度條已減少」兩個 Event，與正向路徑對稱 |
| B | 僅新增「使用者已取消該組」；進度條的回退沿用既有「訓練進度條已增加」（該 Event 已不要求單調遞增，改名為「訓練進度條已變動」） |
| C | 兩者皆不建模：取消勾選與修改為 Command 的反向操作，訓練結算前的過程狀態不進 Event 層 |
| D | 取消勾選建模為 Event，修改重量次數不建模（後者不改變已完成組數，僅改實績值） |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響訓練紀錄流程的 Event 清單與〈Command 清單〉、訓練進度條 Aggregate 的變動路徑、以及訓練紀錄結算前的可稽核性（AI 訓練品質評分的「紀錄合理性」維度需判讀勾選行為）。
相關已解決項目：`resolved/rule/使用者已紀錄該組重量_已記錄的組數可否修改或刪除.md`。
來源：`pending-gaps-2.md` H17。

# 解決結果

**選項 B**

- 新增 Event「使用者已取消該組」與 Command「取消該組」（Actor：使用者）
- Event「訓練進度條已增加」**更名為「訓練進度條已變動」**，漲跌共用單一 Event，
  對應 Command 由「增加訓練進度條」改為「變動訓練進度條」（多對一）
- 修改已記錄的重量與次數**不另建 Event**（承選項 B 的「僅新增」）

理由：進度條已定案不要求單調遞增，且 AI 調整導致總計畫組數變動時允許下降，
「已增加」之名與其自身規則本即不符；漲跌無獨立業務後果，不比照「使用者已失去獎勵加成」拆為雙向 Event。
「使用者已取消該組」獨立成 Event，因取消勾選的行為軌跡為 AI 訓練品質評分「紀錄合理性」維度的判讀輸入。
