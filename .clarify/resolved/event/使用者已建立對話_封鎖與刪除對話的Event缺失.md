# 釐清問題

私訊流程中封鎖對象、刪除對話、刪除訊息、檢舉私訊等 Event 全數缺失，哪些需要建模？

# 定位

流程：聊天私訊流程、管理員管理社群流程
元素：Event：使用者已建立對話、使用者已發送私訊、使用者已讀取私訊
細節：隱含發生但未寫出的 Event（A1）；軟體邊界判斷（A4）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 補上「使用者已封鎖對象」與「使用者已刪除對話」兩個 Event |
| B | 補上封鎖、解除封鎖、刪除對話三個 Event |
| C | 補上封鎖、解除封鎖、刪除對話、檢舉私訊四個 Event |
| D | 僅補上「使用者已封鎖對象」，其餘留在系統邊界之外 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響聊天私訊流程的 Event 清單、私訊 Aggregate 的生命週期、封鎖對關注 / 師徒 / 團隊關係的連動影響、以及與管理員管理社群流程檢舉範圍的關係。

# 優先級

Medium

# 解決結果

C（含使用者補充） — 使用者原話：
「封鎖對象 + 刪除對話 + 檢舉私訊，不包含刪除訊息」，追加補充「可以解除封鎖啊」。

補上四個 Event：使用者已封鎖對象、使用者已解除封鎖、使用者已刪除對話、使用者已檢舉私訊。
不建模「刪除訊息」，單則訊息一經發送即不可刪除。封鎖為可逆操作。

# 連帶影響

封鎖與關注 / 師徒 / 團隊關係的連動效果未定義，已記錄於 `.clarify/pending-gaps.md` G7 供下輪 discovery 立項。

「使用者已檢舉私訊」與管理員管理社群流程的「使用者已檢舉內容」同屬檢舉入口，
其審視與處置沿用「管理員已審視檢舉」，不另開流程。
