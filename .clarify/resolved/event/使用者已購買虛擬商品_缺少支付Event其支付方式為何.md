# 釐清問題

虛擬商品購買流程中沒有支付相關 Event，虛擬商品以何種方式支付？虛擬貨幣、真實金流，還是免費兌換？

# 定位

流程：虛擬商品購買流程
元素：Event：使用者已確認購買、使用者已購買虛擬商品（缺少支付 Event）
細節：隱含發生但未寫出的 Event（A1）；與實體商品購買流程的不對稱性。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 以站內虛擬貨幣支付，補上「虛擬貨幣已扣除」Event |
| B | 以真實金流支付，應與實體商品購買流程一致補上「使用者已支付」Event |
| C | 兩種皆支援：部分商品用虛擬貨幣、部分用真實金流，需補上兩種支付 Event |
| D | 虛擬商品皆為任務獎勵兌換，不需支付，補上「兌換點數已扣除」Event |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響虛擬商品購買流程的 Event 完整性、是否需要虛擬貨幣 Aggregate、外部金流系統的邊界、以及與實體商品購買流程的結構一致性。

# 優先級

High

# 解決結果

C（含使用者補充）— 虛擬商品支援兩種支付方式，且可併用：
- 虛擬貨幣支付 → Event「虛擬貨幣已扣除」
- 真實金流支付 → Event「使用者已支付」
- 兩者併用：部分商品定價為「虛擬貨幣 + 真實金流」，虛擬貨幣不足時可以現金補差額。

併用時，虛擬貨幣扣除與真實金流支付須同時成功，方可完成購買。
