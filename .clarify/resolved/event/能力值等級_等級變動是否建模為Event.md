# 釐清問題

能力值等級（維度能力等級 6 個 ＋ 綜合能力等級 1 個）為點數的衍生標籤，且因能力值可退步而可能下降。等級的變動是否建模為獨立 Event？

# 定位

流程：訓練結算流程、訓練中斷流程、回歸任務流程
元素：Event（待定）「能力值等級已變動」；Aggregate：使用者之能力值等級（衍生欄位）
細節：A1 事件識別完整性、D5 狀態機。00_全域規範〈能力值等級〉之 `[待決策 Partial]` 第 2 項。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 不建模：等級為純衍生標籤，其變動已由「能力值已提升 / 已退步 / 已部分回復」承載，另立 Event 為同一事實的兩個名字 |
| B | 建模為單一 Event「能力值等級已變動」（漲跌共用，攜帶維度、變動前後等級），比照「訓練進度條已變動」的既有處理方式 |
| C | 僅建模上升：「能力值等級已提升」，供成就與通知使用；下降不建模，避免對使用者強調退步 |
| D | 建模為兩個 Event（已提升 / 已下降），比照「使用者已獲得 / 已失去獎勵加成」的既有處理方式 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Event 清單、〈Command 清單〉、通知類 Event 清單（等級變動是否推播），並為 `aggregate/能力值等級_等級是否掛勾成就.md` 的前置。
相關已解決項目：`resolved/aggregate/六維能力值_能力值是否分等級與分級對象為何.md`、`resolved/aggregate/六維能力值_能力值等級的判定基準為何.md`、`resolved/event/使用者已失去獎勵加成_是獨立Event或由連續訓練天數推導.md`（可推導不等於不成立為 Event 之判例）。
相依：`aggregate/能力值等級_綜合能力等級由六維推導的公式為何.md`。
註：本題與 `aggregate/能力值_改採既有公開肌力標準取代自訂訓練量公式.md` 並存 —— 新算法改的是點數的算法，六階門檻與等級機制可保留。

# 優先級

High

# 解決結果

**選項 A** —— 等級變動（升級與降級）**皆不建模為 Event**。

**主要理由**：六階門檻為平台級可調參數，管理員調整門檻的當下，
全平台使用者的等級同時改變，而該變動沒有任何使用者行為、沒有 Command。
建模為 Event 將一次產生大量無 Actor 的 Event。
此即本模型否決「相對百分位」判定基準時所用的同一條理由 ——
「會產生沒有 Command、沒有使用者行為的等級下降」；自另一個入口引入同一個問題，不予採納。

**次要理由**：不建模不遺失任何歷史。「能力值日快照已產生」每日保存六維點數，
等級為點數的純函數，任一日期的等級皆可由快照推導。

**與「使用者已失去獎勵加成」判例的差異**：後者的失去有實質後果（獎勵少拿）且無其他地方記錄；
等級變動目前僅影響四個 Read Model 的呈現，不作為任何 Precondition。

**升級通知的承接方式**：不需要獨立 Event。由「能力值已提升」的 Postcondition 承接
「若該維點數跨越等級門檻則發送通知」，其發送規則屬〈通知類 Event 的發送規則〉範疇
（見待釐清項目 `rule/通知類Event_完整清單與各自的優先序歸類尚未盤點.md`）。
