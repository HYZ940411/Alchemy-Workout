# 釐清問題

是否新增「電子郵件」作為第三種通知渠道（現有推播、App 內紅點兩種）？收集方式與適用範圍為何？

# 定位

流程：跨流程（實體商品購買、管理員管理社群、註冊）
元素：Aggregate — 使用者（是否新增電子郵件欄位）；Rule — 通知類 Event 的發送規則
細節：本項由使用者於第十一輪第 19 題提出（「比較重要的通知也可以加上 Email 通知嗎」），
非 discovery 原有項目。模型原明文「不收集電子郵件」，且註冊管道中僅第三方登入者天然帶有 email。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 不加 email，維持推播 ＋ App 內兩種渠道 |
| B | 加 email 但選填，僅用於少數「有法律或金錢後果」的通知 |
| C | 加 email 且註冊必填，全部推播類通知同步寄一份 |
| D | 加 email 選填，寄送範圍由管理員後台逐項開關 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

使用者 Aggregate 的欄位；註冊流程；通知類 Event 的發送規則；帳號刪除的刪除範圍

# 優先級

Medium

# 解決結果

**B**：新增電子郵件欄位（**選填**），僅用於三類「有法律或金錢後果」的通知。

| 通知 | 對應 Event | 理由 |
|------|-----------|------|
| 出貨通知 | 商品已出貨 | 使用者等待數月換得的實體商品，物流狀態不在系統邊界內 |
| 處罰與申訴結果 | 使用者已受處罰 / 處罰已撤銷 / 申訴已駁回 | **申訴期限僅 30 天**，被停權者可能正因停權而不開 App，紅點對其無效 |
| 帳號刪除排程 | 使用者已申請刪除帳號 / 使用者帳號已刪除 | 30 天冷靜期倒數中，且刪除不可逆 |

- **第三方登入者於授權時帶入**（Apple 可能為私密轉發信箱），手機註冊者可於設定頁自願補填。
- **不採註冊必填**（使用者於本題追問「建議必填嗎」，已說明）：
  手機註冊者本無 email，必填只會取得假信箱、使「重要通知寄得到」成為錯覺；
  Apple 私密轉發信箱使用者隨時可關閉轉發，必填亦保證不了送達；
  且收集即須保護、帳號刪除須一併刪除，與既有的資料最小化立場相反。
- **不採全部推播類通知同步寄送**：訓練與簽到提醒為每日發送，寄 email 將淪為垃圾信，
  一旦被標記為垃圾郵件，重要信件會一併進垃圾桶。
- **不採由管理員逐項開關**：承否決「由管理員逐一指派通知優先序」的同一理由。
- 本渠道不受同日總量上限約束（該上限僅約束推播類）。
- 電子郵件於帳號刪除時一併刪除，已列入〈刪除範圍〉。
