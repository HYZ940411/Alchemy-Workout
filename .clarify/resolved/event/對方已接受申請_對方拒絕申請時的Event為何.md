# 釐清問題

「對方已接受申請」的相反情況——對方拒絕或逾期未回應——會發生什麼 Event？

# 定位

流程：師徒互動流程
元素：Event：使用者已申請 師徒關係、對方已接受申請
細節：分支路徑（接受 / 拒絕 / 逾時）是否都有對應 Event（A3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 補上「對方已拒絕申請」Event，可重新申請 |
| B | 補上「對方已拒絕申請」與「師徒申請已逾期」兩個 Event，逾期後自動失效 |
| C | 補上拒絕與逾期兩個 Event，且拒絕後需間隔 N 天才可再次向同一人申請 |
| D | 不可拒絕，申請即自動建立關係，無需額外 Event |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響師徒互動流程的分支 Event、師徒申請 Aggregate 的狀態機、重複申請的 Precondition 冷卻規則、以及教官帶徒上限的佔用時機（申請中是否佔用名額）。

# 優先級

Medium

# 解決結果

B — 補上「對方已拒絕申請」與「師徒申請已逾期」兩個 Event，逾期後該筆申請自動失效。
拒絕或逾期後可再次向同一對象申請，無冷卻期（未採 C）。

# 連帶影響

- 「師徒申請已逾期」的逾期時限長度尚未量化，屬新產生的決策點，記錄於 `.clarify/pending-gaps.md` G8。
- `aggregate/教官帶徒上限_帶徒上限的初始值與提升幅度.md`：申請中（未接受未拒絕未逾期）是否佔用帶徒名額，該題須一併回答。
