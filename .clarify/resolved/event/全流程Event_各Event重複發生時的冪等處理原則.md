# 釐清問題

全模型未定義任何 Event 的冪等性規則。同一 Event 重複發生時（重複點擊、網路重送、排程重跑）的統一處理原則為何？

# 定位

流程：全流程
元素：所有 Event（A3 冪等性檢查項於全模型皆為 Missing）
細節：同一 Event 是否可能重複發生與冪等性（A3）；狀態邊界：重複執行（C3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 統一以 Command 請求識別碼去重，重複請求回傳原結果不重複產生 Event |
| B | 依 Aggregate 狀態機判定：處於目標狀態時重複執行直接拒絕，不產生 Event |
| C | 獎勵與計數類 Event 一律以「每週期每使用者一次」為唯一鍵去重；狀態類 Event 依狀態機判定 |
| D | 逐一在各 Event 定義，不設統一原則 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響全模型所有 Command 的 Precondition 與重複執行行為、獎勵重複發放的防範、排程類 Event（重置、結算、中斷判定）的重跑安全性，以及各 Aggregate 是否需要冪等鍵欄位。

# 優先級

Medium

# 解決結果

A — 統一以 Command 請求識別碼去重，重複請求回傳原結果，不重複產生 Event。全模型適用單一原則，各 Event 不另行定義。

# 連帶影響

排程觸發的 Event（每日任務已重置、訓練已結算、連簽中斷判定、連續訓練中斷判定、排行榜週期已結算）無使用者端 Command 請求識別碼，其重跑去重鍵來源尚未定義。已記錄於 `.clarify/pending-gaps.md` G6，待下輪 discovery 建立正式釐清項目。
