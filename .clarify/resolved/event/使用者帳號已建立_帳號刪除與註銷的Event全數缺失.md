# 釐清問題

全模型有「使用者帳號已建立」，但無任何帳號刪除、註銷或停用的 Event。使用者主動刪除帳號是否納入軟體邊界？若納入，其連帶效果（訓練紀錄、貼文、關注關係、師徒關係、團隊成員資格、進行中訂單）如何處理？

# 定位

流程：註冊流程（生命週期的另一端）
元素：Event（尚未存在）；Aggregate「使用者」的生命週期
細節：A1 事件識別完整性、D5 生命週期與狀態機、D4 Aggregate 間關係的生命週期。使用者 Aggregate 已定義「處罰狀態」的五值（含永久停權），但永久停權為管理員處置，非使用者主動註銷。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 納入軟體邊界，新增「使用者已申請刪除帳號」「使用者帳號已刪除」兩個 Event，採軟刪除保留內容（比照貼文的軟刪除裁決），個人識別資料匿名化 |
| B | 納入軟體邊界，僅新增「使用者帳號已刪除」單一 Event，硬刪除個人資料，其發布的貼文與留言一併刪除 |
| C | 納入軟體邊界，且設冷靜期（如 7 天內可取消刪除），期間帳號停用但資料保留，期滿才真正執行 |
| D | 留在系統邊界之外，由客服人工處理，模型不建模 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響使用者 Aggregate 的生命週期與終止狀態、42 個獨立 Aggregate 中以使用者 ID 為外鍵者的連帶處理（訓練紀錄、關注關係、師徒關係、團隊、貼文、留言、對話、私訊、訂單、會員權益）、粉絲數等衍生欄位的重算、以及排行榜與團隊分數中已刪除使用者的顯示。
本項為第一輪至第三輪皆未觸及的空白，非既有項目的延伸。

# 解決結果

**選項 A ＋ C，冷靜期 30 天**

帳號刪除納入軟體邊界，採「申請 → 30 天冷靜期 → 軟刪除」三段式：

- 新增 Event 三個：使用者已申請刪除帳號、使用者已取消刪除帳號申請、使用者帳號已刪除
- 新增 Command 三個：申請刪除帳號（使用者）、取消刪除帳號申請（使用者）、刪除帳號（系統）
- 冷靜期 30 天，自刪除申請時戳起算；期間帳號停用、資料全數保留、可取消
- 冷靜期屆滿執行軟刪除：內容全數保留，僅個人識別資料匿名化
- 不採硬刪除，理由為貼文軟刪除與 AI 調整對話永久保存兩條既有稽核鏈

# [裁決修正 2026-08-11] 「軟刪除、內容全數保留」已被推翻

本檔原裁決的兩條——「冷靜期屆滿執行軟刪除：內容全數保留，僅個人識別資料匿名化」與
「不採硬刪除，理由為貼文軟刪除與 AI 調整對話永久保存兩條既有稽核鏈」——**已於第十輪推翻**。

**推翻理由：與 App Store 的帳號刪除要求直接牴觸。** Apple 官方文件明文要求刪除
「the entire account record, along with associated personal data」，且明確涵蓋
「user-generated content that's shared with others, such as photos, video, text posts, and reviews」，
並指出僅提供停用是不足的。平台自身的稽核便利不屬於 Apple 承認的「法律要求」保留例外。

**新裁決**：帳號、個人資料、訓練紀錄、成長數值、貼文、留言、私訊、AI 調整對話一律刪除；
僅「已成案且處理中」的檢舉／申訴所需最小證據暫留至結案，並須告知使用者。
冷靜期 30 天維持不變（Apple 允許刪除流程需時，但須明確告知所需時間）。

詳見 `.clarify/resolved/aggregate/使用者_帳號刪除時個人識別資料匿名化的具體欄位範圍未定.md`
與 `00_全域規範.md`〈帳號生命週期〉之〈刪除範圍〉。
