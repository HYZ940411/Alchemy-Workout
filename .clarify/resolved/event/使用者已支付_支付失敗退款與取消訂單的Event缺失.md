# 釐清問題

實體商品購買流程中支付失敗、使用者取消訂單、退款、退貨等 Event 全數缺失，應如何補齊？

# 定位

流程：實體商品購買流程
元素：Event：使用者已確認購買、使用者已支付、使用者已購買實體商品、商品已出貨（無任何失敗或反向路徑）
細節：分支路徑（成功 / 失敗 / 取消）是否都有對應 Event（A3）；失敗與例外路徑（C5）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 補上「支付已失敗」「使用者已取消訂單」「訂單已退款」三個 Event |
| B | 補上上述三個，另加「使用者已申請退貨」與「退貨已完成」 |
| C | 補上上述五個，另加「訂單已逾時未付款自動取消」 |
| D | 僅補上「支付已失敗」，取消與退款走客服人工流程，留在系統邊界之外 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響實體商品購買流程的 Event 完整性、訂單 Aggregate 的狀態機、庫存回補的時機、以及客服與系統的邊界劃分（A4 軟體邊界）。

# 優先級

High

# 解決結果

A — 補上「支付已失敗」「使用者已取消訂單」「訂單已退款」三個 Event。不納入退貨相關 Event，亦不納入逾時未付款自動取消。
