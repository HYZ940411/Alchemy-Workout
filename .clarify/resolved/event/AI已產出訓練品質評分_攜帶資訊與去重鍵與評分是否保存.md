# 釐清問題

新增的 Event「AI 已產出訓練品質評分」應攜帶哪些資訊、其冪等去重鍵為何、評分結果是否保存於某個 Aggregate（供申訴或重新申請時比對）？

# 定位

流程：教官申請流程
元素：Event「AI 已產出訓練品質評分」；Command「分析歷史訓練品質」（Actor：AI）
細節：A5 事件攜帶的資訊、A3 冪等性。該 Event 於第三輪新增，未納入〈Event 共通攜帶資訊〉的專屬欄位定義，亦未納入〈排程觸發的請求識別碼〉表。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 攜帶三維分數、加權平均分、疑慮標記、評分時點；去重鍵＝使用者 ID ＋ 教官申請 ID；評分保存為獨立的「教官申請」Aggregate 欄位，永久保存 |
| B | 同 A，但不新增 Aggregate，評分寫入既有的教官測驗 Aggregate |
| C | 僅攜帶加權平均分與通過與否；評分明細不保存，重新申請時一律重新評分 |
| D | 攜帶完整明細且保存，並定義 AI 分析逾時或失敗的處理（比照 `rule/AI已微調訓練強度_AI回應逾時或失敗時的處理.md`） |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響教官申請流程的初審可驗收性、〈Event 共通攜帶資訊〉表、是否需新增「教官申請」Aggregate、被駁回者的申訴依據，以及重新申請時是否重新評分。
相關已解決項目：`resolved/rule/教官資格已初審通過_初審門檻的階級與累積訓練次數為何.md`。
來源：`pending-gaps-2.md` H16。

# 優先級

Medium

# 解決結果

**選項 D**

- **攜帶資訊**：三維分數（訓練完成率 / 訓練規律性 / 紀錄合理性，各 0–100）、加權平均分、
  疑慮標記、評分時點
- **冪等去重鍵**：使用者 ID ＋ 教官申請 ID，同一筆申請只評分一次
- **保存**：新增獨立 Aggregate「教官申請」（獨立 Aggregate 由 42 項增為 43 項），
  評分明細永久保存，不隨申請結案而清除；重新申請產生新的一筆，既有評分不被覆寫
- **AI 逾時或失敗**：D 要求一併定義，但本題未給定具體處理方式；
  已將 `.clarify/rule/AI已微調訓練強度_AI回應逾時或失敗時的處理.md` 的適用範圍
  自三條 AI 流程擴充至含本 Event，並將其優先級由 Medium 提升為 High，於該題一併裁決

理由：評分不寫入教官測驗 Aggregate，因品質評分發生於初審階段，
多數被駁回者根本走不到測驗，掛在尚未存在的測驗紀錄上會產生空指涉。
