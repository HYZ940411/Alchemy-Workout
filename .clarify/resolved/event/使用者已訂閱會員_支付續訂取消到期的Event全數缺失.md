# 釐清問題

會員訂閱流程僅有「使用者已訂閱會員」與「會員權益已生效」兩個 Event，支付、續訂、取消訂閱、到期失效等 Event 全數缺失，應如何補齊？

# 定位

流程：會員訂閱流程
元素：Event：使用者已訂閱會員、會員權益已生效（流程嚴重不完整）
細節：隱含發生但未寫出的 Event（A1）；起點與終點 Event（A1）；生命週期（D5）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 補上「使用者已支付訂閱費用」「會員訂閱已續訂」「使用者已取消訂閱」「會員權益已失效」四個 Event |
| B | 補上上述四個，另加「訂閱扣款已失敗」與「訂閱到期提醒已發送」 |
| C | 補上上述六個，另加「使用者已升級 / 降級訂閱方案」 |
| D | 僅補上「使用者已取消訂閱」與「會員權益已失效」，支付視為外部系統不建模 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響會員訂閱流程的完整 Event 清單、會員訂閱 Aggregate 的狀態機與生命週期、外部金流系統的邊界標示、以及所有引用會員身分的 Precondition。此流程目前是全模型中最不完整的一條。

# 優先級

High

# 解決結果

A′（依 App Store 自動續約情境調整後的選項 A）— 補上三個 Event：
- 會員訂閱已續訂（Actor：App Store 外部系統，自動續約通知）
- 使用者已取消訂閱（Actor：App Store 外部系統通知，使用者於 App Store 設定中操作）
- 會員權益已失效

原選項 A 中的「使用者已支付訂閱費用」已由「使用者已訂閱會員」加上 App Store 外部通知涵蓋，不重複建模。

不納入「訂閱扣款已失敗」「訂閱到期提醒已發送」「升級 / 降級訂閱方案」。

軟體邊界：訂閱的支付與自動續約由 App Store 執行，本系統被動接收其通知。
