# 釐清問題

「商品已售完」是一個獨立 Event，還是商品庫存歸零後由系統推導的狀態？售完後是否自動下架？

# 定位

流程：管理員商品上架流程
元素：Event：商品已售完
細節：是否為誤列為 Event 的技術動作（A1）；Event 與 Aggregate 欄位的一致性（E3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 為獨立 Event，由庫存扣減至 0 時系統自動產生，但不自動下架 |
| B | 為獨立 Event 且自動下架，需連帶產生「商品已下架」Event |
| C | 非 Event，僅為商品 Aggregate 的推導狀態，應從流程中移除 |
| D | 為獨立 Event，且分尺寸售完與全商品售完需區分為兩個 Event |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響管理員商品上架流程的 Event 清單、商品 Aggregate 的狀態機、售完與下架的關係、以及商品列表 Read Model 的顯示規則。

# 優先級

Medium

# 解決結果

A（含使用者補充） — 使用者原話：
「售完不下架，應該不可點擊購買按鈕，並顯示暫無庫存等資訊」。

「商品已售完」為獨立 Event，由庫存扣減至 0 時系統自動產生；售完不自動下架，
商品維持已上架狀態，改由 Read Model 提供庫存狀態，使購買按鈕不可點擊並顯示「暫無庫存」。

# 連帶影響

- `read-model/全流程ReadModel_各流程尚未定義任何Read Model.md`：商品頁 Read Model 須包含庫存狀態欄位。
- 售完的粒度（單一尺寸售完 vs 全商品售完）未表態，記錄於 `.clarify/pending-gaps.md` G10。
