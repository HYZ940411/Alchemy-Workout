# 釐清問題

「AI 調整已失敗」在三條 AI 流程（訓練前調整 / 訓練中調整 / 自動優化）各自出現且以「來源」欄位區分，是否應納入〈跨流程同名 Event〉表？其 Actor 為系統或 AI？

# 定位

流程：AI 訓練前調整流程、AI 訓練中調整流程、AI 自動優化訓練流程
元素：Event「AI 調整已失敗」
細節：A3 事件時序與因果、E1 Actor→Command→Event 串聯。00_全域規範〈跨流程同名 Event〉表現有 11 列，本 Event 不在其中；〈Command 清單〉三條 AI 流程亦無對應 Command，為孤兒 Event。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 納入〈跨流程同名 Event〉表（來源值域三值），Command 為「判定 AI 調整失敗」，Actor＝系統（AI 逾時或回傳錯誤由系統判定） |
| B | 納入該表，Command 為「回報調整失敗」，Actor＝AI（失敗由 AI 端主動回報） |
| C | 不納入該表，改為三個獨立 Event（AI 訓練前調整已失敗 / AI 訓練中調整已失敗 / AI 自動優化已失敗），各有各的 Command |
| D | 不建模為 Event，改回前端錯誤提示（推翻既有裁決） |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響〈跨流程同名 Event〉表的列數與收錄判準、〈Command 清單〉三條 AI 流程各增一列、以及該 Event 的冪等去重鍵。
相關已解決項目：`resolved/rule/AI已微調訓練強度_AI回應逾時或失敗時的處理.md`（確立本 Event 存在）、`resolved/event/使用者已拒絕調整_三條AI流程的同名Event是否為同一事實.md`（同類判準）。
相依：`command/全流程Command_八個Event在Command清單中無對應Command.md`。

# 優先級

Medium

# 解決結果

**選項 A** —— 納入〈跨流程同名 Event〉表（來源值域三值：訓練前調整 / 訓練中調整 / 自動優化），
Command 為「判定 AI 調整失敗」，**Actor＝系統**。

理由：三條 AI 流程的另外 5 個 Event 已定案採「單一 Event ＋ 來源欄位」，本 Event 結構相同，
另拆三個會與該裁決不一致；Actor 取系統而非 AI，因逾時的定義為 AI 沒有回應，
AI 無法回報自己沒有回應，只能由等待方判定，與「AI 僅產出建議、不執行套用」的既有裁決方向一致。
