# 釐清問題

無訓練紀錄的新手自選空閒訓練時段，此動作是否建模為 Event（如「使用者已選擇偏好訓練時段」）與對應 Command？該動作應掛在哪一條流程的哪一個時點？

# 定位

流程：新手任務流程、訓練紀錄流程（事前提醒路徑）
元素：Event（尚未存在）；Command（尚未存在）
細節：A1 事件識別完整性、B1 Command 識別。訓練紀錄流程檔第 64–65 行已定案「無訓練紀錄者取自使用者自選的偏好訓練時段」，但該選擇動作本身無 Event、無 Command、無掛載點。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 建模為 Event，掛在新手任務流程的「使用者已完成新手任務」之後，作為引導的最後一步 |
| B | 建模為 Event，掛在註冊流程，成為註冊問卷的第 10 個逐欄位 Event（比照既有 9 項的建模方式） |
| C | 建模為 Event，掛在新手任務範本的一個任務項目（「設定你的訓練時段」），完成即寫入 |
| D | 不建模為獨立 Event：視為使用者 Aggregate 的一般設定變更，與其他個人設定同層，不進 Event 層 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響新手任務流程或註冊流程的 Event 清單與〈Command 清單〉、「訓練提醒已發送」的可發送前提（新手無此欄位即無法發送）、以及使用者 Aggregate「偏好訓練時段」欄位的寫入路徑。
相依：與 `aggregate/使用者_偏好訓練時段欄位的型別與值域.md` 為同一組決策，宜併題處理。
相關已解決項目：`resolved/event/訓練提醒已發送_訓練提醒的Event與發送時段如何決定.md`。
來源：`pending-gaps-2.md` H18 第 2、3 項。

# 解決結果

**選項 A**

建模為獨立 Event「使用者已選擇偏好訓練時段」與 Command「選擇偏好訓練時段」（Actor：使用者），
掛在**新手任務流程**的「使用者已完成新手任務」之後，作為引導的最後一步。

- Precondition：「使用者已完成新手任務」已發生
- Postcondition：寫入使用者 Aggregate 的「偏好訓練時段」欄位

理由：此時使用者已實際體驗過一次訓練，對自己想幾點練才有判斷依據；
不掛註冊流程（會拉長已有 9 項必填的漏斗，且當下尚未體驗訓練）；
不掛新手任務範本的任務項目（範本由管理員可調整，系統必需欄位不應掛在可被刪除的項目上）；
不採「非 Event 的一般設定變更」（與註冊 9 個逐欄位 Event 的既有裁決不一致）。
