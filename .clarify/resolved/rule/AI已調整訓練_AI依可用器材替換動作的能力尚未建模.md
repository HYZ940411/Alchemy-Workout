# 釐清問題

模型的三條 AI 流程調整的皆為**訓練強度**（重量、次數、組數），無任何規則描述「AI 依使用者可用的器材替換動作」。而第 21 題已確立「主要動線為 AI 依可用器材推薦與替換動作，手動篩選留在設定頁」——該能力目前在模型中不存在。應如何建模？

# 定位

流程：AI 訓練前調整流程、AI 訓練中調整流程、AI 自動優化訓練流程
元素：Rule；可能新增 Event 與 Command
細節：A1 事件識別完整性、C1 前置條件完整性。
由使用者於第六輪第 21 題提出：「我們是增加便利度！不是讓使用者在那邊勾來勾去，而便利度關鍵是 AI」。

# 背景

第 21 題已定案的器材結構：

| 層級 | 內容 |
|------|------|
| 動作端 | 只填「所需器材明細」；「可練場所」由器材設定 Aggregate 推導，不儲存 |
| 使用者端 | 註冊填 3 級（必填）；設定頁填「持有器材明細」（選填，有值時優先） |
| 主要動線 | **AI 依可用器材推薦與替換動作**；手動篩選降為設定頁的選項 |

模型現有的 AI 能力：

| Event | 調整對象 |
|-------|---------|
| AI 已微調訓練強度 | 本次訓練課表的強度 |
| AI 已調整訓練 | 本次訓練**尚未完成的剩餘動作**（可改動作，但流程檔僅描述強度調整） |
| AI 已優化訓練強度 | 長期課表範本的強度 |

「AI 已調整訓練」在措辭上可涵蓋換動作，但無任何 Precondition 或 Postcondition 描述器材比對。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 不新增 Event：由既有的「AI 已調整訓練」承接，補上器材比對的 Precondition 與 Postcondition；使用者於訓練前後皆須主動提出調整要求 |
| B | 同 A，另於「使用者已選擇訓練課表」時**自動比對**：課表含使用者不具備之器材的動作時，系統自動觸發 AI 替換，不需使用者提出要求 |
| C | 新增獨立 Event「AI 已替換動作」（攜帶原動作、替換後動作、替換原因），與強度調整分離；觸發時機同 B |
| D | 不由 AI 承擔：於〈Read Model：課表選擇頁〉標示「本課表含你沒有的器材」，由使用者自行改用其他課表或手動替換 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響三條 AI 流程的 Precondition 與 Postcondition、Event 總數（C 增 1）、
「使用者已選擇訓練課表」的 Postcondition（B / C 選項）、
本次訓練課表快照的產生時點、以及〈Read Model：訓練進行中頁〉是否須標示動作已被替換。

**須一併考慮**：使用者「今天在哪練」可能與設定頁填的持有器材不同（如平常在家、今天去健身房）。
若不解決，AI 會依過期的假設替換動作。可能的處理為開始訓練時詢問場所，
但那與「不讓使用者勾來勾去」的方向相衝，須權衡。

相關已解決項目：`resolved/aggregate/動作_所需器材明細的值域清單與粗細兩層的對應關係.md`（本題的前置）；

# 出題修正

原題以「小明在家練卻選了槓鈴課表」為場景，經使用者指出**該情境本不應發生**
（在家練就該選徒手課表，課表選擇頁已有粗層 3 級器材欄位）。
使用者並追問「B 的自動比對是比對什麼」。

查證後確認真正的缺口為：課表選擇頁的「所需器材」為**粗層 3 級**，
而第 21 題新增的「持有器材明細」與動作的「所需器材明細」為**細層 8 品項**，
兩層之間無任何規則銜接。正確場景為
「課表標示居家器材（粗層相符），但當中某動作需要壺鈴，使用者家中只有啞鈴」。
題目據此重出，選項改為：A 課表選擇頁做細層標示不換動作／B 自動比對後由既有 Event 承接／
C 自動比對並新增獨立 Event／D 不做細層比對。

# 解決結果

**選項 C** —— 新增獨立 Event「AI 已替換動作」（攜帶原動作 ID、替換後動作 ID、替換原因），
與強度調整分離；觸發時機為**選定課表產生快照後、開始訓練前**，由系統自動比對細層器材，
不需使用者主動提出調整要求。

判準：
1. 只標示不替換（A）會使幾乎每份課表皆掛上警告 —— 器材共 8 品項，一般使用者僅持有 2～3 樣。
2. 併入既有「AI 已調整訓練」（B）會使其套用端 Event「訓練課表已套用新強度」的名稱對不上事實。
3. 換動作需攜帶三個值供訓練進行中頁標示、AI 品質分析與申訴舉證，強度調整類 Event 攜帶不了。

## 使用者的兩點裁定

1. **不替換，而是解鎖。** 使用者選了超出其持有器材的課表，即代表他今天身處
   具備該器材的場所。系統確認後於後台打開全部器材。
   **此處沒有「否」的分支** —— 使用者原話：「不然他要把健身房訓練全部替換成居家訓練嗎？」
2. **官方訓練計畫於開始訓練前不可直接手動修改。** 開始前要改課表，須先確認
   「將佔用一個自訂訓練名額」，再由 AI 依其器材與歷史紀錄調整。
   訓練中改則不受此限（走既有的 AI 訓練中調整流程，不佔名額）。

## 第 2 題的解決結果（解鎖的有效範圍）

**選項 A ＋ 使用者補充的明示選項** —— 解鎖**預設**當次訓練有效，訓練結束即失效；
但解鎖時一併提供「**套用至未來所有訓練**」的選項（預設不勾選），
勾選者將本次解鎖的器材寫回其持有器材明細。

> 使用者原話：「上一題 A 可以加上『是否套用未來所有訓練』之類的話，那就不是當次訓練有效」。
> 此補充解掉了原推薦中反對選項 C 的理由 —— C 的問題是**靜默**改動使用者設定，
> 改為使用者當場明示勾選後，該風險不存在，且真的辦了健身房會籍者不必再進設定頁。

判準：
- 不採**預設**寫回設定（C）：使用者可能只是今天借用場地，系統自行改動其設定會使其後的
  課表推薦與動作庫篩選全部跟著錯，且他不會知道系統改過；改為明示選項後兩種情況皆涵蓋。
- 不採記住上次場所作為預設（D）：一年僅去 3 次健身房者，其餘 362 天都會拿到
  錯的預設值 —— 等同把過期的假設自設定頁搬到上次紀錄。
- 不採當日有效（B）：同一天內的第二次訓練未必在同一場所。

# 第 3 題（2026-08-05）：AI 調整的依據

原列為本檔的待決策第 1 項，本題解決。

## 出題修正

助理原以「這份健身房課表預設 80kg，他從沒練超過 50kg」為例，
經使用者指出**課表不會預設重量** —— 快照機制帶入的是使用者上次做該動作的重量。
此點模型本已寫明（`訓練紀錄流程.md` 第 6 行前半），為助理舉錯例。

## 使用者同時推翻了一條既有規則

| | 內容 |
|---|---|
| 既有規則 | 「未曾記錄者**沿用來源課表的值**」（`訓練紀錄流程.md:6`、`00_全域規範.md`〈快照〉） |
| 使用者裁定 | 「沒做過那就從**公認身高體重算法**中取出合適重量，後者比較有調整空間」 |

## 解決結果

**選項 B —— 公認身高體重標準推算。**

AI 訓練前課表調整的依據為二：

| 情況 | 依據 |
|------|------|
| 該動作有歷史紀錄 | 該使用者最近一次的實際重量 |
| 該動作無歷史紀錄 | 公認肌力標準，依體重與性別推算 |

判準：
- 不維持現行沿用課表值（A）：官方課表的重量是給平均使用者的，對新手過重、對老手過輕。
- 不採同肌群動作推估（C）：動作間的重量換算係數本身也要查表，只是把問題往後推一層，
  且留下「該肌群一個動作都沒練過」的空窗。
- **器材不作為依據**：已於前一步全部解鎖，無作用對象。
- **不納入六維能力值**：其算法整段待重寫，綁上去會使本路徑一併卡住；
  新算法定案後再加為加法。
- 預帶重量與能力值判定**採同一組肌力標準**（使用者於第五輪第 25 題已定方向：
  「我們的算法不是自己訂的，而是已經有的算法」）。
