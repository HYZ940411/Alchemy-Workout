# 釐清問題

刪除申請當下若存在未出貨的實體訂單、未發放的虛擬訂單，或生效中的會員訂閱，如何處理未定。會員訂閱的取消 Actor 為外部系統（App Store），本系統無法代為取消，使用者刪除帳號後訂閱可能持續扣款（此為模型已知的〈永久停權者的 App Store 訂閱不會自動終止〉同一類問題）。實體訂單的收貨資訊亦屬個人識別資料，與匿名化範圍的裁決相關。

# 定位

流程：實體商品購買流程、虛擬商品購買流程、會員訂閱流程
元素：Event「使用者帳號已刪除」的 Precondition
細節：是否以「無進行中訂單」為刪除的 Precondition（擋下而非處理）；生效中訂閱是否須先由使用者於 App Store 取消。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 比照永久停權者訂閱不會自動終止的既有處理方式：申請刪除時明確告知「訂閱不會自動取消，請自行至 App Store 取消」並提供直達入口；進行中訂單不阻擋刪除申請，已出貨前的收貨資訊豁免匿名化（承既有的物流交付需求），出貨完成後再匿名化（**推薦**：與模型已有的〈永久停權者訂閱不會自動終止〉判例同構，不需另創一套邏輯，且不阻擋刪除申請符合 App Store 對「帳號刪除功能不得附加不合理條件」的審查要求） |
| B | 以「無進行中訂單、無生效中訂閱」作為刪除申請的 Precondition，擋下刪除直到訂單完成、訂閱到期或使用者自行取消 |
| C | 刪除申請自動觸發訂單取消（比照商品下架的自動取消邏輯）與訂閱標記失效，不等待使用者處理 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Event「使用者帳號已刪除」的 Precondition、與 I1（匿名化範圍）的收貨資訊豁免有直接相依。App Store 審查對帳號刪除功能有明確要求，此題屬合規相關。

# 優先級

Medium

# 解決結果

**選項 A**：一律不阻擋刪除申請，改以告知與入口處理。

| 情形 | 處理 |
|------|------|
| 生效中的會員訂閱 | 不阻擋；告知「訂閱不會自動取消，將繼續由 Apple 扣款」＋畫面內提供訂閱管理入口 |
| 未付款的訂單 | 不阻擋；帳號刪除時自動取消並釋放庫存（比照商品下架的既有處理） |
| 已付款未出貨的實體訂單 | 不阻擋；照常履行，收貨資訊豁免刪除至出貨完成 |
| 已付款未發放的虛擬訂單 | 不阻擋；照常履行發放，發放後隨帳號刪除清除 |

**不採 B（以無訂單無訂閱為 Precondition）的關鍵理由**：Apple 官方文件的措辭為
「**request that** they cancel their subscription before continuing」——請求使用者取消，
而非授權平台擋下刪除。以未取消訂閱為由拒絕刪除帳號，屬對帳號刪除附加不合理條件，有審查風險。

**一併查證確認的既有已知限制**：平台無法代為取消訂閱。Apple 未提供任何取消訂閱的 API，
開發者亦不得自製取消按鈕代為執行；可做到的極限為以 StoreKit 2 的
`showManageSubscriptions(in:)` 在 App 內叫出 Apple 原生的訂閱管理面板，
取消仍須由使用者本人按下。
（查證來源：Apple Developer Forums / showManageSubscriptions 文件，2026-08-11）
