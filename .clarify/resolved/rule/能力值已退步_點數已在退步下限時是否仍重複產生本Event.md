# 釐清問題

「能力值已退步」目前沒有任何 Precondition 要求「該維點數必須高於退步下限」。對從未訓練的使用者而言，六維點數皆為初始值 10、而 10 同時就是退步下限，因此自註冊日起每滿 240 小時（10 天）就會產生一次六個維度的「能力值已退步」，點數卻永遠是 10 ——這個沒有任何狀態改變的 Event 會**無限期每 10 天重複一次**。〈連續訓練 Aggregate〉的 `[已知取捨]` 只明示接受「註冊後第 10 日產生一個無狀態改變的 Event」這**一次**，未談其後的無限重複。點數已在退步下限時，是否仍產生本 Event？

# 定位

流程：訓練中斷流程
元素：Rule（Precondition）；Event：能力值已退步（`訓練中斷流程.md:38`）
細節：C3 狀態邊界（在已達下限的狀態下重複執行）、C4 不可逆性、A3 事件重複發生。現有規則為「不變條件：退步下限為註冊初始值，不低於該值」與「Precondition：六維各自獨立計時，自該維最後一次訓練日的日界起算滿 240 小時，才退該維」——前者管住了數值，沒管住 Event 要不要發生。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A（**推薦**） | **補一條 Precondition：「該維點數 > 該維退步下限」，方可發生本 Event。** 點數已在地板時不再產生 Event，該維的 240 小時計時器停止推進，直到該維再次被訓練。理由：模型自己的原則是「Postcondition 是可驗收的斷言」，一個永遠斷言不出任何狀態改變的 Event 無從驗收；且本 Event 是「回歸任務已指派」的唯一觸發源，放著不管會讓回歸任務也跟著無限重複（見相依項目） |
| B | 維持現狀，把既有的 `[已知取捨]` 由「第 10 日一次」擴寫為「無限期每 10 天一次」，明示接受。理由：承「使用者已失去獎勵加成」的判例「可推導不等於不成立為 Event」 |
| C | 只發生一次：該維點數觸及下限後產生最後一次「能力值已退步」，其後不再重複，計時器停止 |
| D | 改以「退步預告已發送」承接：點數已在下限者不產生「能力值已退步」，但仍照常發送退步預告（純召回用途，不改狀態） |
| Short | 提供其他簡短答案（<=5 字） |

# 解決結果

**選項 C** —— 該維點數觸及退步下限時產生**最後一次**「能力值已退步」，其後不再重複，
該維的 240 小時計時器停止推進，直到該維再次被訓練才重新起算。

**提問過程中曾先選 A，經指出與既有共識衝突後改為 C：**

- 選項 A（「該維點數 > 退步下限」方可發生）會使六維初始值 10 即為下限的**從未訓練者
  完全不產生本 Event**，而本 Event 是「回歸任務已指派」的唯一觸發源
  —— 等於推翻 2026-08-20 才定案的
  `resolved/event/使用者已完成註冊_註冊後從未訓練者是否有任何召回機制.md`（選項 A），
  該裁決的全部目的即為讓從未訓練者走完四道門檻並取得回歸任務。
- 選項 C 同時滿足兩端：無限重複被切斷（一年 216 個 → 六個），召回路徑保留（各維仍有一次）。
- 不採 B（明示接受無限重複）：既有 `[已知取捨]` 只接受第 10 日的**那一次**。
- 不採 D（改以退步預告承接）：退步預告為 `[不需精準追蹤]` 的通知類 Event，
  不足以作為回歸任務的 Precondition。

**未推翻任何既有共識**——原欲推翻者已於裁決前攔下。
