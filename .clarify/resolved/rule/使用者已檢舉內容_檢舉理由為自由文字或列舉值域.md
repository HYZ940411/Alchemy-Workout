# 釐清問題

檢舉 Aggregate 的「理由」欄位型別為字串，未定義是否有預設的檢舉類別值域。檢舉理由為自由文字、列舉單選，或兩者並存？

# 定位

流程：管理員管理社群流程、聊天私訊流程
元素：Rule：Command「檢舉內容」「檢舉私訊」的輸入；Aggregate「檢舉」的理由欄位
細節：B3 Command 的輸入、D2 欄位定義、F4 模糊描述。
既有相關裁決：「不採依違規類型分級：**模型未定義違規類型清單**，且同一類型的嚴重程度落差大」—— 該決策的前提正是本欄位無值域。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 列舉單選 ＋ 選填補充文字：值域為 騷擾辱罵 / 色情不雅 / 暴力威脅 / 廣告垃圾 / 假訊息 / 其他，由管理員於後台維護 |
| B | 純自由文字必填，不設類別：與「不依違規類型分級」的既有裁決一致，避免類別與處罰級距被誤解為有對應關係 |
| C | 列舉單選（值域寫死於系統，不做成可調參數）＋ 必填補充文字 |
| D | 多人檢舉合併成案時保留每位檢舉者各自的理由，型別同 A；管理員審視時看到理由分布 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響檢舉 Aggregate 的理由欄位定義、Command「檢舉內容」與「檢舉私訊」的輸入參數、管理員待審佇列 Read Model 的排序與篩選依據（大量檢舉時需優先處理何者），以及「多人檢舉同一內容合併為同一案件」時多筆理由的儲存方式。
相關已解決項目：`resolved/aggregate/檢舉_檢舉的欄位與狀態機.md`、`resolved/rule/使用者已受處罰_處罰的種類與級距為何.md`。
