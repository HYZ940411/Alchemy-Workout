# 釐清問題

「連續訓練中斷判定」中 24 / 36 / 96 / 120 小時的計時起點為何？是上次訓練的開始時間、結束時間，還是上次訓練日的日界？

# 定位

流程：訓練中斷流程
元素：Rule / Policy：連續訓練中斷判定（超過 24 小時未訓練 → 中斷預告；36 小時 → 連練天數中斷、失去加成、中斷通知；96 小時 → 退步預告；120 小時 → 能力值退步）
細節：時間邊界與計時起點（C3）；與每日簽到流程連簽中斷判定的一致性。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 以上次訓練的結束時戳起算 |
| B | 以上次訓練的開始時戳起算 |
| C | 以上次訓練日的日界起算，與簽到換日時點一致 |
| D | 以上次「訓練已結算」的時戳起算，中斷的訓練不重設計時 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響中斷預告已發送、連練天數已中斷、使用者已失去獎勵加成、連練中斷通知已發送、退步預告已發送、能力值已退步六個 Event 的觸發時點，以及訓練紀錄 Aggregate 需記錄哪個時戳。

# 優先級

High

# 既有約束（來自已解決項目）

第 35 題（`resolved/aggregate/連續訓練_連續訓練天數的判定基準.md`，選項 C）已裁決：
連續訓練天數以自然日計數 + 36 小時寬限，**計時起點為上一次訓練**，
判定基準為使用者當地時區時戳。
本題僅剩 24 / 96 / 120 三個門檻是否同樣以「上一次訓練」為起點待確認。

# 解決結果

**選項 C**：以上次訓練日的**日界**（該日結束、次日當地 04:00）起算。

| 距日界 | 判定 |
|--------|------|
| +24 小時 | 中斷預告已發送 |
| +36 小時 | 連續訓練天數已歸零、使用者已失去獎勵加成、連練中斷通知已發送 |
| +96 小時 | 退步預告已發送 |
| +120 小時 | 能力值已退步 |

- 計時基準取自連續訓練 Aggregate 新增的「上次訓練日期」欄位（使用者當地日期），非訓練時戳。
- 單次訓練已逾時中斷者，該筆訓練仍計入上次訓練日期，同樣重設計時
  （承既有裁決：已中斷的訓練仍進入結算、中斷前組數全數保留）。
- 能力值退步的六維各自獨立計時，起點為該維最後一次訓練日的日界。

**推翻的既有共識（已於使用者明確裁決後更新）**：

| 被推翻的裁決 | 原內容 | 修正後 |
|--------------|--------|--------|
| `resolved/aggregate/連續訓練_連續訓練天數的判定基準.md` | 距上一次**訓練**未超過 36 小時再次訓練，連續天數續計（時戳語意） | 距上次訓練**日的日界**未超過 36 小時 |
| `resolved/aggregate/能力值_能力值退步的計算公式與下限.md` | 自該維最後一次**訓練**起算滿 120 小時 | 自該維最後一次訓練**日的日界**起算 |

兩份 resolved 檔案皆已追加〈後續修正〉章節記錄本次變更。

**實際影響**（換日 04:00）：週一 05:00 練完者原本撐到週二 17:00、現撐到週三 16:00；
週一 20:00 練完者原本撐到週三 08:00、現同樣撐到週三 16:00。整體較原本寬鬆，且期限統一。

**採日界的理由**（使用者裁決）：使所有使用者的期限統一落在同一時點，不因當日幾點訓練而差異數小時，
與第 37 題連簽中斷判定的計時基準一致。

**先前建議 A 的理由（未被採納）**：36 小時寬限原設計為跨日寬限，時戳語意較貼合；
且以開始時戳起算會使長訓練吃虧、以結算時戳起算則與「中斷的訓練仍算有練」衝突。
使用者在明確得知衝突後選擇維持 C。
