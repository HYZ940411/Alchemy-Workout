# 釐清問題

教官透過師徒功能提供的訓練建議（回答提問、指派師徒任務、公開訓練課表）若造成學徒受傷或其他損害，平台的立場為何？免責聲明是否納入模型？若納入，其呈現時點與同意方式為何？

# 定位

流程：師徒互動流程、自訂訓練流程（公開訓練）、註冊流程（若採註冊時同意）
元素：Rule（缺失）；可能新增 Aggregate（使用者的條款同意紀錄）與 Event
細節：C5 失敗與例外路徑、A4 軟體邊界判斷。
於第六輪第 14 題（教官專長值域）出題過程中由使用者提出，經同意建為釐清項目。

# 背景

模型目前**完全沒有免責聲明的概念** —— 無相關 Aggregate、欄位、Event 或規則。
而模型已建立三條「一位使用者對另一位使用者提供訓練指導」的路徑：

| 路徑 | Event |
|------|-------|
| 教官回答學徒提問 | 教官已回答 |
| 教官指派師徒任務 | 教官已指派師徒任務 |
| 使用者公開自訂訓練課表 | 管理員已審核公開訓練 |

第三條尤其須注意：**公開訓練經過平台審核**，審核這個動作本身即帶有平台背書的意味。

第 14 題已處理的相鄰問題：教官專長的值域刻意排除具專業執照門檻的項目
（飲食營養 / 傷後復健 / 產後恢復 / 動作矯正 / 銀髮族），理由為
「將專長做成可篩選的標籤等同平台向學徒表示該教官具備此能力」。
本題處理的是**該風險的剩餘部分** —— 即使專長限於訓練範疇，指導仍可能造成損害。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 免責聲明留在系統邊界之外：屬服務條款範疇，於註冊時一次同意，模型不建模同意紀錄 |
| B | 註冊時同意並**建模同意紀錄**：使用者 Aggregate 新增「已同意條款版本」欄位，新增 Event「使用者已同意服務條款」；條款改版時需重新同意 |
| C | 同 B，另於**首次建立師徒關係時**額外呈現一次師徒專屬的免責聲明，新增 Event「學徒已確認師徒免責聲明」 |
| D | 同 C，另於**公開訓練課表**的呈現處標示「本課表由使用者提供，平台不對其安全性負責」，並於〈Read Model：課表選擇頁〉新增該欄位 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Event 總數（B 增 1、C 增 2、D 增 2 ＋ Read Model 欄位）、
使用者 Aggregate 是否新增條款同意欄位、〈Read Model：課表選擇頁〉與〈教官清單〉的呈現、
以及師徒關係建立與公開訓練審核兩處的 Precondition。

**上線地區不只一個**（使用者於第 14 題確認），各地對免責條款的效力認定不同，
本題的裁決結果應經法務確認；模型層面只需決定「同意這件事是否建模為業務事實」。

# 解決結果（2026-08-07，第八輪第 16 題）

**D** —— 三層並行：

| 層 | 內容 | 新增 |
|---|------|------|
| 1 | 註冊時同意服務條款（含免責聲明），**建模同意紀錄** | Command「同意服務條款」／ Event「使用者已同意服務條款」 |
| 2 | **首次**建立師徒關係時，學徒另確認一次師徒專屬聲明 | Command「確認師徒免責聲明」／ Event「學徒已確認師徒免責聲明」 |
| 3 | 自訂訓練於課表選擇頁標示「本課表由使用者提供，平台不對其安全性負責」 | Read Model 欄位 |

## 三層各自的理由（皆非「防止被告」，而是模型自身的缺口）

1. **不採 A（留在邊界外）的關鍵不在法律，在於條款版本會改版。**
   上線地區不只一個，條款必然改版；「誰同意了哪一版」是規則判定會用到的事實
   （未同意新版者的功能可用範圍、爭議發生時適用哪一版），不建模即查不到。
   **判準與第七輪「持有器材明細是否建模」相同**：影響規則判定者即建模。
2. **師徒需要獨立一層，因為配對是平台做的。** 其他功能出事為使用者自己的選擇；
   師徒是平台把兩個人配對起來，並提供聲望等級、專長標籤、六維能力值展示
   —— 這些皆在向學徒表示「此人可信」。註冊時滑過的總則擋不住這一層。
3. **公開課表這一層是在補平台自己挖的洞。**
   `管理員已審核公開訓練` 的存在使使用者合理認為「平台看過了」。

## 實作上的一個調整（助理於回寫時決定）

「學徒已確認師徒免責聲明」**不設為「師徒關係已建立」的 Precondition**，
改為**學徒端互動 Command 的 Precondition**（學徒已提問、學徒已完成師徒任務）。

理由：師徒關係由**教官接受申請**觸發，該時點學徒未必在場；
設為建立的 Precondition 會使關係卡在無人可推進的狀態。

## 裁決範圍的界線

**本題只裁決「同意這件事是否建模為業務事實」。**
條款文字、各地區的效力認定、法務審查，皆留在系統邊界之外，未寫入模型。
