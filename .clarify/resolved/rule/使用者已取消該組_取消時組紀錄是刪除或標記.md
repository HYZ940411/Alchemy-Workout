# 釐清問題

「使用者已取消該組」發生時，該組的組紀錄如何處理 —— 實體刪除、或標記為已取消而保留？（訓練紀錄 Aggregate 有不變條件「已完成組數 ＝ 組紀錄的筆數」，兩種做法對該不變條件的影響不同。）

# 定位

流程：訓練紀錄流程
元素：Rule：Event「使用者已取消該組」的 Postcondition；Aggregate「訓練紀錄」之組紀錄與不變條件
細節：C2 後置條件完整性、D3 內部不變條件。00_全域規範〈訓練紀錄 Aggregate〉列有不變條件「已完成組數 ＝ 組紀錄的筆數」，但取消該組的 Postcondition 從未寫明組紀錄的去向；記於 `pending-gaps-3.md` 之 I14。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 實體刪除該筆組紀錄：不變條件維持「已完成組數 ＝ 組紀錄的筆數」不需改寫，重新勾選時新建一筆 |
| B | 保留並標記：組紀錄新增「已取消」旗標，不變條件改為「已完成組數 ＝ 未取消的組紀錄筆數」。取消行為的軌跡供 AI 訓練品質評分「紀錄合理性」維度判讀 |
| C | 保留但清空實績（重量與次數歸為空值），視為「未記錄的組」；不變條件改為以實績非空者計數 |
| D | 實體刪除組紀錄，另以獨立的操作軌跡（非 Aggregate 欄位）記錄取消行為供 AI 評分使用 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響訓練紀錄 Aggregate 的組紀錄欄位與兩條不變條件（已完成組數、總訓練量）、「使用者已取消該組」的 Postcondition、「訓練進度條已變動」的計算、快照帶入「最近一次該動作的實際重量」時是否會取到已取消的組，以及 AI 訓練品質評分的輸入。
相關已解決項目：`resolved/event/使用者已完成該組_取消勾選與修改成績是否建模為獨立Event.md`（確立本 Event 存在且理由為供 AI 評分判讀）、`resolved/aggregate/訓練紀錄_訓練紀錄的完整欄位與狀態機為何.md`。
來源：`pending-gaps-3.md` I14。

# 解決結果

**B** —— 保留組紀錄並新增「已取消」旗標（bool，預設否），**不實體刪除**。
不變條件改為「已完成組數 ＝ **未取消的**組紀錄筆數」，總訓練量同步改為只累加未取消者。

## 子題（使用者於本題追問）：取消後可否再次勾選

**可以** —— 模型第 124 行原已定義「取消勾選後該組回到未完成狀態」。

由此衍生的裁決：**再次勾選時新建一筆組紀錄，原筆維持已取消，不改回否**（選項 A）。

- 不採「改回否」：「使用者已取消該組」的 Event 已發生，若資料看不出曾取消過，
  Event 與 Aggregate 互相矛盾。
- 「取消 → 降重量 → 重做」正是 AI 判讀〈紀錄合理性〉最有價值的訊號。
- 新建一筆天然帶新的完成時戳，30 秒防作弊不必另定「沿用舊時戳或換新時戳」的規則。

## 子題（使用者於本題追問）：畫面會不會變不乾淨

**不會，但原本沒寫清楚，已補死。**

`00_全域規範.md:5197` 原定義為「各組完成狀態：**每組一筆**，取自組紀錄」——
畫面的列來自本次訓練課表快照的（動作 × 組序），**非組紀錄**，故一組永遠只有一列。
取消再勾一次是資料 2 筆、畫面同一列先變未打勾再變打勾。

原缺口為「同一組有多筆紀錄時該讀哪一筆」未定義，實作可能撈到已取消那筆
而顯示為未完成。已補三條呈現規則。
