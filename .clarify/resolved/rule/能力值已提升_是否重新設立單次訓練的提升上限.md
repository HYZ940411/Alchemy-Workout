# 釐清問題

「單次訓練單維上限 30 點」曾存在於訓練量時代，已於 2026-08-08 能力值改採
Epley ＋ DOTS 時**連同訓練量公式一併作廢**（`03_能力值.md:253-258`），
作廢理由原文為「上限 30 點所防的是『異常訓練量』，而點數已不由訓練量決定，故一併消滅」。

現行模型**無任何單次漲幅限制**：點數由 `估算 1RM → DOTS 正規化 → 換算` 直接得出，
單次訓練即可自 C 級跳至 A 級。

使用者於 2026-08-21 提出應重新設立單次提升上限，理由為
「不應該讓使用者直接從 C 升很多」。本項為該提案的釐清。

# 定位

流程：訓練結算流程
元素：Rule（Postcondition）；Event：能力值已提升；Aggregate：能力值、能力值設定
細節：C4 單調遞增、G3 參數可代入性、D3 不變條件

# 核心取捨

模型明訂「**等級 ＝ 你在同體重、同性別、同年齡層裡多強**」（`03:526`）。
加上單次上限後，點數將成為「你多強，但需逐次逼近」，該定義有一段時間不成立。

最尖銳的情境為**新使用者的第一次訓練**：
訓練資歷五年、臥推 120kg 者其真實水準為 A 級，
有上限則須多次訓練才爬到 A，在此之前排行榜與教官初審門檻（吃階級與能力值）皆低估他。

# 待釐清的子問題（尚未提問）

| # | 子問題 | 備註 |
|---|--------|------|
| 1 | 首次訓練是否豁免上限 | 豁免則新使用者一次到位、老使用者受限；不豁免則排行榜於初期失真 |
| 2 | 上限為固定點數或百分比 | 固定點數（如 30 點）對高分者相對寬鬆；百分比（如 +10%）對低分者絕對值小、爬升慢 |
| 3 | 上限的具體數值 | 需以六階門檻換算「爬完一個主階要幾次訓練」再定 |
| 4 | 未被計入的超額部分是否保留 | 丟棄（下次須重新推起該重量）或記為待兌現的紀錄（下次自動補上） |
| 5 | 上限是否列為平台級可調參數 | 承既有慣例應存於〈能力值設定 Aggregate〉 |
| 6 | 與「點數為單調遞增、取歷史最高」的既有規則如何相容 | 上限使點數落後於實際紀錄，兩者的關係須明確 |

# 解決結果（2026-08-22）

**採用**：重新設立單次提升上限，形式為「首次封頂 ＋ 每場一個節點 ＋ 有條件補格」。

| 子問題 | 答案 |
|--------|------|
| 1. 首次是否豁免 | **不豁免，反而封頂 450（B 級下緣）**——首次無自身歷史可比，是唯一無法驗證的一次 |
| 2. 上限形式 | 以**節點**為單位，非固定點數或百分比 |
| 3. 具體數值 | 每場最多 **1 個小節點**；落點取「下一節點上緣」與實測值之較小者 |
| 4. 超額部分 | **有條件保留**：記入「各維待兌現實測值」，本場實測達當前點數 **80%** 以上才自動補一格 |
| 5. 是否平台可調 | **全部可調**（450／1 節點／80%／退步下限降 2 階） |
| 6. 與單調遞增的相容 | 主句改寫為「點數為**追蹤值**，向實測最高逐步逼近」；其餘論據不變 |
| 防作弊主機制 | **不採漲幅合理性檢查**（使用者裁定） |

**80% 補格門檻的設計意圖**：不要求破紀錄，但要求證明仍在該水準。
誠實者實力遠高於當前點數，正常訓練即遠超門檻，無感；
作弊者填一次假重量後若隨意訓練即不再前進。

**`[已知取捨]`（使用者明示接受）**：

1. 作弊者仍可爬至 S 級，須約 9 場訓練且每場皆須通過 80% 門檻。
   使用者於裁決前已被告知「選 C 等於沒有任何防作弊規則，只有限速」，仍裁定不採漲幅檢查。
2. 真實水準高於 B 級者首次被低估，數場即歸位（實測 A+ 750 者 5 場：450→584→649→714→750）。

**查證更正**：使用者原認為「每次訓練都有提升上限」已存在。
實際上「單次訓練單維上限 30 點」已於 **2026-08-08** 隨訓練量公式一併作廢
（`03_能力值.md`，作廢理由：該上限所防為異常訓練量，而點數已不由訓練量決定）。
本次為**新設**，非復活舊規則——所防對象不同（單次跳階與首次造假，非異常訓練量）。
