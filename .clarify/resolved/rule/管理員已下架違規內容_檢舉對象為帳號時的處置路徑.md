# 釐清問題

檢舉對象類型含「帳號」，但檢舉成立的分支 Event 為「管理員已下架違規內容」—— 帳號無法被下架。檢舉對象為帳號時，成立的處置路徑為何？

# 定位

流程：管理員管理社群流程
元素：Rule：Event「管理員已審視檢舉」的成立分支；Aggregate「檢舉」的狀態機
細節：C3 類別邊界（不同值域的資料分類是否都有對應規則）、C5 例外路徑。
現況：檢舉 Aggregate 對象類型值域為 貼文 / 留言 / 帳號 / 私訊；狀態機的「待審視 → 已成立」僅由「管理員已下架違規內容」觸發。對象為帳號時，語意上應直接進入「使用者已受處罰」。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 對象為帳號時跳過下架，「管理員已審視檢舉」成立直接觸發「使用者已受處罰」；檢舉狀態機新增一條 待審視 →（使用者已受處罰）→ 已成立 |
| B | 將 Event 更名為語意中立的「管理員已認定檢舉成立」，四種對象類型共用；內容下架改為其 Postcondition 之一（對象為帳號時不執行） |
| C | 對象為帳號時，「下架違規內容」解釋為下架該帳號的全部貼文與留言，不改動 Event 與狀態機 |
| D | 移除「帳號」對象類型：帳號層級的問題一律經其具體的貼文 / 留言 / 私訊檢舉，累犯由累計違規次數承擔 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響管理員管理社群流程的 Event 命名與分支、檢舉 Aggregate 的狀態機、「使用者已受處罰」的觸發前提（現為「管理員已下架違規內容」之後），以及〈統一語言〉是否需登記曾用名。
相關已解決項目：`resolved/aggregate/檢舉_檢舉的欄位與狀態機.md`、`resolved/rule/使用者已受處罰_處罰的種類與級距為何.md`。

# 解決結果

**選項 A** —— 對象類型為帳號的檢舉成立時不走下架路徑，直接觸發「使用者已受處罰」；「管理員已下架違規內容」僅適用貼文 / 留言 / 私訊。
