# 釐清問題

成員被隊長踢出團隊後，是否適用 12 小時換隊冷卻期？

# 定位

流程：團隊組隊流程。
元素：Event「隊長已踢除成員」的 Postcondition（檢查項 C2）。
細節：模型僅寫了「隊長可以踢除成員」，**踢除後的狀態完全未定義**
（原 Event 行之後無任何 Precondition、Postcondition 或 Rule）。
對照組：自願退出（`使用者已退出團隊`）已定義 12 小時換隊冷卻期與 3 小時無懲罰退出窗口。

發現方式：使用者表示將以本模型撰寫 Gherkin，掃描「哪些 Event 寫不出 Then」時查出。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 被踢除者不適用冷卻期，可立即加入或建立其他團隊 |
| B | 被踢除者適用冷卻期，與自願退出完全一致（12 小時） |
| C | 被踢除者適用冷卻期但縮短（如 3 小時） |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

- Event「隊長已踢除成員」的 Precondition 與 Postcondition（原本全無）。
- 與〈團隊 Aggregate〉之〈單一團隊歸屬與換隊冷卻〉的既有參數表互動。
- 與〈團隊分數 Aggregate〉的增量累加設計互動（已貢獻分數是否留在原團隊）。

# 解決結果

**選項 A**：被踢除者**不適用** 12 小時換隊冷卻期，可立即加入或建立其他團隊。

- Precondition 兩條：執行者為該團隊隊長且對象為該團隊成員；隊長不得踢除自己。
- Postcondition 四條：成員清單移除、人數 −1、**豁免冷卻期**、
  個人排行榜分數不受影響、已貢獻的團隊分數留在原團隊。
- **豁免的理由**：換隊冷卻期的職責為「避免同一日內反覆進出造成的成員名單與分數抖動」，
  而被踢除**非其本人所為**。承既有判例 ——〈教官申請流程〉已裁定
  「學徒不適用解除後 3 天冷卻期」，理由同為該次解除非學徒所為。
- 不採 B：將使隊長取得「踢人即鎖住對方 12 小時不得入隊」的武器；
  冷卻期的用意是防抖動，非供隊長懲罰。
- 不採 C：3 小時無推導依據，且既有的 3 小時為「無懲罰退出窗口」，語意完全不同。
- `[已知取捨]` 隊長與成員可套招（踢出後立即加回）繞過冷卻期；
  因團隊分數為增量累加、換隊不帶走分數，雙方皆無實質好處，明示接受。
