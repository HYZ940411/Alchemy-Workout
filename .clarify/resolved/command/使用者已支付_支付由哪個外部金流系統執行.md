# 釐清問題

「使用者已支付」的支付由哪個外部金流系統執行？支援哪些支付方式？此 Event 的來源是內部系統還是外部回呼？

# 定位

流程：實體商品購買流程
元素：Command：支付；Actor：使用者 + 外部金流系統；Event：使用者已支付
細節：跨系統邊界的 Event 來源標示（A4）；Actor 是人、系統或外部系統（B4）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 串接第三方金流，支援信用卡與行動支付，「使用者已支付」由金流回呼觸發，來源標示為外部系統 |
| B | 串接第三方金流，僅支援信用卡，Event 由系統輪詢金流狀態後產生 |
| C | 支援金流與站內虛擬貨幣兩種，需拆為兩個支付 Event |
| D | 支援金流、虛擬貨幣與貨到付款三種 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響使用者已支付的 Actor 與觸發源、外部系統邊界標示、支付非同步回呼的時序問題、訂單 Aggregate 的狀態轉換，以及與虛擬商品購買流程支付方式的一致性。

# 優先級

High

# 解決結果

A — 實體商品串接第三方金流，支援信用卡與行動支付（含 Apple Pay）。
「使用者已支付」由金流回呼觸發，Actor 為外部系統。
實體商品不走 App Store 應用內購買。

# 連帶影響

`.clarify/pending-gaps.md` G2（兩個「使用者已支付」是否為同一事實）：
本題確立實體商品的支付來源為第三方金流；虛擬商品的「真實金流」則與會員訂閱同屬 App Store 體系。
兩者的外部系統不同，G2 下輪立項時須以此為前提判斷是否為同一 Event。
