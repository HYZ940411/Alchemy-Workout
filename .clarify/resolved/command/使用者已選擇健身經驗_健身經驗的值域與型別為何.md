# 釐清問題

註冊問卷 9 項必填中的「使用者已選擇健身經驗」，其值域、型別與是否可複選皆未定義。健身經驗的分級為何？

# 定位

流程：註冊流程
元素：Command「選擇健身經驗」的輸入；Event「使用者已選擇健身經驗」；Aggregate「使用者」的健身偏好欄位
細節：B3 Command 的輸入、D2 Aggregate 欄位定義。註冊流程檔第 21 行為 9 項中唯一未標註〔值域〕或〔型別〕者：身高、體重、性別、生日、健身目標、每週天數、每次時長、健身器材皆已定義，僅健身經驗缺。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 三級列舉：新手（未滿 6 個月）/ 中階（6 個月–2 年）/ 進階（2 年以上），必填單選，值域存於平台級設定 Aggregate 由管理員維護 |
| B | 四級列舉：完全沒接觸 / 新手 / 中階 / 進階，必填單選 |
| C | 改以「過去是否規律訓練」布林值 ＋ 訓練年資（int，年）兩欄表達，不用主觀分級 |
| D | 三級列舉，但值域寫死於系統，不做成平台級可調參數（比照性別欄位的處理方式） |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響註冊流程的必填檢核、使用者 Aggregate 的欄位定義、訓練計畫「適用條件」欄位的比對值域（推薦優先序為器材 → 經驗 → 常見目標，經驗為第二順位維度）、以及能力值六維註冊初始值是否依經驗分級（現已定案為一律 10，不分級）。
相關已解決項目：`resolved/command/使用者已填入健身目標_動機類與常見目標類的完整值域清單為何.md`（健身目標的值域已由健身目標設定 Aggregate 承載，本項可比照）、`resolved/aggregate/訓練計畫_訓練計畫與自訂訓練的動作與組數結構為何.md`。

# 解決結果

**選項 A**

三級列舉，**必填單選**，值域存於新增的平台級「健身經驗設定 Aggregate」，由管理員於後台維護：

| 值 | 界定基準 |
|----|----------|
| 新手 | 訓練年資未滿 6 個月 |
| 中階 | 訓練年資 6 個月–2 年 |
| 進階 | 訓練年資 2 年以上 |

訓練計畫 Aggregate 的「適用條件」欄位引用同一份值域清單，比照健身目標的既有處理方式，
使推薦的兩個可調比對維度（經驗、常見目標）處理方式一致。

分級以訓練年資的月數界定而非形容詞，因本欄位為推薦的第二順位比對維度，直接決定推薦哪一份課表，
而使用者對「新手 / 中階 / 進階」的自我判斷會失準。

排除 B：「完全沒接觸」與「新手」在推薦邏輯上拿到同一份入門課表，分兩級卻無不同後果。
排除 C：兩欄仍須折算回三級才能比對，且年資長不等於程度好。
排除 D：與健身目標的平台級可調處理方式不一致；性別寫死是因其為二元事實不會變。
