# 釐清問題

全模型尚未建立正式的 Command 清單（僅有零星 [串聯] 註記）。Command 的盤點顆粒度與命名規範應如何訂定？

# 定位

流程：全部 28 條流程
元素：Command（尚未定義）
細節：Command 識別完整性（B1）；命名與意圖（B2）；輸入參數（B3）；Actor → Command → Event 串聯（E1）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 為每一個 Event 反推一個 Command，命名一律為「動詞＋受詞」（如：建立訓練課表），Command 與 Event 一對一，多對一情形另行標註 |
| B | 同 A 的命名規範，但僅為「有 Actor 主動操作」的 Event 建立 Command；系統排程與外部回呼觸發者不建 Command |
| C | 以流程為單位建立粗顆粒 Command（一條流程一至數個 Command），不逐 Event 對應 |
| D | 本階段不建 Command 清單，延後至實作規劃階段由 API 設計反推 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響全模型 Command 層的建立方式、每個 Command 的輸入參數定義（B3 目前全為 Missing）、
以及冪等原則所依賴的「Command 請求識別碼」由哪些 Command 攜帶。
本項為新掃描發現，非承接 `pending-gaps.md`。為 B1 / B2 / B3 三個檢查項的總綱，須先於個別 Command 項目處理。
相關已解決項目：`resolved/command/Actor_模型中各角色名稱的定義與統一.md`（Actor 清單已定，Command 清單仍缺）。

# 解決結果

**選項 A**：為每一個 Event 反推一個 Command，命名一律「動詞＋受詞」，Command 與 Event 一對一，多對一情形另行標註。

**命名與盤點規範（9 條）**：

- 每一個 Event 皆有對應的 Command，原則上一對一；多對一者於備註標明。
- Command 命名為祈使句「動詞＋受詞」，去除主語與「已」字。
- Command 命名反映使用者意圖，不得使用畫面元件名稱。
- 每一個 Command 必須指派 Actor，值域限於既有五種。
- 系統排程與外部回呼觸發的 Event 同樣有 Command（承第 6 題的排程請求識別碼裁決）。
- 每一個 Command 請求必須攜帶請求識別碼。
- 隊長、學徒、教官、成員、發文者、互動者非 Actor，以括號標明角色。
- `00_全域規範.md` 為 Command 的唯一定義處，各流程檔的 [串聯] 註記為其摘要。
- Command 的輸入參數尚未逐一定義（待決策 Partial）。

**產出**：29 條流程的完整 Command 對照表，共 **226 個 Command**，每一個皆標明 Actor 與所導致的 Event。

**多對一與一 Command 兩結果的標註**：

- 多對一：能力值已提升、經驗值已提升、個人排行榜分數已增加、連簽成就已解鎖、使用者已選擇訓練課表、使用者已確認購買、使用者已支付、教官聲望已變動，以及 AI 調整類 5 個 Event。
- 一 Command 兩結果：審核公開訓練（通過 / 未通過）、回報支付結果（已支付 / 已失敗）、回報儲值結果（已儲值 / 已失敗）、駁回教官資格（三階段）。
