# 解決結果

**選項 A** —— Command＝「修改自訂訓練」「下架自訂訓練」，Actor＝使用者（建立者本人），
兩者**僅適用已公開狀態**；已儲存與已發布的修改為自由編輯，不建模為 Event。

| 項目 | 修改 | 下架 |
|------|------|------|
| Command | 修改自訂訓練 | 下架自訂訓練 |
| Actor | 使用者（建立者） | 使用者（建立者） |
| 狀態轉換 | 已公開 → 已申請公開 | 已公開 → 已儲存 |

**僅適用已公開的理由**：兩個 Event 的存在目的是堵「送審放正常課表 → 過審後改為危險內容」
的規避漏洞，要記錄的事實是「一份**已通過審核**的課表被動了」。

**不採 B（適用全部狀態）的理由**：同一個 Event 會在已公開時改變狀態、在其他狀態下什麼都不改，
成為時而改變 Aggregate、時而不改的 Event（與第 5 題辨識出的「管理員已審視檢舉」為同型缺口）；
且 Precondition 只能寫成「該自訂訓練存在」，不可驗收。
使用者同意：需要編輯軌跡時應加 Aggregate 內的編輯歷史欄位（貼文與留言的既有做法），
不由本 Event 承擔 —— 該欄位為另一個決策點，本題不裁決。

**不採 C 的理由**：「管理員因違規強制下架」屬範圍擴張，模型現行違規處置走
「管理員已下架違規內容」，其對象類型已定案為貼文 / 留言 / 私訊；是否納入自訂訓練為另一個決策點。

**不採 D 的理由**：「取消發布自訂訓練」的既有定義為 已發布 → 已儲存，與下架的
已公開 → 已儲存 起點不同，共用一個 Command 會使其 Postcondition 出現兩種狀態轉換。

## 本題連帶完成的兩項裁決

**1. 自訂訓練三個狀態的語意經使用者推翻並改寫**（推翻 2026-07-30 的既有共識）：

| 狀態 | 原定義 | 現定義 |
|------|--------|--------|
| 已儲存 | 私人課表，僅自己可用 | 已存檔但**未啟用**，不可選用於訓練 |
| 已發布 | 對關注者可見 | **自己可用**，可選用於訓練 |
| 已公開 | 進入公開課表 | **全平台可用**（語意不變） |

`resolved/aggregate/自訂訓練_已儲存與已發布與已申請公開三個狀態的狀態機.md` 已加註後續修正。

**2. 新增自訂訓練欄位「對關注者可見」**（bool，預設否），與狀態正交；
新增 Command「變更自訂訓練可見範圍」與 Event「使用者已變更自訂訓練可見範圍」。
採獨立欄位而非新增狀態：自己可用與關注者可見為兩件互相獨立的事。
變更建模為 Event：本欄位決定關注者能否選用該課表，屬他人下 Command 時的 Precondition，
比照「隊長已變更團隊可見性」；與「六維能力值對外可見」的界線在於後者不影響任何規則判定。
