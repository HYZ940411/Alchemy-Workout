# 釐清問題

「AI 已再次確認需求」與「使用者已確認需求」屬於對話往返的互動步驟，是否值得建模為業務 Event，或應留在系統邊界之外？

# 定位

流程：AI 訓練前調整流程、AI 訓練中調整流程（插入訓練紀錄流程循環）
元素：Event：AI 已再次確認需求、使用者已確認需求
細節：軟體邊界判斷（A4）；是否為誤列為 Event 的畫面操作（A1）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 保留為 Event，對話往返需完整留存以供 AI 品質分析與申訴 |
| B | 不列為 Event，僅保留「使用者已提出調整要求」與「AI 已調整訓練」兩端 |
| C | 合併為單一 Event「調整需求已確認」，中間往返視為實作細節 |
| D | 保留為 Event 但標記為「不需精準自動化追蹤」，僅記錄不做規則驗收 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響兩條 AI 調整流程的 Event 清單長度、是否需要建立對話 Aggregate 保存往返內容、以及 AI 調整流程的 Command 顆粒度。此為軟體邊界判斷的關鍵決策。
