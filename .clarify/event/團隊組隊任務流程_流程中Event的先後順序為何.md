# 釐清問題

團隊組隊任務流程的 Event 清單順序混亂（分數增加與排行榜更新出現在建立團隊之前），正確的 Event 先後順序為何？

# 定位

流程：團隊組隊任務流程
元素：Event：使用者已建立團隊、使用者已加入團隊、團隊日常分數已增加、團隊日常排行榜已更新、管理員已設定限時任務、團隊已指派限時任務、成員已完成一次限時任務、團隊限時分數已增加、團隊限時排行榜已更新、限時任務獎勵已發放
細節：Event 先後順序是否明確（A3）；起點與終點 Event（A1）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 拆為兩條子流程：組隊流程（建立 → 加入）與任務流程（設定 → 指派 → 完成 → 計分 → 排行 → 發獎） |
| B | 拆為三條子流程：組隊、日常分數累計、限時任務 |
| C | 維持單一流程但重排順序為：建立 → 加入 → 日常分數 → 日常排行 → 管理員設定 → 週期指派 → 完成 → 限時分數 → 限時排行 → 發獎 |
| D | 維持現狀，Event 之間無強制順序，皆由各自 Policy 獨立觸發 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響團隊組隊任務流程的檔案結構與 Event 時序、各 Event 的 Precondition 依賴關係、以及後續 Command 與 Aggregate 的推導順序。此為該流程可讀性與可推導性的前提。
