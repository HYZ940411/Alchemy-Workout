## 3. 建議釐清順序

推導方向原則不變：Event → Command/Actor → Aggregate → Rules → Read Model。
前兩層已清空，故實際順序為：

### 第一階段：Read Model（13 項）

**理由**：Read Model 為推導鏈最後一層，也是目前唯一大批未定義者。
在它完成前，覆蓋度檢查項 **D6 與 E4 無法評估**。

**依賴**：`課表選擇頁` 須先解決 §4.1 的矛盾。

### 第二階段：結構題（6 項）

其中 `永久停權者的功能權限範圍` 為 High，且與第 56 題的既有裁決有張力
（第 56 題以「帳號停權者無法登入」為由暫停計時；若永久停權者可訓練，該前提不成立）。

### 第三階段：數值題（13 項，一次全部攤開）

**不可逐題分開答。** 建議順序：

```
金幣對法幣比率（前置）
  → 獎勵定義第二批 ＋ 互動獎勵每日上限（同一組決策）
  → 獎勵定義第三批
  → 會員權益清單
能力值遞減公式 ＋ 套用順序 ＋ 退步平衡點（同一段公式，三題一起）
  → 能力值等級的六階門檻
個人排行榜分數換算率 → 團隊限時分數固定分與加成
```

### 第四階段：`pending-gaps-3.md` 的 I1–I24

這 24 條是第二至四輪 formulation 過程中**手動撿出**的缺口，未建為正式釐清項目。
High 者：I11、I12、I16、I19、I21、I23、I24。

**它們的存在本身即為 discovery 逾期的訊號** —— 應由掃描產出，而非邊做邊撿。
