# 釐清問題

Gherkin 的固定關鍵字（Feature、Rule、Scenario、Given、When、Then、And）要用英文原字，還是改用中文的「功能／場景／假設／當／那麼／而且」？

# 定位

翻譯單元：全部 318 個翻譯單元，不限單一 Aggregate。
Gherkin 位置：每一行句首的關鍵字，以及檔案第一行是否需要 `# language:` 宣告。
對應樣板空格：樣板中 `Rule：`、`Given：`、`When：`、`Then：`、`And：` 這幾個字本身。
相關既有共識：無（`.es-clarify/resolved/` 為事件風暴階段，未觸及 Gherkin 語法）。

# 白話說明

這題和上一題（句子用中文還是英文）是**兩件事**：句子可以是中文，但句首那個關鍵字仍可以維持英文。

選 A（英文關鍵字 ＋ 中文句子）長這樣：

```gherkin
Feature: 使用補簽券

  Rule: 業務規則驗證
    Scenario: 補簽券張數不足時無法補簽
      Given 使用者（U001）的補簽券持有張數為 0
      When 使用者（U001）使用補簽券回補 2026-08-20
      Then 操作失敗
```

選 B（中文關鍵字）長這樣，檔案第一行要加語言宣告：

```gherkin
# language: zh-TW
功能: 使用補簽券

  Rule: 業務規則驗證
    場景: 補簽券張數不足時無法補簽
      假設 使用者（U001）的補簽券持有張數為 0
      當 使用者（U001）使用補簽券回補 2026-08-20
      那麼 操作失敗
```

**請注意選 B 的第 3 行**：官方的繁體中文（zh-TW）關鍵字表裡，`Rule` **沒有中文對應字**，
只能寫英文 `Rule`。所以選 B 實際上得到的是「中文關鍵字裡夾一個英文 Rule」的混合體。
簡體中文（zh-CN）才有「规则」，但那是簡體字。

（以上關鍵字對照已查證 Cucumber 官方 Gherkin 語言表：
zh-TW 的 Feature=功能、Scenario=場景/劇本、Scenario Outline=場景大綱/劇本大綱、
Examples=例子、Given=假如/假設/假定、When=當、Then=那麼、And=而且/並且/同時、
**Rule=Rule（無中文字）**；zh-CN 的 Rule=规则。）

# 多選題

| 選項 | 描述 | 推薦 |
|------|------|------|
| A | 英文關鍵字 ＋ 中文句子，不加 `# language:` 宣告 | ★ |
| B | 中文關鍵字（`# language: zh-TW`），接受 `Rule` 只能維持英文 |  |
| C | 中文關鍵字改用簡體 `# language: zh-CN`，以取得「规则」 |  |
| Short | 提供其他簡短答案（<=5 字） |  |

# 推薦選項與理由

**推薦 A（英文關鍵字 ＋ 中文句子）。**

決定性的理由來自本專案的翻譯樣板本身：這套樣板是**以 `Rule` 區塊為骨架**設計的——
「先分好 Rules，按前置／後置條件分開翻譯」，七項 SOP 補強決議中有三項
（決議 1 依失敗原因分 Rule、決議 2 權限驗證獨立成一種 Rule、決議 3 兩種觸發源分兩個 Rule）
直接以 Rule 為單位。而查證結果顯示 zh-TW 的 `Rule` 沒有中文關鍵字，
選 B 會讓整套骨架上最重要的那個字停在英文，其餘全中文——這是最難看也最難解釋的一種不一致。

不推薦 C：本專案全篇繁體中文（模型、釐清紀錄、決策理由），
為了一個「规则」改用簡體會讓所有中文句子被迫寫成簡體，代價遠大於收益。

業界通例也支持 A：非英語團隊普遍採「英文關鍵字 ＋ 母語句子」，
因為關鍵字只有七個、看幾次就記住，而 IDE 語法上色、linter、多數 step definition 產生器
對英文關鍵字的支援最穩定；真正需要讓非技術人員讀懂的是句子，不是句首那個字。
