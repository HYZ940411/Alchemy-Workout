# 釐清問題

`Feature:` 後面那一行要寫什麼——直接寫 Command 原名（「使用補簽券」），還是寫成一句完整的功能敘述？

# 定位

翻譯單元：全部 318 個翻譯單元。
Gherkin 位置：每個 Feature File 的第一行 `Feature:` 標題。
對應樣板空格：樣板未明訂 Feature 標題，屬決議 7「檔名統一動詞＋名詞格式」的延伸。
相關既有共識：`.es-clarify/resolved/event/使用者已記錄該組成績_流程檔名與標題仍引用已棄用的Event名.md`
（該裁決要求標題不得引用已棄用的 Event 名，顯示本專案在意標題與統一語言的一致）。

# 白話說明

選 A（Feature 標題 = Command 原名，與檔名一致）：

```gherkin
Feature: 使用補簽券
```

選 B（一句完整功能敘述）：

```gherkin
Feature: 使用者以補簽券回補未簽到的日期
```

選 C（Command 原名 ＋ 底下加一段說明段落，Gherkin 允許 Feature 標題後接自由文字）：

```gherkin
Feature: 使用補簽券

  使用者持有補簽券時，可回補最近 7 天內任一未簽到日。
  補簽當日計入累計簽到天數，比照真實簽到；獎勵補發至獎勵信箱，不直接入帳。
```

# 多選題

| 選項 | 描述 | 推薦 |
|------|------|------|
| A | Feature 標題逐字等於 Command 原名，與檔名完全一致 | ★ |
| B | Feature 標題寫成一句完整的功能敘述，與檔名不同 |  |
| C | 標題等於 Command 原名，另在標題下加一段自由文字說明 |  |
| Short | 提供其他簡短答案（<=5 字） |  |

# 推薦選項與理由

**推薦 A（標題 = Command 原名）。**

理由一（可機械翻譯，本階段的核心目標）：選 A 不需要撰寫任何新文字——
`01_Command清單.md` 已列出全部 283 個 Command 名，直接抄。
選 B 需要為 318 個檔案各寫一句敘述，且沒有規則能保證這些句子的體例一致。

理由二（統一語言的可追溯性，本專案已有具體先例）：已查證
`.es-clarify/resolved/event/使用者已記錄該組成績_流程檔名與標題仍引用已棄用的Event名.md`
——本專案曾因「標題引用了已棄用的 Event 名」而專門開一題裁決。
標題若逐字等於 Command 原名，日後模型改名時 grep 舊名即可一次找齊檔名與標題兩處；
選 B 的自由敘述句會漏掉，同一類問題會重演。

理由三：檔名與標題一致，代表在搜尋結果與檔案內容之間不需要做任何對應，
這是多數 Gherkin 專案的預設做法。

**關於選 C 的補充**：Feature 標題下加說明段落本身是 Gherkin 的正規語法，也常見於實務。
但本模型的規則內容已完整存在於 `Event-Storming_事件風暴/` 各流程檔中，
把它抄一份到 `.feature` 檔會產生第二份需要同步的規則描述——
這正是 `.es-clarify/resolved/aggregate/統一語言_尚未建立標準術語詞彙表.md` 裁決
以「散在兩處，反而更難維護」為由否決過的模式。若確實需要說明，
建議改為在標題下放一行來源指標（例如 `# 來源：Event-Storming_事件風暴/補簽流程.md`），
而非複製規則內容。

# 解決結果

**A ＋ 來源行** —— Feature 標題逐字等於 Command / Read Model 原名（與檔名完全一致），
標題下方加**一行**來源指標註解 `# 來源：Event-Storming_事件風暴/<流程檔名>.md`。

使用者於原多選題的 A、B、C 之外採用了提問時提出的折衷寫法：
取 A 的「標題 = 原名、零撰寫成本、可 grep 追溯」，
並取 C 的可追溯性，但**只寫來源指標、不複製規則內容**，
以避免產生第二份須與模型同步的規則描述。

# 回寫位置

`Gherkin_行為規格/00_翻譯規約.md` §1.9 Feature 標題格式
（含來源行的三條取值規則：一般流程檔／不隸屬單一流程者／跨流程重複的 15 個 Command）

# 產出的 Gherkin 片段

```gherkin
Feature: 使用補簽券
  # 來源：Event-Storming_事件風暴/補簽流程.md

  Rule: 業務規則驗證
    Scenario: 補簽券張數不足
      Given 使用者（U001）的補簽券持有張數為 0
      When 使用者（U001）使用補簽券回補 2026-08-20
      Then 操作失敗
      And  使用者（U001）的補簽券持有張數仍為 0
```

# 連帶影響

- §2 Feature 清單需增加「來源流程檔」一欄，供產檔時填入來源行。
- 跨流程重複出現的 15 個 Command（提升經驗值、提升能力值、增加個人排行榜分數等）
  需在 §2 標註主要流程檔與其餘出現處，來源行取主要流程檔。
