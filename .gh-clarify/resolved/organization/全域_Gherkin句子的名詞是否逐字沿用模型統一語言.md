# 釐清問題

Gherkin 句子裡的名詞，是否強制逐字沿用 `00_全域規範.md`〈統一語言：已定案術語〉的原名，不得為了句子通順而改寫或簡稱？

# 定位

翻譯單元：全部 318 個翻譯單元。
Gherkin 位置：Given / When / Then / And 句子中的每一個名詞，以及 Examples 表格的欄名。
對應樣板空格：樣板中「Aggregate」「Command」「Event」「Read Model」四格所填入的名詞。
相關既有共識：`.es-clarify/resolved/aggregate/統一語言_尚未建立標準術語詞彙表.md`
（裁決：詞彙表寫在 `00_全域規範.md`，含 21 條已定案術語與曾用名對照，並訂有三條維護規則）。

# 白話說明

模型的術語表裡有一條規則寫得很硬：「**Policy 與 Rule 中引述行為時，一律直接使用既有 Event 全名，不得另造簡稱**」。
問題是——這條規則是寫給事件風暴模型的，Gherkin 句子要不要照辦？

差別在哪裡，看這個例子。模型的 Event 全名是「個人排行榜分數已增加」、
「使用者已記錄該組成績」、「單次訓練已逾時中斷」。

選 A（逐字沿用）：

```gherkin
  Given 使用者（U001）的單次訓練已逾時中斷
  Then  使用者（U001）的個人排行榜分數已增加 50 點
  And   產生「訓練已結算」Event
```

選 B（允許為句子通順而改寫）：

```gherkin
  Given 使用者（U001）的這次訓練因逾時而中斷
  Then  使用者（U001）的排行榜分數增加 50 點
  And   系統完成本次訓練結算
```

選 B 讀起來順，但「排行榜分數」在模型裡其實有三個不同的東西
（個人排行榜分數、團隊分數、經驗值——術語表〈三個成長數值的區別〉專門警告過這一點），
簡稱之後就分不出是哪一個了。

另外要注意：本模型的術語**其實都不長**（已查證：最長的 Command 名為 10 個中文字，
最長的 Aggregate 名「團隊成員資格申請」為 8 個字），所以「太長需要縮寫」的情況在本模型並不存在。

# 多選題

| 選項 | 描述 | 推薦 |
|------|------|------|
| A | 強制逐字沿用模型原名，不得簡稱、不得改寫；句子的通順度讓位給術語一致性 | ★ |
| B | 以句子通順為優先，允許在不產生歧義時使用自然說法 |  |
| C | 逐字沿用，但另建一份「Gherkin 專用縮寫對照表」，允許表中列出的名詞使用簡稱 |  |
| Short | 提供其他簡短答案（<=5 字） |  |

# 推薦選項與理由

**推薦 A（強制逐字沿用）。**

理由一（模型已有一條直接適用的既有規則，已查證）：
`00_全域規範.md`〈統一語言：已定案術語〉的規則段落明文寫著
「**Policy 與 Rule 中引述行為時，一律直接使用既有 Event 全名，不得另造簡稱**」。
Gherkin 的 `Rule` 區塊翻譯的正是模型的 `[Rule]`，套用同一條規則是延續而非新增裁決。

理由二（本專案已為術語混用付出過代價，已查證）：術語表的
〈三個成長數值的區別〉小節是專門為了「經驗值 vs 能力值 vs 個人排行榜分數」被混用而新增的，
且術語表列出 21 組「曾用名」——追蹤／關注、進階訓練計畫／訓練計畫、
使用者訓練已中斷／單次訓練已逾時中斷、虛擬貨幣／金幣等。
選 B 等於允許這些曾用名以「自然說法」的形式重新回到規格檔裡，
而〈詞彙表維護規則〉第二條明文寫「**曾用名一律不得再出現**」。

理由三（可機械翻譯）：選 A 是零判斷的——名詞直接抄模型；
選 B 要求譯者每一句都判斷「這樣簡稱會不會有歧義」，正是本階段要消除的主觀判斷。

不推薦 C：本模型的術語最長 10 個中文字，沒有任何一個長到需要縮寫，
建立對照表是為不存在的問題增加一份要維護的檔案；且
`.es-clarify/resolved/aggregate/統一語言_尚未建立標準術語詞彙表.md`
已裁決過「另開檔案會使術語定義散在兩處，反而更難維護」。

**須明講的取捨**：選 A 會使部分句子讀起來像模型摘要而非自然中文，
例如「Given 使用者（U001）的單次訓練已逾時中斷」。這是刻意付出的代價——
Gherkin 在本專案的第一用途是可驗收的規格，不是文案。

# 各選項的翻譯後果

| 選項 | Feature 檔數 | Scenario 條數 | 維護成本 |
|------|-------------|--------------|----------|
| A | 318（不受本題影響） | 不受本題影響 | 最低。名詞直接抄；模型改名時 grep 原名可全數命中 |
| B | 318（不受本題影響） | 不受本題影響 | 最高。改名時無法靠 grep 找齊；曾用名可能悄悄回流 |
| C | 318（不受本題影響） | 不受本題影響 | 中。多一份對照表需維護，而本模型無術語過長的實例 |

# 影響範圍

影響每一個 Feature File 的每一個名詞，以及 Examples 表格的欄名。
本題與 `.gh-clarify/organization/全域_Gherkin句子的敘述文字用中文還是英文撰寫.md` 連動：
若句子改用英文，本題的「逐字沿用中文原名」即無從執行，須改為對照表模式。
建議先答語言題，再答本題。

# 解決結果

**A** —— 強制逐字沿用模型原名，不得簡稱、不得為句子通順而改寫；
曾用名一律不得出現；三個成長數值不得互相簡稱；不另建縮寫對照表。

# 回寫位置

`Gherkin_行為規格/00_翻譯規約.md` §1.4 名詞強制逐字沿用統一語言
（含正確／錯誤對照範例與「句子偏向模型摘要」的已知取捨）

# 產出的 Gherkin 片段

```gherkin
# 正確（逐字沿用）
  Given 使用者（U001）的單次訓練已逾時中斷
  Then  使用者（U001）的個人排行榜分數已增加 50 點

# 錯誤（改寫與簡稱）
  Given 使用者（U001）的這次訓練因逾時而中斷      ← 改寫了 Event 全名
  Then  使用者（U001）的排行榜分數增加 50 點       ← 「排行榜分數」有歧義
```

# 連帶影響

- 後續所有 GH3（Given 素材）、GH4（Then 斷言）個案題的句子用詞，一律受本條約束，
  不需再逐題確認「這個名詞可不可以簡稱」。
- GH5（Examples 表格）的欄名同樣受本條約束。
- 本條使「模型改名 → grep 原名 → 找齊所有受影響的 .feature 檔」成為可靠操作。
