# 釐清問題

Feature File 的檔名（決議 7 要求「動詞＋名詞」格式）要直接用中文 Command 原名，還是轉成英文或拼音？

# 定位

翻譯單元：全部 318 個翻譯單元。
Gherkin 位置：檔案路徑（不影響檔案內容）。
對應樣板空格：不對應句子，對應決議 7「資料夾內依 Command / Query 分別建立 Feature File，檔名統一動詞＋名詞格式」。
相關既有共識：`.es-clarify/resolved/event/使用者已記錄該組成績_流程檔名與標題仍引用已棄用的Event名.md`
（該裁決處理的是流程檔名引用棄用術語的問題，顯示本專案已用中文當檔名並在意其正確性）。

# 白話說明

模型裡的 Command 叫「使用補簽券」「記錄該組成績」「審核公開訓練」。要變成一個檔案名字。

選 A（中文檔名）：

```
Gherkin_行為規格/features/補簽券/使用補簽券.feature
Gherkin_行為規格/features/訓練紀錄/記錄該組成績.feature
```

選 B（英文檔名）：

```
Gherkin_行為規格/features/makeup_ticket/use_makeup_ticket.feature
Gherkin_行為規格/features/workout_record/record_set_result.feature
```

選 C（拼音檔名）：

```
Gherkin_行為規格/features/buqianquan/shiyong_buqianquan.feature
```

差別在於：選 B 要為 283 個 Command ＋ 65 個 Aggregate 各想一個英文名；
選 C 不需想名字，但沒有人能靠檔名看出那是什麼。

# 多選題

| 選項 | 描述 | 推薦 |
|------|------|------|
| A | 中文檔名，逐字沿用 Command 原名，例：`使用補簽券.feature` | ★ |
| B | 英文檔名（小寫底線），需另建中英對照表，例：`use_makeup_ticket.feature` |  |
| C | 拼音檔名，例：`shiyong_buqianquan.feature` |  |
| Short | 提供其他簡短答案（<=5 字） |  |

# 推薦選項與理由

**推薦 A（中文檔名）。**

理由一（本專案既有慣例，已查證）：`Event-Storming_事件風暴/` 底下 34 個檔案**全部是中文檔名**，
其中還包含帶括號與 `&` 的長檔名，例如
`訓練紀錄流程（循環：使用者已完成該組 > 組間休息已結束）.md`；
`.es-clarify/resolved/` 的 392 個檔案也全部是中文檔名。本專案已經在中文檔名上跑了整個事件風暴階段，
沒有出現過因檔名編碼而失敗的紀錄。Gherkin 檔名與其一致，才能用同一個關鍵字同時搜到
模型檔與規格檔。

理由二：選 B 要求的中英對照表，正是
`.es-clarify/resolved/aggregate/統一語言_尚未建立標準術語詞彙表.md` 裁決中
以「術語定義散在兩處，反而更難維護」為由否決過的東西。

理由三：Cucumber 對檔名沒有字元限制，`.feature` 的載入靠副檔名而非檔名內容。

**須明講的取捨**：業界通例其實偏向英文檔名（跨平台、CI 路徑安全）。
本專案之所以推薦 A 而非通例，是因為既有 400 多個中文檔名的事實已經先行成立——
此時改用英文只會製造模型檔與規格檔兩套命名。若日後專案要開源或引入非中文協作者，
此決定需重新評估；建議在慣例文件中註記這一點。

不推薦 C：拼音同時失去「看得懂」與「國際化」兩邊的好處。
