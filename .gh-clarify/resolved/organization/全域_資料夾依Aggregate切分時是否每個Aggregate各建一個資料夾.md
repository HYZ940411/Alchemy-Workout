# 釐清問題

決議 7 要求「按 Aggregate 分資料夾」，但本模型有 65 個 Aggregate，其中十多個只有一到兩個 Command。這些小 Aggregate 要各自獨立一個資料夾，還是合併成較大的分類資料夾？

# 定位

翻譯單元：全部 318 個翻譯單元。
Gherkin 位置：檔案路徑的資料夾層。
對應樣板空格：不對應句子，對應決議 7「按 Aggregate 分資料夾」。
相關既有共識：`.es-clarify/resolved/aggregate/使用者_使用者Aggregate的欄位與邊界尚未定義.md`（選項 B-1，即〈獨立 Aggregate 清單〉64 項的來源）。

# 白話說明

模型的 `02_Aggregate定義.md`〈獨立 Aggregate 清單〉列了 **64 個獨立 Aggregate**，
加上「使用者」共 65 個。這份清單本身已經**先分好了 11 個分類**：
訓練、成長設定、簽到、任務、成就與獎勵、社群、師徒與教官、團隊、商城、訂閱、平台。

問題在於：這 65 個裡有很多是「設定類」的小 Aggregate，
例如補簽設定、通知設定、審核時限設定、檢舉理由設定、防作弊設定、能力值設定、教官初審設定——
它們各自只對應一個管理員 Command（如「設定補簽回補範圍」），
獨立成資料夾的話會出現十幾個只裝一個檔案的資料夾。

選 A（每個 Aggregate 各一個資料夾）：

```
features/補簽券/使用補簽券.feature
features/補簽設定/設定補簽回補範圍.feature      ← 整個資料夾只有 1 個檔
features/通知設定/設定通知參數.feature          ← 整個資料夾只有 1 個檔
features/防作弊設定/設定補格門檻.feature        ← 整個資料夾只有 1 個檔
```

選 B（沿用模型既有的 11 個分類當第一層，Aggregate 當第二層）：

```
features/簽到/補簽券/使用補簽券.feature
features/簽到/補簽設定/設定補簽回補範圍.feature
features/平台/通知設定/設定通知參數.feature
```

選 C（設定類合併，其餘各自獨立）：

```
features/補簽券/使用補簽券.feature
features/平台設定/設定補簽回補範圍.feature
features/平台設定/設定通知參數.feature
features/平台設定/設定防作弊門檻.feature
```

# 多選題

| 選項 | 描述 | 推薦 |
|------|------|------|
| A | 65 個 Aggregate 各建一個資料夾，完全照決議 7 字面執行，不做任何合併 | ★ |
| B | 兩層：第一層用模型既有的 11 個分類，第二層用 Aggregate 名 |  |
| C | 一層，但把只有 1–2 個 Command 的設定類 Aggregate 合併為一個 `平台設定` 資料夾 |  |
| Short | 提供其他簡短答案（<=5 字） |  |

# 推薦選項與理由

**推薦 A（每個 Aggregate 各一個資料夾）。**

理由一（可機械執行，這是本階段的目標）：選 A 的歸屬規則是
「這個 Command 改的是哪個 Aggregate，就放哪個資料夾」——一條規則，零判斷。
選 C 需要額外定義「多小算小」「哪些算設定類」，等於在每次新增 Aggregate 時都要重新裁決一次；
選 B 需要每個 Aggregate 額外記住它屬於哪一個分類。本階段的目的正是消除主觀判斷。

理由二（本專案已查證的事實）：模型的 11 個分類**只是〈獨立 Aggregate 清單〉表格中的一個欄位**，
並非任何規則的判定依據——`.es-clarify/resolved/` 中沒有任何裁決引用過這 11 個分類。
把一個純粹的排版分類升格為檔案結構，等於賦予它從未被裁決過的地位。

理由三：「只有一個檔案的資料夾」在 Gherkin 專案裡是正常的，不是壞味道。
Cucumber 以 glob 遞迴載入 `**/*.feature`，資料夾層數與數量對執行毫無影響；
資料夾在此只是給人看的索引。

**須明講的一點**：業界對「小資料夾」確實常見合併做法（選 C），
但那通常出現在資料夾同時是**程式模組邊界**的專案裡。本專案的 `features/` 只放規格檔、
不放任何程式碼，合併帶來的收益（少幾個資料夾）遠小於它帶來的成本（一條需要主觀判斷的歸檔規則）。

# 各選項的翻譯後果

| 選項 | Feature 檔數 | Scenario 條數 | 維護成本 |
|------|-------------|--------------|----------|
| A | 318 檔，分佈於 65 個資料夾（其中約 12 個各只有 1 檔） | 不受本題影響 | 最低。歸檔規則一句話，新增 Aggregate 時自動適用 |

# 解決結果

**A** —— 65 個 Aggregate 各建一個資料夾，一層結構，不做任何合併；
不採模型的 11 個分類作為第一層；不採「設定類合併為 `平台設定/`」。

# 回寫位置

`Gherkin_行為規格/00_翻譯規約.md` §1.5 資料夾切分規則
（含完整的 65 個資料夾清單，並註明模型的 11 個分類僅供對照、不作為資料夾層）

# 產出的 Gherkin 片段

本題不產生句子，產生的是路徑結構：

```
features/補簽券/使用補簽券.feature
features/補簽設定/設定補簽回補範圍.feature      ← 本資料夾只有 1 個檔，正常
features/通知設定/設定通知參數.feature          ← 同上
features/訓練紀錄/記錄該組成績.feature
```
