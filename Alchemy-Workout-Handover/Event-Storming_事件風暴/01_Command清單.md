## Command 清單

### 命名與盤點規範

- 每一個 Event 皆有對應的 Command，Command 與 Event 原則上一對一；多對一者於備註標明。
- Command 命名一律為祈使句「動詞＋受詞」，去除主語與「已」字。
- Command 命名反映使用者意圖，不得使用畫面元件名稱。
- 每一個 Command 必須指派 Actor，值域限於00_全域規範.md〈Actor 清單〉的五種。
- Actor 為管理員的 **34** 個 Command，其所需權限組見02_Aggregate定義.md〈管理員 Aggregate〉之
  02_Aggregate定義.md〈權限組與 Command 的對應〉；各 Command 不於本清單逐列標註權限。
- 系統排程與外部回呼觸發的 Event 同樣有 Command，其 Actor 為系統或外部系統。
- 每一個 Command 請求必須攜帶請求識別碼（承00_全域規範.md〈Event 冪等性原則〉）。
- 隊長、學徒、教官、成員、發文者、互動者皆非 Actor，於備註以括號標明其角色。
- 本清單為 Command 的唯一定義處，各流程檔的 [串聯] 註記為其摘要，不另建清單。

### Command 輸入參數的推導規則

Command 的輸入參數**不逐一列表**，一律由下式推導：

> **Command 的輸入參數 ＝ 其導致的 Event 之專屬攜帶欄位 ＋ 目標 Aggregate ID ＋ 請求識別碼**

#### 規則

- 採推導規則而非逐一列表：Command 的輸入與其導致的 Event 所攜帶的資訊，
  本質上是同一份資料的兩端 —— 使用者填什麼，Event 就記什麼。
  逐一列表會產生大量「請求識別碼 ＋ 對象 ID」的重複列，真正有資訊量的欄位不到三成。
- Event 的**共通 5 欄位**（事件 ID、UTC 時戳、當地時區時戳、觸發 Actor、關聯 Aggregate ID）
  為系統產生，**不是** Command 的輸入。
- 各流程檔以〔攜帶資訊：…〕標註的專屬欄位，即為該 Command 的輸入參數。
- 必填／選填沿用 Event 攜帶欄位的定義：型別標註為「⋯ / 空值」者為選填，其餘為必填。
- 型別、單位與合法範圍沿用該欄位在其 Aggregate 中的既有定義，不另立一套。
- 排程與外部系統觸發的 Command，其請求識別碼由00_全域規範.md〈排程觸發的請求識別碼〉的自然鍵推導，
  不由呼叫方提供。
- **一 Command 兩結果**者（現有 3 處：審核公開訓練、回報支付結果、回報儲值結果），
  輸入另含一個「判定結果」參數，該參數決定產生兩個互斥 Event 中的哪一個。
- 查詢類 Command（不產生 Event 者）的輸入為其 Read Model 的篩選與分頁條件，
  由該 Read Model 的定義承載，不套用本推導規則。
- 本規則不適用時，該 Command 逐一補問並於本節列為例外；本輪盤點未發現例外。

| 持有器材明細 | ✅ | 訓練前的器材比對 Policy、AI 替換動作的調整依據 |
| AI 自動優化已啟用 | ✅ | 〈AI 自動優化訓練流程〉Policy 的 Precondition |
| 偏好訓練時段 | ✅（既有） | 訓練提醒的發送時段判定 |
| 六維能力值對外可見 | ❌ | 無任何規則讀取，僅影響他人檢視時的呈現 |
| **綜合能力等級對外可見** | ❌ | 同上（2026-08-11 新增，理由與上一列相同） |
| 單位偏好 | ❌ | 僅影響顯示，不影響儲存 |

- **模型實際上早已在用本判準**：「偏好訓練時段」正是「只影響自己、但被規則讀到」的欄位，
  其既有 Event「使用者已選擇偏好訓練時段」即依本判準成立。本節僅將該判準明文化。
- **不採「是否影響他人」為判準**：該判準會使偏好訓練時段的既有 Event 被推翻，
  且持有器材明細設定錯誤時，查「為何那天的課表被改了」將無任何紀錄可稽。
- **不採逐一建模全部設定欄位**：單位偏好、雷達圖隱藏等純顯示欄位各給一個 Event，
  Event 總數膨脹而無任何讀者。
- **不採單一泛用 Command「變更個人設定」**：其攜帶任意欄位的任意值，
  Postcondition 只能寫成「該欄位變成新值」，等同無驗收標準
  —— 承〈平台級設定的軟體邊界〉否決「平台設定已變更」單一泛用 Event 的相同理由。
- 設定類 Command 不隸屬任何流程，比照〈系統排程〉的處理方式收納於本節，不寫入流程檔。

| Command | Actor | 導致的 Event |
|---------|-------|--------------|
| 設定持有器材明細 | 使用者 | 使用者已設定持有器材明細 |
| 設定 AI 自動優化開關 | 使用者 | 使用者已設定 AI 自動優化開關 |

- **「使用者已設定持有器材明細」有兩條觸發路徑**，共用同一個 Command：
  ① 於設定頁填寫；② 於「本次訓練器材已解鎖」時勾選「套用至未來所有訓練」。
  後者原為一條無 Command 的暗路，本次收斂。
- 兩個 Event 皆攜帶：變更前的值、變更後的值。

#### 平台級設定的軟體邊界

**判準：該設定改動後，是否會改變使用者已取得或將取得的實質內容。**

| 納入軟體邊界（有 Command 與 Event） | 留在系統邊界之外（後台組態，維持人工作業） |
|-----------------------------------|--------------------------------------|
| 訓練計畫 | 健身目標設定 |
| 動作（平台動作庫） | 健身經驗設定 |
| 成就定義 | 檢舉理由設定〔為 Aggregate，僅不建 Command 與 Event；比照帶徒上限設定與器材設定〕 |
| 獎勵定義 | 器材明細值域 |
| **能力值設定**（2026-08-20 新增） | 帶徒上限設定 |
| **教官初審設定**（2026-08-20 新增） | 教官專長設定 |
| **補簽設定**（2026-08-20 新增） | 器材設定 |
| — | **內容過濾設定**（2026-08-20 新增） |
| — | **防作弊設定**（2026-08-20 新增） |
| — | **通知設定**（2026-08-20 新增） |
| — | **審核時限設定**（2026-08-20 新增） |

- **左欄四者改動後會直接改變使用者拿到什麼**：獎勵數額、成就門檻、課表內容、可選動作。
  三者皆已明文承諾「調整不追溯既有紀錄」，而模型的申訴機制未設時效上限 ——
  既已承諾不追溯，就須有可稽核的依據記錄「何時改的、改成什麼」，否則
  使用者質疑「上個月訓練拿 30 金幣、這個月只有 20」時無從查證。
- **右欄五者為值域清單**，改動只影響下拉選單的選項，不改動任何已發生的事實
  （承既有規則：值域調整不改動任何使用者已填入的健身目標 / 已選擇的健身經驗）。
  為其建模等於把後台的每次存檔記成業務事實。
- 右欄留在邊界之外**不代表資料不可調整**：其仍由管理員於後台維護，僅不建模為 Event。
- 不採「全數納入」：Event 總數為對稱性膨脹 5 個，而該 5 個沒有任何讀者。
- 不採「單一泛用 Event『平台設定已變更』」：其攜帶值域為「任意設定的任意變更」，
  Precondition 與 Postcondition 皆寫不出來，為不可驗收的 Event，
  與「規則即驗收標準」的原則相衝。
- 帶徒上限設定歸右欄：其為聲望門檻與人數參數，調整後既有教官的帶徒上限
  不因此降低（承單調遞增的既有裁決），故不改動任何已取得的內容。
- **能力值設定歸左欄**（2026-08-20 新增）：其為左欄唯一「改動當下即改變使用者**已取得**之物」者
  —— 02_Aggregate定義.md〈能力值設定 Aggregate〉明寫「六階門檻調整後即時生效，
  管理員調整門檻的當下，全平台使用者的等級同時改變」，等級**當場可降**。
  左欄原有四者改動的皆為「將取得」（日後的獎勵數額、成就門檻、課表內容、可選動作），
  本項比其更貼近判準。
- **能力值設定不比照帶徒上限設定歸右欄**：後者歸右欄的理由為「調整後既有教官的帶徒上限
  不因此降低」，即改動拿不走任何東西；能力值設定恰為其反例。
- **能力值設定亦不同於右欄其餘六者**：該六者皆為**值域清單**，改動只換下拉選單的選項；
  本項為餵入即時公式的數值參數。
- 稽核的必要性：六階門檻調降時，點數落於新舊門檻之間的使用者當場跨階，
  「能力值成就已解鎖」隨即觸發並發放金幣與經驗值 —— 設定改動直接發出獎勵，
  而申訴機制未設時效上限，須查得到何時改的、改成什麼。

##### 2026-08-20 新增的七個設定 Aggregate 之分流

同判準逐一套用，結果為左欄 3 個、右欄 4 個。

- **教官初審設定歸左欄**：門檻調升的當下，原本符合資格、可以送出教官申請的使用者
  **即刻不能申請** —— 拿走的是使用者已經具備的資格。
- **補簽設定歸左欄**：回補範圍縮短的當下，原本補得回來的那幾個未簽到日
  **即刻補不回來** —— 拿走的是使用者已經握有的機會，且補簽券為付費可得之物。
- **內容過濾設定歸右欄**：該表已明文「門檻調整不追溯既有內容，已發布或已攔截者不因門檻變動而改判」，
  改動不動任何已發生的事實。
- **防作弊設定歸右欄**：該表已明文「參數調整不追溯既有訓練紀錄，亦不重新判定已完成的組」，
  且同表明訂「本表的參數值不對使用者揭露」—— 使用者看不到的東西，談不上被拿走。
- **通知設定歸右欄**：其改動只影響收到幾則推播、幾點收到，不改變使用者取得的任何實質內容。
- **審核時限設定歸右欄**：時限為管理員端的內部工作期限，逾期依既有裁決
  「僅產生『審核已逾期』，**不改變案件狀態**」，對使用者的處理結果零影響。
- **不採全數納入**：右欄四者各補一個 Event 為對稱性膨脹，而該四個 Event 沒有任何讀者。
- **不採全數排除**：教官初審設定與補簽設定的調整會當場改變使用者的資格與機會，
  排除後該兩處無任何可稽核的依據。
- **不採單一泛用 Command「設定平台參數」**：承本節既有裁決 ——
  其攜帶值域為任意設定的任意變更，Precondition 與 Postcondition 皆寫不出來，為不可驗收的 Event。
