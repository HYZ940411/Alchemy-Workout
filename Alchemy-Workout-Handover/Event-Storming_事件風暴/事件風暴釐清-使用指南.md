## 這兩個指令在做什麼
- `/es-discovery`：幫你「找問題」。它會讀你們寫好的流程與 Event，把沒講清楚的地方整理成一題一題的問題檔。
- `/es-formulation`：幫你「回答問題」。它會一次問你一題，你回答完，它就直接把答案寫回事件風暴模型裡。

先跑 discovery，再跑 formulation，順序不能反。

## 第一次使用
1. 先把你們的流程與 Event 寫成檔案，放進 Event-Storming_事件風暴/ 資料夾
2. 在專案資料夾打開 Claude Code：claude
3. 輸入：/es-discovery
4. 等它跑完，它會建立一個 .es-clarify/ 資料夾，裡面是所有待釐清的問題
5. 打開 .es-clarify/overview.md 看看總共有幾題、建議從哪裡開始

## 開始回答問題
1. 輸入：/es-formulation
2. 它會一次問你一題，並附上選項表格
3. 你回答（三種方式擇一）：
   - 直接打選項代號，例如：A
   - 選項都不對，就直接用文字寫你的答案
   - 這題現在答不出來，就打：skip
4. 它會立刻把答案寫回事件風暴模型，並告訴你改了哪幾行
5. 想結束就打：stop
6. 沒答完沒關係，下次再輸入 /es-formulation 就會從沒答完的地方繼續

## 答完之後
1. 檢查事件風暴模型檔，確認改動符合你們的討論
2. 已經答完的問題會被移到 .es-clarify/resolved/，不用管它，但不要刪掉（它會避免之後重複問同樣的問題）
3. 照 Github-使用指南.md 的步驟 commit 和 push

## 什麼時候要重跑 /es-discovery
- 你們新增或修改了流程與 Event
- 回答某一題時，答案推翻了前面的設定（這時候它會主動提醒你重跑）

## 常見狀況
- 它說找不到流程與 Event：代表檔案還沒放進專案，或還沒 commit，先確認檔案真的在資料夾裡
- 問題太多答不完：從 overview.md 裡標 High 的先答，Low 的可以之後再說
- 答案跟之前的矛盾：它會直接把矛盾點指出來，由你決定要留哪一個
