## 回歸任務流程
[Policy] 使用者久未訓練達門檻 → 指派限時回歸訓練  
[Rule] 「久未訓練達門檻」的門檻與能力值退步的 240 小時對齊，不另設獨立參數  
[Rule] 門檻的判定基準為任一肌群維度發生「能力值已退步」，即該維自最後一次訓練日的日界起滿 240 小時未訓練  
[決策] 門檻與 Precondition 對齊為同一條件：Precondition 已將觸發綁在「能力值已退步」上，另設 168 或 336 小時的門檻會使實際生效的永遠是較晚者，前者形同虛設  
[決策] 不採依每週健身天數動態計算的門檻：每週 1 次的使用者需 21 天才被召回，最需要挽回的對象反而被放最久  
[Rule] Precondition：訓練中斷流程的「能力值已退步」已發生，方可發生「回歸任務已指派」  
回歸任務已指派  
[Rule] Postcondition：寫入指派時戳；時限起算時戳留空  
[Rule] **Postcondition：對該使用者發送推播通知**（2026-08-20 新增），優先序為第 2 級行動引導類，見 02_Aggregate定義.md〈推播類清單與優先序〉  
[決策] 歸第 2 級而非第 1 級期限即將失效類：第 1 級的判準為「不處理就失去東西」，而本任務的時限自首次查看起算，未看見即不逾期、不失去任何東西；其用途為召回而非預防，與「連練中斷通知已發送」同型  
[決策] 不新增「回歸任務通知已發送」Event：推播寫為本 Event 的 Postcondition，比照待回應類（師徒申請、團隊邀請、加入申請）的既有處理 —— 本 Event 已是明確的觸發事實，另造一個 Event 等於把同一件事記兩次  
[Rule] Postcondition 之時限定義：時限長度為 7 天，自使用者首次登入查看時起算，非自指派時刻起算  
[Rule] Precondition（逾期判定）：時限起算時戳為空值者，逾期判定不啟動  
[決策] 採首次查看起算：指派條件為「能力值已退步」（已 240 小時未訓練），使用者當下多半不在使用 App；自指派時刻起算會使其回來時任務所剩無幾或早已逾期，等於懲罰想挽回的對象  
[Rule] 「距前一次指派滿 7 天方可再次指派」為指派頻率規則，與本完成時限無關，兩者並存  
[串聯] 使用者執行「查看回歸任務」導致「使用者已查看回歸任務」— Actor：使用者  
[Rule] Precondition：該筆回歸任務的狀態為已指派，且時限起算時戳為空值  
使用者已查看回歸任務  
[Rule] Postcondition：寫入時限起算時戳，逾期判定自此啟動  
[Rule] Precondition：本 Event 僅發生一次；時限起算時戳已有值者，再次查看不重複發生  
[決策] 首次查看建模為獨立 Event：時限起算時戳原本無任何 Command 可寫入，為模型中唯一的串聯斷點  
[決策] 不由 Read Model 的讀取寫入時戳：Read Model 已定案不改變任何狀態，破例將使該原則失去約束力  
[Rule] 「使用者已查看回歸任務」與「使用者已登入」為兩個不同 Event：登入不等於看見回歸任務  
[分支] 期限內完成 → 使用者已完成回歸任務；逾期未完成 → 回歸任務已逾期  
使用者已完成回歸任務  
[串聯] 使用者執行「領取回歸任務獎勵」導致「使用者已領取回歸任務獎勵」— Actor：使用者
使用者已領取回歸任務獎勵
[Rule] Precondition：「使用者已完成回歸任務」已發生，且該筆獎勵尚未領取
[Rule] 領取位置為回歸任務卡；不進獎勵信箱 —— 回歸任務已定案 7 天逾期即消失且不發放獎勵，維持原樣
回歸任務獎勵已發放  
能力值已部分回復 〔攜帶資訊：肌群維度〕  
[Rule] Postcondition：「使用者已完成回歸任務」發生後，回復先前退步之能力值的一部分，不回復至退步前水準  
[Rule] Postcondition：各肌群維度各自回復「本次中斷累積退步量」的 50%，回復後不超過退步前水準  
[Rule] Postcondition：回復不論該維是否於回歸任務中被訓練，六維各自獨立計算  
[Rule] Postcondition：使用者 Aggregate 須記錄「本次中斷各維累積退步量」，該維恢復訓練時歸零  
[決策] 回復幅度採累積退步量的 50%：停練越久退越多、補回越多，幅度與損耗掛鉤；固定點數或固定抵銷一次退步會使長期停練者的補償形同無感  
[決策] 回復不綁定回歸任務所訓練的維度：該維的訓練本身已產生「能力值已提升」，再對同一維度回復即重複計酬；真正需要補償的是未被回歸任務涵蓋、卻同樣退步的維度  
回歸任務已逾期  
[Rule] Postcondition：逾期後該筆回歸任務消失，不發放獎勵  
[Rule] Precondition：距前一次指派滿 7 天，方可再次指派回歸任務
[Rule] **指派次數上限：連續 3 次「回歸任務已逾期」後停止指派**（2026-08-21 定案），直到該使用者再次訓練為止
[Rule] 停止指派後，該使用者一旦產生任何一筆訓練紀錄，逾期連續計數歸零，指派機制重新啟動
[Rule] 逾期連續計數於「使用者已完成回歸任務」時歸零；逾期與完成交錯者不累計
[決策] 不採「本次中斷累積退步量 > 0 方可指派」：從未訓練者六維皆卡在退步下限、退步量恆為 0，該條會使其永遠收不到回歸任務——與 2026-08-20「兩個計時器初始值＝註冊日」所建立的召回路徑直接衝突
[決策] 不採無限指派：本 Event 已於 2026-08-20 定案為推播類第 2 級，無限指派即每 7 天推播一次且永不停止。已流失者的回歸邊際效益遞減得快，第 10 次叫得回來的人前 3 次多半也叫得回來；代價卻是使用者關閉通知或移除 App，**永久失去唯一的召回管道**
[決策] 不採「一人一筆、逾期後刷新同一筆」：其只改變 Aggregate 的筆數，推播頻率完全不變，對召回無差別
[決策] 上限訂為 3 次：三次指派落在中斷後第 10、17、24 日，涵蓋流失後最可能被召回的窗口；「再次訓練即重置」使長尾不被關死
[已知取捨] 從未訓練者收到的回歸任務，其「本次中斷各維累積退步量」恆為 0，完成後回復 0 點，推播文案「回復退步的能力值」對該群體不成立；是否另訂文案屬呈現層決策，不在本流程處理
