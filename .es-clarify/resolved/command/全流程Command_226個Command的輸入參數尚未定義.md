# 釐清問題

〈Command 清單〉已盤點 226 個 Command 並指派 Actor，但每個 Command 需要哪些輸入參數、各參數的型別與必填 / 選填皆未定義。應以何種方式補齊？

# 定位

流程：全部 29 條流程
元素：Command（全部 226 個）
細節：B3 Command 的輸入。`00_全域規範.md`〈Command 清單〉命名與盤點規範最後一條明載「Command 的輸入參數尚未逐一定義（待決策 Partial），由後續釐清項目補齊」。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 建立通用推導規則：Command 的輸入參數＝其導致的 Event 之專屬攜帶欄位 ＋ 目標 Aggregate ID ＋ 請求識別碼；僅對推導不出的 Command 逐一補問 |
| B | 僅為使用者主動觸發的 Command 定義輸入參數（系統 / 排程 / 外部系統的 Command 由上游資料推導），並逐一列表 |
| C | 226 個逐一定義，於〈Command 清單〉每張表增列「輸入參數」欄位 |
| D | 本階段不定義：輸入參數屬實作規劃階段，於事件風暴模型僅維持 Command 名稱與 Actor |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響〈Command 清單〉29 張表的結構、各 Command 的 Precondition 可驗收性（無輸入即無從檢核輸入有效性）、以及〈Event 冪等性原則〉所要求的請求識別碼在各 Command 中的攜帶方式。
本項為 `00_全域規範.md` 中明文標記的待決策，第三輪 formulation 未處理。

# 解決結果

**選項 A**

建立通用推導規則，不逐一列表：

> **Command 的輸入參數 ＝ 其導致的 Event 之專屬攜帶欄位 ＋ 目標 Aggregate ID ＋ 請求識別碼**

配套的 8 條細則：

1. Event 的共通 5 欄位為系統產生，不是 Command 的輸入
2. 各流程檔以〔攜帶資訊：…〕標註的專屬欄位即為輸入參數
3. 必填／選填沿用 Event 攜帶欄位的定義（「⋯ / 空值」為選填）
4. 型別、單位、合法範圍沿用該欄位在其 Aggregate 中的既有定義
5. 排程與外部系統觸發者，請求識別碼由自然鍵推導，不由呼叫方提供
6. 一 Command 兩結果者（現有 3 處）另含「判定結果」參數
7. 查詢類 Command 的輸入為其 Read Model 的篩選與分頁條件，不套用本規則
8. 規則不適用者逐一補問並列為例外；本輪盤點未發現例外

理由：模型已有現成材料可推導 —— 共通攜帶欄位已定義，多數 Event 已標註專屬攜帶資訊。
排除 C（逐一定義 228 個）：重複列過多，且事件風暴的顆粒度不要求到此層
（方法論檔明載 Command 對應 Vision 第四層 Feature，參數細節屬更下層）。
排除 D（不定義）：已有多條 Precondition 在檢核輸入（重量 ≥ 0、收件人姓名非空、庫存 ≥ 數量），
檢核對象若不存在於模型中，規則即無法驗收。
