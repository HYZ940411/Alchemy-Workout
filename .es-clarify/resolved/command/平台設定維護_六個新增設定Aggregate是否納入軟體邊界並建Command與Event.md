# 釐清問題

2026-08-20 新增的六個設定 Aggregate —— 教官初審設定、內容過濾設定、防作弊設定、通知設定、審核時限設定、補簽設定 —— 每一個都寫著「上述參數皆由管理員調整，非寫死於系統」，但六者一個都沒有維護 Command，也都沒有被放進〈平台級設定的軟體邊界〉的左欄或右欄。這六者的管理員維護，是否要建 Command 與 Event？

# 定位

流程：跨流程（管理員後台，不隸屬既有任一條流程）
元素：Command 與 Event（皆缺失）；Aggregate：教官初審設定（`02:3884`）、內容過濾設定（`02:4009`）、防作弊設定（`02:4032`）、通知設定（`02:4051`）、審核時限設定（`02:4070`）、補簽設定（`02:4091`）
細節：B1 Command 識別完整性、A4 軟體邊界判斷、E1 串聯一致性。既有的〈平台級設定的軟體邊界〉表（`01_Command清單.md`）左欄 4 項、右欄 7 項，均未涵蓋這 6 個新表。

# 多選題

| 選項 | 描述 |

| A（**推薦**） | **依既有判準逐一分流**：判準為「改動後是否改變使用者已取得或將取得的實質內容」。依此，**教官初審設定**（門檻一改，原本可申請教官的人就不能申請了）與**補簽設定**（回補範圍一縮，本來補得回來的日子就補不回來）納入左欄，各建 1 Command ＋ 1 Event；**內容過濾設定、防作弊設定、通知設定、審核時限設定**歸右欄（前二者調整不追溯既有內容與既有訓練紀錄且明文不對外揭露，後二者只影響推播則數與內部時限，不改變使用者拿到什麼）。理由：這正是模型 2026-08-04 已定案的同一條判準，只是六個新表建立時未被跑過一遍 |

# 解決結果

**選項 A** —— 依既有判準「該設定改動後，是否會改變使用者已取得或將取得的實質內容」逐一分流：
**左欄 2 個**（各建 1 Command ＋ 1 Event）、**右欄 4 個**（維持後台人工維護，不建模）。

| 歸左欄（納入軟體邊界） | 歸右欄（後台組態） |
|---------------------|------------------|
| 教官初審設定、補簽設定 | 內容過濾設定、防作弊設定、通知設定、審核時限設定 |

判準與理由：

- **教官初審設定歸左欄**：門檻調升的當下，原本符合資格、可以送出教官申請的使用者即刻不能申請
  —— 拿走的是使用者已經具備的資格。
- **補簽設定歸左欄**：回補範圍縮短的當下，原本補得回來的那幾個未簽到日即刻補不回來
  —— 拿走的是使用者已經握有的機會，且補簽券為付費可得之物。
- **內容過濾設定歸右欄**：該表已明文「門檻調整不追溯既有內容，已發布或已攔截者不改判」。
- **防作弊設定歸右欄**：明文不追溯既有訓練紀錄，且明訂「本表的參數值不對使用者揭露」
  —— 使用者看不到的東西，談不上被拿走。
- **通知設定歸右欄**：改動只影響收到幾則推播、幾點收到，不改變使用者取得的實質內容。
- **審核時限設定歸右欄**：時限為管理員端的內部工作期限，逾期依既有裁決僅產生「審核已逾期」、
  **不改變案件狀態**，對使用者的處理結果零影響。
- 不採 B（全數納入）：右欄四者各補一個 Event 為對稱性膨脹，該四個 Event 沒有任何讀者。
- 不採 C（全數排除）：教官初審設定與補簽設定的調整會當場改變使用者的資格與機會，
  排除後該兩處無任何可稽核的依據。
- 不採 D（單一泛用 Command）：與本節既有裁決直接衝突 —— 其攜帶值域為任意設定的任意變更，
  Precondition 與 Postcondition 皆寫不出來，為不可驗收的 Event。

**併同第 2 題，2026-08-20 新增的七個設定 Aggregate 分流完畢：左欄 3（能力值設定、教官初審設定、
補簽設定）、右欄 4。〈平台級設定的軟體邊界〉表恢復為完整清單。**
