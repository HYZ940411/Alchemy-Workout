# 釐清問題

第四輪新增的「領取」機制（使用者已領取每日任務獎勵 → 每日任務獎勵已發放；未領取者補發至獎勵信箱）目前僅適用每日任務。是否及於其餘 14 個獎勵來源（訓練、簽到、註冊、新手任務、回歸任務、分享 / 發文 / 按讚 / 留言、師徒任務、限時任務、三種排行獎勵）與成就獎勵？

# 定位

流程：每日任務流程（現況）、訓練結算流程、每日簽到流程、發文與互動流程、師徒互動流程、團隊任務流程、排行榜週期結算流程
元素：Command「領取⋯獎勵」（是否新增）；Event（是否新增「使用者已領取⋯獎勵」）
細節：B1 Command 識別完整性、A1 事件識別完整性。00_全域規範〈獎勵信箱 Aggregate〉之 `[待決策 Partial]`：「領取機制是否及於每日任務以外的獎勵來源（訓練、簽到、成就、排行），尚未定案」。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 僅每日任務保留領取機制，其餘 14 個來源維持自動發放。理由：領取的價值在於「每日回訪」，一次性與被動獎勵無此需求 |
| B | 擴及「使用者主動完成的任務類」（每日任務、新手任務、回歸任務、師徒任務、限時任務），其餘維持自動發放 |
| C | 擴及全部 15 個來源與成就獎勵：一律先進獎勵信箱，由使用者統一領取；15 個「⋯獎勵已發放」Event 的觸發者一律改為「使用者已領取信箱獎勵」 |
| D | 擴及「離線期間產生者」（排行獎勵、成就、補發類），因使用者當下不在 App，直接入帳無回饋感；即時互動類（按讚、留言、訓練結算）維持自動發放 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響〈Command 清單〉（可能增列多條領取類 Command）、Event 總數、獎勵信箱 Aggregate 的「來源」欄位值域（現為單值「每日任務」）、各獎勵 Event 的冪等去重鍵，以及〈Read Model：獎勵信箱頁〉的範圍。
相關已解決項目：`resolved/rule/每日任務已重置_重置時已完成未領取的獎勵如何處理.md`（建立本機制）。
相依：`aggregate/成就獎勵_發放路徑與數額尚未建模.md`（成就獎勵是否比照領取機制）；`aggregate/獎勵信箱_信箱獎勵的有效期限與容量上限.md`。

# 優先級

High

# 解決結果

**使用者逐項裁決**（助理依遊戲化常見做法提出 16 項提案，使用者確認 15 項、
一度提議將訓練獎勵改為點擊領取後又改回直接發放）。

**判準**：有明確完成里程碑且已有清單頁可承載領取按鈕者 → 點擊領取；
行為當下已有結算畫面完成回饋、或屬高頻微額者 → 直接發放。

| 點擊領取（9） | 直接發放（7） |
|--------------|--------------|
| 新手任務獎勵（新手任務清單頁） | 註冊獎勵 |
| 每日任務獎勵（每日任務清單頁，既有） | 簽到獎勵 |
| 回歸任務獎勵（回歸任務卡） | 訓練獎勵 |
| 師徒任務獎勵（我的師徒頁） | 分享獎勵 |
| 限時任務獎勵（我的團隊頁） | 發文獎勵 |
| 個人排行獎勵（獎勵信箱） | 按讚獎勵 |
| 團隊日常排行獎勵（獎勵信箱） | 留言獎勵 |
| 團隊限時排行獎勵（獎勵信箱） | |
| 成就獎勵（成就頁） | |

**訓練獎勵維持直接發放的理由**（使用者一度提議改為領取制後撤回）：
訓練結算畫面已完整呈現獎勵，該畫面即為回饋時刻；且訓練獎勵另有每日發放上限與
完成度補發差額的規則，改為領取制須為差額另訂一套領取規則與信箱補發時點。

**獎勵信箱的角色收斂為兩條路徑**：
重置補發（每日任務，既有）與直接寫入（三個排行獎勵，本題新增）。
排行獎勵採直接寫入而非兩段式：其產生於週期結算當下使用者不在 App，
模型中亦無其他頁面可承載該筆待領獎勵，信箱本身即為待領清單。

**五個點擊領取來源不進信箱**（新手任務、回歸任務、師徒任務、限時任務、成就）：
其承載頁不會週期性重置，未領取者一直掛在該頁。回歸任務為例外，
維持既有的「7 天逾期即消失且不發放獎勵」。

**成就獎勵**：發放方式定案為點擊領取（成就頁），但「成就獎勵已發放」與
「使用者已領取成就獎勵」兩個 Event 的建立與數額，仍屬
`aggregate/成就獎勵_發放路徑與數額尚未建模.md`（已延後）的範圍，本題不建立。
