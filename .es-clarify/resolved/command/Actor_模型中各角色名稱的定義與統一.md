# 釐清問題

模型中出現使用者、發文者、互動者、學徒、教官、管理員、成員、對方等多種角色稱呼，這些是不同 Actor 還是同一 Actor 的不同情境？應如何建立統一的 Actor 清單？

# 定位

流程：全流程
元素：Actor：使用者、發文者、互動者、學徒、教官、管理員、成員、對方（全模型皆未正式定義）
細節：Actor 識別（B4）；同義詞混用（F2）；統一語言（F1）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 僅有三種 Actor：使用者 / 管理員 / 系統；發文者、互動者、學徒、教官、成員皆為使用者在特定情境下的稱呼，應統一為「使用者」 |
| B | Actor 為：使用者 / 教官 / 管理員 / 系統（排程）/ AI / 外部系統；教官因具備額外權限而獨立 |
| C | 同 B，另加「團隊隊長」為獨立 Actor |
| D | 保留所有現有稱呼作為獨立 Actor，各自定義權限 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響全模型每個 Command 的 Actor 指派、權限規則定義（誰可以、誰不可以）、統一語言詞彙表，以及「Actor 執行 Command 導致 Event」串聯句的建立。這是 Command 層的根本問題。

# 優先級

High

# 解決結果

A′（經矛盾裁決後修正） — Actor 清單為四種：使用者 / 管理員 / 系統 / 外部系統。

發文者、互動者、學徒、教官、成員、對方皆非獨立 Actor，一律統一為「使用者」；
教官與團隊隊長的權限差異以身分旗標 / 團隊角色欄位表達，不獨立為 Actor。

# 矛盾裁決紀錄

初次回答為 A（僅使用者 / 管理員 / 系統三種），與既有共識
`resolved/event/使用者帳號已建立_帳號建立前是否需要身分驗證Event.md`（選項 D，
「第三方帳號授權已完成」來源標示為外部系統）牴觸，且與 `00_全域規範.md`
「每個 Event 必須攜帶觸發 Actor」規則衝突（3 處外部系統標記將無 Actor 可指派）。

經提示後使用者裁決 A′：**保留 A 的核心主張，另補上「外部系統」為第四種 Actor**。
既有 resolved 檔案不需變動。
