# 釐清問題

「使用者已選擇每週健身天數」與「使用者已選擇每次健身時長」的值域、型別與單位為何？

# 定位

流程：註冊流程
元素：Command「選擇每週健身天數」「選擇每次健身時長」的輸入；Aggregate「使用者」的健身偏好欄位
細節：Command 輸入參數（B3）；欄位定義（D2）；數值邊界（C3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 每週天數為 int 1–7（必填）；每次時長為列舉：30 分鐘以下 / 30–60 分鐘 / 60–90 分鐘 / 90 分鐘以上 |
| B | 每週天數為 int 1–7；每次時長為 int，單位分鐘，範圍 10–240 |
| C | 兩者皆為列舉區間（每週天數：1–2 / 3–4 / 5 天以上；時長同 A） |
| D | 兩者皆為選填，未填時以平台預設值（每週 3 天、每次 60 分鐘）代入推薦比對 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響使用者 Aggregate 的健身偏好欄位型別、註冊 9 項必填的驗收條件、以及推薦 Policy 的比對輸入。
本項為新掃描發現，非承接 `pending-gaps.md`。

# 優先級

Medium

# 解決結果

**選項 A**：每週天數為 int 1–7（必填）；每次時長為區間列舉（必填）。

| 欄位 | 型別 | 單位 | 值域 |
|------|------|------|------|
| 每週健身天數 | int | 天 | 1–7 |
| 每次健身時長 | 列舉 | — | 30 分鐘以下 / 30–60 分鐘 / 60–90 分鐘 / 90 分鐘以上 |

- 兩欄位性質不同故型別不同：天數為使用者答得出的離散小整數，用 int 保留完整資訊；
  時長為使用者無法精確估計者，用區間列舉誠實建模，避免取得取整後的假精確值。
- 兩者皆為註冊 9 項必填之一，不設預設值（不採選項 D，避免推翻既有的「9 項全數填畢」Precondition）。
