# 釐清問題

使用者完成新手任務、以及完成平台提供的訓練計畫後，可對該體驗評分供平台後續優化。此評分如何建模：評分對象是什麼、掛在哪一個時點、是否為獨立 Event 與 Aggregate、評分尺度為何？

# 定位

流程：新手任務流程、訓練結算流程
元素：Event（尚未存在）；Command（尚未存在）；Aggregate（尚未存在）
細節：A1 事件識別完整性、D1 Aggregate 識別、B1 Command 識別。

**使用者已表態的需求**（2026-08-01，第四輪第 6 題）：

> 使用者結束新手任務跟完成我們提供的訓練後，可以有評分，供我們後續優化，管理員可見。

現況：模型已有兩套評分機制可比照 —— 學徒對師徒問答評分、學徒對師徒任務評分，
兩者皆為 1–5 星、寫入各自 Aggregate 的「學徒評分」欄位、並連動「教官聲望已變動」。
但兩者評分的是**人**（教官），本項評分的是**平台提供的內容**（新手任務體驗、訓練計畫），
無對應的既有結構可直接沿用。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 單一 Event「使用者已評分訓練體驗」，攜帶評分對象類型（新手任務 / 訓練計畫）與對象 ID；比照「使用者已支付」單一 Event 涵蓋兩條流程的既有處理方式 |
| B | 拆為兩個 Event：「使用者已評分新手任務」（新手任務流程）與「使用者已評分訓練計畫」（訓練結算流程）；比照 7 個成就 Event 各自獨立的既有裁決 |
| C | 同 A 的單一 Event，但評分對象擴及全部三種課表來源（訓練計畫 / 自訂訓練 / 公開課表），不限平台提供的訓練 |
| D | 不建模為 Event：評分為產品研究用途、不改變任何業務狀態，留在系統邊界之外，以外部問卷工具蒐集 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響新手任務流程與訓練結算流程的 Event 清單、〈Command 清單〉、〈獨立 Aggregate 清單〉是否新增
「體驗評分」Aggregate，以及管理員檢視評分的 Read Model（使用者已明確要求「管理員可見」，
該 Read Model 為本項目的下游，見 `read-model/管理員評分彙總_管理員如何檢視訓練體驗評分.md`）。

若採選項 C，另影響自訂訓練 Aggregate（公開課表被評分後，評分是否對其作者可見、
是否影響公開課表的排序與推薦）。

本項目**不涵蓋**下列子決策，留待本題定案後再拆：評分尺度（星等 / 分數）、是否含文字回饋、
必填或可跳過、同一對象可否重複評分或修改評分、評分是否影響訓練計畫的推薦優先序。

相關已解決項目：`resolved/aggregate/教官已指派師徒任務_師徒任務與問答的Aggregate歸屬與欄位.md`
（兩套既有評分機制的結構）、`resolved/aggregate/訓練計畫_訓練計畫與自訂訓練的動作與組數結構為何.md`。

# 解決結果

**選項 A**

單一 Event「使用者已評分訓練體驗」，攜帶**評分對象類型（新手任務 / 訓練計畫）與對象 ID**，
為跨流程同名 Event，出現於新手任務流程與訓練結算流程。
對應 Command「評分訓練體驗」（Actor：使用者，多對一）。

**Precondition**
- 新手任務流程：「使用者已完成新手任務」已發生
- 訓練結算流程：「訓練已結算」已發生，且本次訓練課表的**來源類型為訓練計畫**
  （自訂訓練與空白課表不觸發，因評分對象為平台提供的內容）

理由：兩種評分的業務意義、後續用途、資料結構完全相同，比照「使用者已支付」單一 Event
涵蓋兩條流程的既有處理方式。
排除 B：7 個成就 Event 各自獨立是因各有不同門檻參數、不同獎勵、不同掛載時點，評分無這些差異。
排除 C：對他人做的公開課表評分會由「產品回饋」變為「使用者互評」，另生一整套新問題，超出原始需求。
排除 D：外部問卷工具無法與訓練計畫 ID 關聯，管理員看得到分數卻對不上是哪一份課表。
