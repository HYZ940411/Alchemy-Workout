# 釐清問題

「使用者已選擇訓練課表」同時出現於訓練紀錄流程與 AI 訓練前調整流程，兩處是否為同一個事實？若是，是否應納入〈跨流程同名 Event〉表並定義其攜帶的來源資訊？

# 定位

流程：訓練紀錄流程、AI 訓練前調整流程
元素：Event「使用者已選擇訓練課表」
細節：A2 事件命名與語意；`00_全域規範.md`〈跨流程同名 Event〉表未收錄本 Event，但〈Command 清單〉已於兩條流程各列一次「選擇訓練課表」並標註「多對一」。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 為同一事實，納入〈跨流程同名 Event〉表，攜帶「後續路徑＝直接開始訓練 / 進入 AI 訓練前調整」以區分來源 |
| B | 為同一事實，且 AI 訓練前調整流程的該 Event 僅為前置條件的引述，自該流程檔移除，不重複列出 |
| C | 為兩個不同事實：AI 流程的選擇帶有「打算調整」的意圖，應改名以區別（如「使用者已選擇待調整訓練課表」） |
| D | 維持現狀兩處各列一次，不納入同名表，於兩流程檔互相註記 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響〈跨流程同名 Event〉表、〈Command 清單〉中兩條「選擇訓練課表」的合併與否、以及「本次訓練課表快照於選擇課表時產生」此一 Postcondition 的歸屬流程。
相關已解決項目：`resolved/event/使用者已拒絕調整_三條AI流程的同名Event是否為同一事實.md`（本項目為其選項 A 未涵蓋的遺留）、`resolved/aggregate/訓練課表_本次訓練課表是否為獨立Aggregate與其快照機制.md`。
來源：`pending-gaps-2.md` H1。

# 解決結果

**選項 B**

兩處為同一事實，且 AI 訓練前調整流程的該行僅為前置條件的引述，
自該流程檔改寫為 Precondition，不重複列為 Event，亦**不納入**〈跨流程同名 Event〉表。

理由：與表中既有 10 個 Event 的關鍵差異在於，那些 Event 在各流程中真的會各自發生一次，
故需攜帶來源值區分；而「使用者已選擇訓練課表」在一次訓練中只發生一次 ——
使用者選了課表，接著才決定要不要找 AI 調整。

排除選項 A 的具體理由：使用者選課表的當下，系統無從得知他接下來要不要調整，
「後續路徑」這個攜帶欄位於 Event 發生時根本填不出來。
排除選項 C：第三輪已定案快照於「使用者已選擇訓練課表」時產生，理由為「AI 訓練前調整改的即為此快照」；
拆為兩個 Event 會使快照的產生時點重新成為問題。
