# 釐清問題

「使用者已支付」同時出現在實體商品購買流程與虛擬商品購買流程，兩者是否為同一個事實？

# 定位

流程：實體商品購買流程、虛擬商品購買流程
元素：Event「使用者已支付」
細節：事件命名與語意（A2）；Event → Aggregate 一致性（E3）；跨流程同名 Event 的定義歸屬。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 同一事實，比照經驗值 / 能力值原則以攜帶資訊區分（商品類型、支付管道），納入 `00_全域規範.md` 的跨流程同名 Event 表 |
| B | 兩個不同事實：實體為第三方金流回呼、虛擬為 App Store 應用內購買，外部系統不同，應拆為兩個 Event 分別命名 |
| C | 同一事實但改名為更中性的名稱（如「訂單付款已完成」），兩流程共用 |
| D | 維持現狀不表態，待金流實作階段再決定 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響訂單 Aggregate 兩個狀態子集的觸發 Event 定義、Actor 指派（外部系統為第三方金流或 App Store）、
以及 `00_全域規範.md` 跨流程同名 Event 表是否新增一列。
承接 G2。**判斷前提**：實體商品支付已定為第三方金流（信用卡 / 行動支付，回呼觸發）；虛擬商品的真實金流與會員訂閱同屬 App Store 體系，兩者外部系統不同。
相關已解決項目：`resolved/command/使用者已支付_支付由哪個外部金流系統執行.md`、`resolved/event/經驗值已提升_多條流程中的同名Event是否為同一事實.md`。

# 優先級

High

# 解決結果

**選項 A**：同一事實，以攜帶資訊（商品類型、支付管道）區分，納入 `00_全域規範.md` 的跨流程同名 Event 表。

- 商品類型值域為二值：實體 / 虛擬。
- 支付管道值域為二值：第三方金流 / App Store。
- 實體商品的支付管道為第三方金流（信用卡 / 行動支付，回呼觸發）；虛擬商品的真實金流為 App Store。
- Actor 一律為外部系統，兩種支付管道僅為提供者差異，不改變 Actor。
- 與訂單為單一 Aggregate（以類型欄位區分狀態子集）的設計對稱，Event 不隨之拆分。

# 回寫位置

- `Event-Storming_事件風暴/00_全域規範.md`〈跨流程同名 Event〉：表格新增 1 列、規則新增 6 條
- `Event-Storming_事件風暴/實體商品購買流程.md`：「使用者已支付」加註〔攜帶資訊：商品類型＝實體、支付管道＝第三方金流〕
- `Event-Storming_事件風暴/虛擬商品購買流程.md`：「使用者已支付」加註〔攜帶資訊：商品類型＝虛擬、支付管道＝App Store〕
