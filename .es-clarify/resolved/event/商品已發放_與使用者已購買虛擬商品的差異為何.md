# 釐清問題

「使用者已購買虛擬商品」與「商品已發放」兩個 Event 的差異為何？發放是否可能延遲或失敗？

# 定位

流程：虛擬商品購買流程
元素：Event：使用者已購買虛擬商品、商品已發放
細節：兩個 Event 是否指涉同一事實（A2）；Event 因果順序（A3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 購買是交易成立、發放是道具入庫，兩者為不同事實且發放可能非同步 |
| B | 兩者為同一事實，應合併為單一 Event「使用者已購買虛擬商品」 |
| C | 兩者為不同事實且需補上「商品發放已失敗」與退款 Event |
| D | 購買為交易成立、發放為使用者主動領取，需區分 Actor |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響虛擬商品購買流程的 Event 數量、訂單與道具庫存 Aggregate 的一致性保證（E2 跨 Aggregate）、以及發放失敗時的補償機制。

# 優先級

Medium

# 解決結果

A — 「使用者已購買虛擬商品」為交易成立、「商品已發放」為道具入庫，兩者為不同事實，不合併。
發放可為非同步，不保證與交易成立在同一時點。未採 C，不補「商品發放已失敗」與退款 Event。

# 連帶影響

發放非同步且無失敗 Event，代表「已扣款但發放失敗」的情境目前無對應路徑，
既有「購買已失敗」的失敗原因（餘額不足 / 商品售完 / 其他）亦未涵蓋此情境。
記錄於 `.es-clarify/pending-gaps.md` G11。
