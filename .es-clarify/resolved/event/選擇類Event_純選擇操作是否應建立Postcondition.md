# 釐清問題

「使用者在畫面上選了東西」這類 Event（選擇商品、選擇數量、選擇動作等），是否應建立 Postcondition？

# 定位

流程：實體商品購買流程、虛擬商品購買流程、自訂訓練流程、新手任務流程（跨流程）。
元素：Event 的 Postcondition（檢查項 C2）。
細節：這些 Event 發生的當下**尚無任何 Aggregate 狀態被改變** —— 訂單未成立、
課表未儲存，使用者可隨時離開而不留下任何狀態。

發現方式：使用者表示將以本模型撰寫 Gherkin，掃描「哪些 Event 寫不出 Then（無斷言）」時查出。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 統一加一條通則「選擇類 Event 不建立 Postcondition，其效果由後續的確認類 Event 承接」 |
| B | 每一個都補上 Postcondition，寫成「暫存區記錄了使用者的選擇」 |
| C | 將這些 Event 移除，因其無狀態改變、不算業務事實 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

- 8 個 Event 的 Postcondition 定義；不影響其 Precondition。
- Gherkin 轉譯：這 8 個在 Gherkin 中只能記錄「發生過」，測不到實質效果。
- 與〈新手任務流程〉「選擇候選動作」的既有建模裁決直接相關。

# 優先級

Medium

---

# 解決結果

**選項 A**：統一通則「**選擇類 Event 不建立 Postcondition**」，涵蓋 8 個 Event。

- 判準：**該 Event 發生的當下，是否已有任何 Aggregate 狀態被改變。**
- 效果由後續的確認類 Event 承接（確認購買 / 儲存自訂訓練 / 完成單項新手任務）。
- **仍為業務 Event，不得移除**：承〈新手任務流程〉既有裁決「不建模會使漏斗分析出現斷點」。
- **仍可有 Precondition**（如「所選規格的庫存 ≥ 所選數量」）——
  Precondition 與 Postcondition 兩者互相獨立。
- 不採 B（建暫存 Aggregate）：該資料於使用者離開頁面後即無用途。
- 與〈〔不需精準追蹤〕Event〉為兩件事：後者不做嚴格規則驗收，
  本節的 Event **仍受 Precondition 驗收**，只是沒有後置狀態。
