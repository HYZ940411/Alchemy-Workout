# 釐清問題

註冊後從未進行過任何一次訓練的使用者，模型中是否應有召回機制？（現行四道中斷門檻與回歸任務對其**全部不會觸發**。）

# 定位

流程：訓練中斷流程、回歸任務流程、新手任務流程、每日簽到流程（跨流程）。
元素：Event（缺失的召回路徑）／ Aggregate：連續訓練（「上次訓練日期」）。
細節（推導鏈，逐條皆可在模型中查得）：

1. `訓練中斷流程.md:3-4`：24 / 36 / 96 / 240 小時四個門檻的**計時起點一律為「上次訓練日的日界」**，
   計時基準取自連續訓練 Aggregate 的「上次訓練日期」欄位。
2. `02_Aggregate定義.md:2034-2040`：該欄位型別為 date，說明僅「使用者當地日期，作為中斷判定的計時基準」，
   **未定義從未訓練者的初始值或空值語意**。
3. 從未訓練者該欄位無值 → 四個門檻皆無起算點 →
   「中斷預告已發送」「連續訓練天數已歸零」「退步預告已發送」「能力值已退步」**四者皆不發生**。
4. `回歸任務流程.md:7`：Precondition 為「能力值已退步」已發生 → **回歸任務永不指派**。
5. `新手任務流程.md:44` 已明文承認此事：「不採『逾期後自動轉為回歸任務』…
   **從未訓練的新手不在其適用範圍**」—— 但當時只裁決了「不轉為回歸任務」，
   **未裁決改由什麼承接**。
6. `新手任務流程.md:41`：新手任務無完成期限、永久有效 → 亦無逾期 Event 可作為觸發源。
7. 訓練提醒：`02_Aggregate定義.md:302-305` —— 偏好訓練時段可跳過，跳過者
   「**完全不發送訓練提醒**」直到累積最近 4 週 ≥ 6 筆訓練紀錄；從未訓練者永遠達不到門檻。
   該處已標記 `[已知代價]`「訓練提醒為模型少數能介入 D7 流失窗口的機制之一」。

**淨結果**：跳過偏好時段且從未訓練者，模型對其發出的唯一訊息是
每日 20:00 的「每日登入提醒」（Precondition 僅為「當日尚未簽到」），且其優先序為最低的第 3 級。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 「上次訓練日期」於註冊時以註冊日填入，使四道既有門檻與回歸任務對從未訓練者照常運作，不新增任何 Event |
| B | 新增一條專屬的新手召回路徑（如 Event「新手引導提醒已發送」），觸發條件為「已完成註冊、距註冊滿 N 日、累積訓練次數為 0」，與既有的中斷門檻分開 |
| C | 為新手任務補上完成期限與逾期 Event，以「新手任務已逾期」作為召回的觸發源 |
| D | 明示接受此缺口，維持現狀（僅每日登入提醒），並比照 `每日簽到流程.md:59` 的既有寫法標記為「明示接受的留存缺口，非待辦」 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

- **Event 清單**：選 B 或 C 將新增 1–2 個 Event 與對應 Command；選 A 不新增 Event，但會使「能力值已退步」在從未訓練者身上發生，連帶影響能力值下限與回歸任務的指派量。
- **連續訓練 Aggregate**：「上次訓練日期」的初始值與空值語意必須在四個選項下都被定義（見 `aggregate/連續訓練_上次訓練日期的初始值與空值語意未定義.md`，兩題須一併裁決）。
- **通知類 Event 的發送規則**：選 B 會在推播類清單（現 10 項）新增一項，須指派優先序，並受同日總量上限 3 則／日約束（`02_Aggregate定義.md:1108`）。
- **能力值**：選 A 使從未訓練者的六維自初始值 10 起退步，但 10 同時為退步下限，實際無變化；惟「能力值已退步」Event 會照常產生，影響回歸任務的指派母體。
- 相關已解決項目：`.es-clarify/resolved/rule/能力值已退步_自建動作與有氧動作是否重置該維的240小時計時.md`（同一計時器的既有裁決）。

# 解決結果

**選項 A**：「上次訓練日期」於註冊時填入註冊日，四道既有中斷門檻與回歸任務對從未訓練者照常運作，**不新增任何 Event、Command 或通知**。

- 連續訓練 Aggregate 的「上次訓練日期」**不允許空值**，初始值＝註冊日（使用者當地日期），
  於「使用者帳號已建立」時一併產生。
- 能力值 Aggregate 的「各維最後訓練日」六維**同採註冊日**為初始值，兩個計時器同時起算。
- 從未訓練者的召回路徑因此成立：註冊日 +24 小時中斷預告 → +96 小時退步預告 →
  +240 小時能力值退步 → 回歸任務指派。
- `[已知取捨]` 第 10 日的「能力值已退步」因六維初始值 10 即為退步下限，
  **點數實際不變**，等同產生一個無狀態改變的 Event；
  承既有判例「使用者已失去獎勵加成」之「可推導不等於不成立為 Event」，明示接受。
- 未採 B（新建新手專屬召回路徑）：須新增 Event 與 Command、另訂觸發天數、
  擠入推播優先序並與同日總量上限 3 則／日競爭，所做的事與既有四道門檻高度重疊。
- 未採 C（新手任務補上完成期限）：與既有裁決「新手任務無完成期限」直接衝突。
- 未採 D（明示接受）：既有兩處已接受的缺口皆為老使用者的長線問題，本處為新使用者且完全零介入。
