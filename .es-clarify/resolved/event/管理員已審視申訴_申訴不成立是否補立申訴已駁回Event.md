# 釐清問題

「管理員已審視申訴」的不成立分支目前無對應 Event，而同一條流程的「管理員已審視檢舉」不成立分支有「檢舉已駁回」Event。是否補立「申訴已駁回」以維持兩條審視路徑的建模顆粒度一致？

# 定位

流程：管理員管理社群流程
元素：Event「管理員已審視申訴」的分支
細節：A1 事件識別完整性、C5 失敗與例外路徑。流程檔第 36 行「[分支] 申訴成立 → 處罰已撤銷；申訴不成立 → 維持原處罰」，第 39 行「[決策] 申訴不成立不另立 Event，維持原處罰」。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 補立「申訴已駁回」Event，與「檢舉已駁回」對稱；使用者可得知申訴結果，且申訴次數可計 |
| B | 不補立，於流程檔明確標記為刻意的不對稱，並寫明理由（申訴不成立不改變任何狀態，故非業務事實） |
| C | 兩條路徑一併簡化：移除「檢舉已駁回」，改以檢舉 Aggregate 的狀態欄位表達，兩條審視路徑皆只保留成立分支 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響管理員管理社群流程的 Event 清單、〈Command 清單〉是否新增「駁回申訴」、申訴 Aggregate 的狀態機終止狀態，以及同一處罰可否重複申訴的判定依據。
相依：須先釐清 `aggregate/申訴_申訴是否為獨立Aggregate及其欄位與狀態機.md`。
相關已解決項目：`resolved/event/使用者已受處罰_申訴與解除處罰的Event缺失.md`（本項目為其選項 A 未涵蓋的遺留）。

# 解決結果

**選項 A** —— 補立「申訴已駁回」Event，與「檢舉已駁回」對稱。為終止狀態；Postcondition 為原處罰維持不變、累計違規次數不變。原「申訴不成立不另立 Event」之決策已刪除。
