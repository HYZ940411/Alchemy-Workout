# 釐清問題

金幣的取得來源已含「儲值」，但全模型無任何儲值流程或 Event。付費取得金幣的路徑是否納入軟體邊界？

# 定位

流程：全模型（虛擬商品購買流程之上游）
元素：Aggregate「虛擬貨幣（金幣）」的取得來源；Event（尚未存在）
細節：事件識別完整性 — 隱含未寫出的 Event（A1）；軟體邊界判斷（A4）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 新增「金幣儲值流程」，走 App Store 應用內購買（數位內容，Apple 強制要求），含「使用者已儲值金幣」與「儲值已失敗」兩個 Event |
| B | 新增儲值流程同 A，但僅建「使用者已儲值金幣」單一 Event，失敗路徑留在外部系統 |
| C | 本階段不做付費儲值，金幣僅由獎勵發放取得；同步修正虛擬貨幣 Aggregate 的取得來源描述，移除「儲值」 |
| D | 金幣可由既有的虛擬商品購買流程反向取得（購買「金幣包」商品），不另立流程 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響虛擬貨幣 Aggregate 的取得來源規則、儲值面額與贈送規則、以及「餘額不足」情境下的補救路徑。
承接 G23；與 `aggregate/虛擬貨幣_金幣對法幣的補差額比率為何.md`（G3）為同一組決策，宜併題處理。
相關已解決項目：`resolved/aggregate/虛擬貨幣_虛擬貨幣的種類取得與消耗規則.md`（選項 A）。

# 優先級

High

# 解決結果

**選項 A**：新增「金幣儲值流程」，走 App Store 應用內購買（數位內容，Apple 強制要求），含「使用者已儲值金幣」與「儲值已失敗」兩個 Event。

- 付費取得金幣的路徑納入軟體邊界，不留在系統邊界之外。
- Actor 為外部系統（App Store 通知觸發），與虛擬商品的真實金流同屬一體系。
- 「使用者已儲值金幣」的 Postcondition：金幣餘額增加所取得的金幣數量。
- 「儲值已失敗」的 Postcondition：金幣餘額不變。
- 失敗路徑與模型既有慣例一致（實體流程「支付已失敗」、虛擬流程「購買已失敗」）。
- 儲值面額與贈送規則未給定，記為待決策 Partial，須待金幣對法幣的比率定案。
