# 釐清問題

註冊流程中「使用者已填入身高 / 體重 / 性別 / 年齡 / 健身目標」與「使用者已選擇健身經驗 / 每週健身天數 / 每次健身時長 / 健身器材」共十個逐欄位 Event，是否每一個都值得個別建模為 Event，或應合併為單一「使用者已完成個人資料填寫」Event？

# 定位

流程：註冊流程
元素：Event：使用者已填入身高、使用者已填入體重、使用者已填入性別、使用者已填入年齡、使用者已填入健身目標、使用者已選擇健身經驗、使用者已選擇每週健身天數、使用者已選擇每次健身時長、使用者已選擇健身器材
細節：軟體邊界判斷（A4）與事件顆粒度（A1）：這十個 Event 目前看起來接近「畫面操作」而非業務事實。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 維持十個獨立 Event，每一欄位的填寫都是可追蹤的業務事實（可分析漏斗流失率） |
| B | 合併為單一 Event「使用者已完成個人資料填寫」，欄位內容為該 Event 攜帶的資訊 |
| C | 分為兩個 Event：「使用者已填寫身體數據」（身高/體重/性別/年齡）與「使用者已填寫訓練偏好」（目標/經驗/天數/時長/器材） |
| D | 保留為畫面操作，不列入 Event，僅保留「使用者已完成註冊」 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響註冊流程 Event 清單長度、使用者 Aggregate 的欄位寫入時機、以及是否需要為每個欄位定義獨立 Command 與 Precondition。若選 B 或 C，將連帶影響「使用者已完成註冊」的 Precondition 定義。

# 優先級

High

# 解決結果

A — 維持 9 個獨立 Event，每一欄位的填寫都是可追蹤的業務事實，供註冊漏斗流失率分析。不合併、不降級為畫面操作。
