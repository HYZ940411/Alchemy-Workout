# 釐清問題

每日任務流程有「每日任務進度已更新」Event，新手任務流程卻無對應的進度 Event。新手任務的逐項完成是否應建模為 Event？

# 定位

流程：新手任務流程
元素：Event「使用者已開始新手任務」與「使用者已完成新手任務」之間的缺口
細節：事件識別完整性（A1）；軟體邊界判斷（A4）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 補「新手任務進度已更新」Event，與每日任務流程對稱 |
| B | 不補 Event，新手任務進度僅為 Aggregate 欄位變動，不視為有業務意義的事實 |
| C | 補「使用者已完成單項新手任務」Event（顆粒度為單項任務，非進度百分比） |
| D | 不補 Event，並同步移除每日任務流程的「每日任務進度已更新」，兩者一致不建模 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響新手任務 Aggregate 的進度欄位是否需 Event 承接、「使用者已完成新手任務」的 Precondition 判定來源、
以及新手任務 Read Model 的資料更新時機。
本項為新掃描發現，非承接 `pending-gaps.md`。

# 優先級

Medium

# 解決結果

**選項 C**：補「使用者已完成單項新手任務」Event，顆粒度為單項任務，非進度百分比。

- 攜帶資訊：任務項目 ID。
- Precondition：「使用者已開始新手任務」已發生。
- 請求識別碼為 使用者 ID ＋ 任務項目 ID，同一項目只能完成一次（新手任務全平台僅一組範本，天然一次性）。
- 「使用者已完成新手任務」新增 Precondition：全部單項皆已完成 —— 補上原先缺失的完成判定基準。
- 不建模「新手任務進度已更新」：進度為衍生值，由逐項完成推導。
- 理由：比照註冊流程 9 個逐欄位 Event 的裁決（供漏斗流失率分析）。新手任務為新用戶引導漏斗，且一輩子只發生一次，事件量極小。
- 不採 A / D 的對稱性論證：「每日任務進度已更新」獨立成立是因其連帶觸發「個人排行榜分數已增加」，新手任務進度無連帶後果，不對稱有其理由。
