# 釐清問題

App Store 自動續約扣款失敗後進入寬限期，本系統是否建模對應 Event？寬限期內會員權益維持或暫停？

# 定位

流程：會員訂閱流程
元素：Event「會員訂閱已續訂」與「會員權益已失效」之間的缺口
細節：軟體邊界判斷（A4）；狀態邊界（C3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 維持不建模，於 `會員訂閱流程.md` 明確標記「扣款失敗與寬限期留在系統邊界之外」，寬限期內權益維持已生效直到 App Store 通知到期 |
| B | 維持不建模，但寬限期內權益即暫停（收到扣款失敗通知即視為失效） |
| C | 補上「訂閱扣款已失敗」Event（Actor：外部系統），寬限期內權益維持，寬限期滿再接「會員權益已失效」 |
| D | 補上「訂閱扣款已失敗」與「訂閱寬限期已結束」兩個 Event，完整建模 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響會員權益 Aggregate 的生效狀態值域是否需新增「寬限中」、以及各流程會員 Precondition 在寬限期的判定結果。
承接 G4。**注意**：`resolved/event/使用者已訂閱會員_支付續訂取消到期的Event全數缺失.md`（選項 A′）已裁決不納入「訂閱扣款已失敗」；本項記錄的是該裁決留下的邊界標記空洞，非推翻裁決。

# 優先級

Medium

# 解決結果

**選項 A**：維持不建模，補上軟體邊界標記；寬限期內權益維持已生效，直到 App Store 通知到期。

- 扣款失敗與寬限期留在系統邊界之外，由 App Store 處理。
- 不建模「訂閱扣款已失敗」Event（尊重既有裁決，本題僅補標記）。
- 寬限期內生效狀態維持「已生效」，不新增「寬限中」狀態值。
- 生效狀態轉為「已失效」僅由 App Store 的到期通知觸發，不由扣款失敗觸發。
