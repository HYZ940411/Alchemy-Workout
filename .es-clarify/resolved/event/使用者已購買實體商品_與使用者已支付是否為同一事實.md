# 釐清問題

「使用者已購買實體商品」在訂單狀態機中沒有對應的狀態轉換（待付款 → 已付款 → 已出貨），它與「使用者已支付」是否為同一事實？

# 定位

流程：實體商品購買流程
元素：Event「使用者已購買實體商品」「使用者已支付」
細節：Actor → Command → Event 串聯 — 孤兒 Event（E1）；Event → Aggregate 一致性（E3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 同一事實，刪除「使用者已購買實體商品」，以「使用者已支付」表達訂單成立 |
| B | 兩個不同事實，比照虛擬流程的「使用者已購買虛擬商品 / 商品已發放」，訂單狀態機須補上「已成立」狀態 |
| C | 保留為業務事實但不對應狀態轉換，標記為僅供統計、不做嚴格驗收 |
| D | 同一事實，但改以「使用者已購買實體商品」為主名稱，「使用者已支付」降為其前置的金流 Event |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響實體訂單狀態子集是否新增狀態、實體與虛擬兩條購買流程的 Event 對稱性、以及訂單成立的判定時點。
本項為新掃描發現，非承接 `pending-gaps.md`。與 `event/使用者已支付_實體與虛擬流程的同名Event是否為同一事實.md`（G2）宜併題處理。
相關已解決項目：`resolved/event/商品已發放_與使用者已購買虛擬商品的差異為何.md`、`resolved/aggregate/訂單_訂單的欄位與狀態機定義.md`。

# 優先級

High

# 解決結果

**選項 A**：同一事實，「使用者已購買實體商品」不再作為獨立 Event，以「使用者已支付」表達訂單成立。

- 該 Event 不改變任何 Aggregate 欄位，不符合 Event 的定義（業務狀態改變）。
- 實體流程不比照虛擬流程新增「已成立」狀態；已付款與已出貨的區隔已由「商品已出貨」承擔。
- 「使用者已購買實體商品」登記為統一語言的曾用名，非無痕刪除（比照「使用者已記錄重量 → 使用者已記錄該組成績」先例）。
- 虛擬流程的「使用者已購買虛擬商品」不受影響，其存在理由為與非同步的「商品已發放」區隔。
