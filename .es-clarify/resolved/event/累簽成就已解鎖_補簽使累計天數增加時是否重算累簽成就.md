# 釐清問題

補簽使累計簽到天數 +1 而跨過累簽成就門檻時，是否應於補簽流程解鎖「累簽成就已解鎖」？

# 定位

流程：補簽流程
元素：Event：累簽成就已解鎖（現僅出現於 `每日簽到流程.md` L50）
細節：`補簽流程.md` L29–L30 只處理了連簽成就，未提累簽成就。

# 白話說明

`補簽流程.md` 的最後兩行只講了連簽成就：

```
L29  [Policy] 簽到成就門檻 連續: 1 / 3 / 5 / 7 / 10 / 15 / 20 / 25 / 30 天（同每日簽到流程）
L30  連簽成就已解鎖
```

但同一份檔案 L14 又寫著：

```
L14  [Rule] Postcondition：補簽當日計入累計簽到天數，比照真實簽到
```

累計天數會增加，而累計天數是有成就門檻的。`每日簽到流程.md` L48 列了兩組門檻：

```
連續: 1 / 3 / 5 / 7 / 10 / 15 / 20 / 25 / 30 天
累計: 3 / 7 / 15 / 30 / 60 / 100 / 180 / 280 / 365 天
```

L50 也明確有「累簽成就已解鎖」這個 Event。

**具體情境**：使用者的累計簽到天數目前是 **29 天**，累簽成就的下一個門檻是 30 天。
他補簽一天，累計變成 30。**那枚 30 天的累簽成就要不要當場解鎖？**

模型現在沒說。補簽流程只複製了連續那一組門檻，累計那一組被漏掉了。

# 多選題

| 選項 | 描述 | 推薦 |
|------|------|------|
| A | **補簽亦重算累簽成就**：於 `補簽流程.md` 補上累計門檻的 [Policy] 與「累簽成就已解鎖」Event，比照連簽成就的處理 | ★ |
| B | **只重算連簽成就**：累簽成就延到下一次真實簽到時才一併重算 | |
| C | **補簽不解鎖任何成就**：連簽與累簽皆待下次真實簽到才判定（推翻 L30） | |
| Short | 提供其他簡短答案（<=5 字） | |

# 推薦選項與理由

**推薦 A（補簽亦重算累簽成就）。**

- **模型已明文要求兩者一致**。`補簽流程.md` L16 的決策寫得很直接：

  > 補簽視同該日有簽到，後果應與真實簽到一致，否則模型中會出現兩種不同等級的簽到日，
  > **累計天數與累簽成就的意義將被稀釋**

  這句話**指名道姓提到了累簽成就**，卻沒在流程裡落實。研判為漏寫而非刻意設計。
- **L14 已裁決累計天數 +1，成就是累計天數的直接下游**。既然數字動了，
  依附於這個數字的門檻判定沒有理由不動。
- **B 會產生一段「成就已達標但尚未解鎖」的懸置期**，長度取決於使用者何時再簽到，
  可能是好幾天。這與 `每日簽到流程.md` L53「使用者成就解鎖紀錄為單調遞增，
  一經解鎖不可撤銷」所隱含的「達標即解鎖」語意不符。
- **重複解鎖的疑慮不存在**：`每日簽到流程.md` L51–L52 已定
  「每個成就門檻終身僅解鎖一次，重複達成不再解鎖亦不再發放獎勵」，
  且 L52 明寫「本規則及於全部 9 類成就，連簽成就與累簽成就皆適用」——
  這條規則已經涵蓋補簽的情形，選 A 不需要再新增任何防重複規則。
- **不推薦 C**：`補簽流程.md` L30 已有「連簽成就已解鎖」，C 是推翻既有內容，
  且與 L16 的決策直接衝突。

# 對 Gherkin 翻譯的影響

影響 `.gh-clarify/then/使用補簽券_連帶產生的Event要斷言到哪一層.md`。

補簽的 Then 要斷言到哪些連帶 Event，取決於補簽會引發哪些後果。
**目前「累簽成就已解鎖」在補簽流程中不存在，翻譯時不會產生任何相關斷言**，
等於「補簽剛好湊到累簽門檻」這條路徑在 Gherkin 中完全沒有驗收。

- 選 A：須新增一條 Scenario——`Given 使用者（U001）的累計天數為 29`、
  `When 使用者（U001）使用補簽券回補 2026-08-18`、
  `Then 使用者（U001）解鎖累計 30 天的累簽成就`。
- 選 B/C：該情境的 Then 要斷言的是「**沒有**解鎖任何累簽成就」，
  這屬於否定式斷言，寫法與 A 完全不同。

# 影響範圍

  目前未如 L113「解鎖連簽成就」那樣註記「亦由補簽流程觸發」）

- 成就獎勵的發放路徑（若補簽解鎖成就，其獎勵的入帳方式須確認是否亦走信箱，
  參見 `02_Aggregate定義.md` L922 已定「成就採點擊領取但不進信箱」）

**與已解決項目的關係**：
`.es-clarify/resolved/rule/連續簽到已恢復_補簽是否計入累計簽到天數與當日獎勵.md`
裁定累計天數 +1，本題為該裁決的下游連動；
`.es-clarify/resolved/rule/連簽成就已解鎖_同一門檻重複達成時是否重複發放.md`（選項 A）

# 解決結果

**選項 A** —— 補簽亦重算累簽成就。

補簽流程補上累計門檻的 [Policy]（3 / 7 / 15 / 30 / 60 / 100 / 180 / 280 / 365 天）
與 Event「累簽成就已解鎖」，比照既有的連簽成就處理。
補簽與真實簽到對兩類成就的判定完全一致。

**判為漏寫而非刻意設計**：`補簽流程.md` 的既有決策原文即指名
「⋯否則模型中會出現兩種不同等級的簽到日，**累計天數與累簽成就的意義將被稀釋**」——
講到了累簽成就，卻只在流程中複製了連續門檻一組。

**重複解鎖的防護不需新增**：`每日簽到流程.md` 已定「每個成就門檻終身僅解鎖一次，
重複達成不再解鎖亦不再發放獎勵」，且明訂「本規則及於全部 9 類成就，
連簽成就與累簽成就皆適用」，已涵蓋補簽的情形。

**不採 B（延至下次真實簽到）的理由**：會產生一段「已達標但未解鎖」的懸置期，
其長度取決於使用者何時再簽到，可能達數日。
