# 釐清問題

冪等原則統一為「以 Command 請求識別碼去重」，但排程觸發的 Command 無使用者端請求，其請求識別碼由何處產生？

# 定位

流程：每日任務流程、訓練結算流程、每日簽到流程、訓練中斷流程、排行榜週期結算流程
元素：Event「每日任務已重置」「訓練已結算」「簽到連續天數已中斷」「連續訓練天數已歸零」「排行榜週期已結算」「能力值已退步」
細節：事件時序與因果 — 冪等性（A3）；狀態邊界（C3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 以「排程名稱 ＋ 週期起點 ＋ 使用者 ID」組合為請求識別碼，同一週期重跑視為重複請求 |
| B | 以「排程名稱 ＋ 排程執行批次 ID」為請求識別碼，同一批次重跑才視為重複；跨批次重跑會重複執行 |
| C | 排程類 Event 不套用請求識別碼去重，改以各自的 Precondition 自然防重（如「當日尚未重置」） |
| D | 每次排程執行皆產生新的 UUID 作為請求識別碼，重跑不去重，由人工確保不重跑 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 `00_全域規範.md` 冪等性原則章節的補充規則、六個排程類 Event 的 Precondition，以及排程重跑的安全性保證。
承接 G6；相關已解決項目：`resolved/event/全流程Event_各Event重複發生時的冪等處理原則.md`（選項 A）。

# 解決結果

**選項 A**：以「排程名稱 ＋ 週期起點 ＋ 使用者 ID」組合為請求識別碼，同一週期重跑視為重複請求。

各排程類 Event 的週期起點語意：

| 排程類 Event | 週期起點 |
|--------------|----------|
| 每日任務已重置 | 使用者當地日期（以當地時間 04:00 為換日點） |
| 訓練已結算 | 該筆訓練的訓練紀錄 ID |
| 簽到連續天數已中斷 | 該次中斷判定所屬的使用者當地日期 |
| 連續訓練天數已歸零 | 該次歸零判定所屬的使用者當地日期 |
| 排行榜週期已結算 | 該排行榜週期的起始日 |
| 能力值已退步 | 該肌群維度的 120 小時計時起算點 |

- 排程類 Command 不產生隨機識別碼，一律由自然鍵推導。
- 「能力值已退步」的去重為肌群維度層級，六維各自獨立。
- 排程類 Event 不因本規則免除各自的 Precondition，兩者並存。
