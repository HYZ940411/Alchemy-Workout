# 釐清問題

下列 5 個欄位已於第五輪的裁決中被引用，但未寫入使用者 Aggregate 的〈已定義欄位〉表，其所屬 Aggregate、型別與合法範圍為何？

| 欄位 | 出處 |
|------|------|
| 教官專長肌群 | 使用者 Aggregate〈欄位群〉表（無型別與範圍） |
| 六維能力值對外可見 | Read Model：使用者個人檔案頁 |
| 已購買計畫清單 | 訓練計畫〈三種解鎖方式〉方式 2 |

| 當日訓練最高完成度 | 同上 |

# 定位

流程：教官申請流程、訓練結算流程、虛擬商品購買流程、關注流程
元素：Aggregate「使用者」之欄位；可能另涉「獎勵發放紀錄」Aggregate
細節：D2 Aggregate 欄位定義、E3 Event→Aggregate 一致性（Postcondition 提及的欄位須存在於 Aggregate 定義中）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 5 者全部歸入使用者 Aggregate。教官專長肌群＝列舉複選（六肌群，教官身分為真時至少 1 項）；六維能力值對外可見＝bool 預設真；已購買計畫清單＝訓練計畫 ID 集合；後兩者為 int 與百分比，於統一換日時點歸零 |
| B | 前三者歸使用者 Aggregate；後兩者（當日兩個計數）歸**獎勵發放紀錄** Aggregate，因其性質為發放額度而非使用者屬性，且可避免使用者 Aggregate 出現每日重置的欄位 |
| C | 前二者歸使用者；已購買計畫清單獨立為新 Aggregate「已購買解鎖項目」（可涵蓋日後其他權限解鎖類商品）；後兩者歸獎勵發放紀錄 |

| Short | 提供其他簡短答案（<=5 字） |

# 解決結果

**選項 B** —— 前三者歸使用者 Aggregate，後兩者（當日兩個計數）歸**獎勵發放紀錄** Aggregate。

| 欄位 | 所屬 Aggregate | 型別 | 合法範圍 |
|------|---------------|------|----------|
| 教官專長肌群 | 使用者 | 列舉複選 / 空值 | 至少 1 項（**值域待重新定義**，見下） |
| 六維能力值對外可見 | 使用者 | bool | 真 / 假，預設真 |
| 已購買計畫清單 | 使用者 | 訓練計畫 ID 集合 | 可為空集合 |
| 當日已發放訓練獎勵金幣數 | **獎勵發放紀錄** | int | ≥ 0 |
| 當日訓練最高完成度 | **獎勵發放紀錄** | 百分比 | 50 / 70 / 100 |

**分界**：這是**使用者的屬性**，還是**某個機制的計數器**。
前三者跟隨使用者長期存在；後兩者每日 04:00 歸零，性質為「訓練獎勵這個機制今天發到哪了」
的暫存，而獎勵發放紀錄本即為記錄「發了什麼給誰」之處。
使用者 Aggregate 承載身分與長期成長數值，不宜混入天天被重置的欄位。

**不採 C（已購買計畫清單獨立為新 Aggregate）**：目前僅有一種內容（進階訓練計畫），
為單一用途另立屬提前抽象；待出現第二種永久解鎖商品時再拆，成本相同。

**不採 D（另立「使用者每日計數」Aggregate）**：其只會裝這兩個欄位，且兩者只服務訓練獎勵
一個機制；獨立後「訓練獎勵的每日上限」這條規則反而要跨兩個 Aggregate 判定。
