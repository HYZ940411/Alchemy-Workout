# 釐清問題

階級提升流程中「經驗達門檻升階（參數待定）」的各階級門檻值為何？共有幾個階級？

# 定位

流程：階級提升流程
元素：Aggregate：階級；Rule / Policy：階級門檻判定（經驗達門檻升階，參數待定）
細節：待決事項 TODO（F3）；欄位範圍與數值邊界（D2、C3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 固定階級數（如 10 階），門檻為等差級數 |
| B | 固定階級數（如 10 階），門檻為等比級數（越高階越難） |
| C | 無上限階級，門檻依公式動態計算 |
| D | 固定階級數，門檻由管理員在後台可調整，需要「階級設定」Aggregate 與管理員 Command |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響階級 Aggregate 的欄位與門檻定義、使用者已提升階級的 Precondition、進階訓練計畫已解鎖的階級對應關係、以及是否需要管理員設定流程。此為模型中明確標記「參數待定」的 TODO。

# 優先級

High

# 解決結果

D — 階級數固定，門檻值由管理員於後台調整，新增「階級設定」Aggregate 與管理員 Command。

新增 Event「管理員已設定階級門檻」，Actor 為管理員。
門檻調整不改動任何使用者既有的階級。

**Partial**：階級總數與各階門檻初始值未給定，模型中的 [待決策 Partial] 標記持續存在。
原 Policy 的「（參數待定）」字樣已移除 —— 參數的**歸屬**已定案（屬階級設定 Aggregate，
由管理員維護），僅剩初始值待給定。

# 結構一致性

與第 29 題（成就定義 + 解鎖紀錄）、第 30 題（獎勵定義 + 發放紀錄）採同一模式：
平台級可調參數獨立於每使用者狀態之外。階級門檻屬階級設定 Aggregate，
使用者的當前階級屬使用者 Aggregate。
