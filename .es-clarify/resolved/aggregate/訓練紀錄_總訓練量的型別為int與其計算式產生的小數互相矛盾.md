# 釐清問題

訓練紀錄的「總訓練量」型別定為 int，但其不變條件為「未取消的重訓組紀錄之（重量 × 次數）累加」，而重量為精度 0.5 的 float（如 62.5 × 3 ＝ 187.5）——型別該如何修正？

# 定位

流程：訓練結算流程
元素：Aggregate — 訓練紀錄（表頭欄位「總訓練量」）
細節：`02_Aggregate定義.md`〈訓練紀錄 Aggregate〉表頭欄位表列為 int（≥ 0），不變條件則會產生 .5 的小數；徒手動作另以體重係數換算（體重亦為一位小數的 float）

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 型別改為 float（一位小數），與重量欄位一致 |
| B | 維持 int，於不變條件加註「累加後四捨五入至整數」；理由為訓練量已降級為純呈現用的統計數值，無精度要求 |
| C | 維持 int，改為逐組先四捨五入再累加 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

- 〈Read Model：訓練歷史〉訓練清單的總訓練量呈現與跨期加總
- 相關已解決項目：`resolved/aggregate/訓練紀錄_訓練紀錄的完整欄位與狀態機為何.md`

# 解決結果

**A ＋ 使用者補充**：型別改為 **float（一位小數）**，**呈現時四捨五入至整數**。

- 儲存採 float 的理由：計算來源（重量）為精度 0.5 的 float，徒手動作另乘以體重係數
  （體重亦為一位小數），小數無法避免；且本欄位已定案為「純呈現用的統計數值、無精度要求」，
  為湊整數而引入捨入規則的成本大於收益。
- **捨入僅發生於呈現層（Read Model），儲存值不改變**。
- **不採逐組先四捨五入再累加**：誤差會累積，一場 20 組的訓練可能相差數公斤。
