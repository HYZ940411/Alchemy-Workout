# 釐清問題

連續簽到 Aggregate 中「連續天數」與「累計天數」的定義、型別與初始值分別為何？兩者關係為何？

# 定位

流程：每日簽到流程
元素：Aggregate：連續簽到（由 Event「連續簽到已紀錄」推導）
細節：欄位型別與定義（D2）、欄位間不變條件（D3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 連續天數 int（中斷歸零），累計天數 int（永不歸零，單調遞增），首次簽到皆為 1 |
| B | 連續天數 int（中斷歸零），累計天數 int，且需額外記錄歷史最長連續天數 |
| C | 僅記錄上次簽到日與連續天數，累計天數由簽到明細表即時彙總，非 Aggregate 欄位 |
| D | 連續天數與累計天數皆保留，另加「本次中斷前的連續天數」以支援補簽回復 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響連續簽到 Aggregate 欄位定義、連簽成就已解鎖與累簽成就已解鎖的門檻比對來源、補簽流程「連續簽到已恢復」的計算依據、以及不變條件「累計天數 >= 連續天數」。

# 優先級

High

# 解決結果

D′（使用者於第 37 題提問時要求改答，原答案 A 已作廢） —
連續簽到 Aggregate 含四個欄位：

| 欄位 | 型別 | 初始值 | 說明 |
|------|------|--------|------|
| 連續天數 | int | 首次簽到為 1 | 中斷時歸零 |
| 累計天數 | int | 首次簽到為 1 | 永不歸零，單調遞增 |
| 中斷前連續天數 | int | 0 | 中斷時保存歸零前的值，供補簽回復 |
| 歷史最長連續天數 | int | 首次簽到為 1 | 永不減少 |

規則：
- 中斷時，連續天數歸零前先將原值寫入中斷前連續天數。
- 補簽成功時，連續天數回復為：中斷前連續天數 ＋ 補回的天數 ＋ 中斷後已簽到的天數。
- 補簽券使用後，中斷前連續天數清空為 0。
- 不變條件：累計天數 ≥ 歷史最長連續天數 ≥ 連續天數。

# 部分推翻（2026-08-23，第十四輪）

本項原定案為**五欄位**。其中「**中斷前連續天數**」已於 2026-08-23 **刪除**，
連續簽到 Aggregate 現為**四欄位**：連續天數、累計天數、歷史最長連續天數、上次簽到日期。

**推翻原因**：該欄位的唯一用途為補簽回復的加法公式
（「中斷前連續天數 ＋ 補回的天數 ＋ 中斷後已簽到的天數」）。
該公式與「同一次中斷可使用多張補簽券」的裁決互相矛盾——
第二張券使用時，中斷前連續天數已被第一張清為 0，會算出比前一張更小的值；
且未補齊時會把被斷點切開的兩段相加。
連續天數已改為**逐日推算**（自「上次簽到日期」起往回檢視〈每日簽到紀錄 Aggregate〉），
不再需要此欄位，亦無其他讀取端。

**未受影響**：其餘四欄位、三條不變條件之其二（累計天數與歷史最長連續天數的單調遞增、
累計天數 ≥ 歷史最長連續天數 ≥ 連續天數）、連簽中斷判定的計時起點（04:00 日界）皆維持原裁決。
第三條不變條件「中斷前連續天數 > 0 代表存在一次尚可補救的中斷」已改寫為
「回補範圍內存在查無〈每日簽到紀錄〉之日，即代表存在一次尚可補救的中斷」。
