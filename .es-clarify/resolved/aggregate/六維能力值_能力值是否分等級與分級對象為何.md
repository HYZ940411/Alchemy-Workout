# 釐清問題

能力值等級（S/A/B/C/D/E/F）套用在哪一個數值上 —— 六個維度各自分級，還是六維彙總後給單一等級？

# 定位

流程：訓練結算流程（能力值已提升）、階級提升流程
元素：Aggregate「使用者」的能力值衍生欄位；Read Model「六維能力值雷達圖」
細節：D2 欄位定義、D3 衍生欄位公式。

本項目由使用者於第 22 題進行中主動提出，非 discovery 掃描產出。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 六維各自分級，每人同時有 6 個等級；不設總等級 |
| B | 僅總能力值分級，六維彙總後給單一等級；六維本身仍以數值呈現 |
| C | 兩者都有：六維各自分級，另設一個由六維推導的總等級 |
| D | 分級不掛在能力值上，改掛在階級（1–99）上，S/A/B/C… 為階級的區段標籤 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響使用者 Aggregate 的能力值衍生欄位、Read Model「六維能力值雷達圖」的欄位、
能力值日快照是否須一併保存等級、以及成就定義 Aggregate 是否新增等級類成就。

# 優先級

High

# 解決結果

**選項 A ＋ 綜合等級（實質等同選項 C）** —— 使用者原話：
「A 每人同時有 6 個等級，但可以有一綜合能力等級」。

另裁決等級值域：**移除 F，為六階 S / A / B / C / D / E**，S 最高、E 最低。

裁決要點：

1. 等級為**衍生欄位**，由能力值點數推導，不獨立儲存為可直接改寫的值。
2. 兩層並存：**維度能力等級**（六維各一，共 6 個）與**綜合能力等級**（1 個）。
3. 兩層並存不視為與階級（1–99）功能重疊：階級由經驗值決定、衡量投入程度；
   綜合能力等級由能力值決定、衡量身體能力。來源數值與業務意義不同。

尚未定案，另列後續釐清項目：

- 等級的判定基準為絕對點數門檻或全平台相對百分位。
- 綜合能力等級由六維推導的公式（取平均 / 取最高 / 加權）。
- 等級變動是否建模為 Event（能力值可退步，等級亦可能下降）。
- 等級是否掛勾成就，以及掛勾方式。
