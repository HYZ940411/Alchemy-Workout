# 釐清問題

教官申請 Aggregate 的狀態機為何（一次申請歷經初審、測驗、人工審核三階段，各階段對應哪些狀態）？教官申請與教官測驗的關聯基數為何（一次申請可作答幾次測驗？重考是否產生新的申請？）

# 定位

流程：教官申請流程
元素：Aggregate「教官申請」「教官測驗」
細節：D5 生命週期與狀態機、D4 Aggregate 間的關係。00_全域規範〈教官申請 Aggregate〉末行自行標記：「本 Aggregate 的狀態機、以及申請與教官測驗的關聯基數尚未定義（待決策 Partial）」。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 狀態值域五值：初審中 / 待作答測驗 / 待人工審核 / 已通過（終止）/ 已駁回（終止）。申請與測驗為**一對多**，重考沿用同一筆申請，不重新評分訓練品質 |
| B | 同 A 的狀態值域，但申請與測驗為**一對一**：重考時產生新的一筆教官申請並重新評分訓練品質，因 14 天間隔內訓練紀錄已有變化 |
| C | 狀態值域簡化為三值：進行中 / 已通過 / 已駁回，各階段由「駁回階段」欄位與是否有測驗紀錄推導；關聯基數採 A 的一對多 |
| D | 不設狀態機：申請的進度由既有的四個 Event（教官資格已初審通過 / 已駁回 / 已通過）與測驗紀錄推導，Aggregate 僅保存評分明細 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響教官申請 Aggregate 的欄位與狀態機、「AI 已產出訓練品質評分」的請求識別碼（＝使用者 ID ＋ 教官申請 ID，若重考不新建申請則不重複評分）、重考 14 天間隔的計時基準、〈Read Model：管理員待審佇列〉教官申請分頁的進入條件，以及〈Read Model：教官申請頁〉的狀態呈現。
相關已解決項目：`resolved/event/AI已產出訓練品質評分_攜帶資訊與去重鍵與評分是否保存.md`、`resolved/rule/使用者已作答教官測驗_可否重考與重考間隔.md`、`resolved/aggregate/教官測驗_題數配分與及格標準.md`。

# 優先級

Medium

# 解決結果

**選項 B** —— 五值狀態機；申請與測驗為**一對零或一**；任何重試皆產生新申請並重跑 AI 評分。

## 狀態機（五值）

| 狀態 | 在等什麼 |
|------|----------|
| 初審中 | 等 AI 產出訓練品質評分 |
| 待作答測驗 | 等使用者作答（無時限） |
| 待人工審核 | 等管理員審簡答題（7 個工作天） |
| 已通過 | 終止 |
| 已駁回 | 終止 |

五個狀態各對應一個**會停下來等的時點**，且等待對象不同。
不簡化為三值（選項 C）：〈Read Model：管理員待審佇列〉的教官申請分頁將分不出
「尚未作答」與「已作答待我審」，而只有後者該進管理員的待辦。

## 關聯基數：一對零或一

**採 B 而非 A 的理由（出題時助理推薦 A，經使用者指正後改判）**：

1. **流程檔本即如此**：`教官申請流程.md` 的失敗路徑明訂
   「初審 / 測驗 / 管理員審核任一階段未通過 → 教官資格已駁回」——
   測驗未通過時該筆申請已進入終止狀態，不存在「同一張申請單再考一次」的路徑。
   助理原推薦的 A 等於要改掉這條既有分支，出題時未察覺。
2. **使用者指出的關鍵**：「小明有可能三個月後才再次申請」。
   14 天僅為**最低**重試間隔，模型未設次數上限亦未設最長間隔；
   數月後訓練紀錄已完全不同，沿用舊評分即以過期資料判定。
   故重跑 AI 評分為**必要而非浪費**。
3. 與既有規則一致：「重新申請時產生新的一筆教官申請，重新評分；既有申請的評分不被覆寫」。

**連帶釐清**：「重考間隔 14 天」的語意為「距上次『使用者已作答教官測驗』滿 14 天，
方可再次**申請**」；「AI 已產出訓練品質評分」的請求識別碼
（＝使用者 ID ＋ 教官申請 ID）不受影響，每筆新申請有各自的申請 ID。

## 本題衍生並已轉記的項目
