# 釐清問題

貼文 Aggregate 的欄位定義為何？支援哪些內容型態（文字 / 圖片 / 影片）？可見範圍如何設定？

# 定位

流程：發文與互動流程
元素：Aggregate：貼文（模型中尚未定義）；Event：發文者已發布貼文、發文者已分享訓練成果
細節：隱含但未明確定義的 Aggregate（D1）；欄位定義（D2）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 欄位含作者 / 文字內容 / 圖片 / 發布時間 / 按讚數 / 留言數，全部公開可見 |
| B | 上述加上可見範圍欄位（公開 / 僅追蹤者 / 私人） |
| C | 上述加上可見範圍與關聯訓練紀錄欄位（分享訓練成果時帶入） |
| D | 支援文字 / 圖片 / 影片，可見範圍三選一，並含標籤欄位供分類 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響貼文 Aggregate 的欄位與不變條件、發布貼文 Command 的輸入參數、互動者按讚 / 留言的 Precondition（可見範圍檢核）、以及與訓練紀錄 Aggregate 的關聯。

# 優先級

High

# 解決結果

C — 貼文 Aggregate 含 8 個欄位：
作者、文字內容、圖片、發布時間、**可見範圍**、**關聯訓練紀錄**、按讚數、留言數。

- 不支援影片，無標籤欄位（未採 D）
- 可見範圍三選一：公開 / 僅關注者 / 私人
- 「發文者已分享訓練成果」→ 關聯訓練紀錄必有值
- 「發文者已發布貼文」→ 關聯訓練紀錄為空
- 互動者按讚或留言前，該貼文須對其可見

# 統一語言修正

選項 C 原文為「僅**追蹤**者」。依 `00_全域規範.md`「『追蹤』為棄用詞，一律改用『關注』」
的既有裁決，回寫時改為「僅關注者」。

# 承接的既有裁決

- 既有裁決已定「分享」與「發文」為兩種不同行為，關聯訓練紀錄欄位正是兩者的資料層區別。
- 第 40 題已定自訂訓練「已發布 = 對關注者可見」，本題的可見範圍與之一致。

# 連帶影響
