# 釐清問題

團隊 Aggregate 的人數上限、角色設定（隊長 / 成員）、以及建立團隊的門檻為何？

# 定位

流程：團隊組隊任務流程
元素：Aggregate：團隊（模型中尚未定義）
細節：隱含但未明確定義的 Aggregate（D1）；欄位定義與範圍（D2）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 人數上限固定（如 10 人），建立者即隊長，隊長可轉讓，無建立門檻 |
| B | 人數上限固定，僅有隊長與成員兩種角色，需達指定階級才可建立團隊 |
| C | 人數上限依團隊等級成長，設隊長 / 副隊長 / 成員三種角色 |
| D | 無人數上限，無角色區分，所有成員權限相同 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響團隊 Aggregate 的欄位定義與不變條件、使用者已建立團隊 / 已加入團隊的 Precondition、管理員已設定限時任務的 Actor 權限、以及團隊分數的計算基數。

# 優先級

High

# 解決結果

A（含使用者給定的上限值） — 使用者原話：「A 5人」。

- 團隊人數上限 **5 人**（含隊長在內）
- 建立團隊無門檻，任何使用者皆可建立
- 建立者預設為隊長，隊長可轉讓
- 僅有隊長與成員兩種角色，無副隊長
- 隊長權限：踢除成員、轉讓隊長、解散團隊；成員權限：參與團隊任務、退出團隊

未採 B（階級門檻，會相依於仍為 Partial 的階級總數）、C（團隊等級為模型中不存在的新概念）、
D（與既有的「隊長已踢除成員」「隊長已轉讓」Event 矛盾）。

# 承接的既有裁決

第 17 題：團隊隊長不為獨立 Actor，權限差異以團隊內的角色欄位表達。
本題的隊長 / 成員皆為「使用者」這個 Actor。

# 連帶影響

`rule/使用者已建立團隊_一位使用者可否同時加入多個團隊.md`：
本題確立人數上限與無建立門檻，但一人可加入幾個團隊未表態，該題仍須回答。

`rule/團隊日常分數已增加_成員中途加入或退出時分數如何計算.md`：
人數上限 5 人已確立，該題的分數基數計算有了明確上界。
