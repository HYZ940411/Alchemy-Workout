# 釐清問題

**（本題已於 2026-08-04 擴充：先定值域，再定數量上限）**

1. **值域**：教官專長應為六大肌群，或改為**教學專長標籤**（如飲食、增肌、新手引導）？
2. **來源**：值域由管理員後台維護的清單，或允許教官自由填寫？
3. **數量上限**：可選幾項？（現為「至少 1 項」，無上限）

> 「我不是希望教官去填專長肌群啦…… 我是希望教官能手動或選填填一些專長，
> 例如 XX 飲食、增肌、新手引導這些」

現行的六肌群值域為**暫定**，本題須先裁決值域，數量上限方有意義。
模型中三處已加註 `[待決策 Partial]`：使用者 Aggregate 的「教官專長肌群」、
教官申請 Aggregate 的「專長肌群」、〈Read Model：教官清單〉的專長篩選。

**候選值域**（供裁決參考，非既有裁決）：訓練目標類（增肌 / 減脂 / 體態雕塑 / 提升體能）、
族群類（新手引導 / 銀髮 / 產後 / 傷後復健）、面向類（飲食營養 / 動作矯正 / 課表規劃）、
以及是否保留肌群作為其中一類。

**若改為標籤制，須一併決定**：值域是否為平台級可調設定（比照健身目標設定的既有做法）、
是否允許教官自由填寫（自由填寫則〈Read Model：教官清單〉的篩選失效）。

# 解決結果

**選項 A ＋ 使用者的法規顧慮** —— 單一扁平清單、移除肌群、平台級可調、**上限 3 項**。

## 值域（初始 11 項，存於新增的〈教官專長設定 Aggregate〉）

| 分類 | 項目 |
|------|------|
| 訓練目標 | 增肌 / 減脂 / 體態雕塑 / 提升體能 |
| 訓練型態 | 肌力訓練 / 耐力訓練 / 徒手訓練 / 居家訓練 |
| 服務對象 | 新手引導 |
| 面向 | 課表規劃 / 動作教學 |

分類僅供後台整理，不影響填寫；教官自 11 項中複選 1–3 項。

## 移除肌群的理由

六維能力值已於〈Read Model：教官清單〉**強制呈現且教官不可隱藏** ——
學徒要找「練胸強的教官」直接看六維雷達即可，而那是**實績**；
肌群專長為同一份資訊的**自述**版本，較實績為差，且帶有模型自己記下的
`[已知風險]`「自述可能與實際實力不符」。
改為教學專長標籤後，本欄位補的是六維表達不了的資訊，與六維並列而不重複。

## 值域排除具專業執照門檻的項目（使用者提出）

助理原提案的 12 項中有 5 項經使用者指出有法規疑慮，**全數移除且不寫入系統**：

| 排除項目 | 理由 |
|----------|------|
| 飲食營養 | 營養諮詢在多數地區屬營養師的專業範圍 |
| 傷後復健 | 復健屬醫療 / 物理治療範疇 |
| 產後恢復 | 醫療相鄰，涉及特殊生理狀態 |
| 動作矯正 | 「矯正」隱含治療性質 |
| 銀髮族 | 高風險族群，平台無從驗證教官是否具相應經驗 |

**核心理由為平台責任**：將專長做成可篩選的標籤，等同平台向學徒表示該教官具備此能力；
而教官資格的取得條件僅為「階級 20 ＋ 累積訓練 50 次 ＋ 通過站內測驗」，未驗證任何專業執照。

**不採「證照上傳 ＋ 管理員審核」的開放路徑**：須新增證照 Aggregate、上傳與審核 Event
與一整條審核流程，屬範圍擴張；日後需要時另案處理。

## 使用者確認的三件事

1. 移除的 5 項**目前沒有寫進系統的想法**。
2. **免責聲明要加** → 已建為 `rule/教官已回答_平台對教官所提供建議的免責聲明尚未建模.md`。
3. **上線地區不只一個**；因值域為管理員可調，現階段由後台調整承接，
   模型加註 `[待決策 Partial]`「值域是否需依地區分設」。
