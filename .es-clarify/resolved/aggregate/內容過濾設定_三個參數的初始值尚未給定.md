# 釐清問題

〈內容過濾設定 Aggregate〉的三個參數 —— 明顯違規門檻、疑似違規門檻、違規類別清單 —— 初始值皆標為「尚未給定」，該節並附有 `[待決策 Partial]`「須於上線前由內容與法務團隊訂定」。違規類別清單同時是兩個 Event（「內容已攔截」「內容已標記待審」）攜帶欄位「命中的違規類別」的值域，值域未定則這兩個 Event 的攜帶資訊寫不完整、對應情境也列不出 Examples。這三個參數要現在定，還是列為上線前的追蹤項？

# 定位

流程：發文與互動流程（發布前的內容過濾）、聊天私訊流程
元素：Aggregate：內容過濾設定（`02_Aggregate定義.md:4009-4028`）
細節：D2 欄位定義（值域）、G3 參數的可代入性、F3 待決事項。本 `[待決策 Partial]` 為 2026-08-20 新增，未列入 `overview.md` §0.6 的追蹤清單，處於無人追蹤的狀態。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A（**推薦**） | **只定違規類別清單（值域），兩個分數門檻列為上線前追蹤項。** 類別清單可直接依 App Store 1.2 明列的項目給出（如：色情、暴力、仇恨與歧視、騷擾與霸凌、違法商品與服務、自我傷害、垃圾訊息與詐騙），本輪定案；兩個門檻的量級取決於實際選用的過濾服務輸出什麼分數區間，模型此刻定了也是猜的。理由：值域是**規則寫得出來的前提**（兩個 Event 的攜帶欄位、管理員待審佇列的分類篩選都要用它），門檻只是數值，比照「各動作相對強度係數由內容團隊上線前補齊」的既有處理 |
| B | 三者全列為上線前追蹤項，寫入 `overview.md` §0.6，本輪不問 |
| C | 三者全部現在定：類別清單同 A，門檻採 0–100 分制，明顯違規 ≥ 85、疑似違規 ≥ 60 |
| D | 違規類別清單不由本 Aggregate 承載，改為沿用〈檢舉理由設定 Aggregate〉的既有理由清單（使用者檢舉與系統過濾用同一套分類），本表只留兩個門檻 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響〈內容過濾設定 Aggregate〉三個參數的初始值、Event「內容已攔截」與「內容已標記待審」的攜帶欄位「命中的違規類別」之值域、〈Read Model：管理員待審佇列〉系統自動標記案件的分類與篩選、以及這兩個 Event 的 Gherkin Examples 是否寫得出來。
若採 D，須一併確認檢舉理由清單（使用者視角的分類）是否適合作為過濾器輸出（機器視角的分類）——兩者的粒度未必相同。
相關已解決項目：`resolved/aggregate/平台參數設定_大量宣告為平台級可調的參數無任何Aggregate承載.md`（建立本 Aggregate）、`resolved/event/內容已攔截_疑似違規自動開立檢舉案件是否應建模為Event與Command.md`、`resolved/aggregate/檢舉理由設定_流程檔稱其為Aggregate而核心檔列為邊界外組態.md`。

# 解決結果

本題經使用者要求拆為 4 小題逐一裁決：

| 小題 | 問題 | 答案 |
|------|------|------|
| 1-1 | 違規類別清單現在定，還是列為上線前追蹤項 | **A：現在定** |
| 1-2 | 違規類別與檢舉理由共用一張清單嗎 | **A：共用一張，加一欄「過濾器是否可命中」** |
| 1-3 | 清單具體有哪幾類 | **B：只留 Apple 明列的 7 類 ＋「其他」** |
| 1-4 | 兩個分數門檻現在定嗎 | **A：不定，列為上線前追蹤項；並確認採外部過濾服務（有分數），不採自建關鍵字黑名單** |

綜合等同於**原選項 A ＋ D 的合成**：值域本輪定案（A），但不由〈內容過濾設定〉自行承載，
改與〈檢舉理由設定〉共用一份（D），並以新欄位「過濾器是否可命中」表達
「機器認得的是使用者可檢舉項目的子集」——解決了原 D 所擔心的「兩者粒度未必相同」。

1-3 定案的清單（打勾＝機器認得出來）：
色情✓／暴力血腥✓／仇恨歧視✓／騷擾霸凌✓／人身威脅✓／垃圾廣告與詐騙✓／違法商品✓／其他✗。
健身相關（極端節食、鼓吹用藥）與假冒他人、盜用內容一律歸「其他」。

**查證更正**：原推薦選項 A 稱類別清單「可依 App Store 1.2 明列的項目給出」，
查 Apple 官方審核指南原文後確認**有誤**——1.2 只列四項必備機制（過濾、檢舉與即時回應、
封鎖、公開聯絡方式），**未列舉任何內容類別**；列舉類別者為 1.1（1.1.1–1.1.7），
另 1.2 段末點名人身威脅與霸凌。原擬清單中的「自我傷害」「垃圾訊息與詐騙」不在 1.1／1.2 之列。

**1-2 的推薦於提問中途改過**：初版以「檢舉理由是白話描述、違規類別是機器標籤」為由推薦分開兩張，
經使用者指出「檢舉理由應是類別而非描述」（模型 `02:4009` 明訂列舉單選＋選填補充文字），
該理由不成立，改推薦共用。
