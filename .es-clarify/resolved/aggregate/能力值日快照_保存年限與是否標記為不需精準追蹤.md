# 釐清問題

能力值日快照已定案為每日一筆的業務 Event，但保存年限未定；且其發生頻率為全平台每使用者每日一筆的高頻排程 Event，是否比照通知類 Event 標記為「不需精準追蹤」尚未裁決。此問題的重要性已因第八輪新增的會員權益「六維能力值歷史變化圖」而提高——該權益直接依賴此快照的長期保存。

# 定位

流程：（不隸屬任何單一流程，屬系統排程）
元素：Aggregate 概念「能力值日快照」；Read Model「六維能力值雷達圖」〈能力值日快照〉子節、「訓練歷史」〈六維能力值歷史變化圖〉會員權益
細節：快照為每日每使用者一筆，若使用者基數成長，長期不設年限的儲存成本與查詢效能需要評估。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 不設保存年限，永久保留：其為會員權益「六維能力值歷史變化圖」的資料基礎，若設年限則會員的「跨時間彙總視角」將有隱形的回溯上限，與訓練歷史「回溯範圍不設限」的既有原則不一致（**推薦**：模型已明文「訓練歷史為使用者自身產生的資料，不以會員身分限制回溯範圍」，能力值日快照現已是會員權益的資料來源，適用同一判準；且模型已判斷「一年 365 筆，資料量可忽略」，多年累積仍屬輕量的純數值紀錄） |
| B | 保存 2 年後自動清除超出範圍的舊快照，兼顧「一般使用者不太需要看兩年前的能力值」與儲存成本 |
| C | 標記為「不需精準追蹤」（比照通知類 Event），僅盡力保存不做嚴格的 Precondition/Postcondition 驗收，遺漏個別幾天不視為系統缺陷 |
| Short | 提供其他簡短答案（<=5 字） |

影響能力值日快照的儲存策略、Read Model「訓練歷史」六維能力值歷史變化圖的可回溯範圍。為 `pending-gaps-3.md` I9 之延續，因第八輪的會員權益新增而提高相關性。

# 解決結果

**選項 A**：不設保存年限，永久保留；不標記為「不需精準追蹤」。

- 承既有判準「訓練歷史為使用者自身產生的資料，不以會員身分限制回溯範圍」——
  快照現為會員權益〈六維能力值的歷史變化圖〉的資料來源，適用同一判準。
- 承既有判斷「一年 365 筆，資料量可忽略」。
- **不採 C（標記為不需精準追蹤）**：與本 Event 的立案理由直接衝突——
  「快照是六維成長軌跡的唯一憑據，某日漏產生即該日歷史永久缺失、無法回補」。
- **不採 B（2 年後清除）與降頻保存**：兩者皆以降低資料完整性換取成本，同樣與立案理由相衝。

## 儲存成本：現階段不處理（使用者裁示）

使用者追問「有什麼方法兼顧儲存成本」，助理提供量級試算與四種方法：

| 規模 | 一年 | 十年 |
|---|---|---|
| 1 萬使用者 | 約 0.36 GB | 約 3.6 GB |
| 10 萬使用者 | 約 3.6 GB | 約 36 GB |
| 100 萬使用者 | 約 36 GB | 約 360 GB |

| 方法 | 影響模型 |
|---|---|
| ① 冷熱分層儲存 | 否，純實作，成本可降約一個數量級 |
| ② 時序壓縮／欄式儲存 | 否，純實作 |
| ③ 舊資料降頻 | **是**，降低會員權益的解析度 |
| ④ 只在變動時寫入 | **是**，模型已明確否決過 |

**使用者裁示「這不用處理，等未來遇到問題再看」**——現階段不納入模型，
僅於規範中註明：成本若日後成為問題，由實作層以 ①② 處理，不以犧牲資料完整性換取。
