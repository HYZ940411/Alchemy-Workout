# 釐清問題

訓練紀錄 Aggregate 目前僅定義「重量」與「次數」兩個欄位，但模型多處引用其他資料（訓練日期、訓練時長、總訓練量、已完成組數、中斷與否、所屬動作、關聯本次訓練課表）。訓練紀錄的完整欄位、層級結構與狀態機為何？

# 定位

流程：訓練紀錄流程、訓練結算流程
元素：Aggregate「訓練紀錄」
細節：D2 欄位定義、D5 生命週期與狀態機、E3 Event → Aggregate 一致性。
既有引用但無欄位承接者：Read Model「訓練歷史」需「日期、課表名稱、總訓練量、訓練時長」；訓練紀錄流程 Postcondition「訓練紀錄進入『已中斷』終止狀態」（狀態機未定義）；「快照帶入最近一次該動作的實際重量」需可依動作查詢；AI 訓練品質評分需「每組耗時」。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 兩層結構：訓練紀錄（表頭：使用者 ID、本次訓練課表 ID、開始時戳、結束時戳、狀態、總訓練量、已完成組數）＋ 組紀錄（動作 ID、組序、重量、次數、完成時戳）；狀態機為 進行中 → 已完成 / 已提前結束 / 已中斷（三者皆終止） |
| B | 同 A 的欄位，但總訓練量與已完成組數不儲存，一律由組紀錄即時彙總 |
| C | 單層結構：一次訓練即一筆訓練紀錄，組明細以巢狀集合表達，不拆為子 Aggregate |
| D | 兩層結構且組紀錄獨立為第 43 個 Aggregate（比照留言自貼文獨立的裁決） |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響訓練紀錄 Aggregate 的全部欄位與狀態機、Read Model「訓練歷史」兩種檢視的欄位來源、能力值提升公式的訓練量計算輸入、個人排行榜分數的換算輸入、快照帶入上次重量的查詢路徑、AI 訓練品質評分三個維度的判讀依據，以及「累積訓練次數」的計數來源。

# 解決結果

**選項 A**

訓練紀錄為單一 Aggregate，其下含「組紀錄」子聚合（結構比照商品與商品規格）。

**表頭欄位（7 個）**：使用者 ID、本次訓練課表 ID、開始時戳、結束時戳、狀態、總訓練量、已完成組數
**組紀錄欄位（5 個）**：動作 ID、組序、重量、次數、完成時戳
**狀態機**：進行中 →（已完成 / 已提前結束 / 已中斷），三者皆為終止狀態

**兩條不變條件**
- 總訓練量 ＝ 各組紀錄「重量 × 次數」的累加（徒手動作代入體重係數換算後的重量）
- 已完成組數 ＝ 組紀錄的筆數

**三個衍生值不另存欄位**：訓練時長（結束時戳 − 開始時戳）、課表名稱（經本次訓練課表取來源課表）、
依肌群分別累加的訓練量（由組紀錄的動作 ID 取所屬肌群後分組累加）

理由：
- 兩層為必要 —— 「快照帶入最近一次該動作的實際重量」要求跨訓練、依動作查詢單組資料，
  單層巢狀做不到而不掃描全部歷史
- 總訓練量與已完成組數採儲存欄位，承粉絲數的既有裁決；且訓練紀錄結算後凍結，
  其彙總值是永遠不會失效的快照
- 排除 D（組紀錄獨立為 Aggregate）：留言獨立的理由是「可被檢舉，需獨立身分供指涉」，
  組紀錄無外部指涉，亦不脫離所屬訓練單獨存在
