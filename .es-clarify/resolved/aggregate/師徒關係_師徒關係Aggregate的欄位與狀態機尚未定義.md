# 釐清問題

「師徒關係」為〈獨立 Aggregate 清單〉45 項之一，且被師徒任務、師徒問答、每週互動評分、帶徒名額佔用、3 天冷卻與恢復路徑等六處引用，但 00_全域規範中**無任何欄位定義與狀態機**。其欄位與狀態機為何？

# 定位

流程：師徒互動流程
元素：Aggregate「師徒關係」
細節：D1 Aggregate 識別與邊界、D2 欄位定義、D5 生命週期與狀態機。〈教官聲望 Aggregate〉之〈每週互動評分〉已裁定「師徒關係 Aggregate 新增欄位『最近一次評分所屬週』」，但該 Aggregate 本身從未定義，該欄位無處可掛。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 欄位＝教官 ID、學徒 ID、建立時戳、狀態、最近一次評分所屬週、解除時戳；狀態值域三值：生效中 / 已解除 / 已恢復。恢復後回到生效中，「已恢復」不作為獨立狀態 |
| B | 同 A 的欄位，狀態值域二值：生效中 / 已解除（終止）；恢復時**新建一筆**師徒關係，原筆維持已解除，供歷史稽核 |
| C | 同 A 的欄位加上「申請中」狀態（值域：申請中 / 生效中 / 已解除），將師徒申請併入本 Aggregate，不另立申請實體 |
| D | 同 A，另加「解除方」欄位（教官 / 學徒 / 系統—因封鎖或教官資格撤銷），供 3 天冷卻與學徒豁免規則判定 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響師徒任務與師徒問答的「師徒關係 ID」外鍵、帶徒名額佔用數的計算（已建立的師徒關係數）、「解除後 3 天內不得與其他對象建立師徒關係」的判定基準欄位、「師徒關係已恢復」的 Precondition、每週互動評分的去重、以及〈Read Model：師徒互動頁〉與教官清單的「目前帶徒數」來源。
相關已解決項目：`resolved/aggregate/教官已指派師徒任務_師徒任務與問答的Aggregate歸屬與欄位.md`、`resolved/aggregate/教官帶徒上限_帶徒上限的初始值與提升幅度.md`（名額佔用規則）、`resolved/rule/使用者已申請師徒關係_一位學徒可否同時有多位教官.md`、`resolved/rule/教官資格已撤銷_撤銷時既有師徒關係與進行中任務如何處理.md`。

# 解決結果

**選項 D ＋ 師徒申請另立為第 46 個 Aggregate。**

## 師徒關係 Aggregate

欄位：教官 ID、學徒 ID、建立時戳、狀態、解除時戳、**解除原因**、最近一次評分所屬週。
狀態**二值**（生效中 / 已解除），已解除非終止狀態，恢復時**同一筆轉回生效中**。

- **加「解除原因」的理由**（D 與 A 的差別）：模型已定案「教官資格撤銷時，
  學徒不適用解除後 3 天冷卻期」，沒有這一欄則系統看到一筆已解除時判不出該不該套冷卻期。
  值域：教官方 / 學徒方 / 封鎖 / 教官資格撤銷。
- **不採 B（恢復時新建一筆）**：「師徒關係已恢復」的 Postcondition 為
  「雙方恢復為師徒關係」並重新佔用名額，語意為同一段關係接回去；
  新建會使既有師徒任務與師徒問答的外鍵指向舊筆。
- **不採 C（將申請併入本 Aggregate）**：一位學徒可同時向多位教官申請、卻只能有一段生效關係，
  併入後「一位學徒同時僅能有一位教官」的唯一性約束在同一張表上寫不出來；
  且師徒申請有自己的生命週期（168 小時逾期、可拒絕、拒絕後可立即再申請）。

## 師徒申請 Aggregate（新增，獨立 Aggregate 清單 45 → 46）

欄位：申請者、對象、申請方角色、申請時戳、狀態（申請中 / 已接受 / 已拒絕 / 已逾期）。

- 建立本 Aggregate 的原因：〈帶徒上限設定〉明訂「名額佔用數 ＝ 已建立的師徒關係數 ＋
  **申請中的師徒申請數**」，但該資料在模型中無處存放；四個 Event
  （使用者已申請師徒關係、對方已接受申請、對方已拒絕申請、師徒申請已逾期）
  皆在改一個不存在的東西的狀態。
- **與「教官申請」為兩個不同 Aggregate**，已於模型中明文區別：
  前者為使用者之間的拜師申請，後者為申請取得教官資格。
