# 釐清問題

訓練紀錄流程的檔名與首行標題仍寫「循環：使用者已記錄重量 > 組間休息已結束」，其中「使用者已記錄重量」已棄用併為「使用者已記錄該組成績」，應如何統一？

# 定位

流程：訓練紀錄流程
元素：Event「使用者已記錄該組成績」（曾用名：使用者已記錄重量）
細節：統一語言（F1）；檔名與標題的術語一致性。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 標題與檔名一併改為「訓練紀錄流程（循環：使用者已記錄該組成績 > 組間休息已結束）」 |
| B | 僅改首行標題，檔名維持不動（避免既有連結失效） |

# 解決結果

**選項 A｜檔名與標題一次改對（Event 名 ＋ 循環節點）**

- 檔名由 `訓練紀錄流程（循環：使用者已記錄重量 > 組間休息已結束）.md`
  更名為 `訓練紀錄流程（循環：使用者已完成該組 > 組間休息已結束）.md`（以 `git mv` 保留歷史）。
- 首行標題同步更新。
- 詞彙表登記「使用者已記錄重量」為「使用者已記錄該組成績」的曾用名。
- 一併移除檔名與標題中的零寬空格。

循環節點取「使用者已完成該組」而非「使用者已記錄該組成績」：
驅動迴圈前進的是完成（勾選 → 進度條前進 → 休息開始 → 休息結束 → 下一組），
記錄則是往旁邊寫實績，不推動迴圈。兩者由同一次勾選同時產生，但職責不同。

不採僅改 Event 名（選項 B）：會把迴圈端點標成不推動迴圈的 Event，
讀檔名者會誤以為「記錄完就休息」。
不採簡化為 `訓練紀錄流程.md`：循環資訊寫在檔名為本批流程檔的既有慣例。

**註**：`.es-clarify/resolved/` 內既有檔案對舊路徑的引用不予修改 ——
resolved 為歷史紀錄，反映當時的事實，不回溯改寫。
