# 釐清問題

模型中出現十餘種「獎勵已發放」Event（註冊 / 新手任務 / 簽到 / 訓練 / 分享 / 發文 / 按讚 / 留言 / 師徒任務 / 限時任務 / 回歸任務 / 三種排行獎勵），獎勵的種類與資料結構為何？是否共用同一個 Aggregate？

# 定位

流程：全流程
元素：Aggregate：獎勵（模型中尚未定義）；Event：多條流程中的各種「獎勵已發放」
細節：隱含但未明確定義的 Aggregate（D1）；統一語言（F1）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 單一獎勵 Aggregate，獎勵內容為多種資源的組合（經驗值 / 能力值 / 虛擬貨幣 / 道具），來源為其欄位 |
| B | 單一獎勵定義 Aggregate 加上「發放紀錄」Aggregate，兩者分離 |
| C | 不建立獎勵 Aggregate，各流程的獎勵直接寫入對應數值 Aggregate，「獎勵已發放」僅為連帶 Event |
| D | 依獎勵來源拆為任務獎勵 / 訓練獎勵 / 社群獎勵 / 排行獎勵四個 Aggregate |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響獎勵 Aggregate 的結構、十餘個「獎勵已發放」Event 是否可統一定義、各獎勵 Event 的 Postcondition 內容（連帶產生哪些數值提升 Event）、以及獎勵內容是否可由管理員調整。

# 優先級

High

# 解決結果

B — 獎勵拆為兩個 Aggregate，結構與成就（第 29 題）一致：

- **獎勵定義**（平台級）：各來源的獎勵內容與數量，可調整
- **獎勵發放紀錄**（每使用者）：已獲得的獎勵與發放時點，寫入後不再變動

獎勵內容為多種資源的組合，可含經驗值、能力值、虛擬貨幣、道具。

實際盤點結果為 **15 個**「⋯獎勵已發放」Event（原釐清項目描述為「十餘種」，
經 grep 全流程檔確認為 15 個，已列表寫入全域規範）。
使用者未表態是否合併，依提問時之聲明**維持 15 個獨立 Event**。

# 連帶影響

- 第 26 題的獨立 Aggregate 清單由 25 項調整為 26 項（「獎勵」拆為兩項），屬細化非推翻。
- `rule/發文獎勵已發放_互動獎勵是否有每日發放上限.md`、
  `rule/按讚獎勵已發放_取消按讚或刪除留言時獎勵與成就是否回收.md`：
  答案須落在獎勵發放紀錄上，且受「寫入後不再變動」約束（回收須以新紀錄表達，不可竄改原紀錄）。
