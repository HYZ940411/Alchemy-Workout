# 釐清問題

「對話往返內容須完整留存」所指的資料，應由哪一個 Aggregate 承接？其欄位、保存期限與訓練紀錄的關係為何？

# 定位

流程：AI 訓練前調整流程、AI 訓練中調整流程
元素：Aggregate（尚未定義）；Event「AI 已再次確認需求」「使用者已確認需求」的 Postcondition
細節：Aggregate 識別與邊界（D1）；欄位定義（D2）；Aggregate 間關係（D4）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 新增獨立「AI 調整對話」Aggregate，欄位含往返序列、時間戳、AI 版本；與本次訓練紀錄一對一關聯，永久保存 |
| B | 新增獨立「AI 調整對話」Aggregate，同 A，但僅保存 90 天，逾期自動清除 |
| C | 併入訓練紀錄 Aggregate，作為其對話欄位，隨訓練紀錄一同保存 |
| D | 不建模為 Aggregate，對話僅寫入應用日誌，留在系統邊界之外 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響三條 AI 流程的 Postcondition 是否可驗收、獨立 Aggregate 清單（`00_全域規範.md`）是否新增一項、以及 AI 品質分析與申訴的資料來源。
承接 `.es-clarify/pending-gaps.md` 之 G1；相關已解決項目：`resolved/event/AI已再次確認需求_對話往返是否應建模為業務Event.md`（選項 A）。

# 解決結果

**選項 A（錨點與基數經修正）**：新增獨立「AI 調整對話」Aggregate，永久保存。

| 欄位 | 型別 | 說明 |
|------|------|------|
| 錨點 | 本次訓練課表 ID | 對話所屬的本次訓練 |
| 來源 | 列舉 | 訓練前調整 / 訓練中調整 |
| 往返序列 | 有序集合 | 逐則對話內容，含發話方與內容 |
| 每則時間戳 | Timestamp | 沿用 Event 共通時戳規範 |
| AI 版本 | 字串 | 產出建議的 AI 模型版本 |

**對原選項 A 的兩處修正**：

1. **錨點由「訓練紀錄」改為「本次訓練課表」**：訓練前調整發生於開始訓練之前，該時點訓練紀錄尚未存在，掛不上去。
   本次訓練課表於選擇課表時即產生（見第 19 題），是唯一貫穿全程的錨點。此問題同時使選項 C 不可行。
2. **一對一改為一對多**：同一次訓練可能先有訓練前調整、中途又有訓練中調整，為兩段獨立對話。

**保存期限採永久而非 90 天**：Postcondition 明寫用途含「申訴」，而第 11 題定案的申訴機制未設時效上限，
90 天清除會使超期申訴無據可查。對話為純文字，量體小，永久保存成本低於清除排程的維護成本。

- AI 自動優化訓練流程無對話往返，不產生本 Aggregate。
- 獨立 Aggregate 清單 34 → 35 項。
