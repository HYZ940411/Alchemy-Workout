# 釐清問題

動作 Aggregate 的「所屬肌群」僅有 6 個重訓維度（胸 / 背 / 腿 / 肩 / 手 / 核心），無有氧 / 心肺概念。跑步、飛輪、划船等有氧項目是否納入模型？若納入，其訓練量如何計算、是否新增第 7 個能力值維度、是否計入個人排行榜分數？

# 定位

流程：訓練紀錄流程、訓練結算流程、註冊流程
元素：Aggregate「動作」的所屬肌群值域；Aggregate「使用者」的能力值欄位；Event「能力值已提升」
細節：D1 Aggregate 邊界、D2 欄位值域、D3 內部不變條件。健身目標的常見目標類四項中，「減重」與「提升體能」主要靠有氧達成，此二類使用者做完一小時有氧，六維能力值與個人排行榜分數皆無變化（訓練量 ＝ 重量 × 次數 × 組數，有氧無此三者）。

# 解決結果

**選項 B**

有氧動作納入模型，但**不新增能力值維度**。

| 項目 | 重訓 | 有氧 |
|------|------|------|
| 所屬肌群 | 六選一，必填 | 空值 |
| 計入能力值 | 是（依所屬肌群提升該維） | **否** |
| 計入經驗值 | 是 | 是 |
| 計入個人排行榜分數 | 是 | 是 |

- 動作 Aggregate 新增「動作類型」欄位（重訓 / 有氧），與重訓共用同一 Aggregate
- 「所屬肌群」欄位改為「重訓類必填六選一；有氧類為空值」
- 有氧不觸發「能力值已提升」，比照使用者自建動作的既有處理方式
- 能力值維持 6 個肌群維度，為純重訓實力指標

理由：
- 有氧計入排行榜與經驗值，使「減重」與「提升體能」兩類使用者不至於零回饋
  （此二項為註冊必填的常見目標類四項中的兩項，主要靠有氧達成）
- 排除 C（折算至既有六維）：只跑步的人腿部能力值會持續上升，而其深蹲能力其實沒變，
  六維語意會被汙染、雷達圖日後無法解讀
- 與「訓練屬性（力量 / 耐力 / 爆發）本階段不進模型」的既有取捨方向一致：先把重訓做完整
