# 釐清問題

團隊任務流程已定案「限時任務獎勵未領取者於當日結束時補發至獎勵信箱」，但獎勵信箱 Aggregate 的「來源」值域不含限時任務，且同節仍記「限時任務⋯尚未定案、不進信箱」——以哪一方為準？

# 定位

流程：團隊任務流程、每日任務流程
元素：Aggregate — 獎勵信箱（來源欄位值域）；Event — 獎勵已補發至信箱
細節：`02_Aggregate定義.md`〈獎勵信箱 Aggregate〉來源值域為「每日任務 / 個人排行 / 團隊日常排行 / 團隊限時排行 / 補簽的簽到獎勵」，且〈不需要信箱的點擊領取來源〉將限時任務列為未定案；`團隊任務流程.md` 則已明文「未領取者於當日結束時補發至獎勵信箱，不作廢」

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 以流程檔為準：來源值域增列「限時任務」，並移除〈不需要信箱的點擊領取來源〉中的未定案敘述；寫入路徑增列第三條（每日結束時補發） |
| B | 以 Aggregate 為準：限時任務獎勵不進信箱，未領取者當日失效（推翻流程檔的定案） |
| C | 限時任務獎勵改為直接發放、不需領取，信箱與領取路徑皆不涉及 |
| Short | 提供其他簡短答案（<=5 字） |

# 解決結果

**A**：以流程檔為準，獎勵信箱的「來源」值域增列**限時任務**。

- 寫入路徑增列第三條〈當日結束補發〉：「成員已完成一次限時任務」已發生，
  且於當日結束（當地 04:00）仍未領取。
- 〈不需要信箱的點擊領取來源〉由五者減為**四者**（新手任務、回歸任務、師徒任務、成就）；
  限時任務改列為例外，理由為其**每日換一組**，昨日的任務卡當日結束即消失，未領取的獎勵無處可掛。
- 承既有裁決「『當日有效』管的是完成任務的期限，非領取獎勵的期限」。

**使用者於本題提問「來源可否不記錄、僅以信件名稱判斷」**，已說明並寫入模型：
**「來源」為機器判讀欄位、不可省略** —— 領取時系統須依其決定產生哪一個「⋯獎勵已發放」Event；
信箱標題為衍生值（由來源與獎勵定義推導），不得反過來以標題字串比對回推來源
（標題為文案，會因改版與多語系而變動）。畫面上是否顯示來源分類屬 Read Model 範疇，
不影響本欄位的存在。
