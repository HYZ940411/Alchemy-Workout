# 釐清問題

使用者能否事後更新註冊問卷的四個欄位（每週健身天數、每次健身時長、健身目標、健身經驗）？
是否每 2–3 個月主動詢問一次？更新後是否重新推薦課表？

# 定位

流程：註冊流程、每日簽到流程（詢問時機）
元素：Aggregate — 使用者（四個欄位）；Command — 是否沿用註冊時的既有 Command
細節：本項由使用者於第十一輪第 27 題提出（「每次健身時間也會因為不同情況而改變啊」），
非 discovery 原有項目。現況為四項填完即凍結、無任何更新路徑；
而模型自身已記載「健身經驗為註冊時自填一次、其後不更新的欄位，作為長期分級基準會逐漸失真」。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 設定頁可改 ＋ 每 90 天於簽到畫面詢問；更新後呈現新推薦但不自動替換 |
| B | 同 A，但更新後**立即重新推薦並自動替換**當前訓練計畫 |
| C | 只開放設定頁隨時改，不主動詢問 |
| D | 只問三項，健身經驗改由系統依訓練資料判斷 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

使用者 Aggregate 的四個欄位；每日簽到流程的詢問時機；「訓練計畫已推薦」的觸發源；設定頁 Read Model

# 優先級

Medium

# 解決結果

**B**：四個欄位可事後更新，每 90 天於簽到畫面詢問一次，**更新後立即重新推薦並自動替換當前訓練計畫**。

- **更新路徑兩條**：設定頁隨時可改；每 90 天於簽到畫面詢問（**可跳過，不得阻擋簽到**，
  跳過者沿用原值且該週期內不再詢問）。
- **沿用註冊時的既有 Command 與 Event**，Event 攜帶「來源＝註冊 / 設定頁更新 / 週期更新」，
  不新增任何 Event ——承〈體重的時效性〉的既有處理方式。
- **「訓練計畫已推薦」因此成為多對一 Event**（完成註冊 / 問卷更新）。
- **週期取 90 天**：四者不若體重會週週變動，一年 4 次（體重為 26 次）不致騷擾；
  且對應〈錨點分佈〉「練 3–6 個月」的進步級距。
- **自動替換當前訓練計畫**（使用者裁決 B，助理原推薦 A）：
  - 進行中的訓練不受影響（本次訓練課表已於選擇時快照並與來源脫鉤）。
  - `[已知風險]` 使用者可能正依當前課表進行一個訓練週期，自動替換會中斷其進度；
    註冊當下「推薦為單向指派、使用者不可拒絕」的規則成立於「彼時尚無進度可毀」的前提，
    本裁決將其延伸至有進度的情境。**使用者明示接受**，列為上線後的觀察項目。
  - 替換不刪除任何資料，原計畫仍可於課表選擇頁自行選回。
- **健身經驗亦納入本機制**，不採「由系統依累積訓練次數自動分級」（須另立一套分級邏輯）。
