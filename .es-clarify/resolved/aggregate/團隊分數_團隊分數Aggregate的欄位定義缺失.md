# 釐清問題

團隊分數為獨立的計分單位（兩個分數、兩個排行榜、依人數分組），但〈團隊分數 Aggregate〉一節只有規則、沒有任何欄位表——其欄位、型別與不變條件為何？

# 定位

流程：團隊任務流程、排行榜週期結算流程
元素：Aggregate — 團隊分數
細節：`02_Aggregate定義.md`〈團隊分數 Aggregate〉為全檔少數沒有欄位表的 Aggregate；規則中已隱含需要的欄位有：團隊日常分數、團隊限時分數、本週期曾達到的最高成員數（分組依據）、是否曾達 3 人（獎勵資格）

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 補上欄位表：團隊 ID、月累計日常分數、月累計限時分數、本週期最高成員數（int）、本週期是否曾達人數下限（bool）、週期起訖 |
| B | 同 A，另加「各成員本週期已貢獻分數」子集合（為〈重新分隊期不累加〉與〈中途加入僅計加入後〉兩條規則所必需） |
| C | 不另立欄位表：團隊分數併入團隊 Aggregate 作為其欄位群，自〈獨立 Aggregate 清單〉的認定中一併釐清 |
| Short | 提供其他簡短答案（<=5 字） |

# 解決結果

**B**：補上欄位表，並含「各成員本隊已貢獻分數」子集合。

**欄位**：團隊 ID、週期起訖、月累計日常分數、月累計限時分數、
本週期最高成員數（int 0–5，**單調遞增**）、本週期是否曾達人數下限（bool）。

**子集合**：各成員的使用者 ID ＋ 本隊已貢獻分數（int ≥ 0），本週期曾為成員者各一筆。

- **不變條件：月累計日常分數 ＝ 各成員「本隊已貢獻分數」的總和** ——
  該條件使資料漂移可被自動偵測；無子集合時團隊分數為孤兒數字，錯了無從發現亦無從回推。
- 量級可忽略（每隊每週期至多 5 筆整數）。
- 成員退出時該筆保留不刪（承「分數計入即歸團隊所有」）。
- 週期結算時全部欄位歸零並重寫週期起訖，歸零前先寫入排行榜歷史紀錄，比照個人排行榜分數。
- **不併入團隊 Aggregate**（C）：團隊資料長期存在、本 Aggregate 每月歸零；
  承使用者 Aggregate 排除每日歸零計數器的既有理由。因此〈獨立 Aggregate 清單〉增列團隊分數。

**使用者於本題追問「B 好維護嗎」**，已說明：子集合帶來的不變條件使錯誤可被偵測，
量級極小；真正難維護的是 C（把每月歸零的東西塞進長期存在的資料）。

**連帶修正的下游敘述**：
- 〈單一團隊歸屬與換隊冷卻〉的「該防刷職責⋯（尚未定案）」→ 已定案（增量累加）
- 〈解散〉與 `團隊組隊流程.md` 兩處「團隊分數為成員個人分數的加總」→ 改為團隊自有的計數器
