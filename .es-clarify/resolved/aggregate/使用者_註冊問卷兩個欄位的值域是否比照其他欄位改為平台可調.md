# 釐清問題

註冊問卷 9 項必填的值域維護方式不一致：健身目標與健身經驗存於各自的設定 Aggregate（可調），性別寫死（已裁決），而「每次健身時長」與「健身器材」的可調性從未被裁決——兩者是否比照改為平台級可調？

# 定位

流程：註冊流程
元素：Aggregate — 使用者（每次健身時長、健身器材的值域來源）
細節：pending-gaps-3 之 I13。健身器材同時是訓練計畫推薦的**第一順位**比對維度，地位與健身經驗相同卻採不同維護方式；每次健身時長目前寫死於使用者 Aggregate 的欄位定義

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 兩者皆改為平台級可調：新增（或沿用器材設定 Aggregate）承載值域，比照健身目標與健身經驗的既有處理 |
| B | 僅健身器材改為可調（其為推薦的硬約束、第一順位）；每次健身時長維持寫死（區間列舉為產品判斷，不會變動） |
| C | 兩者皆維持寫死，於欄位定義加註「刻意不可調」的理由，使三種維護方式的界線明文化 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

- 使用者 Aggregate 的欄位值域來源；可能新增設定類 Aggregate
- 訓練計畫 Aggregate 的「適用條件」欄位所引用的值域清單
- 〈平台級設定的軟體邊界〉右欄（值域清單類）的項目
- 相關已解決項目：`resolved/aggregate/使用者_使用者Aggregate的欄位與邊界尚未定義.md`

# 優先級

Low

# 解決結果

**B**：只有**健身器材**改為平台可調；**每次健身時長**維持寫死。

- **健身器材改為可調**：其為訓練計畫推薦的第一順位比對維度（器材 → 經驗 → 常見目標），
  地位與健身經驗相同卻採不同維護方式；且家用器材種類逐年增加，值域會變。
  沿用既有的〈器材設定 Aggregate〉承載粗層 3 級，不新增 Aggregate。
- **每次健身時長維持寫死**：其為產品對「一次訓練該多久」的切法，不隨外部世界改變；
  真要改切法（如三格或五格）會連帶影響訓練計畫的「適用條件」欄位、須重新對應既有課表，
  屬改版而非日常維運，做成可調參數反而誤導。
- 一併於〈使用者 Aggregate〉補上三種維護方式的對照表，使界線明文化。

**使用者於本題提出「每次健身時間也會因為不同情況而改變」**，經釐清該訴求為
**使用者端能否更新自己的答案**（而非平台端的值域切法），已另建釐清項目
`aggregate/使用者_註冊問卷四個欄位可否事後更新與定期提醒.md`。
