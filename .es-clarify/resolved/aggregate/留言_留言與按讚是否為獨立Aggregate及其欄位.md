# 釐清問題

「留言」與「按讚」是否各自為獨立 Aggregate？其欄位與生命週期為何？

# 定位

流程：發文與互動流程、管理員管理社群流程
元素：Aggregate（尚未定義）；Event「互動者已留言」「互動者已按讚貼文」「留言已編輯」「留言已刪除」「按讚已取消」
細節：Aggregate 識別與邊界（D1）；欄位定義（D2）；Event → Aggregate 一致性（E3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 留言為獨立 Aggregate（作者、貼文 ID、文字、時間、狀態）；按讚為貼文的關聯集合，非獨立 Aggregate |
| B | 留言與按讚皆為獨立 Aggregate，各有自己的狀態機 |
| C | 兩者皆併入貼文 Aggregate，作為其子集合 |
| D | 留言為獨立 Aggregate 且支援巢狀回覆（留言的留言） |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響貼文 Aggregate 的「按讚數 / 留言數」衍生欄位來源、檢舉對象類型「留言」所指涉的標的、
互動獎勵與成就的計數基準，以及獨立 Aggregate 清單（`00_全域規範.md`）是否新增項目。
本項為新掃描發現，非承接 `pending-gaps.md`。依賴 `aggregate/貼文_貼文的狀態機與編輯歷史為何.md` 的刪除語意。

# 優先級

High

# 解決結果

**選項 A**：留言為獨立 Aggregate；按讚為貼文的關聯集合，非獨立 Aggregate。

**留言 Aggregate 欄位**：作者、貼文 ID、文字內容、發布時間、狀態。

- 留言可被檢舉，檢舉對象類型「留言」指涉其 ID —— 這一點直接排除選項 C（併入貼文即無獨立身分可供指涉）。
- 不支援巢狀回覆（不採 D）：模型無「回覆留言」Event，互動成就門檻亦只計留言次數，屬新增功能而非釐清。
- 留言的狀態值域待貼文狀態機定案後給定（待決策 Partial），兩者一併定義，避免兩處各定一套。

**按讚的建模方式**：

- 按讚無內容、不可編輯、不可被檢舉，只有存在與否兩態，升格為 Aggregate（選項 B）成本不對稱。
- 「互動者已按讚貼文」新增一筆關聯；「按讚已取消」移除該筆關聯。
- 唯一鍵為 貼文 ID ＋ 互動者 ID。
- 貼文的「按讚數」「留言數」皆為衍生欄位。

- 獨立 Aggregate 清單 35 → 36 項。
