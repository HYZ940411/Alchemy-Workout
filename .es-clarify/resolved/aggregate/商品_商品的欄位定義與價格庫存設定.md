# 釐清問題

商品 Aggregate 的欄位定義為何？實體商品的尺寸與庫存如何建模（單一庫存或分尺寸庫存）？

# 定位

流程：管理員商品上架流程、實體商品購買流程、虛擬商品購買流程
元素：Aggregate：商品（模型中尚未定義）；Event：管理員已設定商品資訊
細節：隱含但未明確定義的 Aggregate（D1）；欄位定義與不變條件（D2、D3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 單一商品 Aggregate，含類型（實體 / 虛擬）/ 名稱 / 價格 / 圖片 / 上架狀態；實體商品的尺寸為子項目各自有獨立庫存 |
| B | 單一 Aggregate，庫存為商品層級單一數值，尺寸僅為選項不影響庫存 |
| C | 實體商品與虛擬商品拆為兩個 Aggregate，欄位差異大 |
| D | 單一 Aggregate 加上「商品規格」子聚合，每個規格有獨立價格與庫存 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響商品 Aggregate 的欄位與子結構、管理員已設定商品資訊的 Postcondition、「使用者已選擇尺寸與數量」的庫存扣減對象、以及「商品已售完」的判定範圍（單一規格或全商品）。

# 優先級

High

# 解決結果

D（含使用者指定的 Event 粒度） — 使用者原話：「D 尺寸層級」。

商品為單一 Aggregate，其下含「商品規格」子聚合：

- 商品層級欄位：類型（實體 / 虛擬）、名稱、圖片、上架狀態
- 商品規格層級欄位：規格名稱、價格、庫存（各規格獨立）

- 實體商品的規格為尺寸；虛擬商品僅有一個預設規格
- 實體與虛擬商品共用同一個 Aggregate，不拆為兩個（未採 C）
- 「商品已售完」為**規格（尺寸）層級**的 Event，攜帶售完的規格資訊
- 某一規格售完不影響其他規格

# 解決的既有缺口

**`.es-clarify/pending-gaps.md` G10 已消解**：
「商品已售完的粒度未定義（單一尺寸 vs 全商品）」在本題定案為規格層級，
「某尺寸售完但其他尺寸有貨」現可在模型中表達。

# 承接的既有裁決

第 13 題：「商品已售完」為獨立 Event，由庫存扣減至 0 時系統自動產生；
售完不自動下架，改由 Read Model 讓購買按鈕不可點擊。
本題進一步確定該 Event 為規格層級，Read Model 的按鈕控制亦應為規格層級。
