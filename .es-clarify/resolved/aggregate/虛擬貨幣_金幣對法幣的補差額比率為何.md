# 釐清問題

虛擬商品「虛擬貨幣＋真實金流」併用時，金幣對法幣的補差額比率如何定義？比率變動時既有訂單如何處理？

# 定位

流程：虛擬商品購買流程
元素：Aggregate「虛擬貨幣（金幣）」；Event「虛擬貨幣已扣除」「使用者已支付」的併用 Precondition
細節：Aggregate 內部不變條件（D3）；數值邊界（C3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 固定比率（如 1 金幣＝1 元），比率為平台級參數由管理員設定，訂單成立時鎖定當時比率 |
| B | 固定比率且寫死於系統，不可調整 |
| C | 不允許併用：金幣不足時只能全額真實金流或先儲值，無補差額情境 |
| D | 各商品規格自訂可折抵的金幣上限與折抵率，非全站單一比率 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響虛擬商品購買流程的併用 Precondition、訂單 Aggregate 的金額欄位計算、金幣儲值面額設計，以及購買已失敗之「餘額不足」判定基準。
承接 G3；與 `event/金幣_金幣儲值的流程與Event全數缺失.md`（G23）為同一組決策，宜併題處理。
相關已解決項目：`resolved/aggregate/虛擬貨幣_虛擬貨幣的種類取得與消耗規則.md`。

# 優先級

High

# 解決結果

**選項 A**：固定比率，平台級可調參數，訂單成立時鎖定當時比率。

| 參數 | 初始值 |
|------|--------|
| 金幣對法幣比率 | 1 金幣 ＝ 1 元 |

- 全站單一比率，不依商品或規格而異。
- 補差額金額 ＝（商品價格 − 可折抵金幣數）依比率換算後的法幣金額。
- **訂單成立時鎖定當時比率**——此為本題重點：無此條則管理員於使用者付款過程中調整比率會造成
  「結帳頁顯示補 50 元、實際扣 80 元」的爭議。鎖定後既有訂單不受影響，不需補償邏輯。
- 管理員可調與模型慣例一致（階級門檻、任務池、獎勵定義、權益設定皆然）；寫死（選項 B）會使調整比率需改版送審。
- 不採選項 C：會推翻虛擬商品購買流程既有的「兩者併用（虛擬貨幣不足時以現金補差額）」裁決。
- 不採選項 D：逐規格折抵率維護成本高，且使用者難以理解折抵差異。
- 本比率同時為金幣儲值流程的定價基礎。

**連帶影響**：第 5 題將「儲值面額與贈送規則」標記為待決策並註明須待比率定案，本題定案後該項已有計算依據，
惟面額本身仍需另行給定。
