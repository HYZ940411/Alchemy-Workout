# 釐清問題

使用者執行 Command「選擇尺寸與數量」「選擇數量」「確認購買」前必須看到什麼？商品頁除既有註記的庫存狀態外，還需呈現哪些欄位（金幣餘額、可折抵金額、補差額試算）？

# 定位

流程：管理員商品上架流程、實體商品購買流程、虛擬商品購買流程
元素：Read Model（尚未正式定義）；支撐 Command「選擇實體商品」「選擇尺寸與數量」「選擇虛擬商品」「選擇數量」「確認購買」
細節：D6 Read Model 識別、E4 Read Model → Command 支撐。
現況：管理員商品上架流程檔第 12 行有 `[Read Model] 商品頁需提供庫存狀態，供前端判定購買按鈕是否可點擊`，但未依〈Read Model 建立原則〉正式立項（缺服務的 Actor、支撐的 Command、欄位與來源、即時性）。

# 影響範圍

影響 Read Model 清單、商品 / 商品規格 / 虛擬貨幣 / 訂單四個 Aggregate 的查詢組合、「商品已售完」Postcondition 中「購買按鈕不可點擊並顯示暫無庫存」的資料來源、以及庫存扣減時機（現為待釐清）對庫存呈現即時性的要求。

# 解決結果

**選項 C** —— 商品基本資訊 ＋ 規格價格與庫存狀態 ＋ 金幣餘額與補差額試算 ＋ 收貨資訊預帶。即時。

| 欄位 | 說明 |
|------|------|
| 商品名稱、圖片、類型 | — |
| 各規格的價格 | 規格層級，各規格獨立定價 |
| 各規格的庫存狀態 | 有庫存 / 暫無庫存；供前端判定購買按鈕是否可點擊 |
| 我的金幣餘額 | 取自虛擬貨幣 Aggregate |
| **補差額試算** | 金幣不足時所需支付的法幣金額 |
| 收貨資訊預帶值 | 僅實體商品 |

- **補差額試算為必要**：承既有裁決「虛擬貨幣不足時以現金補差額」與「訂單成立時鎖定當時比率」，
  使用者於確認購買前若不知需付多少現金，該 Command 即無決策依據。
  該欄位為衍生值，比率調整時自然更新，不需改動 Read Model。
- 收貨資訊預帶：實體訂單有 5 個必填欄位，每次購買重填為純粹摩擦。
- **權限解鎖類虛擬商品不呈現庫存狀態**：承〈虛擬商品的兩個子類型〉，該類不適用庫存。

**不採 D**（購買人數或熱門度）：須新增跨訂單的統計欄位，
而商城品項少且多為平台自營，不具大型電商「靠銷量排除劣質賣家」的需求。
