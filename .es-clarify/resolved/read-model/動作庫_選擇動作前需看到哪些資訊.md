# 釐清問題

使用者執行 Command「選擇動作」（自訂訓練流程）前必須看到什麼？動作庫的篩選、排序、搜尋規則為何？平台動作庫與自建動作如何並呈？

# 定位

流程：自訂訓練流程
元素：Read Model（尚未定義）；支撐 Command「選擇動作」「建立自訂動作」
細節：D6 Read Model 識別（篩選、排序、分頁規則）、E4 Read Model → Command 支撐。
動作 Aggregate 已定義 8 個欄位（名稱、所屬肌群、所需器材、體重係數、預設組間休息秒數、示範內容、來源、建立者），但何者需呈現、如何找到動作皆未定義。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 依所屬肌群分頁（6 個肌群 ＋ 我的自建）＋ 名稱搜尋；每筆呈現名稱、所需器材、示範內容縮圖；依使用者累積練習次數排序（沿用訓練歷史的排序裁決） |
| B | 同 A，但預設以使用者註冊填入的健身器材篩選（僅顯示可執行的動作），可手動取消篩選 |
| C | 單一清單 ＋ 搜尋，不分肌群；每筆標明所屬肌群與器材 |
| D | 同 B，另標示「本動作不計入能力值」於自建動作，避免使用者誤以為自建動作可累積六維 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Read Model 清單、動作 Aggregate 的查詢維度與索引、自訂訓練流程「使用者已選擇動作」的前置資訊、以及「使用者自建動作不計入能力值」此一既有裁決是否需於選擇當下對使用者揭露。
相依：`aggregate/動作_有氧與心肺是否納入模型及第七個能力值維度.md`（若新增有氧類，分頁維度須一併調整）。
相關待釐清項目：`rule/使用者已建立自訂動作_自建動作的所屬肌群是否必填.md`。

# 優先級

High

# 解決結果

**選項 D** —— 依肌群分頁（6 肌群 ＋ 我的自建）＋ 名稱搜尋 ＋ 器材預設篩選 ＋
自建動作標示「本動作不計入能力值」；排序依累積練習次數由多到少。

## 附帶裁決：器材的兩層粒度（選項 B）

使用者指出既有的 3 級器材值域（健身房 / 居家器材 / 徒手）粒度過粗，
實際器材為啞鈴、槓鈴、彈力繩等具體品項。

| 層級 | 欄位 | 用途 |
|------|------|------|
| 粗（既有） | 所需器材 | 訓練計畫推薦比對（硬約束） |
| 細（新增） | 所需器材明細 | 動作庫的手動篩選 |

- 註冊流程的「使用者已選擇健身器材」**維持 3 級不變**，不改為複選品項。
- 推薦比對的既有規則完全不受影響。
- 明細篩選無預設值，須使用者手動選取：系統僅知其 3 級器材，不知實際擁有的品項。
- 不採全面改明細（選項 C）：推薦比對須改寫、既有訓練計畫的適用條件須重填、值域清單須重建。
