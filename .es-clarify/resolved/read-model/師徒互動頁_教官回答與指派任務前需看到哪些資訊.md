# 釐清問題

教官執行 Command「回答」「指派師徒任務」前必須看到什麼？學徒執行「提問」「完成師徒任務」「評分」前必須看到什麼？

# 定位

流程：師徒互動流程
元素：Read Model（尚未定義）；支撐 Command「提問」「回答」「指派師徒任務」「完成師徒任務」「評分該次問答」「評分該次師徒任務」「解除師徒關係」
細節：D6 Read Model 識別、E4 Read Model → Command 支撐。
師徒互動流程共 19 個 Command，其中 6 個為雙方的日常互動，全無 Read Model 支撐。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 單一師徒互動頁：待回答問答清單 ＋ 已指派任務清單（含狀態）＋ 對方基本資料（階級、六維能力值、近期訓練頻率）；即時 |
| B | 同 A，教官方另加學徒的訓練歷史摘要（近期各動作重量趨勢），供指派任務時判斷難度 |
| C | 同 B，學徒方另加「尚未評分的問答與任務」提示，供觸發評分 Command（評分連動教官聲望，未評分即聲望不變動） |
| D | 拆為兩個 Read Model：教官視角（我的全部學徒 ＋ 待處理事項彙總）與學徒視角（我的教官 ＋ 我的任務與問答） |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Read Model 清單、師徒關係 / 師徒任務 / 師徒問答三個 Aggregate 的查詢組合、教官聲望變動的觸發率（未評分即不變動，Read Model 是否提示評分將直接影響聲望機制的有效性）、以及帶徒上限提升的實際速度（門檻設計依據假設「每位學徒每週 2 次評分」）。
相關已解決項目：`resolved/aggregate/教官已指派師徒任務_師徒任務與問答的Aggregate歸屬與欄位.md`、`resolved/aggregate/教官帶徒上限_帶徒上限的初始值與提升幅度.md`。

# 解決結果

**選項 C** —— 學徒清單 ＋ 待回答提問清單 ＋ 進行中任務清單 ＋ 六維能力值與綜合能力等級
＋ 近期訓練摘要（日期、課表名稱、完成度）。即時。

- 六維能力值為指派任務的依據：無此資訊時教官只能依學徒口述判斷。
- 近期訓練摘要的必要性：能力值為長期累積結果，反映不出「這禮拜有沒有在練」。

## 近期訓練摘要對教官揭露的界線

**僅摘要層，不含逐組重量與次數。**

- 既有裁決〈訓練歷史不對外可見〉的標的為逐組原始紀錄，且明文「不提供開關」；
  摘要層不在其標的範圍內。
- 可對教官揭露的理由：師徒關係為雙方同意建立，與陌生人瀏覽個人檔案頁不同。
- **不採 D**（完整訓練歷史）：等同為教官開一個既有裁決明文排除的例外。
