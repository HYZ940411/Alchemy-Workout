# 釐清問題

補簽頁的日曆顯示範圍應如何定義，才能在月初也涵蓋到落在上個月的可補日期？

# 定位

流程：補簽流程
元素：Read Model：補簽頁（`04_ReadModel清單.md` L195–L219）
細節：「本月日曆」欄位（L208）與 7 天回補範圍（`02_Aggregate定義.md` L4191）不相容。

**本題不是重問補簽頁要有哪些欄位**。
`.es-clarify/resolved/read-model/補簽頁_補簽前需看到哪些資訊.md`（選項 A）
已裁決「日曆＋張數＋可恢復連續天數」三個欄位，該裁決成立不變；
本題補的是**日曆這個欄位的範圍怎麼定**。

# 白話說明

補簽頁的日曆欄位現在寫的是「**本月**日曆」（`04_ReadModel清單.md` L208）：

```
| 本月日曆 | 清單 | 每日一筆，狀態值域三值：已簽 / 未簽 / 可補簽 |
```

但可以補的日期是「最近 7 天」。這兩件事在月初會對不上。

**情境**：今天是 2026-09-03，使用者 08-28 到 09-01 之間都沒簽到，手上有 3 張券。

| 可補的日期 | 落在哪個月 | 本月日曆上看得到嗎 |
|-----------|-----------|-------------------|
| 2026-08-28 | 8 月 | ✗ 看不到 |
| 2026-08-29 | 8 月 | ✗ 看不到 |
| 2026-08-30 | 8 月 | ✗ 看不到 |
| 2026-08-31 | 8 月 | ✗ 看不到 |
| 2026-09-01 | 9 月 | ✓ |
| 2026-09-02 | 9 月 | ✓ |

日曆上只畫得出 9 月，使用者**點不到**那四天，等於每個月的前幾天補簽功能有一半是壞的。
而且愈接近月初愈嚴重：9 月 1 日打開補簽頁，可補的 7 天全部落在 8 月，
日曆上一格可點的都沒有。

`04_ReadModel清單.md` L214 明寫「採日曆而非日期清單：補簽是對特定日期的操作，
日曆使『斷在哪一天』一眼可見」——若那一天畫不出來，這個理由本身就不成立了。

# 多選題

| 選項 | 描述 | 推薦 |
|------|------|------|
| A | **改為「最近 N 天日曆」**，N 取自補簽設定的回補範圍（目前 7 天），顯示範圍恰好等於可補範圍，跨月自動涵蓋 | ★ |
| B | **改為「本月＋上月」兩個月日曆**，固定顯示兩個月 | |
| C | **維持本月日曆，另設一個「可補簽日期清單」入口**承接跨月的日期 | |
| D | **改為可左右翻月的完整日曆**，使用者自行翻到上個月 | |
| Short | 提供其他簡短答案（<=5 字） | |

# 推薦選項與理由

**推薦 A（最近 N 天日曆，N ＝ 回補範圍）。**

- **Read Model 只承載決策所需的資訊，是本模型已明文確立的原則**。
  `04_ReadModel清單.md` L188–L190 對簽到頁寫得非常直接：

  > 簽到頁僅承載「今天要不要簽」這一個決策，故只收今日是否已簽到一個欄位。
  > 連續天數、累計天數、歷史最長連續天數、連簽成就進度皆為回顧型資訊，不影響簽到決策，不納入本 Read Model。

  同一把尺量下來，補簽頁承載的是「這幾天要補哪一天」，可補範圍以外的日子都是回顧型資訊。
  N 天日曆是唯一「不多也不少」的選項。
- **A 會隨平台參數自動連動**。回補範圍是管理員可調的（`02_Aggregate定義.md` L4195），
  若哪天從 7 天改成 14 天，選 A 的日曆自己就跟著變長，選 B/C/D 都要另外再改一次 Read Model。
- **B 在月初仍可能不夠、在月底又顯得多餘**。而且「兩個月」這個數字與回補範圍沒有任何推導關係，
  是一個憑感覺的常數——本模型對這類常數一向要求說明基準（見 `補簽流程.md` L18 對售價的推導）。
- **C 等於承認日曆這個設計沒有做到它宣稱的事**，還多出一個入口要維護與驗收。
- **D 把責任推給使用者**：使用者得自己知道「還要往前翻一個月」才找得到那幾天，
  與 L214「一眼可見」的設計意圖相反。

**實作上的附帶說明**：選 A 之後日曆不再對齊月份格線，UI 上會是一條橫向的日期帶或
連續 N 格，這屬於呈現方式，不改變 Read Model 的欄位定義。

# 對 Gherkin 翻譯的影響

直接阻擋 `.gh-clarify/query/補簽頁_本月日曆的筆數與順序要不要斷言.md`。

該項要決定 Then 要不要斷言日曆的筆數。**筆數現在算不出來**：

- 選 A：筆數固定為 N（目前 7），`Then 補簽頁的日曆共有 7 筆` 可直接寫死，
  且與回補範圍參數同源，Examples 中改參數即改筆數。
- 選 B：筆數為兩個月的天數和，隨月份變動（59～62 筆），Then 只能寫成「不斷言筆數」
  或每個月各寫一列 Examples。
- 選 C：日曆與清單各要一組 Then，Scenario 數量加倍。

同時影響 `.gh-clarify/outline/補簽頁_日曆狀態三值是否每值各寫一列.md`——
「可補簽」這個狀態在跨月情境下究竟出不出現在日曆裡，決定該值要不要單獨寫一列。

# 影響範圍

- Read Model：補簽頁「本月日曆」欄位定義（`04_ReadModel清單.md` L208）
- 補簽頁的資料來源清單（L201，若採 N 天則須增列補簽設定 Aggregate 以取得 N）
- L214「採日曆而非日期清單」的設計理由敘述須同步更新
- 逐日簽到明細的保留期限（見 `aggregate/連續簽到_逐日簽到明細的保留期限為何.md`）——
  選 B/D 需要更長的保留期，選 A 只需要 N 天
- 補簽設定 Aggregate「回補範圍」參數的下游連動（`02_Aggregate定義.md` L4191、L4195）

**與已解決項目的關係**：
`.es-clarify/resolved/read-model/補簽頁_補簽前需看到哪些資訊.md`（選項 A）
裁定三個欄位成立，未定義日曆的時間範圍，本題即補這一段；
`.es-clarify/resolved/rule/使用者已補簽_可回補的時間範圍為何.md`（選項 B）
裁定 7 天為平台可調參數，是本題選項 A 的參數來源。

# 解決結果

**選項 A** —— 改為「最近 N 天日曆」，N ＝ 補簽設定的回補範圍（初始 7）。

顯示範圍恰等於可補範圍，跨月自動涵蓋；管理員調整回補範圍時日曆長度自動跟隨，
不需另行改動本 Read Model。

**附帶決定（助理判定，已於回寫時明示，使用者可推翻）**：
日曆涵蓋**距今 1 至 N 天，共 N 筆，不含今日**。
理由：今日的簽到由〈Read Model：簽到頁〉承載（該頁已定案只收「今日是否已簽到」一個欄位，
且明訂「補簽不在簽到頁進行」），補簽頁只承載「過去哪一天要補」這一個決策，
故日曆涵蓋距今 1 至 N 天，恰為可補範圍。
此點原欄位定義未言明，若不定會使 Gherkin 無法斷言日曆筆數。
