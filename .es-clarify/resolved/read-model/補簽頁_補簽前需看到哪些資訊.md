# 釐清問題

補簽已確定由獨立畫面承載。使用者在使用補簽券之前，需要看到哪些資訊？

# 定位

流程：補簽流程
元素：Read Model「補簽頁」
細節：D6 Read Model 識別；E4 Read Model → Command 支撐。

服務的 Actor：使用者
支撐的 Command：使用補簽券
資料來源：連續簽到 Aggregate、補簽券 Aggregate

# 多選題

| 選項 | 描述 | 推薦 |
|--------|-------------|------|
| A | 本月日曆（標示已簽 / 未簽 / 可補簽）＋ 補簽券張數 ＋ 補簽後可恢復的連續天數 | ★ 推薦 |
| B | 本月日曆（標示已簽 / 未簽 / 可補簽）＋ 補簽券張數 | |
| C | 可補簽日期清單（非日曆）＋ 補簽券張數 | |
| D | 僅補簽券張數，補簽日期由系統自動選定最近一次中斷 | |
| Short | 提供其他簡短答案（<=5 字） | |

# 影響範圍

影響補簽流程的 Command 輸入參數（是否需使用者指定補簽日期）、
以及 `rule/使用者已補簽_可回補的時間範圍為何.md` 的呈現方式。

# 優先級

Medium

# 來源

第三輪第 6 題（`resolved/read-model/每日簽到_使用者簽到前需看到哪些資訊.md`）
使用者裁決「補簽要到其他畫面」後開立。

# 解決結果

**選項 A｜日曆 ＋ 補簽券張數 ＋ 補簽後可恢復的連續天數**

- 本月日曆：每日一筆，狀態三值（已簽 / 未簽 / 可補簽）。
- 補簽券張數：目前持有數（代價）。
- 補簽後可恢復的連續天數：對所選日期試算（收益）。
- 補簽日期由使用者指定，不由系統自動選定最近一次中斷。

不採 B：使用者知道自己斷了，但不知道這張券換回什麼，代價與收益不對稱。
不採 C：補簽為對特定日期的操作，清單不如日曆直觀。
不採 D：補簽券持有上限有限，替使用者決定會拿走「留著補更關鍵一天」的選擇權。
