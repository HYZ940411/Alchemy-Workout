# 釐清問題

使用者執行 Command「關注帳號」「申請師徒關係」「檢舉內容（對象類型＝帳號）」前必須看到什麼？他人的個人檔案頁呈現哪些欄位？六維能力值與訓練歷史是否對他人可見？

# 定位

流程：關注流程、師徒互動流程、管理員管理社群流程
元素：Read Model（尚未定義）；支撐 Command「關注帳號」「取消關注」「申請師徒關係」「檢舉內容」「建立對話」
細節：D6 Read Model 識別、E4 Read Model → Command 支撐。
現況：Read Model「六維能力值雷達圖」與「訓練歷史」皆僅服務本人，模型未定義他人可見的個人檔案內容；但關注與拜師的決策必然需要看到對方是誰。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 欄位＝顯示名稱、階級、粉絲數、教官身分旗標與聲望、公開貼文清單；六維能力值與訓練歷史**不對外可見** |
| B | 同 A，另加六維能力值雷達圖（對外可見）—— 能力值為社群互動的核心賣點，隱藏將使關注與拜師缺乏判斷依據 |
| C | 同 B，且能力值與訓練歷史的對外可見與否由使用者自行設定（使用者 Aggregate 新增隱私設定欄位） |
| D | 同 A，但依關注關係分級：未關注者僅見基本資料，已關注者可見六維能力值 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Read Model 清單、使用者 / 關注關係 / 貼文 / 教官聲望四者的查詢組合、使用者 Aggregate 是否新增隱私設定欄位（現已定案「已讀回條本階段不可關閉，不新增隱私設定欄位」，本題若採選項 C 將建立第一個隱私設定，須確認方向一致）、以及貼文可見範圍三值（公開 / 僅關注者 / 私人）在個人檔案頁的套用。
相依：`read-model/教官清單_申請師徒關係前需看到哪些資訊.md`（兩者的欄位應一致）、`rule/使用者已封鎖對象_封鎖是否連帶解除關注與師徒與團隊關係.md`。
相關已解決項目：`resolved/read-model/六維能力值雷達圖_欄位來源與即時性為何.md`、`resolved/aggregate/對方帳號粉絲數已增加_粉絲數與關注關係的Aggregate歸屬.md`。

# 解決結果

**選項 B ＋ 使用者自訂可見性** —— 六維能力值**對外可見**，但使用者可自行設定隱藏
（使用者原話：「雷達圖可設定隱藏給其他人檢視」）。訓練歷史一律不對外可見，無開關。

使用者 Aggregate 新增欄位「六維能力值對外可見」（bool，預設為**真**）。
預設可見的理由：能力值正是「關注」與「申請師徒關係」的判斷依據，預設隱藏會使該區塊形同不存在。

## 與既有裁決的關係（助理先前陳述之修正）

助理於提問時稱選項 C「與既有裁決衝突」，該陳述**不夠精確**。
既有規則原文為「已讀回條本階段不可關閉，使用者 Aggregate 不新增**相關**隱私設定欄位」，
其範圍限於已讀回條，非全面禁止隱私設定。本裁決不違反該規則。

**連帶修正**：助理曾於第 48 題以同一條規則作為「不採收訊方隱私設定」的方向性論據，
該論據已因本裁決而削弱。第 48 題的決策理由已改寫為其自身更強的理由
（陌生訊息分區已解決同一需求、分區為全體一致行為、避免隊友與教官發不進來的死角），
第 48 題的裁決結果不變。
