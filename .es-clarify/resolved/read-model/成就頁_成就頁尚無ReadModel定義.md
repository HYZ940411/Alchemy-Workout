# 釐清問題

模型有 9 類成就（各 9–12 枚）、成就獎勵採點擊領取且不進信箱、App 內通知類明列「成就已解鎖 → 成就頁」，但〈Read Model 清單〉中沒有成就頁——其欄位、分組與領取入口為何？

# 定位

流程：跨流程（每日簽到、訓練結算、發文與互動、關注、階級提升、新手任務）
元素：Read Model — 成就頁（尚未建立）
細節：檢查項 D6。成就獎勵已定案「採點擊領取但不進信箱，因成就頁永久保留」，該領取入口即位於此頁，而此頁在模型中不存在

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 建立成就頁 Read Model：依 9 類分組，每類列出各門檻的已解鎖 / 未解鎖、解鎖時戳、獎勵內容與領取狀態；提供「一鍵領取全部」 |
| B | 同 A，另加「距下一門檻還差多少」的進度欄位（承小節點「提供高頻進度回饋」的既有設計意圖） |
| C | 不另立成就頁：成就併入〈Read Model：使用者個人檔案頁〉的一個區塊 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

- Read Model 清單新增一頁（現為 31 頁）
- 成就獎勵的領取路徑（Command「領取成就獎勵」的操作入口）
- 〈通知類 Event 的發送規則〉App 內通知類「成就已解鎖 → 成就頁」的落點
- 相關已解決項目：`resolved/aggregate/成就_各類成就的統一資料結構.md`、`resolved/aggregate/成就獎勵_發放路徑與數額尚未建模.md`

# 解決結果

**B**：建立成就頁 Read Model，並納入「距下一門檻所需」的進度欄位。

- 服務的 Actor：使用者（本人）；支撐的 Command：領取成就獎勵；即時性：即時。
- 依 9 類成就分組；各枚成就的欄位含名稱、門檻值、解鎖狀態、解鎖時戳、獎勵內容、領取狀態、
  **當前進度**、**距下一門檻所需**（衍生）。
- 提供「一鍵領取全部」，逐筆各產生一次領取 Event，比照獎勵信箱。
- **納入進度欄位的理由**：9 類中有 7 類為累積次數型門檻，僅顯示已／未解鎖時使用者只看到
  一排灰色圖示；承能力值小節點「使每次訓練都看得到還差多少」的既有設計意圖，且成本僅為相減。
- **不併入使用者個人檔案頁**：該頁同時供他人檢視，而領取為本人專屬操作，
  併入會產生「他人看得到我有沒有領獎」的非必要問題。
