# 釐清問題

自訂訓練有 5 個狀態與 7 個使用者 Command（儲存、發布、取消發布、申請公開、修改、下架、以及編輯內容），但模型無任何服務這些 Command 的 Read Model。使用者在管理自己的自訂訓練前需看到哪些資訊？

# 定位

流程：自訂訓練流程
元素：Read Model（缺失）「自訂訓練管理頁」；服務的 Actor：使用者（建立者）
細節：D6 Read Model 識別、E4 Read Model → Command 支撐。〈Read Model 清單〉的 21 個 Read Model 中無任何一個服務自訂訓練的狀態流轉；審核未通過的結果目前無處呈現。

# 解決結果（2026-08-08，第八輪第 28 題）

**C ＋ 甲** —— 課表清單與狀態 ＋ 名額使用量 ＋ 對關注者可見開關 ＋ 審核狀態與駁回理由
＋ **我自己的使用次數**。

## 三個新增欄位各對應一個「沒有它就下不了 Command」的缺口

| 欄位 | 缺口 |
|------|------|
| **名額使用量（如 3/5）** | 「刪除自訂訓練」為釋放名額的唯一手段（第八輪第 13 題），不知用量即為盲操作；且名額滿時 AI 調整改走快照，使用者需知道原因 |
| **審核狀態與駁回理由** | 模型有「公開訓練審核未通過」Event、審核時限 14 天；無此欄位則送審後進黑洞，亦不知為何被退 |
| **對關注者可見開關** | 正交於狀態的獨立欄位，**本頁為模型中唯一可操作它的位置** |

## 使用次數的算法：甲（我自己用了幾次）

使用者追問後收斂。兩種算法差異極大：

| | 資料來源 | 成本 |
|---|---------|------|
| **甲（採用）** | 本人以該課表訓練的次數，取自訓練紀錄的課表 ID | **現成資料** |
| 乙 | 該課表被所有人採用的次數 | 模型無任何記錄，須新增跨使用者統計 |

甲回答的是「這份課表我還在用嗎」，**正是決定該不該刪除以釋放名額的依據**，
與本頁的管理職責一致。乙為社群虛榮指標，會使管理頁變成排行榜。

## 使用者追問：沒公開的話只會顯示什麼

**審核狀態與駁回理由確實是條件式的**（僅曾送審者有值），
但「對關注者可見」只要**已發布**即有，不需公開。逐狀態呈現已寫入模型。

## 使用者追問：A 的「狀態」是什麼

自訂訓練 Aggregate 的狀態值域。**草稿不列於本頁** ——
其語意為「設計中，尚未儲存」，未存檔者不應出現於管理清單。
已刪除為終止狀態，亦不出現。
