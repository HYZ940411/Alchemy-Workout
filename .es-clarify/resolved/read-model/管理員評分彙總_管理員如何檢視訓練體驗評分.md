# 釐清問題

管理員檢視使用者的訓練體驗評分時需要看到什麼？此 Read Model 支撐管理員的哪一個 Command？

# 定位

流程：新手任務流程、訓練結算流程、管理員後台
元素：Read Model（尚未定義）；服務的 Actor：管理員
細節：D6 Read Model 識別、E4 Read Model → Command 支撐。

**使用者已表態的需求**（2026-08-01，第四輪第 6 題）：評分「供我們後續優化，**管理員可見**」。

判準爭點：〈Read Model 建立原則〉為「僅為 Actor 下某個 Command 之前必須看見的資訊建立 Read Model」。
管理員看評分後會下的 Command 是什麼？現有可能對象為「設定新手任務範本」與訓練計畫的內容維護
（後者目前無對應 Command —— 模型有「訓練計畫」Aggregate，但〈Command 清單〉中無任何維護該
Aggregate 的管理員 Command，此為另一個尚未浮現的缺口）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 建立：欄位＝評分對象、平均分、評分則數、分數分布、文字回饋清單；支撐 Command「設定新手任務範本」與訓練計畫的內容調整 |
| B | 同 A，但依評分對象拆為兩個 Read Model（新手任務體驗彙總、訓練計畫彙總），因兩者服務的維護動作不同 |
| C | 同 A，且併入 `read-model/管理員待審佇列_審視檢舉與各類審核前需看到哪些資訊.md` 所建立的管理員視角 Read Model 群組，不獨立成項 |
| D | 不建立 Read Model：評分為產品研究資料，由後台報表或資料分析工具承接，不屬事件風暴模型的 Read Model |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Read Model 清單是否納入第二個管理員視角的 Read Model、〈Command 清單〉是否需補上
訓練計畫的維護類 Command（目前完全缺席），以及〈Read Model 建立原則〉在「看了之後才知道要不要改內容」
這類**探索型決策**上的適用範圍 —— 此為判準的第三個邊界案例。

相依：`event/使用者已評分訓練體驗_新手任務與訓練計畫的評分如何建模.md`（評分不成立則本項不成立，
且評分對象的值域決定本 Read Model 的分組維度）。
相關待釐清項目：`read-model/管理員待審佇列_審視檢舉與各類審核前需看到哪些資訊.md`、
`read-model/任務清單頁_新手任務與每日任務是否成立ReadModel.md`（同為判準邊界案例）。

# 解決結果

**選項 C ＋ 甲（共用同一張彙總表）＋ 評分尺度 1～5 星必填、文字回饋選填**

## 彙總欄位（每個評分對象一列）

評分對象類型（新手任務 / 訓練計畫）、評分對象名稱、平均評分、評分則數、星等分布（1★–5★ 各筆數）。

## 下鑽欄位

逐筆評分（星等、評分時戳）、文字回饋（選填，可為空）。

## 即時性

**延遲更新** —— 本 Read Model 為分析用途，不支撐任何即時決策，
無理由付出即時彙總的成本。與〈Read Model：動作庫〉同一判斷。

## 理由

- **不採 A**（僅逐筆清單）：承既有裁決「評分的用途為平台優化自身提供的內容」，
  管理員要問的是「哪一份訓練計畫評價差」，逐筆清單答不了。
- 保留下鑽：平均 2.8 星只指出有問題，不指出問題是什麼。
- **不採 D**（時間區間比較）：須新增歷史快照方能計算，
  而訓練計畫改動頻率低，月比月的變化多為噪音。
- **甲而非乙**：使用者選擇兩種對象類型共用同一張彙總表，新手任務為其中一列。
  助理原推薦乙（新手任務單獨一區，理由為它是全平台唯一一份、影響所有新使用者），
  使用者裁決甲。

# 使用者提出的釐清（助理據此查證）

使用者問「這裡訓練是包含一般訓練跟新手任務嗎」。查證結果：

| 來源 | 可否評分 |
|------|---------|
| 新手任務 | 可 |
| 官方訓練計畫 | 可 |
| **自訂訓練** | **否** |
| **空白課表（自由訓練）** | **否** |

即「一般訓練」中**僅走官方訓練計畫者**會觸發評分。
承既有裁決：評分對象為平台提供的內容。
