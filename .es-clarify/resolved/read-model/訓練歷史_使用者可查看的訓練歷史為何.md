# 釐清問題

使用者可查看的訓練歷史為何？以何種單位呈現、可回溯多久、已結算的紀錄可否更正？

# 定位

流程：訓練紀錄流程、訓練結算流程
元素：Read Model「訓練歷史」；Command「查看訓練歷史」（尚未存在）
細節：D6 Read Model 識別；B1 Command 識別完整性；E4 Read Model → Command 支撐。

服務的 Actor：使用者
支撐的 Command：選擇訓練課表、記錄該組成績（決定今天練什麼、加多少重量）
資料來源：訓練紀錄 Aggregate（結算後凍結，永久保存）

# 多選題

| 選項 | 描述 | 推薦 |
|--------|-------------|------|
| A | 以訓練為單位的清單（日期、課表名稱、總訓練量、時長），點入可看該次各動作各組明細 | ★ 推薦 |
| B | 以動作為單位：選定一個動作，看該動作歷來的重量與次數趨勢 | |
| C | A ＋ B 兩種檢視並存 | |
| D | 僅提供最近一次的訓練紀錄，不提供完整歷史 | |
| Short | 提供其他簡短答案（<=5 字） | |

# 影響範圍

影響是否需新增「查看訓練歷史」Command、訓練紀錄的保存期限、
以及已結算紀錄可否更正（現行規則為「結算時凍結，不再接受修改」）。

# 解決結果

**選項 C（兩種檢視並存）＋ 追問排序選項 A（最常練優先）**

- **訓練清單檢視**：以一次訓練為單位（日期、課表名稱、總訓練量、訓練時長），
  點入可看該次各動作各組明細 —— 回答「我上週練了什麼」。
- **動作趨勢檢視**：以一個動作為單位，呈現該動作歷來的重量與次數 ——
  回答「這個動作上次推幾公斤、該不該加重」。
- 動作趨勢的預設排序為**累積練習次數由多到少**。
- 新增 Command「查看訓練歷史」（Actor：使用者，查詢類，不產生 Event）。
- 訓練紀錄結算後凍結，訓練歷史為唯讀。

兩種檢視回答兩個不同問題，且兩者共用同一份資料，僅多一個查詢維度。
不採「依最近一次練到的時間排序」：健身多為分部位循環，
最近練到的動作恰為今天不會練的，排在最前反而擋路；
累積次數排序則長期穩定，使用者記得住位置。

**未定案**（記為 H20）：可回溯的時間範圍、動作趨勢是否含圖表、是否提供動作搜尋。
