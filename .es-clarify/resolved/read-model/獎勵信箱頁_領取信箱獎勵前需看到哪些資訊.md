# 釐清問題

「領取信箱獎勵」為使用者 Command，但獎勵信箱無對應的 Read Model。領取前需看到哪些資訊？

# 定位

流程：每日任務流程（重置與補發路徑）
元素：Read Model（缺失）「獎勵信箱頁」；服務的 Actor：使用者
細節：D6 Read Model 識別、E4 Read Model → Command 支撐。〈Read Model：每日任務清單〉僅承載當日任務，補發至信箱的獎勵不在其範圍內。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 最小集：未領取獎勵清單（獎勵內容、來源、補發時戳），支援逐筆領取 |
| B | A ＋ 一鍵全部領取、以及已領取的歷史紀錄（可切換分頁） |
| C | ~~B ＋ 到期倒數與信箱容量~~ —— **已作廢**：第 19 題定案不設有效期限與容量上限，本選項的兩個欄位皆不存在 |
| D | 不另立 Read Model：未領取獎勵直接呈現於〈Read Model：每日任務清單〉的第二區塊，不設獨立畫面 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Read Model 總數、「領取信箱獎勵」Command 的可執行性、以及獎勵信箱 Aggregate 是否需新增到期與容量欄位。
前置已解除：`resolved/aggregate/獎勵信箱_信箱獎勵的有效期限與容量上限.md`（選項 A：不設期限、不設容量上限）——
故選項 C 作廢，且本 Read Model 須處理**大量未領取**的呈現：
一位完全不領的使用者每年約累積 500 筆，排序、分頁與一鍵全部領取成為本題的重點。
相依：`command/領取獎勵_領取機制是否及於每日任務以外的獎勵來源.md`（決定信箱的內容範圍與量級）。
相關已解決項目：`resolved/rule/每日任務已重置_重置時已完成未領取的獎勵如何處理.md`、`resolved/read-model/任務清單頁_新手任務與每日任務是否成立ReadModel.md`。

# 解決結果（2026-08-08，第八輪第 31 題）

**B，但移除「到期倒數」** —— 獎勵清單（來源、內容、取得日期）＋ 逐筆領取
＋ **一鍵全部領取** ＋ **未領取筆數**。

## 助理的錯誤：引用了不存在的規則

助理原推薦的 B 含「到期倒數」，理由寫「獎勵信箱有有效期限（既有裁決）」。
**使用者當場質疑「我們的獎勵不是沒有到期嗎」，使用者是對的。**

`resolved/aggregate/獎勵信箱_信箱獎勵的有效期限與容量上限.md`（選項 A）明訂：

> **不設有效期限、不設容量上限、無逾期清除機制。**

故到期倒數欄位**不該存在** —— 它會暗示一個不存在的期限，反而製造焦慮。
改由「未領取筆數」佔用該位置。

**教訓**：本輪第 23 題（金幣售價其實是虛擬商品）與本題為同一類錯誤 ——
**憑印象引用既有裁決而未查證**。第 23 題錯在沒查「有無同型的既有物」，
本題錯在沒查「該裁決實際定了什麼」。

## 一鍵全部領取的理由因此更強

既然**永不過期、永不清除**，信箱會無上限累積：

- 完全不領取者一年約累積 500 筆（原 resolved 檔的估算）
- 每日任務未領取者**每日補一筆**，出國一週回來即 7 筆
- 逐筆點擊等同把「忘記點擊」的成本又還給使用者，
  與信箱的立案理由（未領取不作廢）自相矛盾

## 信箱來源為四類，非助理原稱的兩類

| 來源 | 出處 |
|------|------|
| 每日任務未領取 | `每日任務流程.md:39` |
| 三種排行獎勵 | `排行榜週期結算流程.md:11` |
| **補簽當日的簽到獎勵**（助理原漏列） | `補簽流程.md:15` |
| **限時任務未領取**（本題一併裁決） | `團隊任務流程.md:63` |

## 一併解決：限時任務未領取是否進信箱（使用者同意「進」）

`團隊任務流程.md:63` 原有 `[待決策 Partial]`「取決於限時任務的有效期間」，
而該有效期間已於第八輪第 19 題定為**當日有效、隔日失效**，故本題可一併裁決。

**「當日有效」管的是完成任務的期限，非領取獎勵的期限** ——
使用者已完成任務，該獎勵即為其掙得。與每日任務同型（同樣每日重置，未領取者同樣進信箱）。

## 兩項不納入的資訊

- **不放已領取的歷史紀錄**：領取後即結束，回顧價值低；金幣進出屬帳務範疇。
- **不依來源分頁**：來源僅四類，量級有限，分頁是為數百筆清單而設。
