# 釐清問題

平台設定權限組現有 13 個管理員 Command（設定訓練計畫、設定平台動作、設定成就定義、設定獎勵定義、設定階級門檻、設定每日任務池、設定新手任務範本、設定限時任務、設定會員權益、設定教官測驗、新增管理員、停用管理員、調整管理員權限組），全部沒有對應的 Read Model。依〈建立原則〉，管理員改一個設定之前必須先看到它的現值——這是否成立 Read Model？

# 定位

流程：跨流程（管理員後台，不隸屬既有任一條流程）
元素：Read Model（缺失）；支撐的 Command：〈平台設定維護〉一節 7 個 ＋ 分列各流程的既有設定 Command 6 個
細節：D6 Read Model 識別、E4 Read Model → Command 支撐。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A（**推薦**） | **不逐一建立，改於〈建立原則〉補一條通則**：設定類 Command 的 Read Model 一律為「該設定 Aggregate 的現值表」，其欄位即該 Aggregate 的欄位表，不另立條目。理由：模型已在多處採用同型手法（Command 輸入參數改用推導式而非逐一列表、排程識別碼改用兩條推導式而非逐案訂定）；逐一建 13 個 Read Model 會產出 13 份與 Aggregate 欄位表一字不差的副本，日後改欄位得改兩處 |
| B | 逐一建立：13 個設定 Command 各配一個 Read Model，與既有 Read Model 同格式列出欄位與來源 |
| C | 建立單一〈Read Model：平台設定總覽〉，以設定表名稱分頁，涵蓋全部設定 Aggregate 的現值 |
| D | 不建立、也不補通則：管理員後台的設定畫面屬純展示，承〈建立原則〉「純展示、與任何 Command 無關的畫面不納入模型」 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 `04_ReadModel清單.md`〈建立原則〉是否增列一條通則、Read Model 總數（現 34），以及後續新增設定類 Command 時是否需連帶新增 Read Model。
若 `command/平台設定維護_六個新增設定Aggregate是否納入軟體邊界並建Command與Event.md` 與 `command/能力值設定_…` 兩項新增了設定 Command，本項的答案將直接決定它們要不要各配一個 Read Model。
註：選項 D 與〈建立原則〉本身有張力——設定現值並非「與任何 Command 無關」，它正是該 Command 的判斷依據。
相關已解決項目：`resolved/read-model/全流程ReadModel_各流程尚未定義任何Read Model.md`（選項 A，建立盤點方式）、`resolved/read-model/設定頁_設定頁尚無ReadModel定義.md`（使用者端設定頁的同型處理）。

# 解決結果

**選項 A** —— 不逐一建立，於〈建立原則〉補一條通則：
設定類 Command 的 Read Model 恆為「該設定 Aggregate 的現值表」，欄位即該 Aggregate 的欄位表，
不另立條目；新增設定 Aggregate 時本通則自動適用。

- 承模型既有的同型手法：Command 輸入參數改用推導式、排程識別碼改用兩條推導式，
  皆為「以通則取代逐一列表」。
- 不採 B（逐一建 13 個）：產出 13 份與 Aggregate 欄位表一字不差的副本，欄位一改須改兩處。
- 不採 C（單一總覽分頁）：仍須逐表列欄位，副本問題不變。
- 不採 D（不建也不補通則）：設定現值正是該 Command 的判斷依據，
  與〈建立原則〉「純展示、與任何 Command 無關」不符。

**同時明訂界線**：若管理員畫面除現值外還需其他 Aggregate 推導的決策依據，即超出本通則、須另立條目。
本輪第 5 題新增的〈管理員商品清單〉即為此例（需呈現取自訂單 Aggregate 的「未出貨訂單筆數」）。

**連帶效果**：本輪 8/20 已解決的兩項（`command/能力值設定_…`、`command/平台設定維護_…`）
新增的 3 個設定 Command（設定能力值門檻、設定教官初審門檻、設定補簽回補範圍）
依本通則**不需各配一個 Read Model**。
