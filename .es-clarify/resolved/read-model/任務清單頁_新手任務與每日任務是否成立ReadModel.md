# 釐清問題

新手任務與每日任務的清單與進度，是否成立 Read Model？依〈Read Model 建立原則〉的判準（Actor 下 Command 前必須看見），這兩份清單支撐的是哪一個 Command？

# 定位

流程：新手任務流程、每日任務流程、回歸任務流程
元素：Read Model（尚未定義）；支撐 Command「開始新手任務」「完成單項新手任務」
細節：D6 Read Model 識別、E4 Read Model → Command 支撐（判準的邊界案例）。
判準爭點：每日任務的進度更新與完成皆由**系統**執行，使用者不下任何 Command；但使用者需看到任務內容才知道要去做（去訓練、去按讚）。此為「支撐決策」與「純展示」的臨界情形，需明確裁決以免判準日後失去一致性。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 三者皆成立單一「任務清單頁」Read Model：新手任務支撐「完成單項新手任務」Command；每日任務與回歸任務雖無使用者 Command，但其內容決定使用者接下來要下哪一個 Command（如「開始訓練」），仍屬支撐決策 |
| B | 僅新手任務成立（有明確的使用者 Command）；每日任務與回歸任務為純展示，不納入模型 |
| C | 三者皆成立，但拆為三個獨立 Read Model，各自註明服務的 Actor 與支撐的 Command |
| D | 三者皆成立且合併為單一 Read Model，同時修訂〈Read Model 建立原則〉，明訂「引導使用者去下其他 Command 的清單」亦屬支撐決策 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Read Model 清單、〈Read Model 建立原則〉判準的適用邊界（本題的答案將成為其餘臨界案例的判例）、新手任務 / 每日任務 / 回歸任務三個 Aggregate 的查詢欄位、以及回歸任務「時限起算時戳於首次查看時寫入」的觸發落點。
相依：`aggregate/每日任務池_任務項目的結構與完成判定來源為何.md`（清單欄位取決於任務項目結構）、`event/回歸任務已指派_首次登入查看是否應建模為Event.md`。
相關已解決項目：`resolved/read-model/全流程ReadModel_各流程尚未定義任何Read Model.md`（建立原則的來源）。

# 解決結果

**選項 C** —— 三者皆成立，拆為三個獨立 Read Model（新手任務清單、每日任務清單、回歸任務卡），
各自註明服務的 Actor 與支撐的 Command。

## 題目前提已過時

本題於 discovery 階段建立時，前提為「每日任務與回歸任務無使用者 Command」。
該前提在後續輪次已不成立：

| 任務 | 使用者 Command | 新增於 |
|------|---------------|--------|
| 新手任務 | 完成單項新手任務 | 原有 |
| 每日任務 | **領取每日任務獎勵** | 第 35 題 |
| 回歸任務 | **查看回歸任務** | 前面輪次 |

三者皆通過〈Read Model 建立原則〉的現行判準，
故**選項 D 的「修訂建立原則」已無必要**，選項 B 亦不成立。
爭點收斂為「合併一份或拆三份」，即 A 與 C 之爭。

## 拆分理由

1. 更新觸發源不同：註冊時指派 / 每日 04:00 重置 / 能力值退步時指派。
2. 生命週期不同：一次性 / 每日重生 / 條件觸發。
3. 回歸任務卡另有專屬規則「載入不得寫入時限起算時戳」，
   混入合併定義易被誤讀為「打開任務頁即算查看」。
4. 拆分不影響畫面：三份定義仍渲染為同一頁面的三個區塊。
