# 釐清問題

自由訓練以「空白課表」為入口，其動作數為 0 或於訓練中動態增加。「課表全部動作完成 → 使用者已完成訓練」的判定基準為何？

# 定位

流程：訓練紀錄流程
元素：Rule：分支「課表全部動作完成 → 使用者已完成訓練」的 Precondition
細節：狀態邊界（C3）；單調遞增與不可逆性（C4）；與訓練進度條 Aggregate 的一致性（D3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 空白課表不可於訓練中新增動作，且無「全部完成」判定，只能觸發「使用者已提前結束訓練」 |
| B | 空白課表可於訓練中動態新增動作；分母隨之變動，「全部完成」＝已新增的動作皆完成 |
| C | 空白課表可動態新增動作，但不判定「全部完成」，一律以「使用者已提前結束訓練」終止 |
| D | 開始訓練前必須至少加入一個動作，空白課表不得直接開始訓練 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響「使用者已完成訓練」與「使用者已提前結束訓練」的分支判定、訓練進度條的分母是否可變動、
以及訓練獎勵的差異（兩者獎勵不同）。
承接 G17；相關已解決項目：`resolved/command/使用者已開始訓練_未選擇課表可否直接開始訓練.md`（選項 D）、`resolved/aggregate/訓練進度條_進度百分比的計算公式為何.md`（已定總計畫組數為 0 時不顯示進度條）。

# 優先級

High

# 解決結果

**選項 A｜空白課表一律視為「使用者已完成訓練」**

- 空白課表（總計畫組數為 0）的訓練，使用者主動結束一律判定為「使用者已完成訓練」。
- 空白課表的訓練**不會**產生「使用者已提前結束訓練」，終止 Event 僅二種：
  使用者已完成訓練 / 單次訓練已逾時中斷。

理由：「提前結束」的前提是存在預定終點，空白課表無預定內容即無「提前」可言；
一律判為提前結束等於以不存在的標準給予較低獎勵。

不採由使用者自述：無人會選擇較低獎勵的選項，該互動的答案恆為「已完成」。
不採最低組數門檻：門檻數值無依據可循，且會製造新的邊界爭議。
