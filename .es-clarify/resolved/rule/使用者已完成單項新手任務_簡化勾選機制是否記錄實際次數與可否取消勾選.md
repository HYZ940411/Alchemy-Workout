# 釐清問題

新手任務已定案「不走訓練紀錄流程，自成一套簡化的勾選機制」。該機制是否記錄實際次數？勾選後可否取消？未達目標次數可否勾選？

# 定位

流程：新手任務流程
元素：Rule：Event「使用者已完成單項新手任務」的 Precondition 與 Postcondition
細節：C1 前置條件完整性、C4 單調遞增與不可逆性。`新手任務流程.md` 之 `[待決策 Partial]`，另記於 `pending-gaps-3.md` 之 I17。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 純勾選：不記錄實際次數、不可取消、勾選即完成。新手任務為引導而非計量，記錄次數會使其變成一次沒有訓練紀錄的訓練 |
| B | 純勾選但**可取消**：誤觸為常態（承訓練紀錄流程「允許取消勾選」的既有裁決）；取消後該項回到未完成，「使用者已完成單項新手任務」的請求識別碼（使用者 ID ＋ 任務項目 ID）需容許重複 |
| C | 記錄實際次數（供 AI 了解新手起始水準）、不可取消；未達目標次數仍可勾選，實際次數照實記錄 |
| D | 記錄實際次數且可取消，完整比照訓練紀錄的組紀錄行為，僅不產生訓練紀錄 Aggregate |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響「使用者已完成單項新手任務」的 Precondition / Postcondition 與冪等去重鍵（同一項目只能完成一次 vs 可取消後重做）、〈Read Model：新手任務清單〉的欄位（是否呈現實際次數）、新手任務 Aggregate 的欄位，以及新手任務範本的任務項目結構（目標次數的用途）。
相關已解決項目：`resolved/aggregate/新手任務範本_任務項目的結構與執行機制為何.md`、`resolved/event/使用者已完成新手任務_新手任務進度更新是否應建模為Event.md`、`resolved/event/使用者已完成該組_取消勾選與修改成績是否建模為獨立Event.md`。

# 解決結果

**使用者自由作答，非任何候選選項，且推翻了模型的既有機制。**

使用者原話：

> 新手訓練是這樣，從三個動作中選一個做，選了之後才會開訓練，那個訓練就只有一組，
> 可取消，不可調次數，打勾後要手動按完成訓練，然後進行新手獎勵發放

## 定案的機制

```
新手任務清單：三個候選動作
      ↓ 三選一
選定 → 進入執行（單一動作、單一組、次數固定不可調）
      ↓ 勾選（可取消）
使用者已完成單項新手任務
      ↓ 手動按「完成訓練」
使用者已完成新手任務 → 領獎
```

**四個原選項全數作廢**：A/B 假設純勾選清單、C/D 假設記錄次數，
皆建立在「多項待辦全部完成」的錯誤前提上。

## 原題三個子問題的答案

| 子問題 | 答案 |
|--------|------|
| 記錄實際次數？ | **否** —— 獎勵固定，數值無下游消費者 |
| 可否取消勾選？ | **可以** —— 比照訓練紀錄流程，誤觸為常態 |
| 未達目標次數可否勾選？ | **可以**，系統不驗證（引導而非考核） |
| 目標次數可否調整？ | **不可**（使用者新增的限制） |

## 被推翻的既有共識（3 項）

1. **「該使用者的新手任務全部單項皆已完成」方可完成新手任務** → 改為**三選一**，
   完成所選的那一項即可。
2. **「請求識別碼為 使用者 ID ＋ 任務項目 ID，同一項目只能完成一次」**
   → 因勾選可取消，識別碼增加勾選序號，同一項目可重複發生。
3. **「使用者已完成新手任務」的 Actor 為系統** → 改為**使用者**（手動按「完成訓練」）。

另移除 `[決策] 逐項完成建模為獨立 Event，供新手引導漏斗流失率分析` ——
三選一之下已無「逐項」，該理由的前提消失。**但該理由本身仍有效**，
故轉用於新產生的待決策（見下）。

## 未變的部分（使用者明確確認）

**不算一次正式訓練** —— 不產生訓練紀錄、不產生訓練量、不計入累積訓練次數與連續訓練天數，
故「完成新手任務不會觸發自訂訓練解鎖，須待第一次正式訓練結算」**維持不變**。

執行畫面雖形似一次訓練（有組、有勾選、須手動按完成），差別在於它不產生任何下游資料。
