# 釐清問題

一位使用者可否同時建立或加入多個團隊？換隊是否有冷卻期？

# 定位

流程：團隊組隊任務流程
元素：Rule：使用者已建立團隊 / 使用者已加入團隊的 Precondition
細節：Precondition 完整性與數量限制（C1）；組合邊界（C3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 同時僅能屬於一個團隊，需先退出才能加入新團隊，無冷卻期 |
| B | 同時僅能屬於一個團隊，換隊後 7 天內不可再換（防刷分） |
| C | 可同時加入多個團隊，但分數僅計入指定的主要團隊 |
| D | 可同時加入多個團隊，分數同時計入所有團隊 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響兩個加入 / 建立 Command 的 Precondition、使用者與團隊的關聯關係（一對一或一對多）、團隊分數的計算與防刷規則。與「成員中途加入退出分數計算」問題可一併處理。

# 優先級

Medium

# 解決結果

**選項 A ＋ 冷卻期** —— 同時僅能屬於一個團隊，須先退出方可加入新團隊；退出後 **7 天**換隊冷卻期（平台級可調）。

# 後續修正（2026-08-02，第 47 題）

## 被推翻的部分

原解決結果中的「冷卻期 **7 天**」並非使用者裁決，而是助理於使用者提問
「冷卻常見值為何」時逕行填入的建議值。使用者於第 47 題明確定案：

| 項目 | 原值 | 現值 |
|------|------|------|
| 換隊冷卻期 | 7 天 | **12 小時** |
| 無懲罰退出窗口 | 無 | **加入後 3 小時內退出不觸發冷卻** |

## 連帶失效的理由

原理由「7 天約為排行榜週期的四分之一，足以使月底跳到領先團隊蹭排行獎勵不划算」
**在 12 小時下不成立** —— 月底前一天跳槽，隔天即結算。該理由已自模型刪除，
未以任何形式保留，以免留下與規則不符的說明。

冷卻期的職責改寫為：僅避免同一日內反覆進出造成的成員名單與分數抖動。
防止蹭排行獎勵的職責改由團隊分數的加入 / 退出計算規則承擔（尚未定案，
見 `rule/團隊日常分數已增加_成員中途加入或退出時分數如何計算.md`）。

## 未被推翻的部分

「同時僅能屬於一個團隊」維持不變。
