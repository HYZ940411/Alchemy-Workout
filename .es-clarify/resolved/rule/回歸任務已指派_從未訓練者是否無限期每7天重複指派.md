# 釐清問題

「回歸任務已指派」的唯一頻率規則是「距前一次指派滿 7 天，方可再次指派」，沒有任何上限或終止條件。只要「能力值已退步」持續發生，回歸任務就會每 7 天指派一次、永遠指派下去。對註冊後從未訓練的使用者，這代表他從第 10 天起，每 7 天收到一次回歸任務，且因其「本次中斷各維累積退步量」恆為 0，就算完成任務，「能力值已部分回復」也只回復 0 點。回歸任務的重複指派是否應設上限或終止條件？

# 定位

流程：回歸任務流程
元素：Rule（Precondition / 指派頻率）；Event：回歸任務已指派（`回歸任務流程.md:8`）
細節：C3 狀態邊界（重複執行）、A3 事件重複發生、A4 軟體邊界。現有規則僅「距前一次指派滿 7 天方可再次指派」與「逾期後該筆回歸任務消失，不發放獎勵」。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A（**推薦**） | **補一條 Precondition：「該使用者本次中斷的六維累積退步量合計 > 0」，方可指派。** 沒有真的退步過的人（例如從未訓練者，六維都卡在下限 10）不指派回歸任務。理由：回歸任務的用途明文為「回復先前退步之能力值的一部分」，退步量為 0 時它回復不了任何東西，指派出去是一張獎品拿得到、效果卻是空的任務；且此條與上游 `rule/能力值已退步_…` 的答案自然對齊 |
| B | 設重複次數上限（如連續 3 次逾期未完成即停止指派，直到該使用者再次訓練為止），理由是連續無視三次已足以判定召回無效，繼續指派只是消耗 |
| C | 維持無限指派：回歸任務不推播、只在 App 內以回歸任務卡呈現，重複指派不騷擾任何人，且流失者哪天回來都該有一張任務等他 |
| D | 改為「不重複指派、只更新同一筆」：回歸任務改為每位使用者最多一筆，未完成者於下次觸發時刷新其內容與指派時戳，不另開新筆 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響「回歸任務已指派」的 Precondition、回歸任務 Aggregate 的筆數與生命週期（一人多筆或一人一筆）、回歸任務獎勵的發放總量、以及〈Read Model：回歸任務卡〉同時存在多筆時的呈現規則。
相關已解決項目：`resolved/rule/回歸任務已指派_限時的時限長度為何.md`（定案 7 天、自首次查看起算）、`resolved/event/回歸任務已指派_與訓練中斷流程同時觸發時如何協調.md`、`resolved/event/使用者已完成回歸任務_逾期未完成時的Event為何.md`。
相依：上游為 `rule/能力值已退步_點數已在退步下限時是否仍重複產生本Event.md` —— 若該項採 A（下限時不產生 Event），從未訓練者的情形即自動消失，本項只剩「真的退步過但長期不回來者」要不要無限指派。

# 解決結果

**選項 B** —— 連續 3 次「回歸任務已逾期」後停止指派，直到該使用者再次訓練為止。

**原推薦選項 A 已排除**：「本次中斷累積退步量 > 0 方可指派」會使從未訓練者
（六維皆卡在退步下限、退步量恆為 0）永遠收不到回歸任務，與 2026-08-20 定案的
`resolved/event/使用者已完成註冊_註冊後從未訓練者是否有任何召回機制.md`（選項 A）直接衝突。
本項與上游 `resolved/rule/能力值已退步_…` 是同一個陷阱的兩次出現，皆於作答前攔下。

**本題檔案原文對選項 C 的描述有誤**：其理由寫「回歸任務不推播、只在 App 內以回歸任務卡呈現，
重複指派不騷擾任何人」——實際上 `resolved/event/回歸任務已指派_指派時是否對使用者發送通知.md`
（2026-08-20，選項 A）已定案本 Event **列入推播類第 2 級行動引導類**。
該釐清檔寫於此裁決之前，未同步。無限指派實為每 7 天推播一次且永不停止。

**選擇 B 的留存論據**（推理，非量測）：

- 推播才是召回手段，App 內的任務卡對已不開 App 者不可見。
- 三次指派落在中斷後第 10、17、24 日，涵蓋流失後最可能被召回的窗口。
- 無限指派的邊際效益遞減快，代價為使用者關閉通知或移除 App，
  **永久失去唯一的召回管道**——連日後真想回來的人也推不到。
- 選項 D（一人一筆刷新）只改 Aggregate 筆數，推播頻率不變，對留存與 C 無異。
