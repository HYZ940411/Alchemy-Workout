# 釐清問題

「使用者已封鎖對象」發生時，雙方既有的關注、師徒、團隊關係是否連帶解除？

# 定位

流程：聊天私訊流程、關注流程、師徒互動流程、團隊組隊流程
元素：Rule：Event「使用者已封鎖對象」的 Postcondition
細節：後置條件完整性（C2）；Aggregate 間關係與生命週期（D4）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 封鎖僅阻斷私訊，不影響關注、師徒、團隊任何關係 |
| B | 封鎖自動解除雙方關注（觸發「使用者已取消關注」×2），師徒與團隊關係不受影響 |
| C | 封鎖自動解除雙方關注與師徒關係；同隊成員不得互相封鎖（列為 Precondition） |
| D | 封鎖自動解除關注、師徒、團隊成員關係三者，全數斷開 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響「使用者已封鎖對象」的 Postcondition、是否連帶觸發「使用者已取消關注」「師徒關係已解除」「使用者已退出團隊」，
以及封鎖解除時是否需回復上述關係。
承接 G7；相關已解決項目：`resolved/event/使用者已建立對話_封鎖與刪除對話的Event缺失.md`。
依賴 `aggregate/使用者已建立對話_對話與私訊的Aggregate歸屬與欄位.md` 的封鎖歸屬定案。

# 優先級

Medium

# 解決結果

**選項 C** —— 封鎖自動解除雙方關注與師徒關係；同隊成員不得互相封鎖（列為 Precondition），欲封鎖須先退出團隊。

使用者同時裁決推翻換隊冷卻期：由助理所填的 7 天改為 **12 小時**，並新增「加入後 3 小時內退出不觸發冷卻」的無懲罰窗口。

已知代價（使用者明示接受）：騷擾者為同隊隊友時，受害者須先退出團隊才能封鎖。
