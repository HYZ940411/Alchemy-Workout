# 釐清問題

帳號採軟刪除且資料保留（僅匿名化個人識別資料），同一手機號碼或同一 Google / Apple 帳號可否再次註冊？若可，是否視為全新使用者（重新取得註冊獎勵、六維能力值歸零重來）？此問題與既有裁決「重複註冊或重裝時如何確保只發放一次註冊獎勵」直接相關，為其在帳號刪除後的延伸情境。

# 定位

流程：註冊流程
元素：Event「使用者帳號已建立」的 Precondition
細節：若匿名化已抹除手機號碼與第三方帳號綁定（見 I1 匿名化欄位範圍裁決），則同一手機號碼理論上可重新綁定；若未抹除，則需明確規則。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 允許以同一手機號碼或第三方帳號重新註冊，一律視為全新使用者（新的使用者 ID、重新取得註冊獎勵、六維能力值與階級歸零），不回復原帳號的任何資料（**推薦**：與帳號刪除的既有立場一致——刪除即代表使用者主動放棄該帳號的一切，資料保留是為了他人內容的稽核鏈與統計完整性，而非為了本人日後找回；且與「防止刷註冊獎勵」的既有裁決方向一致，不因刪除又重註冊而成為新的刷取管道，只要匿名化已抹除識別碼，兩個帳號在系統中即無關聯） |
| B | 不允許以同一手機號碼或第三方帳號重新註冊，永久封鎖該識別碼 |
| C | 允許重新註冊，但視為原帳號的延續（保留原六維能力值、階級與訓練歷史，不重新發放註冊獎勵） |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Event「使用者帳號已建立」的 Precondition；與 `rule/註冊獎勵已發放_重複註冊或重裝時如何確保只發放一次.md` 為同一組決策，建議併同處理。

# 解決結果

**選項 A**：允許重新註冊，一律視為全新使用者（新使用者 ID、重新取得註冊獎勵、
六維能力值與階級歸零），不回復原帳號的任何資料。

**A 同時為三個選項中最符合 App Store 規範者**（使用者於本題追問「A 符合 App Store 規範嗎」）：
- **B（保留雜湊識別碼黑名單）反而有風險**：雜湊過的手機號碼仍可經查表反推回本人，
  多數個資法規下仍屬個人資料；為防止重新註冊而於刪除後留存識別碼，與帳號刪除要求相衝。
- **C（視為原帳號延續）明確不符**：須保留原始資料，與〈刪除範圍〉的實際刪除裁決直接衝突。
- **A 為實際刪除的必然結果**：帳密與第三方綁定既已刪除，系統本即無從辨識該識別碼曾註冊過。

`[已知風險]` 可藉「刪除 → 重新註冊」重複取得註冊獎勵，但成本為 30 天冷靜期 ＋
全部訓練歷史與能力值歸零，遠高於所得，不構成可行的刷取路徑。

# 本題查證時發現的模型缺口（一併補上）

**Sign in with Apple 的授權權杖撤銷**。Apple 官方文件明文：
「Apps that support Sign in with Apple should use the Sign in with Apple REST API to revoke user tokens.」

模型原本的帳號刪除 Postcondition 只寫「刪除第三方帳號綁定」，**未含撤銷授權權杖**。
兩者為不同的事：前者清本平台這一側的資料，後者是通知 Apple 解除該使用者對本 App 的授權；
只做前者會使該授權於 Apple 帳號的「使用 Apple 帳號登入的 App」清單中持續掛著。
已增列為 Postcondition（Google 登入比照處理），不另立 Event。
