# 釐清問題

個人排行榜已完整定案同分並列與名次判定規則（同分並列同一名次、下一名次順延跳號，且明訂三個「不採」的替代方案與理由）。但團隊日常排行榜與團隊限時排行榜已於第九輪新增「依人數分級距分組」（3人組/4人組/5人組）機制後，兩個團隊排行榜於同一分組內的同分並列、名次判定規則從未給出——`排行榜週期結算流程.md` 僅寫「團隊日常排行獎勵已發放」「團隊限時排行獎勵已發放」兩個 Event 名稱，未附帶任何排名規則，與個人排行榜的詳盡程度不對稱。

# 定位

流程：排行榜週期結算流程
元素：Aggregate「團隊分數」〈團隊分組依據〉子節；Event「團隊日常排行獎勵已發放」「團隊限時排行獎勵已發放」的 Postcondition
細節：個人排行榜的既有規則（同分並列同一名次、順延跳號、不採時間先後/次要指標/獎勵平均分配）是否直接比照套用於團隊排行榜的人數分組結果，或團隊排行榜需要自己的一套規則（例如因分組人數不同，同分機率可能高於個人排行榜）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 團隊排行榜的同分並列與順延跳號規則，直接比照個人排行榜的既有規則（同分者並列同一名次、下一名次順延跳號、不以達成時間或次要指標決斷），兩個團隊排行榜（日常、限時）各自的每個人數分組（3/4/5人組）獨立比較，如同個人排行榜的每個階級組獨立比較（**推薦**：團隊分數同樣是「分數推導排名、依名次發獎勵」的同一種機制，個人排行榜的規則與理由（不讓次要指標或訓練時段影響公平性）同樣適用於團隊，重新發明一套並無新增價值，且維持模型內部一致的設計語言） |
| B | 團隊排行榜同分時不並列，改以團隊建立時間較早者優先排名（早建隊者優先） |
| C | 團隊排行榜同分時採獎勵平均分配（與個人排行榜刻意採取相反的規則，因團隊涉及多人分潤，性質不同） |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響 Event「團隊日常排行獎勵已發放」「團隊限時排行獎勵已發放」的 Postcondition 完整性；團隊排行獎勵已於第九輪定案具體數額（見〈第三批獎勵最終定案〉），但發放給「哪一名」目前無判定依據。

High

# 解決結果

選項 A：團隊排行榜（日常、限時）的同分並列與順延跳號規則，直接比照個人排行榜既有規則，於各自人數分組（3/4/5人組）內獨立比較。
