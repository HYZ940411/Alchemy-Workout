# 釐清問題

訓練提醒採兩段式發送：有訓練紀錄者由系統依訓練紀錄的時戳分布推算慣常時段，無訓練紀錄者取自使用者自選的「偏好訓練時段」。推算路徑的輸出結構已定案與偏好訓練時段完全一致（星期 → 時段區間集合 → 起訖時間，30 分鐘粒度，不可跨日），但兩者的「型別銜接」是否已完整定義仍標記為待決策，需要確認推算演算法的實作輸出是否確實能產生合法的偏好訓練時段結構（如推算出的多個候選時段如何收斂為單一區間、是否可能產生跨日或重疊區間需要額外正規化）。

# 定位

流程：訓練紀錄流程
元素：Rule「訓練提醒的發送時段判定」
細節：`00_全域規範.md` 已定案「推算方式：取該星期幾歷史訓練的開始時戳，以 30 分鐘為粒度，取次數最多的區間作為該日的時段」與「推算門檻：最近 4 週內有 ≥ 6 筆訓練紀錄」，但未說明同一星期幾若有多個次數相近的候選區間時如何決斷（取最高頻一個，或允許多個）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 每個星期幾僅推算出至多一個區間（次數最高者；同票時取最早發生的區間），與偏好訓練時段「每日 0 到 N 個區間」的結構相容但退化為至多 1 個，不做多區間推算（**推薦**：與既有規則「每日至多一則」提醒本就只需要一個時段即可運作，多推算出的候選區間沒有下游用途，維持單一區間輸出最簡單且與既有「取次數最多的區間」文字直接對應） |
| B | 允許每個星期幾推算出多個區間（次數並列最高者全部保留），型別與偏好訓練時段一致地承載 0 到 N 個區間 |
| C | 推算結果不直接寫入偏好訓練時段欄位，而是另存一份「推算時段」唯讀欄位，兩者並存不合併 |
| Short | 提供其他簡短答案（<=5 字） |
