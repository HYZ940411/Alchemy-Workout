# 釐清問題

「單次訓練已逾時中斷且已完成組數 ＝ 總計畫組數者，訓練獎勵金幣給 100%」為既有裁決。但課表全部動作完成即觸發「使用者已完成訓練」（Actor 系統、自動），該情形是否根本無法發生？若不可達，此規則與其所支撐的三處理由應如何處理？

# 定位

流程：訓練紀錄流程、訓練結算流程
元素：Rule：〈訓練獎勵金幣的完成度差額〉表第 3 列
細節：C3 邊界條件（狀態邊界）、C4 不可逆性。overview §4.2 已記錄本矛盾但未建為釐清項目；`pending-gaps-3.md` 之 I19 為其來源。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 該情形**確實不可達**：移除該列，逾時中斷一律 50%。連帶複核三處以「逾時中斷最常見的原因為練畢未按結束」為理由的裁決 |
| B | 該情形**可達**：「使用者已完成訓練」的觸發需要最後一組完成後的系統判定，若使用者在該判定前離開且逾 40 分鐘，仍可能先發生逾時中斷。維持該列不變，並補上 Precondition 說明 |
| C | 該情形可達的另一路徑：訓練中「使用者已加入動作至本次訓練」後不勾選該些組再離開，總計畫組數上升使兩者不相等 —— 反之若加入後全部勾選卻未按結束，即為本情形。維持該列 |
| D | 改寫判準：逾時中斷的金幣係數改為依**完成度百分比連續計算**（已完成組數 ÷ 總計畫組數 × 100%），取消 50% / 100% 的二分，本矛盾隨之消失 |
| Short | 提供其他簡短答案（<=5 字） |

# 解決結果

**A** —— 維持現況：仍記為「單次訓練已逾時中斷」，獎勵與經驗值比照完成發放。

**核心為事實與待遇分離**：「有沒有按結束」與「有沒有練完」是兩件事。
終止方式記錄前者（他確實沒按，且由系統判定終止），獎勵給後者（他確實練完了）。
`00_全域規範.md:4076` 的表原已如此計算，但無任何一行解釋為什麼，易被誤讀為漏寫。

## 使用者於本題追問：回顧時會不會覺得不舒服

查證結果：**現況剛好躲過去了，但是靠漏寫躲過去的。**

1. 〈Read Model：訓練歷史〉的訓練清單欄位為日期、課表名稱、總訓練量、訓練時長
   —— **不含終止狀態**，故回顧時不會看到「逾時中斷」。
2. **〈Read Model：訓練結算頁〉根本不存在** —— 24 個 Read Model 中沒有它，
   而那正是練畢當下會看到終止狀態的地方。

故「使用者會看到什麼」在本題之前**從未定義**。已將「不對使用者呈現終止方式」
明文寫入，不留給實作猜測；並另建 Read Model 缺口項目（見下）。

## 三個不採方案的理由

- **不採「最後一組打勾即自動結算」**：練完最後一組後仍可加組與改重量，
  自動結算等於強制關門；且結算後訓練紀錄凍結，誤觸者失去補救機會。
- **不採「進度 100% 即改記為已完成訓練」**：該筆確為系統判定終止，
  改記將使「使用者已完成訓練」同時代表兩種事實，
  且 AI 將看不出「此人常練畢未按結束」的真實訊號。
- **不採「不比照完成發放獎勵」**：承既有裁決「逾時中斷最常見的原因為練畢未按結束
  而非未訓練，扣除等於懲罰確實有訓練者」。
