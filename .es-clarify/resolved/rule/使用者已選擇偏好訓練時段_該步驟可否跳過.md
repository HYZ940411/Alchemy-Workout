# 釐清問題

新手任務流程中「選擇偏好訓練時段」一步，使用者可否跳過；若跳過，訓練提醒（無訓練紀錄者的兩段式發送路徑）如何處理，尚未定案。

# 定位

流程：新手任務流程
元素：Command「選擇偏好訓練時段」
細節：偏好訓練時段的結構已完整定案（星期 → 區間集合 → 起訖時間），且「某日區間集合為空，代表該日無空閒時段，該日不發送訓練提醒」已有規則，但這是「填了但某天留空」的情形，不等於「整個步驟直接跳過、完全未填」的情形。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 可跳過；跳過視同全部 7 天皆無區間（空集合），使用者於跳過期間不收到任何訓練提醒，直到之後於設定頁補填或累積訓練紀錄達推算門檻（**推薦**：與模型既有規則「某日區間集合為空即該日不發送提醒」自然延伸——全部留空只是空集合的特例，不需要另立新狀態；且新手任務其餘步驟已有「可否跳過」的類似先例（如體重更新可跳過），維持一致的產品語感） |
| B | 不可跳過，為新手任務流程的必填步驟，比照註冊流程 9 項必填的精神 |
| C | 可跳過，但跳過者於下次登入時以彈窗形式重新詢問，直到填寫或連續 N 次忽略後才停止詢問 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響新手任務流程中該 Command 的 Precondition、無訓練紀錄新使用者的訓練提醒能否正常運作。為 `pending-gaps-3.md` I8 之延續。

# 優先級

Low

# 解決結果

**選項 A**：可跳過；跳過者七天的區間集合皆為空 → 不發送訓練提醒，
直到累積足夠訓練紀錄（最近 4 週 ≥ 6 筆）後改由系統依訓練時戳推算。

- 跳過不阻擋任何後續 Command，不影響新手任務的完成與獎勵領取。
- 跳過不產生「使用者已選擇偏好訓練時段」，欄位維持空值。
- **跳過的效果不需新規則**：模型已定「某日的區間集合為空，代表該日無空閒時段，
  該日不發送訓練提醒」，跳過天然落在這條既有規則上。
- 使用者其後仍可於設定頁補填，補填時產生本 Event。

## 理由

- 承既有判例〈體重的時效性〉「可跳過，且不得阻擋簽到」；本步驟位於新手任務收尾，
  強制填寫會擋在獎勵領取之前。
- **不採 C（跳過者改用系統預設時段）**：預設時段猜錯時，提醒會發在該使用者不可能訓練的
  時間，而推播額度僅 3 則／日，錯誤的提醒會排擠掉真正有用的通知；
  承既有裁決「不採推算與偏好時段取聯集」的同型理由。

`[已知代價]` 跳過者於累積足夠訓練紀錄前完全收不到訓練提醒，
而模型已識別「D7 窗口：新使用者於第 3–7 天流失時無任何介入機制」，
訓練提醒為少數能介入的機制之一。**明示接受**——強迫填寫換來的是猜測性的資料，
其提醒品質未必優於不發。
