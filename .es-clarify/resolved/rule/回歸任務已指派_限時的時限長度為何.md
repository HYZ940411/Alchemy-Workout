# 釐清問題

「限時回歸訓練」的時限長度為何？時限起算點為指派時刻還是使用者首次查看時刻？

# 定位

流程：回歸任務流程
元素：Rule：回歸任務已指派的 Postcondition；Event：使用者已完成回歸任務
細節：模糊描述未量化（F4）；時間邊界與計時起點（C3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 指派後 3 天內完成，自指派時刻起算 |
| B | 指派後 7 天內完成，自指派時刻起算 |
| C | 指派後 7 天內完成，自使用者首次登入查看時起算 |
| D | 無固定時限，直到使用者完成一次訓練為止 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響回歸任務已指派的 Postcondition（到期時戳欄位）、回歸任務 Aggregate 的狀態機、以及逾期未完成 Event 的觸發時點。

# 優先級

High

# 解決結果

**選項 C**：指派後 **7 天**內完成，自**使用者首次登入查看**時起算。

**回歸任務 Aggregate 新增三個欄位**：指派時戳、時限起算時戳（首次查看時寫入，未查看時為空）、狀態。

- 時限起算時戳為空值者，逾期判定不啟動——使用者未回來查看即不會逾期。

**採首次查看起算而非指派時刻的理由**：回歸任務的觸發條件是「能力值已退步」，
亦即使用者已 120 小時（5 天）未訓練——指派當下他多半根本沒在看 App。

若自指派時刻起算（選項 A / B）：系統在他消失的第 5 天丟出一個 7 天任務，
他第 10 天回來時只剩 2 天；若選 A（3 天）則早已逾期。**這正好懲罰了這個機制想挽回的人。**

**不採選項 D（無時限）**：模型已明寫「[分支] 期限內完成 → 使用者已完成回歸任務；逾期未完成 → 回歸任務已逾期」，
選 D 須移除該 Event 與既有 Postcondition「逾期後該筆回歸任務消失，不發放獎勵」；
且無時限即無急迫感，回歸任務會變成永遠掛著的待辦。

**與既有規則相容**：「距前一次指派滿 7 天方可再次指派」管的是指派頻率，與完成時限無關，兩者並存。
