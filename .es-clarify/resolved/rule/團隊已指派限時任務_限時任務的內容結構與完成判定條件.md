# 釐清問題

「管理員已設定限時任務」與「團隊已指派限時任務」已定案為每日指派，但限時任務的**內容結構**與「成員已完成一次限時任務」的判定條件皆未定義。

# 定位

流程：團隊任務流程
元素：Rule：Event「成員已完成一次限時任務」的 Precondition；Aggregate（限時任務的承接處未定）
細節：C1 前置條件完整性、D1 Aggregate 識別。
現況：〈獨立 Aggregate 清單〉團隊分類僅有「團隊」一項，無限時任務 Aggregate；「限時」一詞未量化（每日指派，但任務本身的有效時窗為何未定）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 比照每日任務池的結構：任務項目＝名稱 ＋ 判定來源 Event ＋ 目標次數 ＋ 獎勵定義 ID；限時任務為獨立 Aggregate，有效時窗為指派當日（當地 04:00 換日） |
| B | 同 A 的結構，但共用每日任務池 Aggregate，以「適用對象＝個人 / 團隊」欄位區分，不新增 Aggregate |
| C | 限時任務僅有名稱與說明，完成由成員自行回報（Actor：使用者），系統不自動判定 |
| D | 限時任務固定為「當日完成一次訓練」單一內容，不做成可設定的任務池 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響〈獨立 Aggregate 清單〉是否新增限時任務、「成員已完成一次限時任務」的 Precondition 可驗收性、團隊限時分數的計算輸入（完成人數）、「團隊全體成員皆完成時額外加成」的判定時點（每日結束時？即時？），以及團隊頁 Read Model 的欄位。
相依：`aggregate/每日任務池_任務項目的結構與完成判定來源為何.md`（若採選項 A 或 B，兩者結構應一致）。
相關待釐清項目：`rule/團隊已指派限時任務_全平台同一組任務或可分團隊指派.md`（指派範圍）、`rule/團隊限時分數已增加_固定分與全員完成加成幅度為何.md`（分數值） — 三者為同一組決策，宜併題處理。

# 解決結果（2026-08-08，第八輪第 19 題）

**B ＋ 使用者修正** —— 共用〈每日任務池 Aggregate〉，新增「適用對象＝個人 / 團隊」欄位，
**不另立限時任務 Aggregate**。

## 一、結構與完成判定

| 項目 | 裁決 |
|------|------|
| 結構 | 共用每日任務池的四欄位 ＋ 新增「適用對象」 |
| 完成判定 | 成員於指派當日達成該項的判定來源 Event 與目標次數 |
| 有效時窗 | **當日有效**（當地 04:00 換日），隔日失效，不可補做 |
| 全員加成判定 | **即時** —— 最後一位成員完成的當下即給予 |

## 二、使用者推翻了助理的「訓練類項目不列入」建議

**助理原主張**：任務池應以低門檻行為（簽到、按讚）為主，訓練類項目會使
「5 人同日全部訓練」的機率僅約 1.5%，全員加成形同虛設；
且訓練類項目若走訓練紀錄流程，會污染四個下游數值。

**使用者裁定**：

> 限時任務不會像新手任務那麼簡單，會稍微多一點。
> 連續訓練天數 完全沒問題，因為重點是讓使用者可以「習慣上運動」。
> 累積訓練次數 也可以累計。個人排行榜分數 可以累積。六維能力值 可以累積。

**四個下游數值全部照常累計。** 理由為**習慣養成即是目的** ——
每日一小段訓練正是該習慣本身，計入連續訓練天數是設計而非漏洞。

## 三、使用者提出的社交機制（助理原未看出）

> 分派簡單快速的訓練，讓有規律健身的夥伴看到說：這個訓練很簡單快速，
> 然後去鼓勵不常運動的夥伴一起練一下

**訓練類項目產生「這個很快，一起做一下」這句邀請**，由規律訓練者向不常運動的隊友發起，
比要後者主動加入容易得多。而簽到、按讚類任務**產生不了這句邀請**
—— 沒有人會揪別人一起按讚。此為訓練類優於低門檻行為的關鍵理由。

## 四、限時任務的產品定位（助理判讀，經使用者確認方向）

| | 算法 | 由誰決定 |
|---|------|---------|
| 團隊日常分數 | 依訓練量 | 隊裡**最強**的成員 |
| 團隊限時分數 | 完成人數 × 固定分 | 隊裡**最慢**的成員 |

限時任務把團隊分數從「加總最強者」變成「取決於最弱者」，
加上全員完成加成即構成木桶效應，逼團隊去管尚未完成的人。
**即時判定加成**正是為維持「就差你了」的互相催促。

## 五、已知取捨

**累積訓練次數同時為教官初審門檻（≥ 50 次）**，限時任務會使其累積速度快於原設定。
使用者明示接受，理由為習慣養成的價值高於該門檻的精確度，且初審另有 AI 品質評分把關。
**屬明示接受的取捨，非待辦事項。**

## 六、兩個不採方案

- **不採 C（自行回報）**：完成數直接換算為團隊限時分數，而該分數用於排名；
  可自行按鈕加分的排行榜不成立。此點與新手任務不同 —— 後者的勾選不影響任何他人。
- **不採 D（固定單一內容）**：模型已定「多樣性由跨日提供，每日換一組」，
  固定內容會使該規則落空。
