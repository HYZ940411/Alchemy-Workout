# 釐清問題

快照的目標重量帶入「最近一次該動作的實際重量」時，本次組數與上次組數不同如何對應？「最近一次該動作」是否限定為已結算的訓練？

# 定位

流程：訓練紀錄流程
元素：Rule：Event「使用者已選擇訓練課表」的 Postcondition；Aggregate「本次訓練課表」的課表內容
細節：C3 組合邊界。`00_全域規範.md`〈快照產生時的目標重量帶入規則〉現以〔推導〕標記寫入：「以組序逐一對應；本次組數多於上次時，超出的組沿用上次最後一組的重量」，未經使用者確認。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 確認現行推導：以組序逐一對應；本次多於上次時超出的組沿用上次最後一組；本次少於上次時取上次的前 N 組 |
| B | 不做組序對應：全部組一律帶入上次該動作的**最大重量**，使用者再自行下修 |
| C | 不做組序對應：全部組一律帶入上次該動作的**最後一組重量**（多為最終適應重量） |
| D | 同 A 的組序對應，但「最近一次」限定為狀態為已完成的訓練，提前結束與逾時中斷的紀錄不作為帶入來源 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響本次訓練課表快照的產生規則、「使用者已記錄該組成績」未修改預帶值時的實績寫入值、以及訓練紀錄查詢的排序條件（須能依動作取最近一次）。
相依：`aggregate/訓練紀錄_訓練紀錄的完整欄位與狀態機為何.md`（選項 D 需訓練紀錄具備狀態欄位）。
相關已解決項目：`resolved/aggregate/訓練計畫_訓練計畫與自訂訓練的動作與組數結構為何.md`。

# 解決結果

**選項 D 修正** —— 組序逐一對應（多出的組沿用上次最後一組、少的取前 N 組），但帶入來源的粒度由使用者修正為**組**而非整場訓練：

使用者原話「不應該限制為已完成的訓練，應該為已完成的組數或動作」。
故取「該動作最近一次**實際完成該組**的實績」；中斷或提前結束的訓練中已完成的組仍為合法來源。
