# 釐清問題

「能力值已提升」每次提升的幅度如何計算？不同肌群是否適用同一換算率？單次訓練是否有提升上限？

# 定位

流程：訓練結算流程、新手任務流程
元素：Rule：Event「能力值已提升」的 Postcondition
細節：Aggregate 內部不變條件（D3）；數值邊界（C3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 依訓練總量（重量 × 次數 × 組數）換算，全肌群同一換算率，單次訓練無上限 |
| B | 同 A 但設單次訓練提升上限，避免單次爆量 |
| C | 不依訓練量，每完成一個該肌群的動作固定 +N，與重量次數無關 |
| D | 依訓練總量換算，但各肌群換算率不同（如腿部總量天生較高，換算率較低） |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響能力值的六維數值成長、階級與 AI 優化的計算基礎、以及能力值退步幅度的對稱性。
承接 G18；**相依**：`resolved/aggregate/訓練紀錄_重量的單位精度與零或負值是否合法.md` 已定訓練總量的計算基礎。
與 `rule/能力值已提升_徒手動作重量為零時如何計入能力值.md`（G21）及 `rule/能力值已退步_退步百分比與六維註冊初始值為何.md`（G24）為同一組決策，宜併題處理。

# 優先級

High

# 解決結果

**選項 D ＋ B**：依訓練總量換算，各肌群換算率不同，並設單次訓練上限。

**公式**：該維提升點數 ＝（本次該肌群訓練量 ÷ 該肌群基準訓練量）× 基準提升點數
（訓練量 ＝ 重量 × 次數 × 組數，逐組累加）

| 肌群 | 基準訓練量 |
|------|-----------|
| 腿 | 4,000 |
| 背 | 2,500 |
| 胸 | 2,000 |
| 肩 | 1,200 |
| 手 | 800 |
| 核心 | 600 |

| 參數 | 初始值 |
|------|--------|
| 基準提升點數 | 10 點 |
| 單次訓練單維上限 | 30 點 |

**參數化的取捨（使用者追問「這是最平衡的答案嗎」）**：

- D ＋ B 平衡的是**輸出**，代價是 7 個需要靠真實資料校準的參數；校準錯誤會使六維系統性歪斜，
  而使用者無從察覺是公式問題。
- 因此改以「**基準訓練量**」表達，而非 6 個抽象換算率：每個數字的意義為「該肌群一次認真訓練的典型總量」，
  可由訓練資料直接估算，也易於向使用者解釋（一次認真訓練 ≈ 10 點、最多 3 倍）。

**為何各肌群獨立**：深蹲 100kg×10×4 ＝ 4,000，二頭彎舉 15kg×12×3 ＝ 540，差距 7 倍以上，
源於人體結構而非訓練投入。統一換算率會使每位使用者的六維圖恆為同一形狀（腿最高、手最低），
六個維度將失去表達差異的價值。

**為何需要上限**：能力值有退步機制（每 120 小時退步一次），提升若無上限，
一次超長訓練即可抵銷數個月退步，升降兩邊的尺度會對不上。

**明確不處理的兩件事**：

1. 徒手動作（訓練量恆為 0）→ 由 `rule/能力值已提升_徒手動作重量為零時如何計入能力值.md` 處理。
2. 訓練頻率不加權——持續性已由連續訓練天數與獎勵加成承擔，不在能力值重複疊加。
