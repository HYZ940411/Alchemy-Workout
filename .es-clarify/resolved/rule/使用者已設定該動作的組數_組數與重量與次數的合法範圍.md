# 釐清問題

自訂訓練中每個動作的組數、每組的重量與次數，以及單一課表的動作數量上限分別為何？

# 定位

流程：自訂訓練流程（循環 1：使用者已選擇動作 - 使用者已設定該動作的組數、循環 2：使用者已設定該組的重量 & 次數）
元素：Rule：使用者已設定該動作的組數、使用者已設定該組的重量 & 次數的 Precondition
細節：數值邊界與最小 / 最大值（C3）；特殊值：零（C3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 組數 1-20、次數 1-100、重量 0-500 公斤、動作數 1-30 |
| B | 組數 1-10、次數 1-50、重量 0-300 公斤、動作數 1-15 |
| C | 不設上限，僅要求為正整數 / 非負數 |
| D | 設上限但依會員身分不同，免費使用者限制較嚴 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響兩個設定 Command 的 Precondition、自訂訓練 Aggregate 的欄位範圍限制、與訓練紀錄 Aggregate 重量欄位範圍的一致性、以及訓練進度條的分母計算。

# 優先級

Medium

# 解決結果

**選項 A**

| 參數 | 合法範圍 |
|------|----------|
| 動作數（課表第一層） | 1–30 |
| 組數（課表第二層） | 1–20 |
| 目標次數 / 實際次數 | 1–100 |
| 目標重量 / 實際重量 | 0–500 公斤 |

- 上限同時套用於**目標值**（課表內容）與**實績值**（訓練紀錄的組紀錄）。
- 為「使用者已設定該動作的組數」「使用者已設定該組的重量&次數」
  「使用者已記錄該組成績」三者的 Precondition。
- 重量的單位（公斤）、精度（0.5）與非負限制沿用既有裁決，本次僅補上限。

**不採 C**（不設上限）：防作弊機制只擋連續快速勾選，不擋離譜數值；
訓練量直接餵給能力值與個人排行榜分數，無上限即為一條乾淨的刷分管道。

**不採 B**（組數 1–10、次數 1–50、重量 0–300、動作數 1–15）：
深蹲與腿推的實際重量可超過 300 公斤，徒手訓練的單組次數常超過 50，
全身訓練的動作數亦常超過 15。上限的用途是擋離譜值，不是替使用者決定怎麼練。

**不採 D**（依會員身分區分）：以「不能好好記錄訓練」逼使用者付費屬贖回型付費牆，
與〈Read Model：訓練歷史〉不以會員身分限制回溯範圍為同一理由。
