# 釐清問題

模型已定案「逾時中斷判定一律由後端依最後一組的完成時戳判定，與 App 是否在前景無關」「App 切至背景、關閉或離線皆不觸發中斷判定」。健身房訊號不良為常態，使用者若於離線期間先在本機勾選、恢復連線後才同步，其完成時戳以何者為準？防作弊的 30 秒最小組間間隔如何判定？

# 定位

流程：訓練紀錄流程
元素：Rule：Event「使用者已完成該組」的 Precondition（防作弊）與組紀錄的「完成時戳」欄位；連帶「單次訓練已逾時中斷」的 40 分鐘判定
細節：C3 邊界條件（時間邊界）、C5 失敗與例外路徑。`訓練中斷流程.md` 以 `[待決策 Partial]` 標記，另記於 `pending-gaps-3.md` 之 I24。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 不支援離線記錄：無連線時勾選不成立，畫面明示「需連線」。所有時戳一律由後端產生，判定規則完全不變 |
| B | 支援離線記錄：完成時戳以**用戶端時戳**為準並隨同步上傳，後端於同步時一次補判防作弊與逾時中斷。代價為用戶端時戳可被竄改 |
| C | 支援離線記錄，但時戳採「用戶端相對時間 ＋ 後端錨點」：以最後一次連線的伺服器時戳為錨，加上用戶端自該錨點起的經過時間，限制竄改幅度 |
| D | 支援離線記錄，離線期間的組一律標記為「離線補登」：計入訓練量與能力值，但**不計入 AI 訓練品質評分的紀錄合理性維度**，防作弊阻擋於同步時不套用 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響組紀錄「完成時戳」的來源定義、防作弊 Precondition 的可驗收性、「單次訓練已逾時中斷」的 40 分鐘判定、AI 訓練品質評分「紀錄合理性」維度的輸入可信度，以及訓練紀錄 Aggregate 是否需新增「離線補登」旗標。

# 出題修正

助理原推薦選項 D（離線整批豁免防作弊），論據為「用戶端時戳可被竄改」。
**使用者質疑：「誰會沒事改時戳？」** 助理重新檢視後承認推薦有誤：

1. 於每組之間手動改動系統時間為極高成本，且會弄壞裝置上其他功能，該威脅不真實。
2. 真正要防的「隨手亂點灌訓練量」**不需要改時戳**，快速點擊即可。
3. 助理推薦的 D 反而開了一個**無技術門檻**的後門 —— 開飛航模式即可無限制快速勾選。
4. 助理原先漏掉的事實：**防作弊阻擋本即發生於點擊當下、由前端計算**，
   離線時 App 一樣算得出組間間隔並當場阻擋，B 不需要新增任何信任假設。
5. 模型其他處**本即以用戶端當地時間為準**（〈連續簽到 Aggregate〉的「上次簽到日期」
   明訂為使用者當地日期），B 與既有做法一致。

# 解決結果

**選項 B —— 用戶端時戳。**

| 項目 | 裁決 |
|------|------|
| 離線可否勾選完成 | 可 |
| 完成時戳來源 | **用戶端時戳**，同步上傳後原樣寫入，後端不以收訊時間覆寫 |
| 離線期間的防作弊 | **照常套用**，由 App 於本機計算組間間隔並當場阻擋 |
| 後端於同步時 | 不重新判定已於本機阻擋過的組 |
| 逾時中斷的 40 分鐘判定 | 同樣依用戶端時戳，離線與連線的判定結果一致 |

不採其他選項的理由：
- **A（不支援離線）**：地下室健身房、電梯、山區、出國無漫遊皆為真實情境；
  訓練紀錄為本系統的核心動作，不應依賴連線。
- **C（用戶端相對時間 ＋ 後端錨點）**：該方案為限制時戳竄改幅度而設，
  而該威脅經使用者指出並不真實，不值得為其增加錨點同步機制。
- **D（整批豁免防作弊）**：漏洞無技術門檻，較用戶端時戳可被竄改的風險更大。

**[已知取捨]** 決心竄改系統時間者仍可繞過 30 秒阻擋。承既有裁決，
該層防線本即為**事前阻擋**，決心作弊者由 AI 訓練品質評分的「紀錄合理性」維度事後承接。

**未新增「離線補登」旗標**：本檔〈影響範圍〉原列此為可能的連帶改動，
選項 B 下離線與連線的紀錄在判定上完全等價，無區分必要。
