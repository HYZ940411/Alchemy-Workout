# 釐清問題

「每日登入提醒已發送」的發送時間、發送對象與發送渠道分別為何？

# 定位

流程：每日簽到流程
元素：Rule：每日登入提醒已發送的 Precondition / Postcondition
細節：系統自動觸發的 Command（B1）、觸發源（B5）、Precondition 可驗證性（C1）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 每日固定時間推播給所有當日未簽到的使用者，渠道為 App 推播 |
| B | 每日固定時間推播給所有使用者，不論是否已簽到 |
| C | 依使用者設定的提醒時間個別推播，且僅推播給當日未簽到者 |
| D | 僅推播給連續簽到天數大於 0 的使用者，避免打擾長期未活躍者 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響每日登入提醒已發送的 Actor（排程系統）、Precondition、使用者 Aggregate 是否需要「提醒時間」與「推播開關」欄位、以及與連簽中斷預告已發送的重複推播問題。

# 優先級

Medium

# 解決結果

**選項 A** —— 對象為當日尚未簽到者；時間為使用者當地時區固定時點；渠道為推播通知。本通知屬例行提醒類，於通知優先序中最低。具體時刻尚未定案。
