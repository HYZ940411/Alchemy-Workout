# 釐清問題

「AI 已優化訓練強度」由系統於每 3 次訓練後**背景產出**，但其後的「使用者已確認使用新訓練強度」與「使用者已拒絕調整」**須使用者在場**。模型未定義建議產出後在何時、何處呈現給使用者，該段完全空白。建議亦無有效期限：使用者兩個月不開 App，那份建議是否仍然有效？

# 定位

流程：AI 自動優化訓練流程
元素：Rule（Postcondition）、可能新增 Read Model 或通知類 Event
細節：A3 事件時序與因果、E4 Read Model→Command 支撐。
由助理於第七輪第 9 題查證時發現；使用者確認「自動優化應該是使用者不在場時，系統自動跑」後暴露此缺口。

# 背景

| 階段 | 使用者在場？ | 模型有無定義 |
|------|------------|------------|
| 系統偵測滿 3 次訓練 | 否 | 有 |
| AI 產出建議 →「AI 已優化訓練強度」 | 否 | 有 |
| **建議呈現給使用者** | — | **無** |
| 使用者接受或拒絕 | **是** | 有 Event，無觸發時機 |

另兩條 AI 流程無此問題：使用者主動提出調整，建議直接回到他眼前的畫面。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | **下次開 App 時彈出**：以強制對話框呈現，未處理前不進主畫面 |
| B | **進通知中心**：產生通知類 Event「訓練優化建議已發送」，使用者自行點入處理 |
| C | **於課表選擇頁標記**：該課表旁標示「有新的優化建議」，使用者選課表時順帶看到，不另發通知 |
| D | **B ＋ C**：發通知，且在課表選擇頁常駐標記，避免通知被忽略後建議永遠找不到 |
| Short | 提供其他簡短答案（<=5 字） |

# 一併須裁決的子題

1. **建議的有效期限**：產出後多久失效？失效後是否重新觸發 3 次計數？
2. **建議可否累積**：使用者連續 9 次訓練都沒處理建議，是產生 3 份建議、還是後者覆蓋前者？
3. 若採 B 或 D，該通知於〈通知類 Event 優先序〉中的歸類為何
   —— 相依於 `rule/通知類Event_完整清單與各自的優先序歸類尚未盤點.md`。

# 影響範圍

影響〈AI 自動優化訓練流程〉的 Postcondition、可能新增 1 個通知類 Event、
〈Read Model：課表選擇頁〉的欄位（C / D 選項）、以及「AI 已優化訓練強度」是否需新增
「建議狀態」與「產出時戳」欄位以支撐有效期限判定。
相依：`rule/通知類Event_完整清單與各自的優先序歸類尚未盤點.md`（B / D 選項）。

# 優先級

**High** —— 該段空白使「使用者已確認使用新訓練強度」在模型中無觸發路徑，
整條自動優化流程實質上走不完。

---

# 解決結果（2026-08-07，第八輪第 15 題）

**C ＋ 覆蓋** —— 優化建議於**課表選擇頁**該課表旁標示「有新的優化建議」，
**不另發通知、不彈對話框**；**同一課表範本只保留最新一份，後者覆蓋前者**。

## 主要理由

建議的內容即「這份課表的強度」，而課表選擇頁正是使用者決定要不要用這份課表的時點，
**時機天然正確**。常駐標記未處理前不消失，不會像通知那樣被滑掉即永遠找不到。

## 子題答案

| 子題 | 答案 |
|------|------|
| 1. 有效期限 | **不設期限** —— 建議不過期，只會被下一份取代（由子題 2 自然解消） |
| 2. 可否累積 | **不累積**，後者覆蓋前者。每份建議皆依最近 3 次訓練產出，舊建議所本資料已過時 |
| 3. 通知優先序歸類 | **不適用** —— 本方案不產生通知類 Event |

**子題 3 的相依因此解除**：本項不再相依於
`rule/通知類Event_完整清單與各自的優先序歸類尚未盤點.md`。

## 三個不採方案

- **不採 A（下次開 App 彈強制對話框）**：使用者開 App 是為了開始訓練，
  強制處理等於逼他在尚未暖身時決定訓練強度。
- **不採 B（僅發通知）**：通知被滑掉或清空後，模型中無任何地方能重新叫出該建議。
- **不採 D（通知 ＋ 標記並行）**：〈通知類 Event 完整清單與同日總量上限〉尚未盤點，
  增設通知為先行欠帳；常駐標記已解決「會不會漏掉」，而使用者不選課表即代表不訓練，
  屆時通知他亦無意義。

## 與第 2 題的連動

第 2 題已定**自動優化為會員專屬**，故本建議**僅會員收得到**，
〈Read Model：課表選擇頁〉的該欄位僅會員可能為真。
