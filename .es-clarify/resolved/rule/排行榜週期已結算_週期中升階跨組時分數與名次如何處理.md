# 釐清問題

個人排行榜依階級區間分組（每 10 階一組，共 10 組），週期進行中使用者升階跨組（如第 10 階升至第 11 階）時，既有分數如何處理？組別以何時的階級為準？

# 定位

流程：排行榜週期結算流程、階級提升流程
元素：Rule：Event「排行榜週期已結算」「個人排行獎勵已發放」的排名判定；Read Model「個人排行榜」的分組
細節：C3 組合邊界、C4 單調遞增與不可逆性。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 分數帶著走並即時改列新組：組別恆依當下階級判定，結算時亦以當下階級為準 |
| B | 以週期結算當下的階級決定組別，週期中的顯示組別可能與最終結算組別不同（畫面須標明） |
| C | 分數留在原組至週期結束：組別以週期起始時的階級鎖定，升階於下一週期才生效 |
| D | 分數依組別分別累計：跨組時原組分數保留但停止累加，新組自 0 起算，各組獨立競爭 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響「排行榜週期已結算」與「個人排行獎勵已發放」的 Postcondition、Read Model「個人排行榜」的所屬組別欄位推導、以及**刷分風險**：若採選項 A 或 B，使用者可能刻意壓低經驗值不升階以留在低組領獎（階級已定案為單調遞增、永不下降，故無法回退，但可延後升階）。

# 解決結果

**選項 A** —— 分組於**週期起點鎖定**，週期內升階不改變本週期所屬組別；新組別自下一週期生效。
分數全額保留，不歸零、不轉組、不移除舊組名次。

裁決要點：

1. 個人排行榜分數 Aggregate 新增兩個欄位：**週榜所屬組別**、**月榜所屬組別**。
2. 兩榜各自鎖定（週榜每週一 04:00、月榜每月 1 日 04:00），同一使用者兩榜的組別可能不同。
3. 「排行榜已重置」的 Postcondition 因此有兩項：歸零該榜別累計分數，
   並以當下階級重寫該榜別的所屬組別。
4. Read Model「個人排行榜」的「所屬組別」欄位來源由「依使用者階級推導」
   改為「取本週期鎖定的組別」。
