# 釐清問題

出貨後的退換貨已裁決留在系統邊界之外，「訂單已退款」是否僅限出貨前？出貨後若需退款，由誰觸發？

# 定位

流程：實體商品購買流程
元素：Rule：Event「訂單已退款」的 Precondition；Aggregate「訂單」狀態機
細節：失敗與例外路徑（C5）；狀態邊界 — 終止狀態下的再次操作（C3）；訂單狀態機（D5）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 僅限出貨前（已付款 → 已退款）；出貨後的退款為人工作業，明確標記留在系統邊界之外 |
| B | 出貨後亦可退款，由管理員手動觸發，訂單狀態機新增「已出貨 → 已退款」轉換 |
| C | 出貨後可退款，且須補「管理員已受理退貨」Event 承接人工判定 |
| D | 出貨後不可退款，且移除「訂單已退款」的所有非出貨前來源，該 Event 僅由取消訂單觸發 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響訂單狀態機的終止狀態定義（目前「已出貨」為終止狀態）、「訂單已退款」的 Precondition 與 Actor、以及庫存是否回補。
承接 G12。**注意**：`resolved/event/商品已出貨_出貨後的物流與退換貨Event缺失.md`（選項 A）已裁決出貨後留在系統邊界之外；本項記錄的是該裁決留下的空洞，非推翻裁決。

# 優先級

Medium

# 解決結果

**選項 A** —— 僅限出貨前（已付款 → 已退款）；出貨後的退款與退貨明確標記為人工作業，留在系統邊界之外，不建模為 Event。
