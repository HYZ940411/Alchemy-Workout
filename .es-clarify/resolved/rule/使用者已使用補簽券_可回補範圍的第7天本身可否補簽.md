# 釐清問題

「可回補最近 7 天」的邊界，**距今整整第 7 天的那一天本身**可否補簽？

# 定位

流程：補簽流程
元素：Rule：Command「使用補簽券」的 Precondition
細節：`補簽流程.md` L5 與 L6 兩句措辭互相矛盾。

**本題不是重問「回補範圍是幾天」**。
`.es-clarify/resolved/rule/使用者已補簽_可回補的時間範圍為何.md`
已裁決 7 天且為平台級可調參數（存於補簽設定 Aggregate，
`02_Aggregate定義.md` L4185–L4191），該裁決成立不變；
本題補的是**該裁決未觸及的端點含不含**。

# 白話說明

同一份 `補簽流程.md` 裡有兩句話，講的是同一件事，但意思不一樣：

```
L5  [Rule] 可回補最近 7 天內的任一未簽到日
L6  [Rule] Precondition：所補之日期距今未滿 7 天
```

「7 天**內**」一般人讀起來包含第 7 天；「**未滿** 7 天」則明確不含第 7 天。
差的就是那一天。

具體一點：今天是 2026-08-23。

| 補簽日期 | 距今 | 依 L5「7 天內」 | 依 L6「未滿 7 天」 |
|----------|------|----------------|-------------------|
| 2026-08-17 | 6 天 | 可補 | 可補 |
| **2026-08-16** | **7 天** | **可補** | **不可補** |
| 2026-08-15 | 8 天 | 不可補 | 不可補 |

08-16 這一天到底補不補得成，模型現在給不出答案。

# 多選題

| 選項 | 描述 | 推薦 |
|------|------|------|
| A | **含端點**：距今 ≤ 7 天者可補，08-16 補簽成功。L6 改寫為「所補之日期距今不超過 7 天」，與 L5 統一 | ★ |
| B | **不含端點**：距今 < 7 天者才可補，08-16 補簽失敗。L5 改寫為「可回補最近 6 天內的任一未簽到日」 | |
| C | **改以自然日計數**：「最近 7 個自然日（含今日）」，即實際可補到距今 6 天，08-16 失敗 | |
| D | 交由補簽設定 Aggregate 另設一個「是否含端點」的參數，由管理員決定 | |
| Short | 提供其他簡短答案（<=5 字） | |

# 推薦選項與理由

**推薦 A（含端點，判定式為「今日 − 補簽日 ≤ 回補範圍」）。**

- **符合使用者對「最近 7 天」的直覺**。使用者看到補簽頁上寫「可回補最近 7 天」，
  會預期第 7 天能點。做成不能點，會被視為系統出錯而不是規則設計。
- **多數團隊在「對使用者有利／不利」的邊界上，選擇對使用者有利的一側**。
  這裡多開一天的成本極低（補簽仍受補簽券張數上限 5 張的硬約束，
  見 `02_Aggregate定義.md` L2471），但少開一天造成的客訴成本不低。
- **本模型既有慣例支持用 ≤ 表達門檻**：`02_Aggregate定義.md` L2165 的不變條件寫作
  「累計天數 ≥ 歷史最長連續天數 ≥ 連續天數」、L4223 的及格標準寫作「答對 ≥ 80%」，
  皆採含端點的比較符號。L6 的「未滿」是全檔中少見的排除式措辭，
  研判為撰寫時的隨手用語而非刻意設計。
- **不推薦 D**：多一個參數就多一組組合要驗收，而這個參數不會有人去調。
  `02_Aggregate定義.md` L4202 已有「補簽券的持有上限不列入本表」的先例，
  顯示本模型傾向讓補簽設定只保留真正需要調整的參數。

# 對 Gherkin 翻譯的影響

直接阻擋 `.gh-clarify/outline/使用補簽券_回補範圍的邊界要寫幾列Examples.md`。

該項要用 `Scenario Outline` ＋ `Examples` 表格寫邊界，典型的三列是
「剛好達標／邊界／超過」。但**第二列（邊界那一列）的預期結果現在填不出來**：

```gherkin
    Examples:
      | 補簽日期距今 | 結果 |
      | 6 天        | 成功 |
      | 7 天        | ???  |   ← 這一格填不出來
      | 8 天        | 失敗 |
```

選 A 則第 7 天為「成功」、第 8 天為「失敗」；選 B 則第 7 天為「失敗」，
且第一列要改成「5 天成功／6 天成功／7 天失敗」。**表格要寫幾列、每列填什麼，
完全取決於本題。**

同時也影響 `.gh-clarify/given/使用補簽券_回補範圍7天這個平台參數要不要寫進Given.md`：
若判定式改為 `今日 − 補簽日 ≤ 回補範圍`，Given 就必須寫明回補範圍的值才能算出邊界。

# 解決結果

**選項 A** —— 含端點。

判定式統一為：**距今天數 ≤ 回補範圍**（回補範圍初始值 7 天，取自補簽設定 Aggregate）。
即距今第 7 天**仍可補**、第 8 天起不可補。

範例（今日 2026-08-23）：08-17（距今 6 天）可補、**08-16（距今 7 天）可補**、08-15（距今 8 天）不可補。

「距今」的起算基準另由第 6 題定案，本題只裁決比較符號。
