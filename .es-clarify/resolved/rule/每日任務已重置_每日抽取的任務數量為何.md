# 釐清問題

每日重置時自任務池隨機抽取的「固定數量」是幾項？抽取是否避免連續多日重複？任務池數量不足時如何處理？

# 定位

流程：每日任務流程
元素：Rule：Event「每日任務已重置」的 Postcondition
細節：欄位定義（D2）；數值邊界（C3）；待決事項（F3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 每日 3 項，允許與前一日重複，任務池不足時抽出全部 |
| B | 每日 5 項，避免與前一日完全重複，任務池不足時抽出全部 |
| C | 每日 3 項，且與前一日不重複（池內項目須 ≥ 6 項方可設定） |
| D | 數量為平台級可調參數由管理員設定，預設 3 項 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響「每日任務已重置」的 Postcondition 驗收、「每日任務已完成」的全部完成判定基準、以及每日任務池的最小項目數限制。
承接 G25；相關已解決項目：`resolved/aggregate/每日任務_任務項目與數量由誰定義.md`（選項 B，僅定歸屬未定數量）。

# 解決結果

**選項 A ＋ 依模型慣例的可調性**：每日抽取 **3 項**，允許與前一日重複，任務池不足時抽出全部；
數量存於每日任務池 Aggregate 由管理員調整（預設 3 項）。

- **採 3 項而非 5 項**：每日任務的完成方式為「完成每日訓練 / 互動」，一位使用者一日的合理行為量
  約為練一次、發個文、按幾個讚。5 項會使「每日任務已完成」的加碼獎勵與加碼分數變成少數人才拿得到，
  而該獎勵應為多數認真使用者可達成。
- **不做跨日去重**：任務池內容本為「訓練一次」「按讚 3 次」等日常行為，連續兩日重複屬使用者預期內。
  且選項 B / C 的去重規則會帶來隱形約束——任務池必須維持足夠數量，管理員縮減池子時系統將抽不出來。
- **任務池不足時抽出全部**：唯一不會卡住的處理方式。
- 可調性採選項 D 的精神：此數字**確實影響平衡性**（3 項或 5 項直接改變全部完成獎勵的取得率），
  且每日任務池本就是管理員維護的 Aggregate，抽取數量放入同一設定為自然做法。
  此點與第 41 題（師徒逾期時限不做參數）的判準一致：影響平衡性者做成參數，純等待窗口者不做。
