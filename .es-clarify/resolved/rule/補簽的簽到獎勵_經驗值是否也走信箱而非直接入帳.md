# 釐清問題

補簽當日的簽到獎勵中，**經驗值**是否也隨金幣一起進獎勵信箱、待領取才入帳，
還是比照真實簽到直接入帳？

# 定位

流程：補簽流程
元素：Rule：`補簽流程.md` L15 的 Postcondition
細節：「經驗值 10 ＋ 金幣 10」這一整包獎勵的入帳路徑，未區分兩種幣別。

# 白話說明

真實簽到時，經驗值是**當場直接入帳**的。`每日簽到流程.md` L45–L47：

```
L45  簽到獎勵已發放
L46  [Rule] Postcondition：簽到獎勵內容：經驗值 10 ＋ 金幣 10
L47  經驗值已提升 〔攜帶資訊：來源＝每日簽到〕
```

簽到 → 獎勵發放 → 經驗值馬上就提升了，接著才有可能觸發升階
（`階級提升流程.md` L6–L7：經驗值達門檻即升階）。

補簽的規則寫的是（`補簽流程.md` L15）：

> Postcondition：補簽當日的簽到獎勵（經驗值 10 ＋ 金幣 10）照常發放，
> 但**補發至獎勵信箱**，不直接入帳

問題是這句話把經驗值和金幣綁在一起講，沒說經驗值要怎麼「進信箱」。

**具體差別**：使用者目前經驗值差 8 點就要升到下一階，他補簽三天（經驗值 3 × 10 ＝ 30）。

| 做法 | 升階發生在什麼時候 |
|------|-------------------|
| 經驗值也進信箱 | 補簽當下不升階；使用者哪天想起來去信箱按「領取」，才升階 |
| 經驗值直接入帳 | 補簽當下立刻升階，信箱裡只有 30 金幣 |

差別是**升階的時點會被使用者的領取行為延後**，可能延後好幾天，甚至永遠不領。

# 多選題

| 選項 | 描述 | 推薦 |
|------|------|------|
| A | **整包進信箱**：經驗值與金幣一併寫入信箱，使用者領取時才入帳，此時才產生「經驗值已提升」〔來源＝補簽〕 | ★ |
| B | **拆開處理**：經驗值直接入帳並立即產生「經驗值已提升」，只有金幣進信箱 | |
| C | **補簽不發經驗值**：只發金幣，經驗值為真實簽到專屬 | |
| Short | 提供其他簡短答案（<=5 字） | |

# 推薦選項與理由

**推薦 A（整包進信箱）。**

- **既有裁決的文字本來就是整包語意**。`補簽流程.md` L15 寫的是
  「簽到獎勵（經驗值 10 ＋ 金幣 10）⋯補發至獎勵信箱」——括號裡兩樣東西，
  後面接一個動作，沒有任何「其中金幣如何、經驗值如何」的分述。
  選 B 是在既有裁決上另切一刀，需要更強的理由。
- **信箱 Aggregate 的結構不支援拆帳**。`02_Aggregate定義.md` L893 的信箱以
  **一筆「獎勵定義 ID」為單位**，L896 的領取狀態也是整筆的未領取／已領取。
  把一筆獎勵拆成「一半直接給、一半掛信箱」，會讓「已領取」這個狀態失去意義——
  已經領了一半的獎勵，領取狀態要填什麼？
- **B 會造成兩種簽到獎勵有兩套規則**。模型在 `補簽流程.md` L16 的決策明白反對這件事：

  > 補簽視同該日有簽到，後果應與真實簽到一致，否則模型中會出現兩種不同等級的簽到日

  但這句話講的是「數額」要一致，不是「路徑」要一致——路徑上模型已經刻意讓補簽走信箱。
  選 B 等於在路徑上又做了一半的例外，變成三種模式（真實簽到全直接／補簽金幣走信箱／補簽經驗值直接），
  最難解釋的一種。
- **不推薦 C**：直接違反 L16 的既有決策，會使補簽日在累計上算數、在經驗值上不算數。
- **選 A 須明示接受的副作用**：升階時點延後至領取時。這在本模型不是新問題——
  三個排行獎勵早已是「結算時進信箱、領取時才發放」（`02_Aggregate定義.md` L4992），
  其中同樣含經驗值類獎勵，補簽採同一形狀不引入新的例外。
  另需注意「經驗值已提升」Event 的攜帶資訊須新增「來源＝補簽」
  （對照 `每日簽到流程.md` L47 已有「來源＝每日簽到」）。

# 對 Gherkin 翻譯的影響

影響 `.gh-clarify/then/使用補簽券_連帶產生的Event要斷言到哪一層.md`——
該項要決定 Then 斷言到哪一層 Event 為止。**這題不答，那一層的界線劃不出來**：

- 選 A：補簽的 Scenario **不會**出現「經驗值已提升」與「使用者已提升階級」，
  Then 到「獎勵已補發至信箱」為止；升階要另寫一條以「使用者已領取信箱獎勵」為 When 的 Scenario。
- 選 B：補簽的 Scenario **必須**一路斷言到 `Then 使用者（U001）的經驗值為 <N>`，
  甚至還要涵蓋「補簽剛好觸發升階」這條分支，Scenario 數量與 Given 的鋪陳都不同。

# 解決結果

**選項 A** —— 整包進信箱。

經驗值與金幣一併寫入信箱，兩者皆於使用者**領取時**才入帳；
「經驗值已提升」亦於領取時才發生，攜帶資訊「來源＝補簽」
（對照真實簽到為「來源＝每日簽到」，於簽到當下即發生）。

**明示接受的取捨**：補簽所得經驗值使階級提升的時點延後至領取時，可能延後數日或永不發生。
此非新引入的問題 —— 三個排行獎勵早已是「結算時進信箱、領取時才發放」的形狀，
其中同樣含經驗值類獎勵。

**不採 B（拆帳）的理由**：獎勵信箱以一筆「獎勵定義 ID」為單位，領取狀態亦為整筆的
未領取／已領取，拆成「一半直接給、一半掛信箱」後「已領取」無從表達；
且將形成三種模式（真實簽到全直接／補簽金幣走信箱／補簽經驗值直接），最難解釋。

**不採 C（不發經驗值）的理由**：違反「補簽視同該日有簽到，後果應與真實簽到一致」之既有決策。
