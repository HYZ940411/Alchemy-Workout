# 釐清問題

「師徒申請已逾期」的時限長度為何？自「使用者已申請師徒關係」起算多久未回應視為逾期？

# 定位

流程：師徒互動流程
元素：Rule：Event「師徒申請已逾期」的 Precondition
細節：時間邊界（C3）；模糊描述量化（F4）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 72 小時（3 天）未回應即逾期 |
| B | 168 小時（7 天）未回應即逾期 |
| C | 24 小時未回應即逾期 |
| D | 時限為平台級可調參數，由管理員於後台設定，預設 72 小時 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響「師徒申請已逾期」的 Precondition 驗收、帶徒名額的釋放時點（申請中申請佔用名額）、以及師徒申請的 Read Model 倒數顯示。
計時基準沿用 `00_全域規範.md` 的使用者當地時區時戳。
承接 G8；相關已解決項目：`resolved/event/對方已接受申請_對方拒絕申請時的Event為何.md`（選項 B）。

# 優先級

Medium

# 解決結果

**選項 B**：168 小時（7 天）未回應即逾期。

- Precondition：自「使用者已申請師徒關係」起算滿 168 小時未回應。
- 計時起點為申請時戳，計時基準為使用者當地時區時戳。

**採 7 天的理由**：申請中的申請會佔用教官的帶徒名額（既有裁決），而第 29 題定案教官從 1 人升至 2 人
約需 7.5 週，名額為稀缺資源。時限取捨兩端皆有代價：

- 太短（24 小時）：教官週末外出兩天，回來申請已全數逾期；學徒白等、教官白白錯過收徒機會。
- 太長：名額長期被卡住，教官想收其他人也收不了。

7 天為一個完整週，涵蓋「平日忙碌、週末才開 App」的常態使用情境；3 天會使「週五申請、週一才看到」
這種很普通的情況直接逾期。

**不採選項 D（做成可調參數）**：此數字不影響營收與平衡性，僅為等待窗口，做成參數只會增加一個
無人調整的後台欄位。對照組——階級門檻、聲望門檻做成參數有意義，因需依實際數據校準。

**連帶**：`pending-gaps-2.md` 之 H4（團隊邀請與加入申請的逾期失效）若日後決定要做，建議沿用同一時限。
