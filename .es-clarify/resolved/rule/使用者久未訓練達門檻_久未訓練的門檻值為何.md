# 釐清問題

「使用者久未訓練達門檻 → 指派限時回歸訓練」中的門檻值為何？與訓練中斷流程的 120 小時門檻如何區分？

# 定位

流程：回歸任務流程、訓練中斷流程
元素：Rule / Policy：使用者久未訓練達門檻 → 指派限時回歸訓練
細節：模糊描述未量化（F4）；數值與時間邊界（C3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 超過 7 天未訓練即指派回歸任務 |
| B | 超過 14 天未訓練即指派回歸任務 |
| C | 與訓練中斷流程串接：能力值已退步（120 小時）後再過 N 天指派 |
| D | 超過 30 天未訓練才指派，避免與訓練中斷流程的通知重疊擾民 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響回歸任務已指派的 Precondition、與訓練中斷流程各時間門檻的協調、使用者 Aggregate 需記錄的最後訓練時戳、以及推播通知的頻率控制。

# 優先級

High

# 既有約束（來自已解決項目）

第 6 題（`resolved/event/回歸任務已指派_與訓練中斷流程同時觸發時如何協調.md`，選項 D′）已裁決：
「回歸任務已指派」的 Precondition 為「能力值已退步」已發生。
故本門檻的下界為訓練中斷流程的 120 小時未訓練，不得早於該時點。

# 解決結果

**選項 A｜與 120 小時對齊，不另設獨立參數**

- 門檻的判定基準為**任一肌群維度發生「能力值已退步」**，即該維自最後一次訓練日的日界起滿 120 小時未訓練。
- Policy「使用者久未訓練達門檻 → 指派限時回歸訓練」直接掛在「能力值已退步」Event 上，
  門檻與 Precondition 為同一條件，一處維護。

不採 168 / 336 小時：Precondition 已將觸發綁在「能力值已退步」上，
另設較晚的門檻會使實際生效的永遠是較晚者，前者形同虛設。
不採依每週健身天數動態計算：每週 1 次的使用者需 21 天才被召回，最需要挽回的對象反而被放最久。
