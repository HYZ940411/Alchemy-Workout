# 釐清問題

「管理員已下架商品」時，既有的未付款訂單與已付款未出貨訂單如何處理？

# 定位

流程：管理員商品上架流程、實體商品購買流程
元素：Rule：管理員已下架商品的 Postcondition；Aggregate：商品與訂單的關聯
細節：關聯的生命週期（D4）；跨 Aggregate 一致性（D4）；狀態邊界（C3）。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 下架僅停止新訂單，既有訂單一律照常履行 |
| B | 下架時未付款訂單自動取消，已付款訂單照常出貨 |
| C | 下架時所有未出貨訂單一律取消並退款，需連帶產生退款 Event |
| D | 下架需先確認無未出貨訂單，否則不可下架（作為 Precondition） |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響管理員已下架商品的 Precondition 與 Postcondition、商品與訂單 Aggregate 的關聯生命週期、是否連帶產生訂單取消與退款 Event、以及庫存的回補處理。

# 既有約束（來自已解決項目）

第 47 題（`resolved/aggregate/商品_商品的欄位定義與價格庫存設定.md`，選項 D）已裁決：

第 13 題已裁決售完不自動下架，兩者為獨立概念。

# 解決結果

**選項 B** —— 依訂單狀態分別處理，分界為「是否已付款」：

| 訂單狀態 | 處理 |
|----------|------|
| 待付款 | **自動取消**，並釋放該筆佔用的庫存 |
| 已付款（未出貨 / 未發放） | **照常履行** |
| 已出貨 / 已發放 / 已取消 / 已失敗 | 終止狀態，不受影響 |

- 已付款者屬已成立的交易，承模型的「成立時鎖定、不追溯」原則。
- 本規則同時適用實體商品與虛擬商品。

**不採 C**（一律取消並退款）：使用者已付款而商品仍在庫，因管理員下架而退款為平台單方毀約；
且須新增退款 Event 與雙向退款流程，與虛擬商品既有裁決「不自動退款」相衝。

**不採 D**（下架前須無未出貨訂單）：使下架隨時可能被一張待付款訂單擋住，
管理員無法即時停售有問題的商品，違背下架的用途。

# 助理推導（非使用者裁決）

待付款訂單的自動取消由**系統**觸發，而既有 Event「使用者已取消訂單」的 Actor 為使用者。
故新增 Event **「訂單已因商品下架取消」**（待付款 → 已取消），連帶「庫存已釋放」。

未採將「使用者已取消訂單」改為多對一 —— 該 Event 名稱含「使用者已」，系統觸發時語意不符。
