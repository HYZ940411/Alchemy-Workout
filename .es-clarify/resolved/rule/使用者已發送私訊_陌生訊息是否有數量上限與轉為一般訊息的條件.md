# 釐清問題

陌生訊息已定案「不阻擋而是分區呈現」。陌生訊息是否有數量上限（單一發送者對同一收訊方、或收訊方的陌生訊息總量）？是否須經收訊方回覆後才轉為一般訊息？

# 定位

流程：聊天私訊流程
元素：Rule：Event「使用者已發送私訊」的 Precondition；Aggregate「私訊」之訊息分類欄位
細節：C3 邊界條件（數值邊界）、C1 前置條件完整性。`聊天私訊流程.md` 之 `[待決策 Partial]`。既有規則已定「分類於發送當下固定，其後關係變化不回溯改寫既有訊息的分類」，與「回覆後轉為一般訊息」可能牴觸。

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 皆不設限、亦不轉換：分區呈現已解決騷擾問題；設上限須維護計數器，而封鎖機制已是使用者的最終手段 |
| B | 設上限：同一發送者對同一未回覆的收訊方最多 3 則，超出者 Command 被拒。**不轉換分類**（承「分類於發送當下固定」的既有規則），但收訊方回覆後該對話的**後續**訊息自然歸為一般訊息（雙方已產生互動關係） |
| C | 同 B 的上限，且**回溯轉換**：收訊方一旦回覆，該對話既有的陌生訊息一律改為一般訊息，推翻「不回溯改寫」的既有規則 |
| D | 不設每對話上限，改設收訊方的陌生訊息**總量上限**（如 100 則），超量時最舊者不再呈現 |
| Short | 提供其他簡短答案（<=5 字） |

# 影響範圍

影響「使用者已發送私訊」的 Precondition、私訊 Aggregate 的訊息分類欄位規則、〈Read Model：對話清單〉分類分頁的內容，以及「可發送私訊的對象限制」既有裁決的邊界。

# 解決結果

**A** —— 陌生訊息**不設任何數量上限**，亦**不因收訊方回覆而轉換分類**。

- 單一發送者對同一收訊方：不設限。
- 收訊方的陌生訊息總量：不設限。
- 分類於發送當下固定，承既有規則不回溯改寫。
- 收訊方回覆後，後續訊息仍依發送當下的雙方關係判定 ——
  **回覆本身不建立互相關注、師徒或同隊關係**，故後續訊息通常仍為陌生訊息。

## 使用者明示接受的已知風險

**陌生人可對同一對象無限發送訊息。** 移除騷擾的成本由**收訊方**承擔（須主動封鎖），
且封鎖為逐帳號，換帳號可再次發送。

助理原推薦 B（同一發送者對未回覆對象上限 3 則），理由為「不設限等於把成本丟給受害者、
且換帳號即可繞過封鎖」。**使用者選 A，理由為分區呈現已足夠、封鎖機制已存在。**
已於模型記為 `[已知風險]`，比照〈註冊獎勵可被多帳號刷取〉等既有條目的處理方式
—— **屬明示接受的取捨，非待辦事項，後續輪次不重提。**
