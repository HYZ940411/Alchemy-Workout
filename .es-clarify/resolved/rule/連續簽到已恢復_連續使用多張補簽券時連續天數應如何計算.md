# 釐清問題

同一次中斷連續使用多張補簽券補回多天時，最終的「連續天數」應如何計算？

# 定位

流程：補簽流程
元素：Rule：Event「連續簽到已恢復」的 Postcondition
細節：`補簽流程.md` L27–L28 兩條 Postcondition 的並存矛盾，以及
`02_Aggregate定義.md` L2163–L2164 同一組規則的複本。

**本題不是重問「可否使用多張」**。
`.es-clarify/resolved/rule/使用者已使用補簽券_同一次中斷可否使用多張補簽券.md`
已裁決選項 A（一張補一天、可用多張），該裁決成立不變；
本題補的是**該裁決留下的計算式空缺**。

# 白話說明

假設今天是 2026-08-23，某位使用者的情況是：

| 日期 | 狀態 |
|------|------|
| 08-15 / 08-16 / 08-17 | 已簽到（＝中斷前連續 3 天） |
| 08-18 / 08-19 / 08-20 | 未簽到（中斷） |
| 08-21 / 08-22 | 已簽到（中斷後已簽 2 天） |

他手上有 3 張補簽券，想把 08-18、08-19、08-20 三天全部補回來。
**補完之後他的連續天數應該是多少？**

直覺上答案是 8（08-15 一路連到 08-22）。但模型目前算不出這個數字：

```
L27  連續天數 ＝ 中斷前連續天數 ＋ 補回的天數 ＋ 中斷後已簽到的天數
L28  補簽券使用後，中斷前連續天數清空為 0
```

用第一張券補 08-18 時：3 ＋ 1 ＋ 2 ＝ 6，接著「中斷前連續天數」被清為 0。
用第二張券補 08-19 時，公式裡的「中斷前連續天數」已經是 0，
算出來變成 0 ＋ 1 ＋ 2 ＝ 3 —— **連續天數不升反降**。

還有一個更麻煩的情況：如果他只補回 08-18 這一天，08-19、08-20 仍然是洞，
L27 的公式依然會算出 3 ＋ 1 ＋ 2 ＝ 6，但實際上 08-19 那個洞把前後切開了，
真正的連續天數只有 2（08-21、08-22）。**公式對「補了但沒補齊」的情況會給出錯誤的大數字。**

# 多選題

| 選項 | 描述 | 推薦 |
|------|------|------|
| A | **逐日推算**：連續天數改為「從今日（或上次簽到日）往回數，連續有簽到紀錄的天數」，補簽只是往逐日明細補寫一筆，連續天數整個重算。中斷前連續天數退化為快取值，不再參與計算 | ★ |
| B | **整批延後清空**：把一次補多天視為一批操作，L27 的「補回的天數」＝本批補回的總天數，「中斷前連續天數」於整批全部完成後才清空為 0 | |
| C | **逐張遞增**：第一張券套用 L27 完整公式，第二張起改為「當前連續天數 ＋ 1」，每張各自結算 | |
| D | **維持現狀，改為單張限制**：推翻既有裁決，改回一次中斷只能用一張券 | |
| Short | 提供其他簡短答案（<=5 字） | |

# 推薦選項與理由

**推薦 A（逐日推算）。**

- **只有 A 能對所有情況算出唯一且正確的數字。** B 與 C 在「補齊整段中斷」時都能得到 8，
  但在「只補回中間一天、其餘仍是洞」時都會算錯（會把被洞切開的兩段硬加起來）。
  A 因為是逐日回溯，遇到洞自然停住，不需要另外寫例外規則。
- **這是連續天數／streak 類機制的通行做法**：業界普遍把 streak 定義為對逐日紀錄的衍生計算，
  而不是一個獨立維護的計數器。獨立計數器的問題正是本題——每多一條會改動它的路徑，
  就要多寫一條加減規則，規則之間遲早互相矛盾。
- **本模型的既有慣例支持 A**：`02_Aggregate定義.md` L2141 已經有「獎勵加成為連續訓練天數的**衍生值**」
  的先例，把可推導的數字定義為衍生值是本模型已採用過的手法。
- **代價**：A 需要有逐日簽到明細可查，因此與本輪的〈連續簽到_逐日簽到明細應由哪一個 Aggregate 承載〉
  為前置依賴關係，兩題須一併決定。若該題最終決定不建逐日明細，則本題只能退而選 B。
- B 為改動最小的選項（只改一句話、不動 Aggregate 欄位），若希望本輪不擴大改動範圍，B 是次選。

三個選項對範例情境（補回 08-18/19/20 三天）的答案：**A ＝ 8、B ＝ 8、C ＝ 8**；
但對「只補回 08-18」：**A ＝ 2（正確）、B ＝ 6（錯）、C ＝ 6（錯）**。

# 解決結果

**選項 A** —— 逐日推算。

連續天數改為衍生值：**自「上次簽到日期」起往回逐日檢視〈每日簽到紀錄 Aggregate〉，
連續有紀錄的天數即為連續天數，遇查無紀錄之日即停止。**
補簽不以加法回復連續天數，只是往每日簽到紀錄補寫一筆，連續天數隨之整個重算。

驗算（今日 2026-08-23，中斷前連續 3 天、補回 08-18/19/20、中斷後已簽 2 天）：
上次簽到日期＝08-22，往回 22→21→20→19→18→17→16→15，遇 08-14 查無紀錄停止 → **8 天**。
未補齊之情形（僅補回 08-18）：22→21，遇 08-20 查無紀錄停止 → **2 天**（加法公式會誤算為 6）。

**連帶裁決（使用者於本題一併裁決）**：
「**中斷前連續天數**」欄位**刪除**，連續簽到 Aggregate 由五欄位減為**四欄位**。
查證確認該欄位在模型中共 5 處引用，選 A 後全數失去讀取端：
欄位定義（用途字面即「供補簽回復使用」）、中斷時的寫入動作、不變條件、
`每日簽到流程.md` 的中斷 Postcondition、補簽頁的試算欄位。
「曾達到的最高連續天數」已由歷史最長連續天數承載，刪除不損失資訊。

**滿足第 2 題的可重入要求**：逐日推算為「由當前狀態重算」，
連補多天時每天觸發一次與整批觸發一次結果相同，第 2 題選項 A 成立，不需改選 D。
